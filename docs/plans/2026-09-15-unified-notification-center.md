## 数据与投递设计

通知权威状态位于 `dsh-trading-core` 的 SQLite 数据库。事件接收、站内消息、渠道任务和审计在同一事务中写入。事件以 `(producer, event_id)` 唯一；每类事件另有确定性聚合键和窗口。消息阅读状态与各渠道投递状态分离。

投递任务使用 `pending`、`leased`、`retry_wait`、`sent`、`dead_letter`、`suppressed`、`cancelled` 状态。worker 以事务领取租约，在事务外调用渠道，再以事务确认结果；进程重启会回收过期租约。临时错误采用有界指数退避，永久错误进入死信。外部渠道提供至少一次语义，模糊超时必须记录可能重复的审计。

浏览器订阅属于登录身份和设备。登录且已授权时恢复订阅，退出登录时停用。系统通知、浏览器通知、Server酱、企业微信与邮件只接收通知中心生成的脱敏投影，不接收任意 URL 或业务命令。

## 实施顺序

1. 新增通知领域类型、SQLite schema、仓储和应用服务；先覆盖幂等、阅读状态、偏好、租约、重试与恢复测试。
2. 在交易核心注册消息查询、状态变更、偏好、订阅、内部事件发布与投递 worker；扩展数据备份，恢复时不得重新激活历史投递。
3. 将现有 Server酱、企业微信、简报和闭环发送迁入统一通道；为邮件、Web Push 和 Electron 设备领取提供适配器。旧路径由单一切换配置控制，不与新路径同时外发。
4. 让 `market-watch` 在业务触发状态提交后发布结构化事件，并保留原冷却和每日上限。持仓同步只在权威快照提交后发布变化、失败、陈旧和恢复事件。
5. 扩展 Python Runtime 的固定请求白名单和 Electron 窄 IPC。实现顶栏未读下拉框与通知中心大模态框：桌面双栏，窄屏在同一模态框中切换列表和详情，设置作为同一表面的内部视图。
6. 完成聚焦测试、真实组合测试、类型检查和构建。worktree 中不启动共享服务；将实机浏览器、Electron、macOS 权限与外部渠道验证交给 `local-integrator`。

## 体验状态

首次加载、后台刷新、空数据、筛选无结果、部分成功、过期、可恢复错误、无权限、禁用、成功、确认和撤销均适用。下拉框只显示最近未读消息，打开不改变阅读状态；点击消息后大模态框定位详情并标记已读。通过“查看全部通知”打开时不自动选择或读取第一条。人工重试必须说明模糊超时可能重复发送。

## 验证范围

- Python：schema 迁移、事件幂等、聚合、分页、过滤、阅读和归档、偏好、并发租约、重启恢复、退避、永久错误、脱敏及备份恢复。
- 生产者：行情冷却和每日上限不变；简报、闭环和持仓只在业务提交点发布；新旧外发路径互斥。
- Host/Electron：固定请求白名单、浏览器订阅身份、退出失效、主 frame 校验、设备领取与确认、任意 URL 和命令拒绝。
- UI：下拉框、大模态框、列表与详情、过滤、设置、状态矩阵、键盘、焦点、撤销、长中文和大未读数。
- 组合：真实应用装配下从事件发布到站内消息和模拟渠道投递；worker 在领取后重启可恢复。
- UAT：由 `local-integrator` 使用独立数据和测试凭据检查 1440、1024、768、390px、明暗主题、浏览器后台推送、Electron/macOS 权限和真实渠道。

## 回滚与风险

生产者切换配置按来源在旧直推与通知中心之间二选一。回滚只切回旧路径并保留通知数据库，不执行破坏性降级。Web Push 受浏览器和系统能力限制；站内消息始终是权威记录。新增 SQLite 必须纳入状态目录、迁移和备份恢复；凭据、订阅私钥和完整敏感持仓不得进入消息正文或审计。
