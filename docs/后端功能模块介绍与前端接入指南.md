# 后端功能模块介绍与前端接入指南

> 面向：前端 / Electron UI 开发团队。本文把**后端当前已实现**的功能模块、设计思路、使用方式
> 一次性梳理清楚，直接照着连 UI。
> 端点级契约的唯一事实源是 [API-接口文档.md](API-接口文档.md)；本文是模块视角的导读 + 接入示例。
> 截止：2026-08-25，覆盖三服务当前全部路由。

---

## 0. 三服务全景

后端是三个独立 FastAPI 进程，全部本机部署、CORS 全开、JSON in/out、UTF-8：

| 服务 | 端口 | 职责 | 有无异步任务 |
|---|---|---|---|
| **trading-core** | **8000** | 主后端：分析 / 持仓 / 简报 / 回测 / 策略流 / 影子验证 / KYC / 个性化 / 风险预警 / 自进化 | 有（六类任务 + SSE） |
| **market-watch** | **8100** | 盯盘数据源：行情快照 / 预警规则 / 新闻速递 / 结构化事件 / 简报 / 扫描信号 | 无（全秒级同步） |
| **industry-chain** | **8200** | 产业链图谱：公司检索 / 单股五列产业链 / 多层上下游展开 / 全局网络切片 | 无（只读秒级） |

调用关系：`trading-core` 通过 HTTP 拉取 `market-watch /news/events`（事件源）和
`industry-chain /graph/chain`（事件影响图谱扩展）。前端**不需要**理解这些内部调用，
只需要把三个 base URL 配置好。产品壳的做法：

```js
PA.API = { tc: 'http://127.0.0.1:8000', mw: 'http://127.0.0.1:8100', ic: 'http://127.0.0.1:8200' }
```

## 1. 设计总则（前端必须理解的三件事）

### 1.1 三种交互面，超时策略完全不同

| 类型 | 特征 | 超时建议 |
|---|---|---|
| **同步短请求** | `GET/POST` 秒级返回：持仓 / 自选 / 风险偏好 / KYC / 各类查询 / 风险 / 进化 | 普通 10s |
| **同步慢接口** | `POST /strategies/hypothesize`：LLM 生成假设阻塞 **10–30s** | **≥60s**，别设短超时 |
| **异步任务** | `POST /analyze`、`/holdings/analyze`、`/brief`、`/backtest/run`、`/strategies/run`、`/shadow/run`：先拿 `task_id`，再订 SSE | SSE 长连接 |

### 1.2 六类异步任务共用一个 SSE 协议

所有长任务走同一套 `task_id → /analyze/{task_id}/stream`，事件类型统一：

```
event: pipeline  → 任务启动时一次，下发管道清单 {phases, total_steps}
event: stage     → 节点完成 {node_id, phase, status, step_index, elapsed_ms}
event: trace     → agent 产出内容摘要 {content_preview, content_len}
event: progress  → 进度百分比 {percent, phase}
event: result    → 最终结果 {signal, reports, ...}
event: error     → 异常 {message, node_id?}
event: done      → 流结束
```

15s 心跳保活。**重要**：SSE 传输层断开不代表任务失败——用轮询 `/analyze/{task_id}/result`
兜底（未完返回 409，done 后返回结果）。产品壳 `PA.runTask` 已实现这套逻辑，可直接复用。

### 1.3 数据与降级哲学

- **本地 JSON 持久化**：所有业务数据落 `data/adapter/*.json`，无数据库依赖，重启不丢。
- **单用户模型**：所有个性化数据用 `"default"` 键。未来多用户需在 key 加 user_id 前缀。
- **LLM 永远可降级**：假设生成、KYC 解析、卡片点评、事件抽取都有规则兜底；LLM 挂了返回
  规则结果或 `null`，**绝不 500、绝不阻塞主路径**。前端要把 `null` 当正常值处理。
- **外部依赖优雅降级**：`market-watch` 无事件 → 假设接口返回空列表 + note；`industry-chain`
  挂掉 → 事件保持原样（无 impact 字段），卡片/假设行为与没有图谱时完全一致。
- **幂等优先**：影子按 `trade_date` 幂等、进化按 `apply` 预览/写库、决策按 `ticker_date` 覆盖。

## 2. trading-core :8000 —— 模块详解

按「前端使用域」分组。每组给：**职责 · 端点 · 关键形状 · 设计要点 · 前端注意**。

### 2.1 基础数据：持仓 / 自选 / 风险偏好

| 端点 | 方法 | 说明 |
|---|---|---|
| `/holdings` | GET | 持仓列表。**注意：`name` 恒为空**——这是刻意设计（避免逐票打外部接口补名），前端自行补展示名 |
| `/holdings/save` | POST | 保存持仓（`HoldingsRequest`：`{holdings:[{ticker,quantity,cost_price}]}`） |
| `/watchlist` | GET | 自选代码列表 `{tickers:["600519",...]}` |
| `/watchlist` | POST | 整体替换自选 `{tickers:[...]}` |
| `/risk_profile` | GET | `{risk_profile, label}`，label 为 保守型/稳健型/进取型 |
| `/risk_profile` | POST | 持久化全局画像 `{risk_profile: "conservative"\|"balanced"\|"aggressive"}` |

**设计要点**：`risk_profile` 是全局下游唯一事实源——引擎基调、持仓预算、简报过滤、卡片匹配、风险预警全读它。前端修改它要小心，改画像 = 改全局行为。

**前端接入**：

```js
await PA.api(PA.API.tc, '/holdings/save', { holdings: [{ ticker: '600519', quantity: 100, cost_price: 1500 }] })
const { items } = await PA.api(PA.API.tc, '/holdings')   // items[].ticker/quantity/cost_price/name=""
```

### 2.2 KYC：风险偏好问卷 → 画像

| 端点 | 方法 | 说明 |
|---|---|---|
| `/kyc/profile` | GET | **前端唯一事实源**：现状 + 题组 schema + 阈值 + 三档画像详情（护栏/预算）。一次拉全，前端照此渲染问卷 |
| `/kyc/questionnaire` | POST | 提交问卷答案 → 计分 → 推断画像**立即写入** `risk_profile` |
| `/kyc/adjust` | POST | 滑块微调已推断画像（漂移后再次写入） |
| `/kyc/parse` | POST | 整段自然语言（语音/手打）→ 结构化问卷答案（LLM + 关键词降级） |

**KYC 与 risk_profile 的关系**（重要）：
- 问卷推断结果单独存 `preferences.kyc`，其中 `inferred_profile` 不被手动调整污染；
- 生效画像 = 最后一次写入的 `risk_profile`（可能被微调漂移）；
- UI 展示「推断 X，当前生效 Y」：用 `/kyc/profile` 的 `inferred_profile` vs `effective_profile`。

**前端接入（KYC 页三态）**：
```js
const view = await PA.api(PA.API.tc, '/kyc/profile')
// view.tiers.quick / tiers.full   → 题组 ID 列表
// view.question_bank[qid]         → {qid, title, options:[{label, score}]}
// view.profiles_detail            → 各档画像的护栏/预算，渲染「该画像下生效的护栏」卡
// view.status                     → not_started / completed / adjusted

// 提交问卷
await PA.api(PA.API.tc, '/kyc/questionnaire', {
  answers: [{ qid: 'horizon', label: '3个月以内', score: 1 }, ...], // 覆盖该档全部题
  tier: 'quick',                 // quick=三问速测 / full=8题完整
  method: 'questionnaire',       // 或 'voice'
})
```

### 2.3 任务式分析：个股 / 持仓 / 简报

| 端点 | 方法 | task_type | 说明 |
|---|---|---|---|
| `/analyze` | POST | stock | 单股深度分析（LLM，3–9 分钟） |
| `/holdings/analyze` | POST | holdings | 持仓分析（deep=逐股引擎慢，quick=秒级定量） |
| `/brief` | POST | brief | 盘前/盘后/当前简报 |

请求体各自见 `schemas.py`（`AnalyzeRequest`/`HoldingsRequest`/`BriefRequest`）。三者都走
「POST → task_id → SSE → result」流程。

**前端接入**：见 §2.9 的 `PA.runTask` 通用模板；`research_depth` 控制个股分析深度
（quick/basic/standard/deep/full），简报 `period` 取 pre_market/post_market/now。

### 2.4 简报查询与推送去重

| 端点 | 方法 | 说明 |
|---|---|---|
| `/brief/latest` | GET | 最近简报，5 字段：`{id, period, trade_date, summary, dsh_pushed}`；无简报时全空串 + false |
| `/brief/{brief_id}/dsh-pushed` | POST | 标记已在 dsh 对话内播报（幂等，供推送去重） |

**设计要点**：`dsh_pushed` 让「简报生成」与「对话播报」解耦——UI 收到简报后可主动 POST
标记已播，避免重复推送。

### 2.5 回测（基于历史决策的前瞻评估）

| 端点 | 方法 | 说明 |
|---|---|---|
| `/backtest/run` | POST | 异步任务（task_type=backtest）：收集决策 → 拉行情 → 逐条评估 → 聚合 |
| `/backtest/results` | GET | 最近运行记录（`?limit=`，created_at 倒序） |
| `/backtest/performance` | GET | 从 `decisions.eval_meta` 重算整体表现（`?code=` 可选） |

`/backtest/run` 关键参数（`BacktestRunRequest`）：`code`、`force`、`eval_window_days`、
`min_age_days`、`stop_loss_pct`、`take_profit_pct`、`neutral_band_pct`。默认止损 5% / 止盈 10%。

### 2.6 策略流（核心特色模块：事件 → 假设 → 回测 → 候选池 → 影子验证 → 自进化）

这是后端最有特色的纵向切片，前端做「策略研究」页要打通这条链：

```
market-watch 事件 ──fetch_events(TTL缓存)──> [E] 生成投资假设 (LLM/规则)
    ──> [G] 校验入库(candidate) ──/strategies/run──> [H] 回测(样本内70%/样本外30%)
    ──> 达标→active / 不足→candidate / 不达标→rejected
    ──> [I] 影子验证(active 逐日记账) ──> [T/W/H] 自进化(归因/升降级/变异回流)
```

| 端点 | 方法 | 说明 |
|---|---|---|
| `/strategies/hypothesize` | POST | 事件→假设→候选入库。**同步慢（LLM 10–30s）**。`{limit, dry_run}`；`dry_run=true` 只返回假设不落库，供前端预览 |
| `/strategies/run` | POST | 候选策略历史+样本外回测（异步任务 task_type=strategy）。`{strategy_id, lookback_years, oos_frac, initial_capital, min_oos_trades}` |
| `/strategies` | GET | 策略池列表（`?limit=`，created_at 倒序） |
| `/strategies/{sid}` | GET | 单条详情（含 `backtest`） |
| `/strategies/{sid}/{action}` | POST | 状态迁移：`activate`→active / `reject`→rejected / `retire`→retired |
| `/shadow/run` | POST | 影子验证（异步任务 task_type=shadow）：active 策略逐日记账，`{force, strategy_id?}` |
| `/shadow/status` | GET | 最近一次影子运行汇总（`shadows/latest`） |
| `/shadow/positions` | GET | 影子账户当前持仓（`?strategy_id=` 过滤） |
| `/shadow/equity` | GET | 影子净值历史（`?strategy_id=&limit=`，日期倒序，`overall_nav` + 每策略 `nav`） |

**三类策略（kind）与方向约束**：
- `ma_cross` 均线交叉（趋势跟随）、`rsi_reversal` 超跌反弹（利空强制）、`momentum` 动量；
- 系统**只做多**——利空事件强制转 `rsi_reversal`。

**假设数据结构**（`/strategies/hypothesize` 响应里 `hypotheses[]`）：
```json
{ "event_idx": 3, "symbols": ["600519"], "direction": "利好", "kind": "momentum",
  "params": { "n": 10 }, "rationale": "事件与假设的因果一句话", "holding_window_days": 20 }
```
`event_idx` 语义：指向后端内部事件表的下标，**前端不要拿它当事件 ID**；要用事件内容请走
`/news/events` 或卡片流里的 `source_event_id`。

**候选入库去重**：策略 id = md5(event_id + kind + 排序后 symbols)，同事件同参不重复入库。

**前端接入（策略页建议流程）**：
```js
// 1) 生成假设（dry_run 预览，不落库）
const { hypotheses, n_events } = await PA.api(PA.API.tc, '/strategies/hypothesize', { limit: 20, dry_run: true })
// 2) 用户选假设 → 真生成（落库）
await PA.api(PA.API.tc, '/strategies/hypothesize', { limit: 20, dry_run: false })
// 3) 回测（异步任务）
PA.runTask({ base: PA.API.tc, path: '/strategies/run',
  body: { strategy_id: 'strat-xxx', lookback_years: 2.0 },
  onStage, onResult, onDone })
// 4) 刷新池 → 看到回测结果（backtest.oos_win_rate / oos_avg_return / status）
// 5) 手动迁移
await PA.api(PA.API.tc, `/strategies/${sid}/activate`)
// 6) 影子验证
await PA.api(PA.API.tc, '/shadow/run', {})
// 7) 影子净值/持仓
const { items } = await PA.api(PA.API.tc, '/shadow/equity')
```

**状态机**（前端要渲染 badges）：`candidate`（待回测/回测中）→ `active`（通过样本外）/
`rejected`（不达标）；active 可被进化降为 `watch` 或 `retired`。回测达标线：
样本外成交数 ≥ 4 且胜率 ≥ 50% 且平均收益 > 0。

### 2.7 个性化右链：策略匹配 O + 资讯卡片 D/P + 行为捕获 R + 画像增强 K

| 端点 | 方法 | 说明 |
|---|---|---|
| `/personalized/matches` | GET | O：active 策略 × 画像 → 确定性推荐排序（0-100 可解释） |
| `/personalized/cards` | GET | D+P：个性化资讯卡片 feed（桶优先级 + relevance 排序） |
| `/personalized/interactions` | POST | R：view/click 阅读行为埋点（环形缓冲落 behavior.json） |
| `/personalized/interactions` | GET | 最近行为记录（时间倒序） |
| `/personalized/feedback` | POST | R：显式反馈 useful/useless（决策信号，影响排序/预警） |
| `/personalized/profile` | GET | K：画像增强——基础画像 + 行为推断（effective_aggression + 关注/方向/策略亲和） |
| `/personalized/impact` | GET | C 调试：事件影响图谱扩展结果（`?limit=`） |

**`/personalized/cards` 参数**：`limit`、`bucket`（all/holdings/watchlist/strategy/fresh）、
`match`（=1 仅命中关注）、`comment`（=1 附加 LLM 一句话点评）、`strategy_id`。

**卡片 item 形状**（前端渲染核心契约）：
```json
{ "card_id": "card-<md5>", "event_id": "ev-...", "bucket": "holdings|watchlist|strategy|fresh",
  "relevance_score": 87, "type": "...", "direction": "利好|利空|中性",
  "title": "...", "summary": "...", "time": "...", "source": "...", "url": "...",
  "tickers": [{"name": "...", "code": "..."}], "industries": ["..."],
  "impact": {"codes": ["603986"], "industries": ["半导体"], "by": ["688981 产业链: ..."]},
  "matched": {"holdings": ["600519"], "watchlist": [], "strategies": [{"id":"strat-...","nav":1.03,"closed_count":1}]},
  "risk": {"level": "中", "note": "..."},
  "reasons": ["命中持仓：...", "间接波及：..."],
  "llm_comment": null, "event": { /* 原始事件全文 */ } }
```
响应外层：`{as_of, profile, profile_label, effective_aggression, behavior, count, cards}`。

**排序规则**（前端可展示来源标签）：桶优先级 持仓 > 自选 > 策略 > 新鲜；桶内按
relevance_score 降序。`reasons` 前 3 条解释「为什么推给你」。

**行为埋点（R）**：卡片渲染后回传 `card_id`。`action=view` 每卡每会话一次、`click` 每次记。
`meta` 建议带上 `{bucket, ticker, strategy_id, direction}` —— `direction` 是关键，行为画像
据此推断方向偏差（aggression_delta）。旧记录无 direction，服务端按不参与处理，不报错。

```js
await PA.api(PA.API.tc, '/personalized/interactions', {
  card_id: 'card-xxx', action: 'click',
  meta: { bucket: 'holdings', ticker: '600519', strategy_id: 'strat-...', direction: '利好' }
})
// 显式反馈（可选）
await PA.api(PA.API.tc, '/personalized/feedback', {
  card_id: 'card-xxx', sentiment: 'useful',
  meta: { source: 'cards', ticker: '600519', direction: '利好' }
})
```

### 2.8 风险预警中心：组合风险 N + 四源预警 Q

| 端点 | 方法 | 说明 |
|---|---|---|
| `/risk/portfolio` | GET | N：组合风险模型——等权确定性估算（单股权重 / HHI 集中度 / 影子回撤波动）对比画像预算 |
| `/risk/alerts` | GET | Q：四源聚合预警（组合 + 影子 + 事件 + 画像），按严重度 高>中>低 排序 |

**`/risk/alerts` item 形状**：
```json
{ "id": "risk-<md5>", "source": "portfolio|shadow|event|profile",
  "severity": "高|中|低", "title": "单股权重超预算",
  "detail": "当前等权 100%，稳健型预算上限 25%（超 3 倍）",
  "codes": ["600519"], "strategy_id": null, "ts": "2026-08-25 10:00:00" }
```

**设计要点**：N 用等权确定性算法（无实时行情，秒级）；影子净值不足 2 日时回撤/波动记为
`null` + `data_note="数据不足"`，**不产出 0 值假预警**。`event` 源预警复用画像风险等级校准
（K 内嵌）。

**前端接入**：首页右列顶部放「⚠️ 风险预警」面板，按 `severity` 着色（高红/中黄/低灰），
行内 `source` 标签 + title + detail；60s 轮询刷新。

### 2.9 任务式接口统一接入模板（复用产品壳 PA.runTask）

```js
const cancel = PA.runTask({
  base: PA.API.tc,
  path: '/analyze',                          // 或 /holdings/analyze /brief /backtest/run /strategies/run /shadow/run
  body: { ticker: '600519', research_depth: 'standard' },
  onStage: (msg) => renderProgress(msg),      // SSE stage 事件消息
  onResult: (r) => renderResult(r),           // final result
  onError: (msg) => showError(msg),
  onDone: () => finish(),
})
// runTask 内部已把 cancel 注册进 PA.active；路由切换时统一 PA.active.forEach(c => c()) 取消，防 SSE 残留
```

`PA.runTask` 已处理：拿 task_id → 订 SSE → 解析 stage/result/error/done → **SSE 断开后自动
轮询 `/analyze/{task_id}/result` 兜底**（未完退避重试）。后端侧任务状态查询用
`GET /analyze/{task_id}`（pending/running/done/failed）。

### 2.10 自进化闭环：归因 / 升降级 / 变异

| 端点 | 方法 | 说明 |
|---|---|---|
| `/evolution/status` | GET | 闭环状态：影子数据是否就绪 + 策略生命周期统计 |
| `/evolution/attribution` | GET | T 归因：影子组合整体 + 每策略 收益/回撤/平仓胜率（只读） |
| `/evolution/run` | POST | 进化执行：`{apply: bool}`。false=仅预览返回 actions 清单；true=写库升降级/变异回流 |

**前端注意**：进化有护栏——影子净值不足 `EVOLVE_MIN_DAYS`（默认 5 日）时 `/evolution/run`
返回 `waiting_data` + 空 actions，不动作。UI 应优先展示归因，再给「预览」按钮，确认后再
`apply=true`。

## 3. market-watch :8100 —— 盯盘与事件数据源

纯同步、秒级、有 TTL 行情缓存。前端「盯盘/新闻/事件」页面直接连它。

| 端点 | 方法 | 说明 |
|---|---|---|
| `/overview` | GET | 盯盘面板：自选行情 + 主力净流入 + 命中/临近预警规则 |
| `/watchlist` /add `/remove` | GET/POST/POST | 自选管理 |
| `/alerts` | GET/POST | 预警规则列表/新增（`AlertRule`：field∈price/pct_change/volume_ratio/amount/turnover，operator∈>/>=/</<=） |
| `/alerts/{rule_id}` | DELETE | 删除规则 |
| `/scan` | POST | 市场扫描（`ScanRequest`：kind/top_n/min_amount_yi） |
| `/tech-signal` | POST | 单股技术指标 + 信号汇总 |
| `/news/express` | POST | 触发新闻速递抓取 |
| `/news/latest` | GET | 最近速递（无则 404） |
| `/news/flash` | GET | **实时快讯**：`?limit=&enrich=&personal=`；enrich=1 附加结构化事件与命中，personal=1 命中项置顶。前端滚动刷新 + 点开看全文就靠它 |
| `/news/events` | GET | **结构化投资事件**（trading-core 策略假设/卡片流的事件源）：`{as_of, count, items:[{id,type,tickers[],industries[],direction,summary,time,...}]}` |
| `/news/event-alerts` | GET | 事件预警中心：命中自选/持仓的事件 |
| `/brief/generate` | POST | 触发简报生成 |
| `/brief/latest` | GET | 最近简报 |
| `/scheduler/status` | GET | 定时任务状态 |
| `/scheduler/tick` | POST | 手动触发调度 tick |

**设计要点**：`/news/events` 的 `items[]` 是全部个性化/策略功能的**事件底座**——结构化字段
`type / tickers / industries / direction / summary` 是硬契约，前端若直接消费要注意字段存在。
LLM 抽取失败自动降级规则抽取，`direction` 可能为 中性。

## 4. industry-chain :8200 —— 产业链图谱

只读、纯内存图谱、数据懒加载。前端「产业链」页直接连它。

| 端点 | 方法 | 说明 |
|---|---|---|
| `/companies` | GET | 模糊搜索（`?keyword=` 名称/代码/行业，`?limit=`） |
| `/companies/{code}` | GET | 公司档案（404 表示不存在） |
| `/graph/entity/{key}` | GET | 通用实体档案 |
| `/graph/single/{code}` | GET | 单公司五列产业链：供应商 → 原材料 → 核心公司 → 主营产品 → 下游客户 |
| `/graph/chain/{code}` | GET | 多层上下游展开（`?depth_up=&depth_down=&top_up=&top_down=`，BFS 环回去重） |
| `/graph/network` | GET | 全局网络切片（服务端过滤后返回渲染子集，浏览器**不要拉全量**） |

**设计要点**：trading-core 通过 `/graph/chain` + `/companies` 给事件做「影响图谱」扩展（C），
前端不需要直接调这两端做这个事——看 `/personalized/cards` 里的 `impact` 字段即可。

## 8. 联调速查表（后端侧常见状态）

| 现象 | 原因/处理 |
|---|---|
| `/strategies/hypothesize` 返回 `note:"事件源暂无事件"` | market-watch :8100 未开或无新事件；TTL 缓存 60s 未过期也会吞新事件 |
| `/strategies/hypothesize` 卡 10–30s | 正常——LLM 生成假设阻塞 |
| SSE 流断开但任务在跑 | 传输层抖动，前端必须用 `/analyze/{id}/result` 轮询兜底 |
| 卡片 `llm_comment: null` | LLM 点评降级（正常，前端当普通卡片渲染） |
| 影子净值缺当日 | baostock 日线收盘后才出现当日 bar；当日重放只 mark-to-market，次日照常 |
| `/risk/portfolio` 回撤/波动为 null | 影子净值不足 2 日，`data_note` 有说明，不是 bug |
| 页面里策略 status=watch | 进化降级观察（仍 active 记账，但不再进推荐），UI 应灰显 |
