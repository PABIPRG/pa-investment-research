## 首阶段实现

1. 复用导入/重置事务的精确 before/after，在 finalize 清理前追加独立的私有持仓操作归档，不增加公开写入口。

3. 事务 UUID 为幂等身份；相同记录不重复写，不同内容不能覆盖；已归档 UUID 不得开启新事务。保留开始、局部提交、回滚及归档观察时间，旧事务缺少的时间维持 null。
4. 已配置 Host 协调目录时，成功归档必须核验该事务的全局 committed 决定；没有该目录的独立调用只记 backend-only，不冒称全局成功。审计失败保留原事务与恢复材料。
5. 归档不进入普通分类导入/导出或重置；部署整卷备份需包含它。默认仍为私有，后续公开投影不能透传原文。

## 第三阶段：日常持仓与成交留痕

沿用已分配的 worktree-writer、目录、分支和基准。范围为 JsonStore 持仓／成交写路径、传输门禁、启动恢复、固定字段公开投影、聚焦测试与本说明；不修改真实账户、部署或 Git 历史。界面复用既有操作列表／详情，验收端口仍为 3208／3209。

能力核查确认：手工持仓、手工成交、券商同步、CLI 都经过 JsonStore；`holdings.default`、`holdings.snapshots`、`holdings.manual_trades`、历史起点校正和 `trades.entries` 是本阶段监控事实。新增完整账户快照与重复同步没有这些事实变化时，不生成普通操作；历史补种和来源切换仅记为资料变化，不冒称发生买卖。业务文档内 outbox 会改变成交版本和备份格式，并被现有完整文档 transform 丢弃，因此选择存储层独立预写日志，不改变既有 JSON 契约。

实施顺序与恢复契约：

1. 根目录事务增加跨进程锁，串行化 CLI 与服务写入；匿名 GET 继续直接有界读取，不建锁、不执行恢复。
2. 正常写入之前恢复唯一 pending，再读取基线和执行变换；生成完整文档前后摘要与紧凑业务差异，先 fsync 意图，再原子替换业务文件。持仓保存前后状态；成交用多重集合差异，保留相同内容多笔，不反复复制全部历史。
3. 业务落盘后不可变归档。归档失败不伪报业务回滚，保留 pending 并记录告警；下一次写入、传输 prepare 与启动必须恢复。当前文档等于新摘要则补记，等于旧摘要则取消未生效意图；两者都不等则保留证据、阻止覆盖。公共读取遇 pending 明确暂不可用。
4. 导入／重置／回滚仍只使用原有传输终态归档，禁止把中间镜像写入普通操作历史。普通历史不进入分类备份或重置；恢复整卷需要包含审计目录。外部手改文件与恶意整卷回退不在此保证范围。
5. 公开仍由起始时间许可控制，固定文案区分持仓资料更新和成交记录更新，不披露私有标识、自由文本和路径；成交记录更新不冒充新执行交易或现金变化。沿用有界读取及容量失败关闭，不静默删历史；有界索引优化仍是发布容量门禁。

先失败回归覆盖普通入口、幂等、业务替换前／后的中断、归档重试、无法判定状态、传输抑制与多进程并发，再执行领域回归和真实公开入口验收。磁盘错误时的语义、Windows 锁与 Linux 容器验证分别记录，不以 macOS 通过推断所有平台。资金校准和导出完成事件仍由其各自事实所有者后续处理。

能力核查：完整 JSON 归档是不可变事实源；既有 SQLite 通知仓库可参考短连接／事务模式，但不能复用其数据库（生命周期、备份和数据所有者不同）。普通写入、传输 finalize 与私有启动恢复是已有唯一所有者入口。公开 GET 不得维护索引。新增可重建 SQLite 派生投影只保存白名单摘要和明细，不保存原始自由文本。

实施与恢复顺序：

1. 先写回归，证明大于旧容量的历史、有界查询、冻结翻页、许可变化和故障恢复。
2. 普通流程按业务落盘 → 归档 fsync → 索引提交 → 清 pending；传输流程在清事务前提交索引。索引失败保留恢复材料。私有启动／首次写入流式迁移旧归档，单事务重建；失败不替换已完整索引，未完成索引不公开。
3. 匿名连接使用 SQLite mode=ro、query_only、短超时和执行预算，不创建文件、不扫描归档；列表只取 limit+1 条摘要，详情按公开 ID 点查。索引损坏或缺失明确暂不可用，不静默截断历史。归档原文仍受单文件上限保护，累计数量不再限制公开容量。
4. 游标固定首屏入库上界，按标准化时间与公开 ID 键集翻页；系统快照仍受现有 366 条许可上限约束。绑定日期、筛选、许可起点、已验证快照集合和索引代次。用现有 cryptography 的 AES-GCM 隐藏私有序号并校验完整性；不自行实现加密。
5. 许可或索引代次变化返回脱敏 409，客户端清旧页／旧详情并重新读首屏；篡改返回 422。索引重建旋转代次与密钥。业务写锁先于 SQLite 锁，GET 不获取业务写锁。

验证覆盖普通／传输两条所有者路径、归档后索引前中断、索引后清理前中断、失败重建、超过 1000 条及 8 MiB 原文、同秒排序、插入回填、筛选／许可失效、无副作用读取、跨层 409 和实际页面恢复。浏览器用 3208／3209 临时数据；发布前 CI 重放、Linux 与真实 Host 编排债务不因本阶段自动关闭。

### 第四阶段验证结果

先失败证明不存在索引能力及页面不能自动处理失效游标，再完成实现。两轮独立只读复审发现并修复：首次建库失败后空库不能重试、SQLite hot journal 被私有只读检查卡住、授权元数据未签名、合法内容跨行拼接、签名与元数据未在 SQL 内限长。新增回归覆盖这些路径；子进程用未提交事务与 `os._exit` 制造真实 hot journal，确认匿名 GET 拒绝、私有 owner 恢复成功。最终安全与恢复复审均未发现剩余阻断；损坏 8 MiB 签名试验读取前拒绝，Python 峰值约 15 KiB。

自动化证据：十个相关 Python 模块首轮 154 项通过；最后增加跨行拼接回归并修改签名绑定后，索引／公开／传输三个受影响模块 39 项通过，随后索引 11 项再次通过。容量测试实际生成 1,100 份、累计超过 8 MiB 的私有归档，禁用 `os.scandir` 后完整读取 22 页，ID 无重复、无缺漏，GET 前后文件字节相同，索引与公开 DTO 不含私有 canary。新到及回填记录不混入已开始的分页。真实 YAML Loader → Host → Python 首轮 18 项（含网关单测）通过，末轮 7 项跨层通过，验证实际游标翻页、筛选失效、私有重建后 409、脱敏与 no-store。

前端 API 与实际 App 延迟响应回归共 10 项通过，包含 409 后清旧页、触发首屏读取、保持账户／活动分支独立。类型检查及生产构建通过；既有约 717 KiB 主包警告未扩大处理。`git diff --check` 通过。

## 第五阶段：导出文件完成留痕

延续同一 worktree-writer、路径、分支、基准与唯一写入代理，范围为 Host 备份生成及恢复、Python 私有确认与公开固定文案、测试和说明。关联 PAB-30；不部署、不操作真实账户、不改其他 worktree。能力核查、UI 交付与真实验收规范适用，布局和公开六类 GET 不增加。

| 用户动作 | 既有入口／事实所有者 | 缺口和副作用 | 决策 | 证据 |
|---|---|---|---|---|
| 生成持仓备份 | BackupService.create | 文件回读校验后才是完成；选名后原子覆盖存在同秒竞争 | Extend | backup-service.ts create、availableFilename |
| 导入／清空前自动备份 | importPreview/reset → create | 用途需要保留；reset 内部 exportSnapshot 仅为读取 | Reuse | 同一 Host 服务 |
| 下载或取消下载 | beginDownload/downloadChunk/cancelDownload | 只能证明服务端给出字节，不能证明浏览器保存成功，不新增完成事件 | Reuse | 既有下载状态机 |
| 崩溃／投递失败恢复 | Host transfer-transactions 与 Python pending/归档/index | 导出没有跨层持久回执；原 writeFileAtomic 不承诺 fsync | Extend | 私有协调目录、数据传输 token、既有留痕恢复 |

确定性边界：时间、文件哈希、大小、用途、确认、归档与重试由代码和落盘证据决定，不调用模型。导出不改变账户金额、持仓或盈亏。界面显示“持仓数据导出／导入前备份／重置前备份”，明确只确认备份文件生成及校验，不声明浏览器下载完成。

实现顺序：先失败回归；Host 生成并 fsync 唯一临时归档后，写持久 preparing 回执，再以不覆盖硬链接发布可读文件名；同秒冲突选择下一个名称。记录固定目录、文件身份、预期 SHA256／大小，回读精确匹配才发布 verified 回执。崩溃时只接受原始文件身份与内容证据，不重新导出当前数据代替历史；恢复核验时间只标记核验时间。已完成回执不依赖备份文件继续存在。

私有 `export-completed` 仅接收 UUID，沿用 Host Bearer 与共享协调目录核验完成回执；写既有不可变归档及索引，普通 pending 保证索引失败可恢复。Host 投递失败保留回执，成功后仅清投递材料；后台私有重试与业务入口恢复串行，卸载停止重试并等待在途工作退出。浏览器公共 GET 不参与恢复，撤销仍由 OPERATIONS_SINCE 控制。

状态矩阵：生成中沿用私有备份界面忙碌态；文件成功但留痕失败明确提示“已生成，留痕待恢复”，不删除文件；生成／核验失败不发布成功事件。公共加载、刷新、空数据、筛选、部分失败、过期、无权限、禁用和撤销沿用现有组件，本轮只新增成功摘要。无新公开确认或危险操作。验证导出、同秒并发、不覆盖、精确校验、回执后丢响应、重启幂等、目录切换、文件删除、伪造请求、非持仓备份与内部读取不误记，并用真实 Host→Python→观察室验证固定文案。CI 浏览器重放与 Linux／Windows 债务仍为发布门禁。

### 第五阶段实施与验证结果

实现复用 BackupService、私有数据传输鉴权、不可变操作归档及派生索引，不创建新的公开写接口或策略展示。新增 Host 私有导出回执协调器，固定 UUID／原路径／inode／大小／哈希，文件发布使用硬链接不覆盖；已验证的文件后来删除、目录设置改变、确认响应丢失均不会改写历史。Runtime 启动及 30 秒私有定时重试，不依赖观察室访客；单次确认默认 10 秒超时，均通过 Config 暴露。卸载中止请求并等待文件工作退出。

先失败证据：旧实现不投递完成事实，3 次同秒导出只有 1 个文件；旧后端没有确认端点。实现后保留导入前／重置前用途，内读 export、预览与下载取消不记成功。Python 严格接受单 UUID，读取固定目录内不超过 16 KiB 的已验证普通文件；错误 token、路径参数、未验证回执、错误用途、时间倒置、符号链接和超大文件拒绝。相同 UUID 不同内容拒绝且不覆盖历史。导出事件不写持仓／现金，索引故障可由既有 pending 恢复。
