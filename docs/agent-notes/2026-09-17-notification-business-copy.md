## 体验契约与复用审计

目标用户为查看研究持仓与通知的业务用户。通知需解释原因、持仓影响和下一步；主要操作必须抵达已有业务入口。取消读取不代表同步故障；系统通知发送状态不代表持仓更新状态。全局止盈止损只支持百分比，固定值以文字显示，计算说明通过共享 UI 库的图标与提示提供，并附成本价 100 元的计算例子。说明支持悬停、键盘聚焦及点击聚焦；不额外打开嵌套对话框。

| 用户动作 | 现有入口与状态所有者 | 缺口与证据 | 决策 |
|---|---|---|---|
| 理解风险画像建议 | PositionRiskDialog；KYC 的三档画像 | 直接显示 suggestion.profile | 扩展中文呈现 |
| 理解同步异常 | NotificationService / NotificationRepository；SQLite 事件 payload | sourceName 与 reasonCode 直接拼接，历史记录保存旧文案 | 扩展共享确定性呈现函数，读投影与新消息共用 |
| 从通知处理同步 | InvestmentUiState → ResearchWorkbenchPage → WorkbenchOverviewDialog → HoldingsEditor | holdings-sync 被映射到 portfolio 分析页 | 组合已有导航与同步面板，仅打开入口，不发起读取或保存 |
| 查看计算说明 | ui-primitives 的 Tooltip、Button、IconQuestionOutline14 | 全局固定计算方式仍呈现 disabled select | 组合现有组件 |
| 归档与撤销 | NotificationCenter 现有归档接口与撤销状态 | 按钮缺少用户要求的红色背景 | 复用行为，调整语义 token 样式 |

所有文案、导航、严重程度与计算说明均为确定性规则，不使用模型生成。业务状态由后端持有；新增导航请求只表达一次打开意图，重复同页点击可再次打开，离开路由后不保留旧入口。

## 实施与兼容

先补新旧通知、按钮目标、全局非选项与提示的失败断言；再实现后端统一文案、前端展示和导航；最后验证取消、超时、未知原因、同步不可用、重复进入与归档撤销。无数据库迁移，不改写历史事件、阅读状态或原始错误码。取消读取的历史记录通过读取投影显示为信息通知，筛选也采用同一严重程度语义。已发出的外部通知不能追溯修改，不重新发送历史消息。

## 状态与验证矩阵

| 状态 | 适用范围与处理 |
|---|---|
| 加载、后台刷新 | 沿用通知和持仓资源加载状态；等待持仓数据就绪后进入面板 |
| 空数据、筛选无结果 | 保留既有空态与筛选；不把未知状态当成功 |
| 部分成功、过期 | 原有持仓与渠道状态分别显示；不推断客户端当前健康程度 |
| 错误、无权限、不可用 | 按原因说明影响和恢复动作；不支持券商同步时显示原因并保留导入入口 |
| 禁用、成功、确认 | 保存期间保留禁用行为；跳转只打开入口，读取与导入仍需要原有用户动作 |
| 撤销 | 归档保留撤销，不改为删除 |
| 响应式、主题、键盘 | 复用既有双栏/窄屏布局和共享组件；需真实浏览器验证长文案、提示与按钮颜色 |
