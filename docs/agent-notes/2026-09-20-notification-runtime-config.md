## 实施顺序和安全契约

1. 增加受管配置快照和白名单校验。整个快照通过既有凭据服务原子保存，不回显秘密；不用通用 request-data 传机密。专用 Remote 限本机调用并要求 owned backend。
2. Host 启动受管后台时阻止外发，健康后发布配置并放行；保存和凭据更新时发布新快照。配置保存成功与应用成功分别报告，失败可再次同步，不伪装成测试成功。
3. 渠道配置带版本，队列目标绑定版本。发送前核对配置及类别偏好；变更/停用取消旧未发送任务，已发起网络请求不可撤回。测试只发固定非业务文案、只选单渠道、同一次请求幂等。
4. UI 先展示渠道配置与通知类型设置，后展示简短凭据获取帮助。秘密字段留空表示保留；查询只返回是否已保存。未配置引导配置，错误可重试，取消编辑不写入；不自动测试或改偏好。
5. 验证后端鉴权/持久化恢复/热更新/目标隔离/幂等，Host 凭据不泄漏与本机限制，前端表单及宽窄屏真实行为。真实渠道外发仅由用户显式触发；本轮用假适配器验证，不消费用户密钥。

## 状态与限制

适用状态：加载、刷新、空配置、已保存待同步、已启用未测试、测试排队/成功/失败/结果不确定、只读凭据源、保存失败、停用、移除确认和取消编辑。坏 JSON 或非法存储配置只阻断外发，不阻断持仓与研究后台，并可在应用内明确确认后重置。筛选无结果不适用；配置不做分页/过滤；不涉及 AI 推断，校验、状态和投递均为确定性逻辑。

复用的 credentials-local 在 POSIX 使用 0600 文件，但不是 OS 钥匙串加密，Windows 依赖用户目录 ACL；不得向用户宣称已加密。凭据不纳入业务数据备份。云端管理员配置与远程访问开放不在本轮范围。环境变量仅保留给非受管后端部署；受管桌面配置不通过 env 更新。

同一实例目录只支持一个 Host 配置写入方；同 Host 的多窗口保存受串行与旧版本检查保护，但不是跨进程文件 CAS，不支持两个 Host 或外部编辑器并发改写同一凭据目录。测试异常和过期租约（例如发送中进程退出）均不会自动重发；结果不确定时先由用户核对接收端。
