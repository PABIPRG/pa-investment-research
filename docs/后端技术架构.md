# 后端技术架构

> 面向：新加入的后端/全栈贡献者、维护者与评审人。
> 本文描述**后端是什么、由哪些进程组成、如何被上层调用、数据落在哪里**，并给出扩展一个新后端或新接口时必须守住的边界。
> 端点级逐字段契约以各模块 `docs/API-接口文档.md` 为唯一事实源；本文是架构视角的导读。截止：2026-10-08。

---

## 1. 范围与术语

| 术语 | 含义 |
|---|---|
| **三个 Python 后端** | `trading-core`(:8000)、`market-watch`(:8100)、`industry-chain`(:8200)，互相独立、各自 venv 与 `requirements.txt` |
| **Host** | deepseek-harness 的 Node 宿主进程；掌握端口、凭据、子进程生命周期与 operation 白名单 |
| **Client / renderer** | 浏览器或 Electron 渲染进程；只能提交「operation 名 + 白名单 JSON」，不能提交 base URL、端口、路径 |
| **operation** | 形如 `trading-core.analyze` 的稳定业务动作名，发布后视为兼容性契约 |
| **sidecar** | Electron / 容器打包时内置的「Python 解释器 + 三个后端 + 依赖」只读闭集，带 SHA-256 清单 |
| **lease（租约）** | Host 对某个后端的引用计数句柄；最后一个租约释放时才停掉自己 `owned` 的子进程 |

后端**不是**单体：它是「多智能体引擎 / 盯盘数据源 / 产业链图谱」三个 Python 进程，被同一个 Host 桥接层按固定白名单调度，并共享同一份持久卷。

## 3. 进程与生命周期模型

### 3.1 三种所有权（ownership）

Host 为每个后端维护 `InvestmentBackendDefinition`（[types.ts:264](../frontend/packages/investment-research/python-runtime/src/types.ts#L264)），由业务插件的 `mode` 决定：

| mode | 行为 | 健康探测失败时 |
|---|---|---|
| `managed`（默认） | 校验回环 URL → 解析后端目录（不依赖调用方 cwd）→ 校验 venv 解释器 → 探测 `/health` → **仅在连接被拒时**才拉起 uvicorn | 未知网络错误 / 端口被占 / 服务身份不符 → **启动失败，且不碰应答进程** |
| `external` | 接受 http/https，校验配置的健康身份，返回 `external` 租约 | 只在启动、信号、停止上完全不管该服务 |

租约来源进一步区分：

- `attached`：spawn 之前就发现了一个健康服务；
- `owned`：由 `ctx.subprocess` 拉起的子进程；
- `external`：外部托管。

**释放规则**：最后一个租约释放时只停掉内存中的 `owned` 句柄；`attached` 与 `external` 存活。Runtime dispose 会先拒绝新工作、等在途 acquire 结束，再 join 所有 owned 进程树。同一 backendId 的并发 acquire 共享一次启动；健康结果在 `healthFreshnessMs`(默认 5000ms) 内可复用，过期后并发请求共享一次探测。同 id 但 command/URL/mode/identity/path 冲突的注册会失败。

**状态文件只是诊断记录，永不授权 PID/端口接管**——不要用「杀掉占端口的进程」来绕过健康身份校验。

### 3.2 三种部署形态

| 形态 | 后端从哪来 | 解释器 | 备注 |
|---|---|---|---|
| **源码开发** | 从已安装包向上发现 `backend/dsh-trading-core`、`backend/market-watch`、`backend/industry-chain` | `<projectDir>/env/bin/python`（POSIX）/ `env\Scripts\python.exe`（Windows） | 需先 `pnpm run investment:python:init`；`verify` 只报告缺失不安装 |
| **Electron 桌面包** | 打包内置 sidecar，入口 `Resources/investment-python/runtime.json` | sidecar 内固定 Python 3.10.x | 打包启动**离线且不安装/修复依赖** |
| **容器云（cloud-web）** | 同一个容器内，仅容器回环可达 | sidecar | 单实例 + 单持久卷，见 §9 |

解析优先级是**严格有序**的：显式绝对 projectDir/解释器 > sidecar `runtime.json` > 源码 checkout。显式候选非法时**直接失败，不回落**。

### 3.3 端口与启动脚本

| 端口 | 模块 | uvicorn 模块串 | 启动脚本 |
|---|---|---|---|
| 8000 | dsh-trading-core | `adapter.app:app` | `backend/dsh-trading-core/start.sh`（`start_all.bat`） |
| 8100 | market-watch | `market_watch.app:app` | `backend/market-watch/start.sh` |
| 8200 | industry-chain | `industry_chain.app:app` | `backend/industry-chain/start.sh` |

根入口统一在 `start.sh`（`scripts/main.sh` 注册）：`init`、`investment-web`、`investment-electron`、`investment-package`、`backend-start`、`backend-stop`、`sync-upstream`、`demo-evolution-data`。产品入口会自己托管并清理后台；`backend-start` 只用于独立调试，进程会跨 Web/Electron 生命周期存活，需 `backend-stop` 显式停止。三服务串行启动并在失败时**回滚**本次已启动的服务（[start-investment-backends.sh](../scripts/start-investment-backends.sh)）。

## 4. 调用契约层（最重要的一层）

### 4.1 operation 白名单

浏览器提交的是 `{ operation, input }`，operation 是**闭集联合类型** `InvestmentDataOperation`（[types.ts:114](../frontend/packages/investment-research/python-runtime/src/types.ts#L114)），当前 100+ 项，按 `trading-core.` / `market-watch.` / `industry-chain.` 前缀分段。

命名与约束：

- 格式 `<backend-id>.<business-action>`；表达业务能力，不暴露 HTTP 路径；
- 发布后视为兼容 contract：**后端改路径不改 operation**；
- 禁止 `request`、`proxy`、`fetch-url` 之类泛化名。

Host broker 的 `SPECS` 表把每个 operation 映射到固定 `backendId / method / path`（[data.ts](../frontend/packages/investment-research/python-runtime/src/data.ts)）：

- 所有 input key 必须经 `knownKeys()` 显式列出，未知字段**在获取租约前**就拒绝；
- 数字有 min/max/default，枚举做闭集校验，query 一律走 `URLSearchParams`；
- 写请求只重建允许字段，**不整包透传** input；
- 成功、失败、取消三条路径都必须释放 lease。

**双构建坑（务必记住）**：`build:lib` = `build:lib:host` + `build:lib:client`。operation 白名单被编译进两面产物——host 侧（跑在 Host 里的 dsh）与 client 侧（Electron renderer）。新增/修改 operation 后**必须两个构建都重跑**，否则会有一侧白名单静默拒绝请求。

### 4.2 三条消费链路，同一个 HTTP 契约

同一个 Python 端点可以被三条链路消费，但不能互相替代：

1. **页面读取/写入**：Host operation 白名单 → broker → HTTP；
2. **模型工具**：业务插件在 `frontend/packages/investment-research/{market-watch,stock-analysis}` 注册正式工具，由模型在会话中自主调用；
3. **独立 Python 客户端/对话插件**：`adapter_client/`（Python SDK）与各模块 `dsh-plugin/`（Cordis TS 插件）直接调 HTTP。

页面接口不能替代模型工具；UI 也不能绕过正式会话管线（模型选择、附件、审批、发送策略）直接发请求。

### 4.3 异步任务与 SSE 协议

六类长任务（`analyze` / `holdings/analyze` / `brief` / `backtest/run` / `strategies/run` / `shadow/run`）共用一条通道：

```text
POST /...  →  { task_id }
GET  /analyze/{task_id}/stream        # SSE，事件类型统一
GET  /analyze/{task_id}               # 状态：pending/running/done/failed
GET  /analyze/{task_id}/result        # 未完 409，done 后返回结果
```

SSE 事件类型：`pipeline`（管道清单 `{phases,total_steps}`）、`stage`（节点完成）、`trace`（agent 产出摘要）、`progress`、`result`、`error`、`done`；15s 心跳保活。

**关键约定**：SSE 传输层断开 ≠ 任务失败。前端必须用 `/analyze/{task_id}/result` 轮询兜底（产品壳 `PA.runTask` 已实现退避重试）。任务态**只在内存**（`TaskManager`，[analyzer.py](../backend/dsh-trading-core/adapter/analyzer.py)），重启即失；成功任务的报告正文落 `reports.json` 可回查。

### 4.4 超时与交互面分类

| 类型 | 代表接口 | 建议超时 |
|---|---|---|
| 同步短请求 | 持仓、自选、风险偏好、KYC、各类查询 | 10s |
| 同步慢接口 | `POST /strategies/hypothesize`（LLM 阻塞 10–30s） | **≥60s** |
| 异步任务 | §4.3 六类 | SSE 长连接 + 轮询兜底 |

## 5. 模块详解

### 5.1 dsh-trading-core（:8000）—— 引擎 + 主后端

**定位**：`tradingagents/`（多智能体引擎）+ `adapter/`（FastAPI 适配器，46+ 端点 + 通知中心约 19 个 + 数据迁移 7 个）+ `dsh-plugin/`（对话插件外壳）。引擎/适配器本体不是 dsh 插件，`dsh-plugin/` 才是。

**多智能体 Graph（LangGraph）**

```text
START → 4 位分析师（Market / Social / News / Fundamentals，
        每位 = Analyst ⇄ tools_* 条件循环 → Msg Clear，按 selected_analysts 串联）
      → Bull ⇄ Bear 多空辩论（should_continue_debate，达 max_debate_rounds 转下）
      → Research Manager → Trader
      → Risky ⇄ Neutral ⇄ Safe 风险辩论（should_continue_risk_analysis）
      → Risk Judge → END
```

节点步数 `total = n_analysts + max_debate*2 + 1 + 1 + max_risk*3 + 1`（`adapter/engine_bridge.py::pipeline_manifest`）。编排实现见 `tradingagents/graph/{trading_graph,setup,conditional_logic,propagation,reflection,signal_processing}.py`；分析师/研究员/经理/风控/交易员见 `tradingagents/agents/`。有 `progress_callback` 时用 `stream_mode="updates"` 出节点级进度。**每个任务独立建图**，避免共享 state 并发污染。

**adapter 内部职能分组**（`backend/dsh-trading-core/adapter/`）

| 领域 | 代表文件 |
|---|---|
| 引擎桥接与任务 | `engine_bridge.py`、`runner.py`、`analyzer.py`（含 `TaskManager`） |
| 持仓与成交 | `holdings_*.py`、`holdings_providers/`、`trades_*.py`、`manual_trades.py`、`trade_dedup.py`、`trade_profile.py` |
| 策略 / 回测 / 影子 | `strategies.py`、`backtest_*.py`、`shadow*.py`、`decision_recorder.py`、`ledger.py` |
| 自进化闭环 | `evolution*.py`、`genome.py`、`gene_archive.py`、`fitness.py`、`recombine.py`、`priors.py`、`regime.py`、`governance.py` |
| 个性化与画像 | `personalize.py`、`behavior_profile.py`、`risk_profiles.py`、`kyc.py`、`impact.py` |
| 风险与组合 | `risk_engine.py`、`position_risk.py`、`portfolio_performance.py`、`portfolio_price_cache.py` |
| 简报与通知 | `brief_engine.py`、`report_store.py`、`notifications/`、`push/` |
| 数据与配置 | `store.py`、`data_transfer.py`、`config.py`、`schemas.py`、`llm.py` |

**策略流（最有特色的纵向切片）**

```text
market-watch 事件 ──fetch_events(TTL 缓存)──> 生成投资假设（LLM / 规则兜底）
  ──> 校验入库(candidate) ──/strategies/run──> 回测（样本内 70% / 样本外 30%）
  ──> 首次回测完成即 candidate→active（无论是否达标，结论记在 verification_status）
  ──> 影子验证（active 逐日记账）──> 自进化（归因 / 升降级 / 变异回流）
```

- 六类策略 `kind`（[strategies.py:35](../backend/dsh-trading-core/adapter/strategies.py#L35)）：`ma_cross`（均线交叉/趋势跟随）、`momentum`（动量）、`breakout`（通道突破）、`volume_breakout`（放量突破）、`rsi_reversal`（超跌反弹）、`bollinger`（布林下轨回归）。全是只做多的规则信号；**利空事件只允许 `rsi_reversal` / `bollinger`**，拿到其它 kind 会被强制改写。
- 候选去重：主键 `strategy id = md5(event_id + kind + 排序后 symbols)`，另有一层「kind+symbols+direction+params+hypothesis+持仓窗口」的语义指纹去重，避免跨事件复制同一条可执行假设。
- 回测达标线：样本外成交数 ≥ 4 **且** 胜率 ≥ 50% **且** 平均收益 > 0；达标与否只影响 `verification_status`（`passed` / `not_passed` / `insufficient`），**不影响 `status`**——`active` 只代表「已回测、仍参与」。
- 状态机：`candidate → active / rejected`；active 可被进化降为 `watch`（仍记账但不进推荐）或 `retired`。
- 进化有护栏：影子净值不足 `EVOLVE_MIN_DAYS`(默认 5) 时返回 `waiting_data` + 空 actions，不动作；`/evolution/run` 支持 `apply=false` 预览。

**风险偏好是全局唯一事实源**：引擎基调、持仓预算、简报过滤、卡片匹配、风险预警全读 `risk_profile`。解析优先级「请求参数 > 已保存偏好 > `.env RISK_PROFILE` > balanced」，引擎决策再经 `risk_profiles.calibrate_stock_decision` 做确定性护栏修正。KYC 推断结果单独存 `preferences.kyc`，`inferred_profile` 不被手动微调污染；生效画像 = 最后一次写入的 `risk_profile`。

**LLM 两条路径**：① 引擎路径 `engine_bridge.py` 强制 `llm_provider=deepseek`、并显式覆盖 `backend_url` 指向 DeepSeek（否则会误发 api.openai.com），底层走 `tradingagents/llm_clients/factory.py`；② 轻总结路径 `adapter/llm.py` 用 `openai.OpenAI` 直连，仅供简报/持仓总结等结构化→Markdown 轻任务。

**`ADAPTER_RUNNER`**：`fake` 只把 `stock/holdings/brief` 三个 runner 换成假实现；`backtest/strategy/shadow` **恒走真实纯逻辑**（pandas+baostock，无 LLM）。联调神器。

### 5.2 market-watch（:8100）—— 盯盘与事件数据源

**定位**：纯同步、秒级、TTL 缓存。设计基调是「**数据源多级降级 + 短 deadline + TTL/stale-while-revalidate 缓存 + single-flight**」，保证 UI 永不被慢数据源卡死。共 28 个业务路由 + 7 个数据迁移路由（后者需 `Authorization: Bearer <DSH_DATA_TRANSFER_TOKEN>`）。

**五块能力**

| 能力 | 实现要点 |
|---|---|
| 条件触发告警 | `rules.py` 字段 `price/pct_change/volume_ratio/amount(亿)/turnover`，AND/OR；涨跌停按板块 10/20/30/ST 5%；「逼近」启发式 = 阈值的 90%/110%；`scheduler.py` 用 `JsonStore.mutate` 原子检查冷却/日上限；命中后 best-effort LLM 解读（≤80 字）拼进推送 |
| 异动扫描 | `scanner.py` 五类 `gainers/volume_ratio/limit/turnover/amount`；东财 clist 服务端排序为主，新浪 `Market_Center` 降级（不支持 volume_ratio）；scan 缓存 15s/fresh、300s/stale |
| 技术信号 | `indicators.py` 纯 pandas 算 MA/MACD/RSI/KDJ/BOLL/支撑压力/量价形态；K 线三态合同 `ready/preparing/unavailable`（冷请求超 2.5s 返回 202 preparing）；K 线源**新浪 → 东财 push2his → baostock**，baostock 用 `multiprocessing spawn` 子进程隔离全局 socket |
| 新闻与事件 | 实时快讯跨源聚合（新浪 7x24 / 财联社 / 华尔街见闻 / IT之家 / 36氪 / 虎嗅 经 Google News RSS，走 `MW_FLASH_PROXY`）；`events.py` 用 LLM 抽 `type/tickers/industries/direction/summary`，失败**自动降级规则抽取**；定向个股新闻走东财搜索 JSONP（`curl_cffi` 指纹模拟）；事件预警命中自选+持仓（持仓从 trading-core `/holdings` 拉，60s 缓存） |
| LLM 简报 | 盘前 08:50 / 盘后 15:30（`TIMEZONE=Asia/Shanghai`，默认关闭）；无 LLM 走 `_fallback_brief` 纯数据模板 |

**后台任务**：APScheduler `BackgroundScheduler`（`watch-poll` 30s、可选 `news-express`、`pre-brief`、`post-brief`）；app.py 常驻 `event-warm` daemon 线程（45s 增量续热事件缓存）；news 的 `flash-refresh`/`flash-source`/`directed-news` 与 quotes 的 `kline-refresh`/`quote-name` 线程池——全部在 shutdown 收敛。

**降级哲学的一处硬契约**：`/news/events` 的 `items[]` 是全部个性化/策略功能的**事件底座**，字段 `type / tickers / industries / direction / summary` 是硬契约；LLM 抽取失败自动降级规则抽取，`direction` 可能为「中性」。

### 5.3 industry-chain（:8200）—— 产业链图谱 + 自建研报管线

**定位**：只读、纯内存图谱、懒加载。数据来自 iducsite 种子（约 1297 家核心公司、8600+ 实体），外加自建的三条离线管线。

**读路径**（在线）：`app.py` → `graph.py`（首次访问懒加载 + 模块级缓存 + `threading.Lock`，派生索引全部 `lru_cache`）→ `invalidate()` 由 bootstrap/delete 触发。核心设计是**关系权重溯源** `_relation_weight()`：

| provenance | 语义 | 合并优先级 |
|---|---|---|
| `disclosed` | 研报明确披露占比（**0 也保留**） | 最高 |
| `default` | 上游默认（上游 20 / 下游 10） | 中 |
| `inferred` | LLM 推断边，`share` 置 null | 最低 |

`/graph/network` 在**服务端过滤并瘦身**（`_slim_node`），避免前端拉 14.8MB 全量。

**写路径**（离线 CLI，三段式、幂等、可分段重跑）：

```text
scripts/build_report_pipeline.py
  ① 抓取  reports.py：东财 reportapi 研报列表 → 详情页正则抽正文（串行限速 ≥0.6s、退避）
  ② 抽取  extract.py：DeepSeek chat_json（temperature 0、json_object、重试 2）→ _normalize 规整
  ③ 合并  merge.py：幂等并入 data/reports/overlay.json（按 name 去重追加）
         → graph._view_merged() 把 overlay 叠加到每公司记录，overlay 独立可整体回滚
```

**全 A 股扩充**：`universe.py` 从东财 push2delay `clist` 分页拉全量（约 5900 家）→ `a_share_universe.json`；`build_llm_links.py` 对约 3692 家孤立股按行业分批推断供应链边（断点续跑、置信度阈值 0.5）→ `a_share_llm_links.json`；布局按行业簇网格装箱，`crc32` 稳定着色。

**种子下载**：`seed_data.py::SeedDataManager` — `status()` 只校验磁盘不联网；`bootstrap()` 下载五文件到临时目录 → 校验大小上限（64MB/文件、128MB 总）、JSON 合法性、最低结构 → 原子 `os.replace` 发布（失败回滚）；并发请求经 `threading.Condition` 复用同一任务；`delete()` 拒绝下载中删除。**健康检查与数据就绪解耦**：数据缺失返回 503，但 `/health` 恒 200。

## 6. 数据与持久化

### 6.1 原则

- **无数据库依赖（除通知中心）**：统一 `JsonStore` —— 同一进程内同路径实例共享一把锁；依据旧值写新值必须走**锁内单 key `mutate`**（不得在调用方分离 `get`/改/`set`）；写临时文件 + `os.replace` 原子提交；文件不存在 = 无状态，但 **JSON 损坏/编码错误/顶层非对象必须显式失败并保留原文件**，不得静默退化为空。
- **单用户模型**：个性化数据统一用 `"default"` 键；未来多用户需在 key 加 user_id 前缀。
- **任务态在内存**：`TaskManager` 重启即失，成功报告正文落盘可回查。
- **整体替换接口**必须区分「字段未提供」与「显式空列表」（后者用于清空集合）。

### 6.2 数据目录

源码模式：各模块内 `data/`。打包/容器模式：由 `DSH_INVESTMENT_STATE_DIR`（必须绝对路径）重定向，Host 管理的三个后端分别收到：

```text
$DSH_HOME/investment-research/trading-core
$DSH_HOME/investment-research/market-watch
$DSH_HOME/investment-research/industry-chain
```

### 6.3 落盘清单

| 模块 | 文件 | 内容 |
|---|---|---|
| trading-core | `data/adapter/*.json` | `holdings` `watchlist` `preferences`(risk_profile/KYC) `briefs` `reports` `decisions` `strategies` `strategy_backtests` `backtests` `shadows` `shadow_equity` `shadow_tasks` `behavior` `events_ledger` `market_index` `market_regime` 等 |
| trading-core | `data/notifications.sqlite3` | **唯一 SQLite**：统一通知权威记录 + 外部渠道持久投递队列 |
| market-watch | `data/*.json` | `watchlist` `alerts` `news` `briefs` `events`(latest+seen_ids) `event_alerts` `state`(cooldowns/daily_counts/triggers) `position_risk_rules` `position_risk_deliveries` `notifications` + `_transfer_transactions/` |
| industry-chain | `data/seed/` | 5 个种子 JSON（约 25MB） |
| industry-chain | `data/reports/{code}/` | `*.html` + `meta.json` + `extracted.json`，以及 `overlay.json` |
| industry-chain | `data/a_share_universe.json`、`data/a_share_llm_links.json` | 全 A 股清单（约 5900）与 LLM 推断 A→A 边 |

**缓存（内存态，重启即失）**：trading-core 走 `TA_CACHE_STRATEGY=file`（`tradingagents/dataflows/data_cache/`，gitignore）；market-watch 各数据源 TTL（快照 60s、K 线 fresh/stale 60/1800s、scan 15/300s、flash 15/300s、事件 300s 等）。

## 7. 配置与密钥

**加载顺序**（三模块一致）：shell 环境变量 > 用户配置 > 模块 `.env` > 代码默认（`load_dotenv(override=False)`）。

| 模块 | 前缀 | 必读键 |
|---|---|---|
| trading-core | 无前缀 / `DSH_*` | `DEEPSEEK_API_KEY`、`DEEPSEEK_BASE_URL`、`ADAPTER_RUNNER`、`DEFAULT_CHINA_DATA_SOURCE`、`HOLDINGS_PROVIDER`、`EVOLVE_*`、`CLOSED_LOOP_ENABLED`、`SHADOW_SCHEDULE_ENABLED`、`DSH_INVESTMENT_STATE_DIR` |
| market-watch | `MW_*` | `MW_LLM_ENABLED`、`DEEPSEEK_API_KEY`、`MW_SCHEDULE_ENABLED`、`MW_POLL_INTERVAL`、`MW_QUOTE_CACHE_TTL`、`MW_FLASH_*`、`MW_KLINE_*`、`MW_EVENT_*`、`NO_PROXY`（**必须含 eastmoney 域**）、`MW_FLASH_PROXY` |
| industry-chain | `IC_*` | `IC_HOST/IC_PORT`、`IC_DATA_DIR`、`IC_SEED_BASE_URL`、`IC_DEEPSEEK_API_KEY`、`IC_LLM_MODEL`、`DSH_INVESTMENT_STATE_DIR` |

**凭据流转（安全要点）**：`DEEPSEEK_API_KEY` 只以 Models 设置页为唯一产品入口，凭据 provider 仅在 **owned managed 子进程 spawn 时**解析引用，并且只转发给显式声明允许的后端定义。**密钥值绝不写入后端 `.env`、Runtime 状态、日志、readiness 快照或 Client Remote 数据**。`attached` / `external` 端点拿不到本地凭据（由该服务自己运营方负责）。更新 Key 会把活跃 owned 后端标记为 `restart-required`，在完成静默重启前，新的 LLM 依赖调用会在 preflight 失败，非 LLM 操作按能力声明继续可用。

> ⚠️ **现状风险**：`backend/*/.env` 中目前明文写有真实 DeepSeek Key（文件已 gitignore，但一旦曾误提交即视为泄露）。建议轮换并改为宿主注入，文档与提交中不得引用其值。

## 8. 可观测性

- **健康检查必须校验服务身份**，不能只返回无区分度的 200。容器聚合健康检查逐服务校验：
  - web：`/healthz` → `status === 'ok'`
  - trading-core：`/health` → `status === 'ok' && service === 'trading-core'`
  - market-watch：`/health` → `ok === true && service === 'market-watch'`
  - industry-chain：`/health` → `ok === true && service === 'industry-chain'`
  （见 [investment-healthcheck.mjs](../containers/investment-healthcheck.mjs)）
- **启动脚本**均在拉起后轮询 `/health` 最多 120s 判定就绪。
- **readiness 投影**：`InvestmentReadinessSnapshot.backends[]` 给设置页展示 ownership / backendStatus / credential status / capability status + toolCount / restartRequired / runtimeLogPath（**Cloud Web 不返回日志路径**）。能力档位：`stock-full` / `market-template-only` / `market-full` / `industry-full` / `unavailable`。
- **日志**：`logs/adapter.log`（三模块同构）；Host 侧另有有界 tail（`logTailBytes`）与单文件轮转（`logMaxBytes` 4MB）。
- **任务进度**：SSE `stage/trace/progress` 事件即进度观测面。

## 9. 部署形态

### 9.1 Electron 桌面包

`./start.sh investment-package` 打包：内置 Python 3.10.x sidecar（`investment:sidecar:build`），输出 ZIP。sidecar descriptor 是**固定、完整、带 SHA-256 的闭集**——每个常规文件都必须登记哈希，路径必须留在 sidecar 根之下，缺失/多余/符号链接/被改动都会在 Python 启动前判定「安装已损坏」。打包启动**离线且不安装、不修复依赖**。

### 9.2 容器云（cloud-web）

- 单容器 `investment`，内部包含 Node Host + Web 前端 + 三个 Python sidecar；**不拆成多实例**。
- 安全基线（`compose.yaml`）：`read_only: true`、`cap_drop: ALL`、`no-new-privileges`、`pids_limit`、`init: true`、非 root `10001:10001`、`DSH_WEB_AUTH=required`、`DSH_WEB_INSECURE_COOKIES=0`、tmpfs 挂 `/tmp` 与 `/run/dsh`。
- 端口只发布到 `127.0.0.1:${PORT:-3080}`；公网只开 80/443，由同机反向代理终止 TLS（`DSH_WEB_TRUSTED_HOSTS` 为真实 authority，`DSH_WEB_TRUSTED_PROXIES` 为反向代理**精确源 IP**）。
- **唯一持久卷** `dsh-data` → `/var/lib/dsh`（即 `$DSH_HOME`）：设置、profile、会话、附件、storage、投研备份与三个后端状态全在其中。**禁止** `docker compose down -v`，禁止删 `.container-instance.lock` / `application.lock` 绕过单实例保护，禁止新旧容器共享同一卷。
- 升级/回滚：镜像身份固定到不可变 digest 或完整 commit SHA，**禁用 `latest`**；若新版本已写入或迁移数据，不能只回退镜像，必须先停全部进程 + 恢复整卷备份。
- 完整契约见 [云端部署指南](云端部署指南.md)、[容器部署与回滚](maintainers/容器部署与回滚.md)、[单实例数据目录与迁移](maintainers/单实例数据目录与迁移.md)。

## 11. 安全边界（合并前逐项确认）

- 浏览器不能传 `baseUrl`、port、path、method 或任意 URL；
- operation 是闭集，Host 中每项都有固定 backend 与 route；
- input 拒绝未知 key、错误类型、越界数字、非法枚举；写请求只重建允许字段；
- 非 2xx 响应详情有长度上限，错误中无密钥；Client snapshot 与 response 不含凭据值；
- managed child 的凭据只由 Host credential service 注入；
- 成功、失败、取消路径都释放 lease；
- Profile 外的通用 `web` UI 无法访问投研 facade；
- sidecar 文件与 descriptor 仍经过完整性校验；
- 后端不返回密钥、内部绝对路径或不必要的诊断信息。

### 13.3 新增能力时的最小检查单

1. 归类接入类型：A 现有后端新接口 / B 模型工具 / C 新增独立后端 / D 产品实体能力（走 Client Runtime，别包装成 Python HTTP）；

4. 补 Host contract 测试（路由、默认值、越界、未知字段、非 2xx、lease 释放、写不透传）；
5. **重跑 `build:lib:host` 与 `build:lib:client`**；
6. UI 用真实数据，覆盖 loading/empty/error/retry/pending/过期响应保护；
7. 新增独立后端还要补 Runtime 类型闭集、业务插件与生命周期、descriptor/path/sidecar、bundle 与 Profile、就绪与设置页；
8. 更新对应 README/API 文档，跑完定向门禁再做 Web 实机验收。
