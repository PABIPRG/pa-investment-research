# 版本目标、范围与指标

## 1. 问题定义

现有闭环能够生成个性化资讯、策略匹配和风险预警，也能接收部分反馈，但缺少统一、可审计且可由用户控制的本地行为证据。用户无法回答“我最近在关注什么、系统为何这样判断、这些行为是否改变了推荐”，产品也无法可靠地区分被动曝光、主动打开、进入分析和明确反馈。

如果直接把点击解释为风险偏好或投资意愿，系统会产生危险的错误归因：阅读负面新闻不代表风险承受能力更强，关闭某类信息不代表风险本身消失，多次点击某策略也不等于策略通过验证。因此 0.1.0-rc.8 的目标不是尽可能多地采集，而是建立一套最小、透明、可纠正的本地学习机制。

## 2. 版本目标

- `LL-001`：对关键产品表面建立统一的本地交互事件，至少区分页面访问、有效曝光、打开、带入分析和主动反馈。
- `LL-002`：只保存归一化对象标识和白名单上下文，不保存用户输入原文、搜索词、对话、报告正文或持仓敏感数值。
- `PR-001`：在“我的投研”提供 7 天和 30 天偏好复盘，展示结论、证据量、置信度、漏斗和最近活动。
- `PR-002`：用户可以纠正内容反馈、暂停或恢复本地学习、清空本地记录，并在数据不足时看到明确说明。
- `FB-001`：将本地行为聚合为可复现的偏好快照，供内容软排序和归因使用，同时保留规则版本与快照标识。
- `FB-002`：显式风险约束、关键预警等级和策略验证生命周期与行为兴趣完全隔离。
- `NF-001`：记录失败不阻塞搜索、阅读、分析、预警或其他核心流程。

## 3. 目标用户与任务

主要用户是持续使用本产品阅读资讯、研究标的、查看风险和验证策略的个人投资者。用户需要完成三类任务：理解近期注意力分布；确认系统是否准确理解自己；在错误或不希望继续记录时进行纠正和控制。

产品和研究系统使用同一份本地证据完成三类后台任务：解释个性化排序；衡量卡片、预警和策略入口的有效性；为后续归因提供经过治理的事实输入。

## 4. 版本范围

### 4.1 P0 范围

- 研究工作台的事件卡片、风险预警和策略候选交互。
- 搜索结果的归一化证券选择，不记录原始搜索词。
- “带入分析”等明确研究意图，不记录提示词或对话内容。
- 本地学习状态、偏好复盘、反馈纠正、暂停、恢复和清空。
- 7 天、30 天聚合；样本量、置信度、证据标签和最近活动。
- 固定事件与元数据白名单、服务端时间、去重、按时间和数量双重保留。
- 外部后端模式下，本地学习与反馈在网络请求发生前被拒绝。
- 行为兴趣与显式风险画像、风险预警严重度、策略生命周期隔离。

### 4.2 P1 范围

- 复盘摘要的本地 JSON 导出。
- 对报告、产业链和影子验证等更多表面的同一事件协议覆盖。
- 更细的时间比较和“偏好变化”解释。

### 4.3 不在本版本范围

- 跨设备同步、云端画像、广告用途或第三方数据销售。
- 键盘、鼠标轨迹、停留热力图、完整导航历史或原始页面内容采集。
- 从点击行为推断适当性等级、净资产、收入、交易能力或风险承受能力。
- 使用行为直接触发真实交易、策略晋级、策略淘汰或降低风险预警。
- 以大模型自由生成偏好结论；0.1.0-rc.8 使用确定性规则。

## 5. 成功指标

| 指标 | 0.1.0-rc.8 目标 | 说明 |
|---|---:|---|
| 关键交互覆盖率 | 100% | P0 表面均可产生合法事件或明确降级 |
| 敏感字段落盘数 | 0 | 白名单外字段必须在写入前拒绝或丢弃 |
| 核心流程受埋点故障阻塞数 | 0 | 记录失败不改变业务结果 |
| 外部后端埋点请求数 | 0 | 客户端主机在发起网络请求前拦截 |
| 偏好结论可解释率 | 100% | 每条结论含样本量、时间窗、规则与置信度 |
| 小样本误导性结论数 | 0 | 未达阈值统一显示“数据不足” |
| 行为导致风险等级下降数 | 0 | 由负面保证和回归测试约束 |

## 6. 发布判定

P0 需求、隐私边界与负面保证全部通过才可发布。P1 未完成不阻塞 0.1.0-rc.8，但界面不得展示不可用入口。若偏好复盘不可用，本地学习可独立降级且不影响原有投资研究能力；若无法证明外部后端隔离，则不得发布埋点功能。
