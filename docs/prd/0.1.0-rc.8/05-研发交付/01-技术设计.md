# 技术设计：本地学习与偏好复盘

## 1. 设计目标

本设计为 `LL-*`、`PR-*`、`FB-*`、`DG-*` 和 `NF-*` 提供实现契约。核心选择是复用后端现有原子 JSON 存储作为唯一事实源，在前端仅保留有界会话去重状态，并在主机运行时阻止任何本地学习操作访问外部后端。

## 2. 系统分层

```text
产品组件
  → 无状态/有界内存记录器
  → 投研主机操作协议（本地操作前置限制）
  → 本地交易核心 HTTP 接口
  → 本地学习服务（校验、去重、裁剪、聚合）
  → behavior.json（原子写入的唯一事实源）
```

产品组件只提交规范化动作，不直接写存储。主机操作协议负责跨包类型和本地运行时限制；后端再次执行白名单和长度校验，不能信任客户端已清洗。

## 3. 事件模式

事件采用以下逻辑字段：

| 字段 | 约束 |
|---|---|
| `event_id` | 客户端生成，1—80 个安全字符；用于批次重试去重 |
| `schema_version` | 固定为 `1` |
| `action` | `page_view`、`impression`、`open`、`analyze`、`follow`、`unfollow` |
| `surface` | `dashboard`、`search`、`opportunity`、`stock_detail`、`portfolio`、`strategy`、`evolution`、`industry`、`reports`、`assistant` |
| `target_type` | `page`、`event`、`risk`、`strategy`、`security`、`portfolio`、`industry`、`report` |
| `target_id` | 归一化标识，1—120 个安全字符 |
| `session_id` | 匿名短会话标识，1—80 个安全字符 |
| `context` | 固定键集合；字符串、字符串数组或有限整数 |
| `occurred_at` | 服务端生成的 UTC 时间，不接受客户端覆盖 |

上下文允许键为 `ticker`、`industries`、`strategy_id`、`direction`、`bucket`、`event_type`、`risk_source`、`risk_severity`、`analysis_kind`、`position` 和 `reason_codes`。每个值和数组长度都有上限；未知键使整个事件拒绝，避免“先接收再忽略”掩盖泄漏。

旧版浏览与反馈记录按兼容读取器解析。新事件写入 `events` 集合，显式反馈保留在 `feedback` 集合并改为同对象最后值覆盖。两类数据共同受暂停、清空、保留与聚合规则管理。

## 4. 后端接口

| 方法与路径 | 用途 |
|---|---|
| `POST /personalized/local-learning/events` | 批量写入 1—50 条合法事件，返回写入、重复和忽略数量 |
| `GET /personalized/local-learning/status` | 返回启用状态、保留配置、记录数量和协议/规则版本 |
| `POST /personalized/local-learning/settings` | 更新启用状态；保留上限暂由系统固定 |
| `POST /personalized/local-learning/clear` | 清空事件和反馈，返回删除数量 |
| `GET /personalized/review?days=7|30|90` | 返回确定性复盘摘要与偏好快照 |
| `POST /personalized/feedback` | 兼容接口；执行元数据白名单与最后值覆盖 |

后端使用服务端当前时间写入、按 `event_id` 幂等去重、在每次写入后按 90 天和 2,000 条上限裁剪。复盘对缺失或损坏的单条旧记录安全跳过，但存储整体损坏仍由现有存储错误路径报告。

## 5. 偏好聚合

聚合规则版本固定为 `local-preference-v1`。曝光仅作漏斗分母；打开计 1，带入分析计 2，明确正向反馈计 3，明确负向反馈计 -3。证券、行业和策略分别聚合，分数相同按有效事件数、最近服务端时间和稳定标识排序。

只有有效信号不少于 3 且覆盖至少 2 个自然日时生成洞察。置信度由有效证据数与活跃天数的确定性分段得到：低、中、高；不得用高置信度暗示投资适当性或预测可靠性。

快照标识对规则版本、时间窗和规范化有效记录序列计算摘要。同一输入序列和时间窗产生相同标识。复盘响应同时返回 `explicit_risk_profile`，但该字段独立读取显式设置，不参与行为分数。

## 6. 前端记录器

记录器在投研 UI 实例初始化时创建，生命周期长于单个 React 组件。它生成匿名会话标识和事件标识，维护最大容量的内存去重集合，并通过主机操作异步提交。

记录器提供两类去重：有效曝光按会话、页面、对象永久去重；页面访问按短时间窗口去重以吸收严格模式重复挂载，同时允许稍后真实返回。打开、分析和反馈不做会话永久去重。

被动事件采用“尽力而为”语义并吞吐失败；用户主动反馈由组件处理可见失败。记录器不使用 `localStorage`、`sessionStorage`、文件日志或分析 SDK。

有效曝光组件使用 `IntersectionObserver`，阈值为 0.5，连续 1 秒计时。元素离开阈值立即取消计时；卸载时清理观察者与定时器。

## 7. 主机运行时限制

主机新增本地学习事件、状态、设置、清空和复盘操作，并将既有个性化反馈也标为本地操作。请求规范增加 `localOnly` 属性；取得后端租约后、执行 `fetch` 前检查租约所有权。所有权为 `external` 时抛出稳定错误并在 `finally` 中释放租约。

运行时先验证操作输入，再取得租约。未知上下文、超出批量上限或敏感键应在任何后端启动和网络动作前失败。`owned` 和 `attached` 两类租约允许执行本地操作。

## 8. 产品界面

偏好复盘作为“我的投研”的二级页面实现，包含页头返回、7/30 天筛选、记录状态、摘要、兴趣洞察、行为漏斗、最近活动和数据控制区。复盘不新增一级导航。

研究工作台的事件与风险卡片增加显式反馈控件。反馈按钮必须与卡片打开动作隔离，避免点击反馈同时触发打开。当前选择通过 `aria-pressed` 表达，失败信息由状态区域播报。

## 9. 风险与策略负面保证

行为画像中任何“风险倾向增量”固定为零，有效风险参数等于显式设置。历史字段为兼容可保留，但不得把点击或反馈换算为风险变化。

风险引擎可以附带内容反馈统计用于效果归因，但不执行严重度降级。策略引擎可以消费参与度作为解释背景，但不能把行为事件转换为验证结果或生命周期状态。

## 10. 迁移与兼容

升级为增量模式，无破坏性迁移。缺少 `local_learning` 设置时使用启用、90 天、2,000 条默认值；缺少 `events` 时视为空集合。旧反馈读取时执行安全字段投影，后续写入逐步转为最后值模型。

API 增加字段时保持既有响应字段，前端对新字段采用容错读取。降级到旧后端时，事件记录失败被吞吐，偏好复盘显示局部不可用，不影响原有页面。
