# 实现计划与自审

## 1. 决策状态

用户已授权本版本无需额外人工评审并直接实施。本计划基于产品完整性、架构边界、隐私安全和回归风险四个维度完成自审；实施中如出现超出 PRD 的新能力，必须先更新 PRD 和追踪矩阵。

## 2. 实施顺序

### 阶段一：本地事实与安全边界

1. 新增后端本地学习服务、模式和接口，实现白名单、服务端时间、幂等、裁剪、设置、清空和复盘。
2. 将旧反馈改为安全元数据与最后值覆盖，保持既有接口兼容。
3. 移除行为对显式风险的调整和反馈对风险严重度的降级。
4. 新增后端单元与回归测试，先固定负面保证。

### 阶段二：主机协议

1. 新增本地学习操作类型与请求映射。
2. 增加请求前校验和 `localOnly` 租约所有权检查。
3. 验证外部后端零请求、租约释放、无效输入前置失败和旧操作兼容。

### 阶段三：产品交互

1. 新增有界、无持久副本的前端记录器与有效曝光观察器。
2. 覆盖研究工作台、搜索选择和带入分析等 P0 入口。
3. 增加事件与风险反馈纠正控件。
4. 在“我的投研”实现偏好复盘、时间窗、暂停/恢复和清空确认。

### 阶段四：验证与交付

1. 完成组件、GUI 和 Web 组装层测试，并检查深浅主题、窄屏、键盘和错误状态。
2. 运行后端与前端全量回归、覆盖率、类型、静态检查、构建和文档同步。
3. 对照需求追踪矩阵逐项复核，检查无敏感数据样本和无风险边界回退。
4. 输出实现、测试、已知限制和工作区状态说明；不在未获授权时提交或推送。

## 3. 自审结论

### 3.1 产品自审

偏好复盘放入“我的投研”符合用户心智，不新增一级导航。记录、解释、纠正和删除构成完整可控闭环；小样本状态和证据说明避免把偶然点击包装为稳定偏好。

### 3.2 架构自审

复用现有本地行为存储避免双重事实源。前端只负责产生规范化意图和短期去重，后端拥有时间、治理与聚合，主机拥有本地运行时边界，职责可独立测试。

### 3.3 隐私与安全自审

最大风险不是记录数量，而是自由元数据和错误推断。四层白名单、服务端二次校验、外部后端前置拒绝、禁止自由文本和用户可清空共同构成数据边界。行为与风险、策略生命周期隔离是发布级负面保证。

### 3.4 回归自审

现有个性化、风险和策略代码会消费行为数据，因此只新增接口不足以保证安全。回归必须直接覆盖旧行为记录兼容、显式风险参数不变、关键预警不降级、策略状态不由交互改变，以及埋点失败不阻断原业务。

## 4. 完成定义

- PRD、设计、计划和需求追踪矩阵与实现一致。
- 所有 P0 需求可在产品界面或稳定接口中使用。
- 安全负面保证具备直接自动化测试且全部通过。
- 受影响文件满足既有覆盖率和文档要求。
- 全量回归通过，或每个无法执行的检查都有明确环境原因和等价证据。
- 原始用户工作区保持不变，所有实现仅位于独立 `codex/0.1.0-rc.8-local-telemetry` 分支工作树。
