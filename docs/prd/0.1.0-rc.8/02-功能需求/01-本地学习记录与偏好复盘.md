# 本地学习记录与偏好复盘

## 1. 用户故事

- 作为投资者，我希望看到系统根据哪些本地行为判断我的关注方向，以便识别自己真实的研究偏好而不是被不透明画像定义。
- 作为投资者，我希望纠正“值得关注/减少此类”的选择，以便后续内容排序使用我最后确认的偏好。
- 作为谨慎的投资者，我希望暂停或清空本地学习，并确认这些操作不会删除持仓、风险资料或研究成果。
- 作为复盘者，我希望比较曝光、打开、分析和反馈，以便区分“看见了”与“真正投入研究”。
- 作为系统维护者，我希望事件协议固定、可验证且不影响业务流程，以便安全地进行后续归因和演进。

## 2. 本地事件记录

### `LL-001` 统一事件协议

系统必须用统一协议记录页面访问、有效曝光、打开、带入分析、关注和取消关注。每条事件包含唯一标识、协议版本、动作、产品表面、目标类型、目标标识、匿名会话标识、服务端时间和白名单上下文。

验收条件：未知动作、表面、目标类型或上下文字段不能落盘；合法事件可在偏好复盘中被聚合；事件不要求用户身份或云端账号。

### `LL-002` 有效曝光

卡片进入视口至少 50%，并持续至少 1 秒后才记录有效曝光。同一会话、页面和目标只记录一次曝光。快速滚过、组件预渲染和 React 严格模式重复挂载不得重复计数。

验收条件：不足 1 秒不记录；达到阈值记录一次；离开后再次进入同一会话不重复；新会话可重新记录。

### `LL-003` 主动交互

打开、带入分析和关注类动作由真实用户操作触发。搜索只记录用户最终选择的归一化证券标识，绝不记录查询原文。带入分析只记录目标和分析类型，绝不记录提示词、问题或对话内容。

验收条件：用户仍可在埋点接口失败时完成原操作；记录中不存在搜索词、标题、正文、提示词或 URL。

### `LL-004` 显式反馈与纠正

事件卡片和风险卡片提供“值得关注”和“减少此类”反馈。用户可以修改选择，系统以同一对象最后一次有效选择作为当前反馈，不重复增加正负样本。

验收条件：按钮显示当前选择；修改后复盘和排序使用新值；风险卡片被标为“减少此类”后仍按原严重度显示；反馈失败有非阻断提示并允许重试。

## 3. 偏好复盘

### `PR-001` 复盘入口

“我的投研”提供“偏好复盘”入口，不新增一级导航。进入后可返回组合概览，页面加载失败不影响“我的投研”的其他功能。

### `PR-002` 时间窗与摘要

复盘支持 7 天和 30 天时间窗，默认 7 天。摘要显示记录状态、有效信号数、活跃天数、打开数、分析数和反馈数，并标明本地数据。

### `PR-003` 洞察与证据

系统按确定性规则展示最多若干条兴趣洞察，包括关注证券、行业、策略或研究动作。每条洞察必须包含证据数、覆盖天数、置信度和明确的“仅用于兴趣排序”说明。

验收条件：有效信号少于 3 个或覆盖少于 2 天时显示数据不足；规则版本相同且输入相同，洞察顺序与内容相同；负向反馈不会被表述为风险降低。

### `PR-004` 行为漏斗与最近活动

复盘展示有效曝光、打开、带入分析和反馈的绝对数量。只有分母达到最小样本阈值时才显示转化比例。最近活动使用安全标签，例如“打开证券 600519.SH”，不回显自由文本或敏感持仓数据。

### `PR-005` 用户控制

用户可以暂停或恢复本地学习。用户可以清空全部本地行为与反馈，清空前必须二次确认并说明持仓、显式风险资料和研究成果不会被删除。清空成功后复盘立即显示空状态。

### `PR-006` 本地摘要导出

在具备安全下载能力时，用户可以导出当前复盘摘要的 JSON 文件。导出内容与页面聚合一致，不包含事件原始自由文本、持仓数量、成本或用户身份。该能力为 P1，不影响 P0 发布。

## 4. 安全回输

### `FB-001` 偏好快照

复盘、画像说明和非关键内容排序引用同一规则版本与偏好快照标识。快照由本地事实确定性计算，不由大模型生成。

### `FB-002` 内容软排序

行为兴趣只能作为相同风险级别内容的次级排序信号。用户明确反馈的正负偏好强于普通打开，普通打开强于曝光。排序必须保留原因码，便于用户和测试解释。

### `FB-003` 风险隔离

行为事件与内容反馈不得改变用户显式风险承受能力、风险预算或组合风险结论；不得降低或隐藏关键预警严重度；不得直接触发真实交易。

### `FB-004` 策略生命周期隔离

行为参与度可以进入策略归因背景，但不能替代历史、样本外和实时影子验证，不能直接触发策略晋级、降级或淘汰。

## 5. 错误与空状态

记录操作采用静默降级，不打断原业务动作；用户主动反馈失败时显示轻量、可重试提示。复盘加载失败提供重试和返回入口。无记录、已暂停和记录不足是三个不同状态，文案不得混淆。
