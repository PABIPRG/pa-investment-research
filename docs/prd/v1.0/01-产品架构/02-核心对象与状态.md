# 核心对象与状态

## 1. 对象归属

| 对象 | 事实来源 | 关键关系 |
|---|---|---|
| 证券 | 市场后端 | 被持仓、自选、分析和产业链引用 |
| 市场事件/信号 | 市场后端 | 可触发分析或策略假设 |
| 事件研究详情 | 事件事实来源与投研后端 | 按稳定事件标识整理安全 Markdown；有 `report_id` 时关联持久报告 |
| 风险预警 | 投研后端 | 关联组合、画像、证券、策略、影子或事件，并提供阈值与来源 |
| 分析任务 | 投研后端 | 完成后生成报告 |
| 投研报告 | 投研后端 | 关联来源模块、任务和业务对象 |
| 策略 | 投研后端 | 引用证据报告，进入影子验证 |
| 影子运行/持仓/净值 | 投研后端 | 归属于策略，为进化提供证据 |
| 进化预案 | 投研后端 | 来源于归因，确认后形成策略变更 |
| 持仓、自选、风险画像 | 投研后端 | 驱动工作台、分析和个性化 |
| 公司、产业节点与关系 | 产业链后端 | 可进入公司分析与策略研究 |
| 会话 | 正式会话服务 | 引用业务对象，不拥有其事实副本 |

## 2. 通用任务状态

```text
queued → running → succeeded
                 ↘ failed
```

- 前台等待超时是 UI 状态，不等于后端任务失败。
- 超时后任务仍可在报告中心继续显示 `running`，最终变为 `succeeded` 或 `failed`。
- 1.0 不承诺取消已进入后端执行的任务；离开页面只停止前台等待。

## 3. 报告状态

```text
processing → completed
           ↘ failed
```

- `processing` 报告可被再次打开并刷新。
- `completed` 是当时事实的不可变快照；新一次任务生成新报告版本。
- `failed` 保留可理解的失败原因和重试入口，不展示半成品为完成结果。

## 4. 策略状态

```text
候选 candidate → 活跃 active → 观察 watch → 退役 retired
       └──────→ 拒绝 rejected
观察 watch ──→ 活跃 active
```

- 每次状态迁移必须记录操作者、时间、来源报告和原因。
- 不允许从拒绝或退役状态静默恢复；恢复规则由设计文档明确并需要显式确认。
- 页面不得根据模型文字自行推断策略状态。

## 5. 影子验证状态

一次交易日运行必须具备幂等键。同一策略、同一交易日重复触发不得重复记账。

运行结果至少关联：策略、交易日、状态、持仓快照、净值点、错误或提示、生成时间。

## 6. 策略验证分类

验证分类是对最新有效验证证据的只读派生，与策略生命周期状态并列：

```text
已验证通过 passed
未验证 pending
验证未通过 failed
已归档 archived
```

- `archived` 优先：退役、被替代或已退出验证队列。
- 最新有效验证达到准入阈值时为 `passed`。
- 尚未运行、运行中、样本不足、成交不足或证据过期时为 `pending`。
- 验证已经完成且证据明确未达阈值，或已有明确拒绝证据时为 `failed`。
- 分类不得由模型文字直接决定，也不得作为可手工迁移的生命周期状态。
- 后端尚无独立验证字段时，前端只允许基于状态和最新有效回测证据做明确标注的临时投影，不得回写。

## 7. 自进化状态

```text
数据不足 → 可预览 → 预案就绪 → 已确认 → 已应用
                         └────→ 已放弃
                         └────→ 应用失败
```

- 默认至少需要 5 个有效影子交易日，实际门槛由后端规则返回。
- 预览不修改策略。
- 确认只对当前预案版本有效；基础数据变化后旧预案必须失效或重新确认。

## 8. 风险详情最小模型

风险预警至少包含稳定风险标识、严重度、来源、标题、触发原因、关联对象、当前值、阈值或预算、数据时间、降级状态和研究性复核建议。缺失数值不能转换为 `0`。

## 9. 浏览器允许持有的状态

浏览器可以持有：当前路由、筛选、滚动、独立输入草稿、选中的不透明标识、加载与错误状态，以及助理 `closed / docked / expanded` 显示状态。

浏览器不得成为以下事实的唯一来源：策略状态、影子净值、风险画像、报告正文、产业关系和任务最终结果。
