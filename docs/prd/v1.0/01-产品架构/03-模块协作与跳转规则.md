# 模块协作与跳转规则

## 1. 协作原则

跨模块流转只传递最小标识和用户意图。目标模块重新读取最新事实，不能把源页面完整状态复制过去。

每次流转至少保留：来源模块、来源对象标识、目标动作和用户可理解的返回路径。

## 2. 标准流转

| 来源 | 动作 | 目标 | 必须携带 |
|---|---|---|---|
| 研究工作台事件 | 深入分析 | 智能分析 | 证券/事件标识、来源 |
| 实时盯盘结果 | 分析 | 智能分析 | 证券标识、信号标识 |
| 产业链公司/节点 | 分析公司 | 智能分析 | 公司或证券标识、关系标识 |
| 智能分析结果 | 查看成果 | 投研报告 | 报告标识 |
| 分析报告 | 形成策略 | 策略研究 | 报告标识、相关证券 |
| 策略研究·策略池 | 开始纸面验证 | 策略研究·影子验证视图 | 策略标识 |
| 影子验证 | 查看归因 | 自进化 | 策略标识、运行区间 |
| 自进化 | 查看策略 | 策略研究 | 策略标识、预案或变更标识 |
| 我的投研 | 分析持仓 | 智能分析 | 组合版本标识，不复制持仓 JSON |
| 任一报告 | 继续研究 | 投研助理或来源模块 | 报告标识、自然语言意图 |

## 3. 选择保留

- 策略研究选择某策略后切换到影子验证视图，再进入自进化，全程保持同一策略标识。
- 从产业链进入分析再返回，应恢复原公司、视图和展开参数。
- 从实时盯盘进入个股详情或分析再返回，应恢复榜单、筛选和选中证券。
- 跨模块传入的值只能初始化目标模块对应输入，不得修改其他模块草稿。

## 4. 写入边界

- 导航和查看不产生持久业务写入。
- 加入自选、保存持仓、创建候选策略、迁移状态、运行影子验证和应用进化是显式写入。
- 所有写入按钮必须在执行前明确对象与影响，在执行后显示结果和可追溯标识。
- 高影响写入不得由助手直接静默完成；助手可以解释并引导到结构化确认界面。

## 5. 失败与回退

- 目标模块读取失败时，保留来源标识与返回路径，不退回空白首页。
- 对象已删除或失效时，明确说明并允许返回来源列表。
- 后端暂不可用时，不把旧页面数据冒充最新；可显示上次成功值及其时间。
- 同一动作重复点击不得创建不可辨识的重复记录；设计文档必须给出防重复方案。

## 6. 助手协作

助手接收“研究某对象/解释某报告”等意图和标识。模型需要事实时调用统一工具读取，不要求页面在输入框中预填对象 JSON。

- 打开助理只修改助理显示状态，不执行业务路由跳转。
- 分析模块选择只限定工具范围和提示，不改变业务页面表单。
- 业务页的“运行分析/回测/验证”执行真实结构化任务；只有“让助理解读/继续研究”进入会话。
- 助理新建会话不清空当前业务路由、筛选、任务和表单草稿。

## 7. 风险与事件详情协作

- 工作台和“我的投研”用同一 `risk_id` 打开同一风险详情模型。
- 风险详情进入智能分析时只传证券、策略或组合标识及用户可读意图。
- 事件列表优先使用 `event_id` 或 `source_event_id`；不得把 `event_idx` 保存为跨页身份。
- 事件有稳定 `report_id` 时打开报告中心详情；无 `report_id` 时打开安全 Markdown 事件研究详情。
