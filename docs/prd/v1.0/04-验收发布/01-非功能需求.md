# 非功能需求

> 需求前缀：`NFR`

## 1. 性能与响应

以下目标在发布候选构建、推荐硬件、三套本机后端健康的环境测量；设计文档必须补充具体基准机与测量方法。

| ID | 指标 | 1.0 目标 |
|---|---|---|
| NFR-001 | 用户操作视觉反馈 | ≤ 100ms |
| NFR-002 | 一级路由壳切换 P75 | ≤ 300ms |
| NFR-003 | 暖启动首个可交互页面 P75 | ≤ 2.5s |
| NFR-004 | 直接数据区首次出现状态反馈 | ≤ 300ms |
| NFR-005 | 长任务提供“后台继续”路径 | 前台等待不超过 30s 后必须提供 |
| NFR-006 | 快速切换筛选后的旧响应污染 | 0 次 |

性能目标不要求等待全部区域完成才展示页面。

## 2. 可靠性

| ID | 要求 | 1.0 目标 |
|---|---|---|
| NFR-007 | 发布版本无崩溃会话比例 | ≥ 99.5% |
| NFR-008 | 成功任务到报告的投影 | 100% |
| NFR-009 | 高影响写入审计记录 | 100% |
| NFR-010 | 影子同日重复记账 | 0 次 |
| NFR-011 | 新会话草稿串写 | 0 次 |
| NFR-012 | 单后端失败导致无关域不可用 | 0 次 |

## 3. 安全边界

- 浏览器只能请求编译期固定业务操作，不能指定后端地址、端口和任意路径。
- 动态对象标识在访问前校验并安全编码。
- 模型密钥只进入正式凭据服务，不出现在日志、报告、上下文工具或埋点。
- 高影响动作使用显式确认、幂等保护和审计。
- 1.0 不提供真实交易执行。
- 前端展示的外部新闻链接使用安全打开策略，不继承任意脚本权限。

## 4. 隐私

- 持仓、成本、风险画像、报告正文和模型对话正文默认不进入产品分析事件。
- 诊断日志在用户导出前需说明范围，并对密钥和敏感字段脱敏。
- 会话存储位置切换不等于允许上传或共享数据。
- 模型工具按最小需要返回数据，避免无界全量组合和报告正文。

## 5. 可访问性

- 目标为 WCAG 2.1 AA。
- 键盘可完成所有 P0 流程。
- 可见焦点、语义标签、错误说明和图表文字摘要完整。
- 明暗主题、200% 文本缩放和减少动态效果偏好不破坏关键操作。

## 6. 兼容性

- 支持项目正式声明的桌面浏览器版本与 Electron 运行时。
- 主要验收宽度：1024、1280、1440px；更宽窗口不得无限拉长正文。
- macOS 标准启动必须处理已安装原生模块的 quarantine 属性。
- Windows 与 Linux 至少通过构建、核心合同和启动脚本验证；端差异在设计文档记录。

## 7. 可观测性

必须能关联：会话、页面动作、业务任务、报告和后端服务，但不记录敏感正文。

最低事件包括：页面可达、任务创建/完成/失败、报告打开、跨模块后续动作、工具调用结果类别、后端健康和未捕获 UI 错误。

每条失败诊断包含相关 ID、阶段和可脱敏原因，普通 UI 只显示用户可理解信息。

## 8. 可维护性

- 需求、设计、实现和测试使用稳定需求编号关联。
- 共享交互组件和主题令牌不得由业务页复制改造。
- 三套后端的能力和版本兼容矩阵在设计文档维护。
- 不允许把演示数据作为生产失败回退。
