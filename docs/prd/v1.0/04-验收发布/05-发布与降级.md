# 发布、降级与回滚

## 1. 发布前置

- PRD、设计文档和实现计划完成对应评审。
- 追踪矩阵无 P0 空缺。
- 回归矩阵通过并有可复查证据。
- 三套后端与前端版本兼容关系已锁定。
- 数据或状态迁移完成演练并具备回滚方案。

## 2. 功能降级原则

- 模型不可用：直接数据页、报告查看和本地业务状态保持可用。
- 市场后端不可用：盯盘和证券实时区降级，持仓、策略和历史报告保持可用。
- 投研后端不可用：分析、策略、影子、自进化和“我的投研”写入降级；市场与产业链仍可浏览。
- 产业链后端不可用：产业链显示可重试错误，其他业务域不受影响。
- 报告中心不可用：阻断新的报告型任务或明确标记风险，不允许任务成功后丢失成果。

降级时必须显示真实影响和数据时间，不使用模拟内容补齐。

## 3. 回滚原则

- 前端回滚不得读取新版本无法理解的状态后静默改写。
- 后端状态迁移必须向后兼容或提供可验证回滚步骤。
- 已生成报告和影子账本属于用户成果，回滚不得删除。
- 自进化已应用变更需按策略审计记录另行恢复，不能靠代码回滚隐式撤销。

## 4. 发布后观察

至少观察：启动成功率、三后端健康率、页面错误、任务到报告投影、工具调用失败、新会话串写、高影响动作失败和主题缺陷反馈。

发现 P0 问题时停止扩大发布，按影响选择功能关闭、版本回滚或后端降级，并保留诊断证据。

## 5. 版本声明

1.0 发布说明必须明确：

- 这是研究辅助产品，不提供真实交易。
- 行情时效取决于数据源。
- 影子验证是模拟结果。
- 模型结论可能出错，需要结合证据复核。
- 已知限制及其恢复路径。
