# 全量回归测试矩阵

## 1. 测试目标

回归不只证明组件能渲染，还要证明用户能完成研究闭环、业务事实不串线、失败可恢复、主题状态一致。

## 2. 环境矩阵

| 维度 | 必测组合 |
|---|---|
| 端 | 生产 Web、Electron |
| 主题 | 浅色、深色、跟随系统切换 |
| 宽度 | 1024、1280、1440px |
| 模型 | 已配置、未配置、调用失败 |
| 后端 | 全健康、逐一不可用、慢响应、空数据 |
| 数据规模 | 空、最小有效、常规、边界上限 |
| 会话 | 首次使用、已有历史、新建、运行中 |

不要求对所有维度做笛卡尔积，但每项 P0 至少覆盖最不利组合。

## 3. 关键用户旅程

| 用例 | 路径 | 核心断言 |
|---|---|---|
| E2E-01 | 启动 → 研究工作台 → 7 个域 | 全部可达，标题和选中态一致 |

## 4. 分层测试

| 层级 | 必须覆盖 |
|---|---|
| 状态单测 | 路由、输入隔离、会话所有权、状态机、旧响应保护 |
| 组件测试 | 空/慢/错/成功、按钮状态、确认流程、报告列表与详情 |
| 合同测试 | 固定 operation、输入边界、对象 ID、响应最小字段 |
| 后端测试 | 任务、报告投影、策略迁移、影子幂等、自进化审计 |
| 组合测试 | 三套后端 Loader、托管租约、无密钥工具集合 |
| 浏览器 E2E | 关键旅程、真实点击、焦点、主题和控制台错误 |
| 视觉回归 | 1+7、报告、助理、设置在明暗主题和目标宽度 |
| 启动冒烟 | Web/Electron、干净环境、依赖刷新后、退出清理 |

## 5. 六项专项回归

### R-REPORT 统一报告

- 每种报告来源创建、运行、完成、失败、重试和返回来源。

### R-THEME 组件与深色主题

- 所有按钮层级和状态；弹窗、抽屉、下拉、图表 Tooltip；键盘焦点。

### R-CONTEXT 上下文工具化

- 输入框无 JSON；按领域读取；非法 URL/路径拒绝；部分工具失败。

### R-SESSION 空白新会话

- 新建时清消息/草稿/附件；晚到预填；用户先编辑；打开历史再新建。

### R-INPUT 独立输入

- 全局搜索、分析、回测、盯盘、产业链同时输入和跨页返回。

### R-WORKSPACE 工作区弱感知

- 首次启动、无工作区、设置切换、取消、失败、业务事实保持。

## 6. 通过标准

- P0 用例 100% 通过。
- P1 用例无未批准失败。
- 浏览器控制台无未解释 error/warn。
- 无 P0/P1 可访问性或视觉阻断缺陷。
- 失败重跑必须记录原因；不得用“偶现”直接关闭。

## 7. 回归报告

每次候选发布输出：提交号、环境、覆盖矩阵、失败证据、已知限制、豁免编号和最终签署。报告不得只写“测试通过”。
