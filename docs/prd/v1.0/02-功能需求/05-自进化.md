# 自进化

> 需求前缀：`EVO`

## 1. 产品目标

基于影子验证的业绩归因提出可解释的策略调整预案，并把“计算建议”和“应用变更”严格分开。

## 2. 核心流程

```text
检查数据门槛 → 查看业绩归因 → 预览本轮动作
→ 用户复核影响 → 明确确认 → 应用并记录结果
```

## 3. 功能需求

| ID | 要求 | 级别 |
|---|---|---|
| EVO-001 | 页面显示有效影子天数、要求天数和就绪原因 | P0 |
| EVO-002 | 数据不足时禁止生成可应用预案，并说明还缺什么 | P0 |
| EVO-003 | 归因至少展示收益、最大回撤、交易样本和胜率可用性 | P0 |
| EVO-004 | “预览本轮动作”只读，不修改策略池 | P0 |
| EVO-005 | 预案逐项说明对象、当前值、建议值、依据和风险 | P0 |
| EVO-006 | 应用前必须使用独立确认界面，不能复用普通按钮二次点击 | P0 |
| EVO-007 | 确认绑定预案版本；基础事实变化后必须重新预览 | P0 |
| EVO-008 | 应用结果记录成功项、失败项、策略版本和审计信息 | P0 |
| EVO-009 | 完成或失败结果进入报告中心 | P0 |
| EVO-010 | 用户可以放弃预案而不产生策略变化 | P0 |

## 4. 安全规则

- 模型可以解释归因或预案，但不能绕过确认直接应用。
- 前端不得自行判断数据已满足门槛；以受控后端状态为准。
- 部分应用必须在设计文档中明确事务语义；1.0 不允许无说明的半成功。
- 应用失败保留旧策略有效状态和可恢复路径。

## 5. 空状态

- 数据不足：显示当前有效天数、默认门槛和下一步。
- 无可调整项：明确说明本轮保持不变，不制造动作。
- 归因不可用：允许重试，但禁用预览和应用。
- 预案过期：说明事实已变化，要求重新计算。

## 6. 验收

- 未达到门槛、未预览、预案过期三种情况都不能应用。
- 关闭确认框不产生任何写入。
- 应用后策略详情、审计记录和报告内容一致。
- 无模型密钥时仍可查看后端已有归因与预案状态。

## 7. 范围外

- 定时无人值守自动应用。
- 自动把策略变化映射到真实账户。
