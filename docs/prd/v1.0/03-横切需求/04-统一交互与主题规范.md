# 统一交互与主题规范

> 需求前缀：`UX`

## 1. 目标

让 1+7、报告、助理和设置使用同一交互语言。按钮大小、层级、主题状态和浮层行为必须由语义决定，不能由各页面自由发挥。

## 2. 控件层级

| 层级 | 用途 | 同一区域约束 |
|---|---|---|
| 主按钮 | 当前区域唯一推荐动作 | 通常不超过 1 个 |
| 次按钮 | 安全的替代或辅助动作 | 与主按钮高度一致 |
| 文字按钮 | 低强调导航或局部操作 | 不伪装成主按钮 |
| 危险按钮 | 删除或不可逆动作 | 独立色义并二次确认 |
| 图标按钮 | 主题、关闭、刷新等 | 有可访问名称和提示 |

具体像素由设计文档定义；同一层级、同一密度的控件必须引用统一尺寸令牌。

## 3. 状态矩阵

每个可交互组件在浅色和深色主题都必须覆盖：

```text
default / hover / focus-visible / active / selected / disabled / loading / error
```

| ID | 要求 | 级别 |
|---|---|---|
| UX-001 | 同层级按钮在同一页面高度、圆角、内边距一致 | P0 |
| UX-002 | Hover 不得降低文字、图标或边框到不可辨识 | P0 |
| UX-003 | 深色主题不得出现浅色硬编码背景或反向低对比文字 | P0 |
| UX-004 | `focus-visible` 清晰且不只依赖颜色变化 | P0 |
| UX-005 | Disabled 与 Loading 可区分，Loading 防止重复提交 | P0 |
| UX-006 | 选中态与 Hover 同时存在时仍能看出当前选中项 | P0 |
| UX-007 | 所有对话框、抽屉和菜单使用正确主题与层级 | P0 |
| UX-008 | 浮层打开后焦点进入浮层，关闭后回到触发控件 | P0 |
| UX-009 | 错误、成功和警告不只用红绿颜色表达 | P0 |
| UX-010 | 1024px 及以上桌面宽度无关键操作遮挡或横向溢出 | P1 |

## 4. 页面反馈

- 用户操作后 100ms 内出现视觉反馈。
- 长任务显示阶段、已耗时或可离开说明，不使用无期限旋转图标。
- Toast 只做补充；持久结果必须在页面或报告中心可再次找到。
- 空状态说明原因和下一步，不用禁用按钮替代解释。
- 表格、卡片和图表必须显示数据时间或状态来源。

## 5. 初次使用浮层

- 内测声明与模型配置可以依次出现，但必须可跳过。
- 跳过模型配置后，直接数据页保持可用。
- 同一版本已确认的声明不重复阻断导航。
- 后续浮层出现前不得让被遮挡导航看似可点却无反应。

## 6. 可访问性

- 键盘可完成导航、筛选、打开报告、关闭浮层和确认动作。
- 所有输入有可见标签或等价可访问名称。
- 文本与背景、交互控件与背景满足 WCAG 2.1 AA 对比度目标。
- 动画尊重减少动态效果偏好。
- 图表提供文字摘要或可访问数据表。

## 7. 验收

- 明暗主题逐页执行组件状态矩阵，不以单张首页截图代替。
- 自动扫描颜色与组件约束，人工验证 Hover、焦点、浮层和图表。
- 至少覆盖鼠标、键盘、1024/1280/1440px 和 Electron 窗口。
- 发布前不存在按钮文字跳动、尺寸随加载改变或透明 Hover。
