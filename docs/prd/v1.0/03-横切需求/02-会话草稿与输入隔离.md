# 会话、草稿与输入隔离

> 需求前缀：`SESSION`

## 1. 目标

保证新会话真正为空，异步预填不会跨会话写入；同时让全局搜索和各模块输入拥有独立生命周期。

## 2. 新建对话原子语义

用户点击“新建对话”后，必须在同一状态提交中完成：

1. 创建新的会话身份。
2. 清空上一会话消息视图。
3. 清空文本草稿、附件、命令、引用和编辑态。
4. 取消或作废仍在进行的页面预填所有权。
5. 显示空白欢迎态和空输入框。

页面当前业务路由可以保留，但不得自动把旧问题重新写入新会话。

## 3. 功能需求

| ID | 要求 | 级别 |
|---|---|---|
| SESSION-001 | 新建对话后输入框和消息区均为空 | P0 |
| SESSION-002 | 新建对话清空附件、引用、命令和待发送状态 | P0 |
| SESSION-003 | 旧异步预填完成后不得写入新会话 | P0 |
| SESSION-004 | 页面显式研究动作创建新会话并获得唯一预填所有权 | P0 |
| SESSION-005 | 用户开始编辑后，晚到系统预填不得覆盖用户文字 | P0 |
| SESSION-006 | 打开历史会话恢复该会话自身草稿，不串用当前草稿 | P0 |
| SESSION-007 | 会话重命名和归档不影响业务报告与业务对象 | P1 |
| SESSION-008 | 切换业务页不自动创建新会话 | P0 |

## 4. 独立输入状态

以下输入必须分别绑定：

- 全局证券搜索。
- 智能分析的个股代码。
- 智能分析的历史回测代码。
- 实时盯盘当前证券与筛选。
- 产业链搜索关键词。
- 持仓编辑中的证券字段。
- 助手输入草稿。

只有显式跨模块动作可以用对象标识初始化目标输入；初始化一次后，各模块继续独立编辑。

## 5. 竞态规则

- 每次预填绑定会话 ID 和所有权令牌。
- 会话变化、用户编辑、第二次预填或取消动作都会使旧令牌失效。
- 旧请求可以在后台完成，但结果只能丢弃，不能写入当前草稿。
- 页面卸载后不得向已销毁输入状态写入。

## 6. 验收

- 连续执行“页面动作 → 立即新建对话”100 次，无一次旧预填串入。
- 在预填等待期间手动输入，用户文本不被覆盖。
- 同时编辑全局搜索与两个分析代码，三者值互不变化。
- 打开历史会话再新建，对话显示空白且业务页面状态保持。
