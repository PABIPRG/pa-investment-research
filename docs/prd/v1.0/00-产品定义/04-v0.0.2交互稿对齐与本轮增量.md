# v0.0.2 交互稿对齐与本轮增量

> 状态：已确认，进入实现
> 决策日期：2026-08-26
> 适用范围：投研产品 1.0 Web 与 Electron

## 1. 决策背景

本轮以现有产品代码为开发基线，以 `投研智能体交互 v0.0.2` 的业务能力、页面结构和任务流程为主要交互参照，并吸收 2026-08-26 浏览器走查反馈。交互稿中的业务能力应尽可能保留，但不得用静态演示数据、纯聊天页面或前端自造事实替代当前已接入的真实后端能力。

当交互稿、旧 PRD 与本轮确认发生冲突时，按以下优先级执行：

1. 本文件记录的已确认产品决策。
2. v1.0 各模块 PRD 与横切规范。
3. v0.0.2 的业务流程和视觉结构。
4. 现有实现细节。

## 2. 本轮正式产品决策

### DEC-001 信息架构改为“研究工作台 + 6 个一级业务入口、7 项业务能力”

一级业务入口为：智能分析、实时盯盘、策略研究、自进化、我的投研、产业链。影子验证仍是独立业务能力、对象和需求域，但并入“策略研究”页面的内部视图，不再占用一级导航。

旧影子验证深链必须兼容进入“策略研究 → 影子验证”，不得出现第二个一级入口，也不得丢失有效的 `strategy_id`。

### DEC-002 智能分析是结构化任务工作台，不是聊天页

“智能分析”首屏以 v0.0.2 为基线，至少直接承载：

- 个股多智能体分析；
- 持仓风险分析；
- 市场简报；
- 历史决策回测；
- 任务进度与统一报告入口。

模块卡、参数、运行状态和结果入口是页面主体。专家团或分析模块详情用于解释研究分工、工具、数据来源和产出，不得把页面改造成聊天欢迎页或消息时间线。

### DEC-003 投研助理采用全局浮窗三态

投研助理是覆盖在任一业务页之上的全局能力，状态为：

```text
关闭 closed → 右侧停靠 docked → 近全屏 expanded
             ←               ←
```

- 右侧停靠：建议宽度 380～420px，保留当前业务页和关键操作；宽度不足时可使用覆盖式停靠，但不改变业务路由。
- 近全屏：以具名模态对话框覆盖大部分界面，保留安全边距和明确收起、关闭动作。
- 右侧停靠与近全屏只改变同一会话的呈现方式，不重新挂载或替换智能分析；业务表单、滚动位置、后台任务和已生成结果必须完整保留。
- 展开、收起、关闭均不得重建业务页或清除股票代码、筛选、选中策略、滚动位置和任务状态。
- `Escape` 在近全屏时先收起为右侧停靠，在右侧停靠时再关闭；关闭后焦点回到打开入口。
- 会话区提供分析模块选择器。选择模块只改变助理的工具范围和研究提示，不向输入框写入 JSON、内部路径或整份业务快照。
- “新建对话”清空消息、草稿、附件、晚到预填和会话模块选择，显示真正空白会话。

### DEC-004 风险详情使用跨模块复用的模态框

研究工作台和“我的投研”使用同一风险详情模型与组件。详情至少展示：风险标题、严重度、触发原因、影响说明、当前值与阈值、关联对象、数据来源、数据时间、降级状态、研究性复核建议和免责声明。

缺失字段显示“—”或“数据不足”，不得补成 `0`。后续动作只传稳定对象标识和自然语言意图，不在助理输入框展开风险 JSON。

### DEC-005 事件列表使用安全 Markdown 研究文档

“我的投研”新增事件列表；工作台和“我的投研”可以从同一事件打开一致的 Markdown 研究文档。章节顺序为：标题与摘要、快速结论、关联原因、关联标的、匹配策略、风险说明、来源与事件时间、免责声明。

- 只有后端返回稳定 `report_id` 且报告可从报告中心再次打开时，界面才称为“投研报告”。
- 暂无 `report_id` 时称为“事件研究详情”，由后端事件字段即时整理，不能冒充持久报告。
- `event_idx` 只能作为一次响应内的位置，不能保存或展示为事件身份；优先使用 `event_id` 或 `source_event_id`。
- Markdown 禁止危险 HTML、脚本协议、任意本地路径和未受控资源加载。

### DEC-006 策略研究内合并策略池和影子验证

策略研究页面至少提供“策略池”和“影子验证”两个内部视图。策略池以独立的验证分类组织：

| 验证分类 | 派生规则 |
|---|---|
| 已验证通过 | 最新有效样本外验证达到准入阈值 |
| 未验证 | 未运行、运行中、样本不足、成交不足或证据过期 |
| 验证未通过 | 最新有效验证已完成但未达到阈值，或已有明确拒绝证据 |
| 已归档 | 已退役、被替代或退出当前验证队列 |

验证分类是只读派生结果，与 `candidate / active / watch / rejected / retired` 生命周期状态并列展示，不能互相替代。模型文字不能直接决定分类。

策略详情模态框至少展示类型与标签、标的、策略逻辑、投资假设、触发与退出、持有期、风险约束、验证摘要、样本区间、交易数、胜率、收益、回撤、数据来源、数据日期、关联事件、最近报告和失败原因。

## 3. 本轮实现边界

### P0

- 智能分析恢复为结构化四任务工作台，并保留独立输入和真实任务状态。
- 投研助理实现关闭、右侧停靠、近全屏三态和模块选择。
- 风险详情在工作台和“我的投研”复用。
- “我的投研”增加事件列表与安全 Markdown 详情。
- 策略研究合并影子验证，提供四类验证筛选和策略详情。
- 报告、上下文工具、新建对话、工作区弱感知和明暗主题回归继续满足既有 P0。

### 后端未支持时的诚实降级

- 没有独立 `verification_status` 时，可用后端生命周期状态和最新有效回测证据做临时只读投影；界面必须标明“按当前验证证据归类”，且不得回写该投影。
- 没有事件 `report_id` 时只提供“事件研究详情”，不写入浏览器伪造报告记录。
- 字段不足时展示数据不足，不用文案生成器补造当前事实。

## 4. 交付与核对规则

1. 每项实现必须能反向追踪到本文件决策编号及模块需求编号。
2. 智能分析、助理、风险、事件、策略和影子验证都要覆盖加载、空、错误、成功和刷新保持。
3. 浏览器回归必须验证业务页在助理展开、收起和关闭前后状态一致。
4. Web 和 Electron 共用业务语义；仅存储实现、窗口能力等端差异进入设计说明。
5. 任何与本文件冲突的旧截图或旧测试均应更新，不得为保留旧测试而恢复错误交互。
