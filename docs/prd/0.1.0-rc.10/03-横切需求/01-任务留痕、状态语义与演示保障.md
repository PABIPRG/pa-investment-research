# 任务留痕、状态语义与演示保障

## `NF-001` 现状与目标分离

PRD 中的要求均为 rc.10 目标，不代表当前实现已经具备。实现、验收和演示记录必须分别标记“未开始、进行中、已实现、已验证、受限降级”，不得把会议决策或测试数据描述为现网事实。

## `NF-002` 持久化任务留痕

策略回测和影子验证任务在创建时即持久化，不能只在成功后保存报告。任务状态变化使用同一任务编号更新，保留创建、开始和结束时间；失败原因面向用户展示安全摘要，诊断细节留在本地日志。

列表查询必须支持按业务对象过滤和稳定排序。最近摘要可以缓存，但必须指向真实任务。服务重启后，运行中且无法恢复的任务要变为可解释的中断或失败状态，不能永久停留在运行中。

## `NF-003` 时间、交易日与调度

- 产品展示使用用户所在时区；存储必须采用无歧义时间格式。
- 15 天复测按自然日计算，从最近一次回测完成时间起算。
- 自进化五日门槛按不同的有效交易日计算，重复写入同一交易日不增加天数。
- 调度巡检必须幂等；进程重启或错过计划时刻后，下一次巡检补建应建任务，但不得重复补建。

## `NF-004` 状态语义一致性

策略参与状态、回测任务状态、验证结论、置信层级和来源是五个独立维度。前端列表、详情、AI 上下文、报告、风险中心和演示脚本使用同一词汇映射。机器字段可以保留英文，用户界面不得同时混用“生效”“通过”“升级”等不同维度的概念。

## `NF-005` 局部失败与可恢复性

- 回测、影子、风险、产业链和事件传导均按区域降级。
- 新请求失败时保留仍然有效的已加载数据，并明确标注更新时间和失败状态。
- 批量任务允许部分成功，逐项错误不会被汇总状态吞掉。
- 重试不生成无法解释的重复历史；用户主动重跑时明确标记重跑来源。

## `NF-006` 可访问性与响应式

新增帮助入口、状态筛选、任务列表、对话专家选择和 AI 让位布局均支持键盘操作、可见焦点、准确可访问名称和不小于 `44×44` 像素的主要触控目标。状态和权重来源不能只依赖颜色表达。页面在 rc.9 已覆盖的宽屏、窄桌面和移动基准视口下不得出现页面级横向溢出。

## `NF-007` 研究与交易隔离

智能分析、AI 对话、回测、影子验证、自进化、风险处理和演示数据都不得触发真实委托。影子资金、收益和净值必须标注为虚拟或纸面数据；报告不得使用“已成交”等会被理解为真实交易的无标识表述。

## 1. 演示保障

### `DEMO-001` 五个交易日影子数据（P0）

演示数据覆盖最近五个有效交易日，至少包含：一条正常运行策略、一条满足升级条件的策略、一条观察或淘汰示例，以及可展示的母子变异关系。数据必须标识为演示测试数据，可重复生成且不会污染真实用户数据。

验收条件：自进化看板显示五日门槛已满足；升级、观察/淘汰和变异至少各有可解释证据；清理演示数据不会删除真实持仓、报告或用户设置。

### `DEMO-002` 演示环境与操作脚本（P0）

演示使用浅色模式，按以下主线执行：

```text
用户画像与持仓
→ 实时行情和事件发现
→ AI 研究专家协同分析
→ 事件形成策略假设
→ 入池与自动回测
→ 回测历史
→ 影子验证与历史
→ 自进化升降级、淘汰和变异
→ 变异候选回流策略池
```

演示前逐项检查：浅色显示、实时盯盘 AI 让位、自动闭环开关、最近五日影子数据、回测历史、影子历史、产业链默认权重标识、报告入口以及全链路跳转。环境开关关闭或数据不足时必须在彩排阶段直接暴露，不得现场临时伪造完成状态。
