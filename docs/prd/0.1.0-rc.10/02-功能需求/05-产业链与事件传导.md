# 产业链与事件传导

## 1. 产业链图谱

### `CHAIN-001` 关系权重来源（P1）

页面统一使用“供应链关系权重”，不得描述为营收占比。每条关系必须区分以下来源：

| 来源 | 展示 | 百分比规则 |
|---|---|---|
| 披露 | “披露关系占比” | 展示接口返回的真实 `share` |
| 默认 | “默认关系权重 · 非披露占比” | 上游可用 20%、下游可用 10%，仅用于图谱展示和排序 |
| 推断 | “推断关系”与置信度 | 不展示默认百分比 |

关系详情统一说明：

> 关系权重用于表达当前图谱中的供应链关联强度。标记为“披露”的数值来自财报或研报；标记为“默认”的数值仅用于图谱展示和排序，不代表真实采购、销售或营收占比。

验收条件：任何默认值都能从数据和界面识别；推断关系没有伪造百分比；悬浮提示或详情注明财报、研报抽取或图谱推断来源。

### `CHAIN-002` 重新定中心、层级与图例（P1）

用户从搜索结果选择企业或执行“设为中心”后，以该企业为新根重新加载上下游图谱，不把旧根继续伪装为当前中心。普通节点聚焦和重新定中心是不同操作。

页面默认加载上下游各三层，并提供 1、2、3 层控制。颜色图例区分中心、上游、下游和推断关系；方向说明明确“供应商 → 当前企业 → 客户”。

验收条件：更换中心后标题、根节点、上下游方向和请求对象一致；层级变化不会残留超出当前层级的旧节点；颜色不能成为唯一辨识方式。

## 2. 事件传导

### `IMPACT-001` 有界分页与增量加载（P1）

事件传导与公司产业链分别加载。优先提供 `offset/page/cursor` 之一以及总数或 `has_more`，前端支持滚动或“加载更多”、增量去重、加载中、加载失败、重试和没有更多数据。

若上游只能返回固定数量，适配层必须明确返回“不支持继续分页”和当前最大可见数量；前端展示“当前最多显示 N 条”，不显示虚假的加载更多，也不推断不存在的总数。

验收条件：重复页或重复事件不会产生重复卡片；增量失败保留已加载内容；公司图谱失败不阻止事件传导，反之亦然；直接标的和扩展影响明确区分。
