# 影子验证与自进化

## 1. 影子验证

### `SHADOW-001` 准入规则（P0）

首次回测任务执行状态为 `completed` 且参与状态为 `active` 或 `watch` 的策略可以运行影子验证，不要求 `verification_status` 为 `passed`。`candidate` 在首次任务尚未成功完成前不可运行；`retired/rejected/archived` 不可运行。

影子验证只使用真实行情和虚拟资金，不创建真实订单，不连接真实交易委托。

验收条件：`passed/not_passed/insufficient` 三类已完成回测的参与中策略均可发起；任务仍在运行、执行失败、取消或策略已退出时，会得到准确、可解释的阻止原因。

### `SHADOW-002` 影子验证历史（P0）

建立持久化影子验证任务及逐策略结果。页面区分：最近一次影子验证摘要、当前策略历史、全部策略历史。历史记录至少包含策略名称和编号、验证交易日、任务创建/开始/完成时间、手动或自动来源、单策略或批量范围、运行状态、跟踪起始时间、初始资金、当前权益和净值、持仓与平仓数量、数据异常、失败原因和报告入口。

净值时间序列作为任务证据展示，但不能替代任务历史。批量任务需要保留总体状态以及每条策略的成功、失败或跳过结果。

验收条件：可从最近摘要定位到任务；按策略筛选只返回该策略参与的任务；失败和部分成功记录不会消失；服务重启后仍可查询。

### `SHADOW-003` 单策略与批量运行（P0）

用户可以对当前策略运行，也可以对全部符合条件的策略批量运行。页面继续提供纸面持仓、策略净值和正式报告入口，并明确“真实行情、虚拟资金、不会下单”。

验收条件：批量运行不会因单策略异常而丢失其他结果；重复运行同一交易日遵守明确的幂等或重跑规则；历史清楚标记重跑来源。

## 2. 自进化

### `EVO-001` 状态与文案统一（P1）

- “带内运行”统一展示为“正常运行”。
- `watch` 展示为“观察中”。
- `tier=2` 展示为“已升级”。
- `retired` 按上下文展示为“已淘汰”或“已退役”。
- 变异展示为“变异来源”标记，不作为独立运行状态或与候选重复计数。

验收条件：列表、看板、详情、报告和 AI 上下文使用同一映射；用户可以同时看到参与状态、回测结论、置信层级和变异来源而不混淆。

### `EVO-002` 首屏闭环看板（P1）

页面上方以紧凑看板展示：自动闭环是否启用、最近运行时间、下一次计划时间、影子数据完成度、正常/观察/升级/淘汰策略数量和最近自动动作。母子策略关系在首屏提供可展开入口，进入单策略后可查看完整衍生链。

验收条件：无需向下滚动即可判断闭环是否运行、数据是否足够和最近发生了什么；数量统计不把变异候选重复当作独立生命周期状态。

### 自进化判定展示

达到五个有效交易日后，按产品架构定义的 `1.03/0.95/0.90`、三笔平仓和 `35%` 胜率规则执行。未达到门槛时只展示证据与完成度，不产生升降级、淘汰或变异动作。变异动作同时展示母策略、变异参数摘要、生成时间和冷却期状态。
