# 数据可用性与失败恢复

## 1. 统一状态语义

| 产品状态 | 展示规则 | 用户操作 | 系统行为 |
|---|---|---|---|
| 准备中 | 中性骨架或状态文案，不使用红色告警 | 可切股、最小化或关闭 | 保持单一后台任务并自动获取结果 |
| 可用 | 展示数据和事实时间 | 可刷新 | 在缓存有效期内复用结果 |
| 缓存可用 | 展示旧数据、缓存标签和原始时间 | 可继续研究或主动刷新 | 后台静默刷新，不清空旧数据 |
| 最终失败 | 只在失败区域显示错误 | 可手动重试 | 不影响其他区域，不形成请求风暴 |
| 空数据 | 明确说明当前没有结果 | 可切换条件或证券 | 不把空数据包装为错误或伪造结果 |

HTTP 前台等待预算、后台任务状态和产品失败状态不得混为一谈。请求仍在后台运行时属于“准备中”，不是“最终失败”。

## 2. 数据有效性

- 所有写入 JSON 响应的浮点数必须是有限数；非有限数统一转换为缺失值。
- 缺失价格、涨跌幅、量比或成交额使用 `—`，不得使用 `0` 冒充真实值。
- 缓存响应保留最初获取时间，不得用本次读取时间覆盖事实时间。
- 个股资讯必须携带归一化证券代码；市场快讯不得获得虚假的证券归属。
- 供应商代码由统一证券市场事实生成，不允许各调用点按前缀重复猜测。

## 3. 外部源失败分类

外部行情请求至少区分：超时、连接断开、限流或上游服务错误、合法空结果、响应格式错误。用户界面只显示安全且可行动的摘要，来源、扫描类型、耗时、回退路径和异常类别记录到本地日志，不记录凭据或完整响应正文。

参数校验错误使用输入错误语义；外部行情不可用使用服务可用性语义；后台仍在执行使用准备中语义。三者不得互相替代。

## 4. 主备源与缓存

- 每类扫描声明主源、可用备用源和字段能力；备用源缺少关键字段时只返回其真实能力。
- 最近成功缓存按扫描条件、证券代码和数据类型隔离，使用有界容量与有效期。
- 实时源失败时优先返回仍在允许陈旧窗口内的缓存；超过窗口后不再展示为可用数据。
- 同一请求键在后台只运行一个刷新任务；重复前端查询复用该任务。
- 失败结果使用短时负缓存，避免同一无数据证券持续触发完整供应商链路；用户主动重试可在规则允许时重新发起。

## 5. 并发与切换

- 用户的最后选择是界面唯一权威对象。
- 请求键至少包含操作、证券代码、扫描类型和影响结果的参数。
- 新选择产生新代次；旧代次完成后只能进入对应缓存，不能更新当前视图。
- A→B→A 时，未完成的同键任务可以复用；已完成的同键缓存可以先展示再刷新。
- 关闭研究窗停止该窗口的前端轮询和定时器，但不强制中止已经由后端接管的唯一刷新任务。

## 6. 移动端与可访问性

- 覆盖层打开时背景使用不可交互语义并锁定滚动，关闭后恢复原滚动位置和触发焦点。
- 模态状态限制焦点在悬浮窗内；标准桌面状态不错误地声明模态。
- 图标按钮必须有中文可访问名称，错误重试名称包含对应区域。
- 状态更新使用礼貌播报，最终失败使用警示语义；准备中不得反复播报警告。
- 支持深浅主题、系统安全区、`prefers-reduced-motion` 和至少 `44×44` 像素触控目标。

## 7. 降级边界

以下情况不得伪装成成功：所有实时源失败且没有合格缓存；个股资讯源失败却展示全市场新闻；北交所数据源不支持却请求沪市代码；K 线后台已经确认无数据却无限显示准备中。

以下情况不得扩大为整页失败：单个指数数字异常；一个扫描来源断连；技术信号仍在冷加载；个股资讯为空；全市场快讯不可用。
