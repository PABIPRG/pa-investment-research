# 统一上下文与模型工具

> 需求前缀：`CTX`

## 1. 目标

让模型在需要时读取最新业务事实，同时保持输入框可读、上下文可追溯、访问边界受控。0.1.0-rc.7 禁止把页面业务快照序列化成 JSON 塞入用户输入框。

## 2. 产品模型

页面只提交：

- 用户可读的自然语言意图。
- 当前模块和必要的不透明对象标识。

模型通过统一上下文能力（本文简称 `investment_context`）或证券、盯盘等领域工具读取：

- `portfolio`：持仓、自选、风险画像和组合风险。
- `strategy`：策略、状态、证据与回测摘要。
- `shadow`：影子状态、持仓和净值。
- `evolution`：就绪状态、归因和预案。
- `reports`：报告列表或指定报告。
- `industry`：公司、节点和关系。
- 证券与市场领域工具：证券详情、行情、信号和新闻。

## 3. 功能需求

| ID | 要求 | 级别 |
|---|---|---|
| CTX-001 | 输入框只展示用户可理解的自然语言，不展示系统 JSON | P0 |
| CTX-002 | 上下文读取只接受固定领域、受控筛选和可校验对象标识 | P0 |
| CTX-003 | 工具不接受浏览器提供的任意 URL、端口、路径或后端名 | P0 |
| CTX-004 | 模型按问题需要调用工具，不在每轮无条件加载全量数据 | P0 |
| CTX-005 | 工具结果标明领域、对象、数据时间、可用性和截断状态 | P0 |
| CTX-006 | 工具调用进入正式可持久重放的会话轨迹 | P0 |
| CTX-007 | 后端事实变化后再次读取获得新版本，不复用页面旧副本 | P0 |
| CTX-008 | 无权限、不存在、过期和后端失败必须可区分 | P0 |
| CTX-009 | 工具结果有大小边界，超出时提供分页或进一步读取方式 | P0 |
| CTX-010 | 页面与模型对同一对象使用同一稳定标识 | P0 |

## 4. 调用时机

- 用户只浏览、筛选或刷新页面时，不自动调用模型。
- 用户发送普通问题时，模型根据问题决定需要哪些领域。
- 页面内“解读当前策略”等动作可提示模型优先读取对应领域和对象。
- 模型不得仅凭对象名称猜测标识；歧义时应调用搜索或请求用户选择。

## 5. 上下文卫生

- 不把持仓全量、报告正文或产业全图预先注入每个会话。
- 不把代码、接口实现和工作区路径作为默认投研上下文。
- 不在产品埋点记录工具完整结果。
- 模型回答区分工具事实、基于事实的推断和无法确认的信息。

## 6. 失败体验

- 单一领域失败不阻止模型使用其他已获得事实。
- 助手明确说出哪个领域不可用以及数据时间，不用常识补成当前事实。
- 用户可以重试读取或返回直接数据页。
- 工具失败不修改业务对象，也不清空输入草稿。

## 7. 验收

- 从 7 个业务域分别发起助理动作，输入框均无 `{...}` 业务 JSON。
- 工具拒绝未知领域、任意路径和非法对象标识，且在后端租约前完成拒绝。
- 会话重放后仍能看到相同工具调用边界和对象引用。
- 页面数据更新后，模型的新一轮读取能获得新版本并显示新时间。

## 8. 设计留白

工具、Skill 或二者组合的具体编排进入设计文档，但不能改变以上产品边界。
