# 异步任务、数据状态与失败恢复

> 需求前缀：`ASYNC`

## 1. 目标

慢后端、部分失败、切页和前台超时是正常运行状态。产品必须保留已获得结果、解释当前状态并提供恢复路径。

## 2. 数据区状态

每个独立数据区至少支持：

```text
idle / loading / ready / empty / refreshing / error / stale
```

- 首次加载可展示骨架。
- 刷新保留上次成功值，并标明正在更新。
- 新筛选使旧响应失效；晚到响应不得覆盖当前选择。
- `empty` 是成功无数据，不能与 `error` 混用。
- `stale` 展示上次成功时间和刷新入口。

## 3. 任务状态

| ID | 要求 | 级别 |
|---|---|---|
| ASYNC-001 | 创建任务后立即展示稳定任务或报告标识 | P0 |
| ASYNC-002 | 任务状态在来源页和报告中心保持一致 | P0 |
| ASYNC-003 | 前台等待有明确上限，超时不等于任务失败 | P0 |
| ASYNC-004 | 用户离开来源页后任务继续运行并可恢复查看 | P0 |
| ASYNC-005 | 重复提交使用幂等键或明确二次确认 | P0 |
| ASYNC-006 | 失败区分校验、后端不可用、执行失败和超时 | P0 |
| ASYNC-007 | 可重试动作不覆盖旧失败记录和证据 | P0 |
| ASYNC-008 | 后端无能力时明确“当前版本不支持”，不展示假成功 | P0 |
| ASYNC-009 | 三套后端分别健康检查，一个失败不拖垮无关模块 | P0 |
| ASYNC-010 | 应用关闭时正确清理托管进程，不遗留冲突端口 | P0 |

## 4. 错误呈现

错误信息回答三件事：发生了什么、哪些数据仍可信、用户下一步能做什么。

不直接向普通用户展示堆栈、内部路径、端口、租约或原始异常；排障信息进入可复制的诊断详情。

## 5. 启动与托管

- 标准启动脚本负责校验依赖、准备 macOS 原生模块、构建并启动应用。
- 启动阶段超过合理时间必须输出当前阶段，不能静默卡住。
- 后端启动失败显示具体服务和恢复动作；已健康服务不被误报为全局失败。
- 退出应用后由本次启动拥有的托管后端应被清理；外部托管服务不被误杀。

## 6. 数据诚实性

- 不可用值显示 `—` 或说明，不把缺失值转换为 `0`。
- 旧数据可以保留，但必须带时间和过期状态。
- 模型生成解释不能替换后端失败区的真实状态。
- 模拟/影子数据始终与真实持仓和真实收益明确区分。

## 7. 验收

- 分别关闭三套后端，验证受影响模块和无关模块的隔离。
- 对慢请求快速切换筛选，最终页面与最新选择一致。
- 在任务运行时切页、关助理、刷新浏览器，最终报告仍可恢复。
- macOS 干净安装后标准脚本可完成启动，原生模块失败有明确提示。
