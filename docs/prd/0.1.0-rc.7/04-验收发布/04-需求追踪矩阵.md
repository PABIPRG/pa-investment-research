## 3. 更新规则

- 设计文档必须逐项声明 `满足 / 部分满足 / 不满足`，不能只引用整个文件。
- 实现计划必须列出会修改的模块和对应需求编号。
- 测试必须能反向查到需求；同一用例可覆盖多个编号。
- 需求删除或延期时保留行并链接正式变更记录。
- 状态只允许：待评审、已批准、设计中、实现中、待验收、已验收、已延期。
