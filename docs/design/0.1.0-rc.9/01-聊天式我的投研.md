# 聊天式「我的投研」设计文档

> 文档版本：0.1.0-rc.9
> 文档状态：设计评审通过
> 对应需求：[聊天式「我的投研」需求文档](../../prd/0.1.0-rc.9/02-功能需求/01-聊天式我的投研.md)
> 最后更新：2026-09-01

## 1. 设计摘要

本设计将现有 `portfolio` 路由改造成共享对话的主展示模式，并在 `conversation.input.left` 插槽中提供会话级策略和标的选择器。选择结果不写入用户消息正文，而是通过固定、受校验的数据操作保存到本地交易后端；模型在回答涉及当前策略或标的的问题前，通过一个无参数、只读的工具按当前 Agent 会话标识读取上下文和最新策略事实。

该方案的核心是把三类状态分开：

1. 会话消息、草稿和生成状态继续由统一会话系统负责。
2. 当前会话选中的策略标识与标的元数据由会话研究上下文负责。
3. 策略详情、验证状态、行情和新闻始终从各自业务数据源按需读取，不复制到会话上下文中作为事实快照。

原有持仓、自选、风险和偏好页面不会删除，而是重组为按需展开的「投研资料」面板。其他页面现有的悬浮/停靠式投研助理保持原行为。

## 2. 设计原则

- 复用共享对话，不复制消息列表、输入框或会话历史实现。
- 选择器真实参与模型上下文，不以纯视觉标签冒充功能。
- 用户正文保持自然语言，不注入隐藏 JSON 或机器提示词。
- 策略事实按使用时读取，避免会话长期存在造成状态陈旧。
- 默认只读；聊天链路不注册或调用任何策略状态变更能力。
- 每个会话独立保存上下文，先确认保存，再更新可见选中态。
- 失败状态分域呈现；策略、标的、资料和聊天互不伪装为空。
- 首期只覆盖当前工具链可靠支持的 A 股与场内 ETF。

## 3. 现状约束

### 3.1 共享对话

- `conversation.input.left` 是输入框工具栏左侧的小控件插槽，拥有当前 `InputZone.session` 与 `InputZone.input` 快照。
- 共享对话发送接口当前只接收文本和图片，不接受业务元数据。
- 因此不能通过修改 `prompt` 参数直接附带策略或标的，也不应把业务 JSON 拼到消息正文。

### 3.2 我的投研页面

- 当前 `portfolio` 路由渲染资产、风险、自选和事件看板。
- 共享对话在投研助理关闭时由工作台 CSS 隐藏；打开助理后以停靠或展开浮层显示。
- 当前 `InvestmentUiSnapshot.selectedStrategyId` 是工作台全局状态，不能满足会话隔离。

### 3.3 策略与证券数据

- `GET /strategies` 和 `GET /strategies/{sid}` 已提供策略列表和详情。
- 策略详情包含生命周期、验证状态、参数、证券范围和回测证据。
- `GET /securities/search` 已同时搜索 A 股和场内 ETF，并返回代码、名称、市场和类型。
- `analyze_stock` 面向 A 股；场内 ETF 首期主要使用行情、技术信号和新闻类工具，不声称具备公司基本面分析。

### 3.4 后端与浏览器边界

- 浏览器只能通过 `InvestmentDataOperation` 固定白名单访问后端。
- `JsonStore` 已具备集合名校验、线程锁和原子替换，可承载少量本地会话选择状态。
- 工具执行上下文可通过 `exec.agent.session.header.id` 获取真实会话标识，不需要模型传入会话 ID。

## 4. 方案比较与结论

| 方案 | 优点 | 主要问题 | 结论 |
| --- | --- | --- | --- |
| 仅保存在前端全局状态 | 改动小 | 会串会话、刷新丢失、模型无法可靠读取 | 不采用 |
| 把策略和标的拼进用户正文 | 实现直接 | 污染消息、暴露机器提示、历史难以区分用户原话 | 不采用 |
| 扩展共享对话发送协议携带任意业务元数据 | 表面统一 | 扩大通用层职责，形成无边界业务载荷 | 不采用 |
| 会话级本地上下文 + 无参数只读工具 | 隔离、持久、可追踪，保持正文纯净 | 需要前后端契约和工具改造 | 采用 |

## 5. 总体架构

```mermaid
flowchart LR
    U[用户] --> C[共享对话输入框]
    U --> S[策略选择器]
    U --> I[标的选择器]
    S --> O[浏览器固定数据操作]
    I --> O
    O --> R[(research_chat_contexts)]
    S --> P[策略池 /strategies]
    I --> M[证券搜索 /securities/search]
    C --> A[当前会话 Agent]
    A --> T[investment_research_context]
    T --> R
    T --> D[策略详情 /strategies/{sid}]
    A --> E[现有行情、新闻、分析工具]
    T --> A
    E --> A
    A --> V[带事实与风险边界的回答]
```

### 5.1 选择链路

1. 选择器从策略池或证券目录取得候选项。
2. 用户确认候选项时，前端携带当前会话 ID、完整目标上下文和期望修订号调用固定保存操作。
3. 后端在同一文件锁中验证修订号并写入新记录。
4. 保存成功后，前端才更新工具栏中的已确认标签。
5. 保存失败时，前端继续展示上一次已确认上下文。

### 5.2 回答链路

1. 用户发送自然语言问题，消息正文不包含隐藏策略或标的字段。
2. 模型遇到策略、具体证券或“当前/这个/选中的”等上下文指代时，先调用 `investment_research_context`。
3. 工具从 `exec.agent.session.header.id` 获取会话 ID，读取该会话上下文。
4. 如存在策略标识，工具再次读取最新策略详情并计算推荐状态、适用性和警告。
5. 模型再按标的类型调用现有 A 股分析或行情、技术信号、新闻工具。
6. 工具结果进入正常会话记录，使本轮使用的上下文和证据可追踪。

## 6. 前端设计

### 6.1 页面展示模式

新增“我的投研主对话”展示语义，不创建第二套 Conversation：

- 当 `route === 'portfolio'` 时，工作台根节点设置 `data-investment-conversation-primary="true"`。
- 主内容区让共享 `[data-conversation-scroll]` 按正常页面宽度展示，不使用助理停靠浮层定位。
- `AssistantFloatingSurface` 在该路由不显示启动按钮、停靠头部或展开遮罩。
- 其他路由继续使用当前 `assistantMode = closed | docked | expanded` 行为。
- 路由切换只改变展示方式，不销毁当前共享会话。

建议将现有 CSS 条件从“工作台激活即隐藏对话”拆成两个明确状态：

- `data-investment-workbench-active`：投研工作台导航与外壳存在。
- `data-investment-conversation-primary`：共享对话是当前路由主内容。

### 6.2 输入框控件

将当前单一的 `InvestmentAssistantModuleSelect` 重组为 `InvestmentComposerContextControls`：

- `route === 'portfolio'`：渲染 `StrategyContextPicker` 与 `InstrumentContextPicker`。
- 其他路由且助理已打开：继续渲染原固定研究模块选择器。
- 其他情况：不渲染业务控件。

控件继续注册在 `conversation.input.left`，建议顺序为：

```text
[附件] [策略：选择策略/名称+状态] [标的：添加标的/名称+代码] … [模型] [语音] [发送]
```

策略和标的触发器使用紧凑按钮；已选状态显示可截断名称，完整信息通过标题、辅助文本和选择面板提供。非推荐策略触发器需包含文字或图标加可读名称的风险态，不能只改变颜色。

### 6.3 策略选择器

选择器采用可搜索的浮层或对话框，不使用只能展示短标签的简单菜单。

内容顺序：

1. 搜索框。
2. 当前已选策略摘要与清除操作（如有）。
3. “推荐策略”分组：`status=active && verification_status=passed`。
4. “其他策略”分组：其余全部策略。
5. 当前焦点项的详情预览：假设、类型、关键参数、证券范围、更新时间和状态说明。

排序规则：

- 推荐分组在前，组内按 `updated_at || created_at` 倒序。
- 其他分组按生命周期风险级别和更新时间稳定排序，不隐藏任何状态。
- 搜索仅过滤当前已加载策略；打开选择器时重新请求最多 200 条，避免沿用长期缓存。

交互规则：

- 点击候选项后进入“正在保存”，候选项和确认操作暂时禁用。
- 保存成功才关闭浮层并更新触发器。
- 409 修订冲突时重新读取上下文，展示“该会话已在其他位置更新，请重新选择”。
- 其他失败保留原选择并允许原地重试。

### 6.4 标的选择器

- 输入代码或名称后，延迟约 180ms 调用 `market-watch.security-search`。
- 每次新搜索增加请求代次；只接纳最新代次结果。
- 结果展示名称、代码、市场和 `股票 | ETF` 类型。
- 只允许从搜索结果确认标的，不允许把任意文本直接保存为标的代码。
- 清除、更换和失败恢复与策略选择器使用同一上下文保存协议。
- ETF 需在详情说明中提示“首期提供行情、技术信号和相关新闻研究，不等同于成分股基本面分析”。

### 6.5 会话状态控制器

新增客户端 `ResearchChatContextController`，以会话 ID 为键管理：

```ts
type ResearchChatContextPhase =
  | 'idle'
  | 'loading'
  | 'ready'
  | 'saving'
  | 'error'

interface ResearchChatContextEntry {
  phase: ResearchChatContextPhase
  confirmed: ResearchChatContext | null
  error?: string
  loadGeneration: number
  saveGeneration: number
}
```

职责：

- 首次看见一个会话 ID 时读取上下文。
- 缓存每个已访问会话的确认值，同时在重新进入时执行后台刷新。
- 只有对应请求代次仍为最新时才接纳响应。
- 保存时发送完整目标状态和 `expected_revision`，避免两个局部更新互相覆盖。
- 选择器内部的待选值不进入 `confirmed`，因此用户在保存过程中发送消息时，模型仍读取并使用工具栏当前可见的旧确认值。
- 新会话 ID 默认读取为空，不从前一个会话复制。

会话生成期间，策略和标的控件只读，避免模型首次读取上下文前发生同窗口切换。工具一旦执行，其结果随该轮对话持久化；后续更改只影响下一轮。

### 6.6 投研资料面板

将现有 `PortfolioPage` 的业务卡片重组为 `InvestmentMaterialsDrawer`，保留原数据请求与子组件：

- 持仓概览与持仓分析入口。
- 自选列表。
- 风险提醒。
- 个性化事件。
- 偏好复核。

「我的投研」主内容仅保留一个轻量“投研资料”入口和必要的高风险数量提示。面板从侧边或底部按需展开，关闭后不改变会话、草稿和研究上下文。资料区加载状态独立于对话区。

### 6.7 可访问性与响应式

- 触发器使用 `aria-haspopup`、`aria-expanded` 和包含当前值的 `aria-label`。
- 搜索结果使用组合框与列表框语义，并维护 `aria-activedescendant`。
- `Escape` 关闭并将焦点返回原触发器；上下键移动，Enter 确认。
- 保存中和错误信息通过可读状态区播报。
- 窄屏时两个选择器允许缩短为图标加短标签，但不能隐藏当前状态风险。
- 面板不得遮住共享输入框的主要发送操作。

### 6.8 研究工作台二级模态框

`ResearchWorkbenchPage` 的概览指标改为当前页详情状态，不再调用 `navigate('portfolio')` 或 `scrollIntoView`：

```ts
type WorkbenchDetailKind =
  | 'holdings'
  | 'cost'
  | 'market-value'
  | 'risk-profile'
  | 'risk-center'
```

新增 `WorkbenchOverviewDialog`，复用 `DetailDialog` 的 Portal、焦点约束、`Escape`、遮罩关闭和焦点返回能力。页面只保存当前详情类型；模态框消费工作台已经加载并规范化的 `positions`、`quoteMap`、`riskValue`、`riskSummary`、`alertValue` 和 `alertItems`，不发起第二套数据请求。持仓、行情、组合风险和预警的 `loaded`、`busy`、`error` 状态一并传入，分别展示加载中、首次失败、保留旧数据和真实空态，禁止把未知状态显示成零持仓或零预警。

- `holdings`：持仓总数及完整持仓列表，逐项显示名称、代码、数量和成本价。
- `cost`：组合成本总额及逐项“数量 × 成本价 = 成本金额”；缺失字段显示“—”并说明数据不足。
- `market-value`：组合现价总额及逐项“数量 × 实时价 = 市值”；没有实时价时不使用成本价代替。
- `risk-profile`：画像名称、组合风险预算、集中度 HHI、等权占比和预算突破。`risk-portfolio` 在同一响应中返回完整 `risk_budget`，即使没有突破也展示单股、HHI、组合波动和 Beta 上限。
- `risk-center`：风险画像摘要、完整风险预算、预算突破和全部预警；突破项展示 `value`、`limit`、`excess`，预警展示来源、代码或策略关联范围，并聚合安全的研究复核建议。“需关注预警”卡片与“查看完整风险详情”均打开该模态框，前者优先展示高/中风险计数，但不隐藏低风险事实。

概览五张卡片统一声明 `aria-haspopup="dialog"`。`DetailDialog` 在挂载时记录触发按钮，关闭后恢复焦点，因此不在工作台重新实现焦点管理。模态框使用宽版布局容纳明细表，窄屏下转为纵向卡片；明暗主题沿用现有详情变量。

明确跨模块的“查看个股”“进入策略研究”等动作保留 `navigate`。本设计只替换概览指标和“查看完整风险详情”的详情承接方式。

### 6.9 当前页持仓编辑

`holdings` 详情由只读表升级为同一二级模态框内的查看与编辑状态。`ResearchWorkbenchPage` 继续拥有已加载持仓资源，并向 `WorkbenchOverviewDialog` 注入 `onSaveHoldings`；模态框只维护未保存的草稿、编辑目标、校验错误和删除确认状态，不另建持仓数据源。

编辑采用单一内联表单，避免在二级模态框之上叠加第三层弹窗：

- 默认展示持仓表和“导入持仓”；点击某行“编辑”后，在表格上方显示股票代码、数量和成本价表单，新增持仓统一进入 6.10 的录入子流程。
- 编辑既有持仓时用原代码标识被替换项。六位代码、数量大于零、成本价大于零和代码唯一性在提交前统一校验。
- 某行首次点击“删除”只进入该行确认态，显示“确认删除”和“取消”；确认后修改草稿并立即通过统一保存回调提交，取消不产生请求。
- 所有写操作调用 `trading-core.holdings-save`，请求体始终为完整的 `{ holdings: [...] }`，与后端整体替换语义一致。保存期间禁用新增、编辑、删除、关闭和重复提交。
- 保存失败时保留编辑草稿和当前已加载持仓，错误在模态框内播报；保存成功后清理编辑态、显示成功状态，把服务端已接受的完整 payload 暂存为乐观操作快照，并递增工作台 `refreshVersion`。

工作台刷新版本变化后复用现有资源请求重新加载持仓、组合风险、风险预警、个性化匹配和事件；行情轮询以新持仓集合重新取数。模态框保持打开；在新持仓资源与乐观快照逐项对账一致前，列表展示和后续编辑、删除继续以快照为基线，避免用刷新前列表覆盖已保存结果；对账一致后再释放快照并恢复服务器数据。现有 CSV/TSV 导入入口保持不变。

### 6.10 当前页批量导入持仓

`HoldingsEditor` 使用“查看层 → 录入子流程”的两级内容结构，不把查看持仓和导入方式做成平级入口：

- 查看层是模态框默认内容，只展示持仓数量、完整持仓表、“导入持仓”按钮，以及每行独立的编辑、删除操作。行内编辑继续使用现有内联表单。
- 点击“导入持仓”后，同一模态框内容切换到录入子流程。子流程顶部展示“返回持仓明细”，其内部才提供“单条录入 / 批量导入”分段入口。
- 单条录入使用独立新增草稿和现有字段校验，保存成功后返回查看层；批量导入展示导入区、统计、错误列表和预览表，同样在成功后返回查看层。
- 查看层与录入子流程不叠加弹窗，也不复用 `InvestmentShell` 中独立的 `HoldingsImportDialog`，避免二级模态框之上形成第三层弹窗。

批量导入复用 `parseHoldingsImport` 作为唯一解析器，并把文件选择、拖放文件和粘贴文本统一收敛为字符串 `importSource`：

- 文件区同时提供可点击的文件选择器和拖放反馈，接收 `.csv`、`.tsv`、`.txt`；读取失败只更新导入错误，不清空已有文本。
- 文本变化后通过纯解析函数即时生成 `items` 与逐行 `errors`。摘要显示有效项和错误数；预览最多展示前 20 项，超过部分用数量说明。
- 只有 `items.length > 0 && errors.length === 0 && !saving` 时允许提交。提交区明确展示“当前 N 条 → 导入后 M 条”，按钮文案为“确认替换 M 条持仓”。
- “单条录入 / 批量导入”分段切换及返回查看层只改变可见内容，不销毁单条草稿、`importSource`、解析结果或错误；关闭整个详情模态框后再由组件生命周期清理。

单条录入把新增项与当前持仓合并后调用 `onSaveHoldings`；批量导入继续调用 `onSaveHoldings(result.items)`，两者请求均为完整 `{ holdings: [...] }`。保存开始后通过现有 `onSavingChange(true)` 锁定返回、方式切换、文件输入、文本框、详情模态框关闭和重复提交；保存失败保留对应草稿，成功后清空已提交草稿、把完整 payload 提升为乐观操作快照、返回持仓查看层、播报结果，并由工作台现有刷新版本重新加载全部组合资源。

层级切换由 `focusRequestRef` 记录目标：进入录入子流程后聚焦当前选中的“单条录入”标签，返回查看层或保存成功并解除锁定后聚焦“导入持仓”。`DetailDialog` 本身可聚焦；当保存锁导致内部没有任何可用控件时，其 `Tab` 焦点约束回退到模态框容器，保证焦点不会进入背景页面。

布局复用现有表格和按钮视觉语言。桌面端导入说明与输入保持清晰分区；窄屏下导入控件纵向排列，文件区和按钮占满可用宽度，预览只在自身容器内横向滚动。所有模式按钮、文件输入、文本框、错误和成功信息均提供可读名称或 `role`，保证键盘和辅助技术能够完成流程。

## 7. 会话研究上下文数据设计

### 7.1 持久化对象

```ts
interface ResearchChatInstrument {
  code: string
  name: string
  market: string
  type: 'stock' | 'etf'
}

interface ResearchChatContext {
  schema_version: 1
  session_id: string
  strategy_id: string | null
  instrument: ResearchChatInstrument | null
  revision: number
  updated_at: string
}
```

持久化集合：`research_chat_contexts`。集合键为 `session_id`。

### 7.2 数据边界

- 只存策略 ID，不存策略名称、参数、状态或回测结果。
- 标的名称与市场作为恢复展示元数据；分析和适用性以代码、类型及实时业务接口为准。
- 不存用户消息、模型回答、持仓数据、凭证或交易权限。
- 上下文为空时保留空记录和递增修订号，防止删除记录后陈旧的 `expected_revision=0` 写入成功。

### 7.3 校验

- `session_id`：1–128 位，仅允许字母、数字、`.`、`_`、`:`、`-`。
- `strategy_id`：复用现有安全路径标识约束；非空时保存前确认策略存在。
- `instrument.code`：六位数字。
- `instrument.name`：去除首尾空白，1–80 个字符。
- `instrument.market`：去除首尾空白，1–32 个字符。
- `instrument.type`：仅 `stock | etf`。
- 请求拒绝未知字段；服务端生成修订号和更新时间。

## 8. 后端接口设计

浏览器运行时当前仅支持 `GET | POST` 固定操作，因此保存使用 `POST`，而不是为了 REST 形式扩展通用请求面。

### 8.1 读取上下文

```http
GET /research-chat/contexts/{session_id}
```

存在记录：

```json
{
  "exists": true,
  "context": {
    "schema_version": 1,
    "session_id": "session-id",
    "strategy_id": "strategy-id",
    "instrument": {
      "code": "600519",
      "name": "贵州茅台",
      "market": "沪市",
      "type": "stock"
    },
    "revision": 4,
    "updated_at": "2026-09-01T08:00:00Z"
  }
}
```

从未保存时返回 `200`、`exists=false`、`context=null`，不使用 404 表示正常空状态。

### 8.2 保存完整上下文

```http
POST /research-chat/contexts/{session_id}
Content-Type: application/json
```

```json
{
  "expected_revision": 4,
  "strategy_id": "strategy-id",
  "instrument": {
    "code": "510300",
    "name": "沪深300ETF",
    "market": "沪市 ETF",
    "type": "etf"
  }
}
```

规则：

- 请求表达完整目标状态；需要清除某一字段时显式传 `null`。
- 首次写入使用 `expected_revision=0`。
- 服务端在 `JsonStore.mutate` 的同一把集合锁内比较修订号并写入。
- 成功返回最新完整上下文。
- 修订不一致返回 HTTP 409，不自动覆盖其他位置的新状态。
- 策略不存在返回 HTTP 404；输入不合法返回 HTTP 422；存储损坏返回受控 500 并记录日志。

### 8.3 浏览器固定操作

扩展 `InvestmentDataOperation`：

| 操作 | 方法与路径 | 关键输入 | 本地限制 |
| --- | --- | --- | --- |
| `trading-core.research-chat-context` | `GET /research-chat/contexts/{session_id}` | `session_id` | `localOnly: true` |
| `trading-core.research-chat-context-save` | `POST /research-chat/contexts/{session_id}` | `session_id`、`expected_revision`、`strategy_id`、`instrument` | `localOnly: true` |

固定操作层必须拒绝未知键、非法会话 ID、非法策略 ID、非六位证券代码和非白名单标的类型。上下文属于个性化本地状态；当交易后端配置为 `external` 时，选择器显示明确不可用原因，不把选择静默发送到外部后端。

## 9. 模型工具设计

### 9.1 新工具

新增只读工具：

```text
investment_research_context()
```

工具不接受参数。会话 ID 只能来自 `exec.agent.session.header.id`，缺少 Agent 会话时返回受控不可用结果，不能退化为读取全局最近上下文。

### 9.2 执行逻辑

1. 断言 `trading-core` 非 LLM 能力可用。
2. 读取当前会话上下文。
3. 若上下文为空，返回 `status=empty`。
4. 若有策略 ID，读取 `/strategies/{sid}` 最新详情。
5. 若策略不存在，返回 `status=invalid` 和 `STRATEGY_NOT_FOUND`，保留标的信息。
6. 计算推荐状态、策略与标的适用性以及结构化警告。
7. 返回时间戳、上下文修订号、策略事实、标的和警告。

建议输出：

```ts
interface InvestmentResearchContextResult {
  status: 'ready' | 'empty' | 'invalid' | 'unavailable'
  context_revision?: number
  context_updated_at?: string
  strategy?: Record<string, unknown>
  instrument?: ResearchChatInstrument
  recommended?: boolean
  compatibility?: 'direct' | 'method_only' | 'not_applicable'
  warnings: Array<{
    code: 'STRATEGY_NOT_RECOMMENDED' | 'STRATEGY_NOT_FOUND' | 'METHOD_TRANSFER' | 'CONTEXT_UNAVAILABLE'
    message: string
  }>
}
```

### 9.3 推荐与适用性计算

```text
recommended = strategy.status == active
              && strategy.verification_status == passed

compatibility =
  not_applicable  无策略或无标的
  direct          标的代码存在于 strategy.symbols 或 strategy.tickers
  method_only     有策略和受支持标的，但不在原证券范围
```

`method_only` 必须生成警告：“当前仅迁移策略方法；原回测或验证结果不验证该标的。”

### 9.4 工具展示与系统指令

- 调用卡片标题为“读取当前会话投研上下文”，结果卡片只显示已读取、策略状态和标的摘要，不展开冗长原始 JSON。
- 工具结果本身保留结构化详情，供模型使用并进入会话证据链。
- 在投研系统提示中增加以下行为约束：
  - 回答策略、具体证券或当前选择的指代问题前，先调用该工具。
  - `status=empty` 时不得假定用户已选择上下文。
  - A 股可按需调用 `analyze_stock`；ETF 使用当前支持的行情、技术信号和新闻工具，并说明能力差异。
  - 非推荐策略和 `method_only` 警告必须出现在依赖该结论的回答中。
  - 不调用策略生命周期变更、回测启动或交易类能力。

现有 `investment_context(domain=...)` 保持兼容，用于组合、策略池、影子验证、进化、报告和行业等领域；新工具只负责当前会话已选上下文，不改变旧工具参数语义。

## 10. 状态与并发设计

### 10.1 前端请求代次

- 加载、策略搜索和标的搜索分别维护独立代次或 `AbortController`。
- 会话切换后，旧会话响应只能写回旧会话缓存，不能成为当前 UI 状态。
- 同一会话的旧保存响应只有在 `saveGeneration` 仍匹配时才可接纳。

### 10.2 乐观与确认状态

本功能不做可见值的乐观提交：

- 用户在浮层内点选的是 `pending`。
- 工具栏芯片展示的是 `confirmed`。
- 后端保存成功后再把 `pending` 提升为 `confirmed`。
- 保存失败时模型和用户看到的仍是同一个旧确认值。

### 10.3 轮次一致性

- 发送前只使用已确认上下文。
- 当前会话生成中或存在待发送队列时，选择器只读，避免同窗口内在工具首次读取前切换上下文。
- 工具结果写入本轮后成为该轮的事实快照；生成结束后更换上下文只影响后续轮次。
- 其他窗口并发修改通过修订号阻止无提示覆盖；当前轮最终以工具实际返回并留痕的上下文为准。

### 10.4 异常映射

| 失败 | 界面行为 | 模型行为 |
| --- | --- | --- |
| 策略列表失败 | 显示失败与重试；不显示“暂无策略” | 不受影响；已确认上下文仍可由工具读取 |
| 标的搜索失败 | 保留搜索词与旧选择，允许重试 | 不受影响 |
| 上下文读取失败 | 芯片显示不可用，不猜测旧值 | 工具返回 `unavailable`，回答说明缺失 |
| 上下文保存失败 | 保留旧确认值，不关闭为成功态 | 继续使用旧确认值 |
| 修订冲突 | 刷新确认值，要求重新选择 | 读取后端当前值 |
| 策略已删除 | 标记选择失效并引导重选 | 返回 `invalid`，不自动换策略 |
| 行情或新闻失败 | 对话仍可讨论策略方法 | 明确具体数据域不可用，不伪造实时事实 |
| 投研资料失败 | 面板内独立提示 | 基础聊天不被阻断 |

## 11. 安全与隐私设计

- 浏览器无法指定后端 URL；只可调用固定操作名。
- 工具无法由模型提供会话 ID、策略 ID、URL 或本地路径。
- 会话 ID 和策略 ID进入 URL 前分别经过固定正则校验与编码。
- 保存接口拒绝未知字段，证券类型使用枚举，代码只接收六位数字。
- 会话上下文固定写入 `research_chat_contexts` 集合，不接受集合名。
- 上下文操作标记为本地专用，不发送到外部模式后端。
- 策略详情读取与上下文读取均为只读；状态变更数据操作不暴露给新工具。
- 日志记录操作结果、会话 ID 的安全摘要和错误类型，不记录用户正文或凭证。

## 12. 兼容与迁移

- 无数据库迁移；`research_chat_contexts.json` 首次保存时创建。
- 旧会话没有上下文记录时按空上下文处理，不补写全局默认策略。
- 当前 `selectedStrategyId` 继续服务策略研究、影子验证等页面导航，不再作为「我的投研」聊天选择来源。
- 原固定研究模块选择器在其他页面继续可用；仅「我的投研」路由切换为动态策略和标的控件。
- 现有 `investment_context` 工具、策略状态接口和统一会话发送协议保持不变。
- 若后续支持场外基金，只扩展证券目录、标的类型和对应分析工具，不改变会话上下文主结构；届时提升 `schema_version` 或新增兼容枚举。

## 13. 测试设计

### 13.1 后端

- 请求模型拒绝未知字段、非法会话 ID、非法代码和非法类型。
- 首次读取返回正常空状态。
- 首次保存、覆盖策略、更换标的、清除单项和清空全部均递增修订号。
- 错误 `expected_revision` 返回 409 且不改数据。
- 并发写入只有一个匹配修订号的请求成功。
- 策略不存在时拒绝保存；策略保存后被删除时读取上下文仍保留 ID。
- JsonStore 损坏映射为可诊断错误，不用空对象掩盖。

### 13.2 浏览器固定操作

- 两个新操作生成精确方法、路径和请求体。
- 未知输入键和非法标识在发请求前被拒绝。
- 外部后端模式拒绝上下文读写。
- HTTP 409、404、422 和 500 被保留为可区分错误信息。

### 13.3 模型工具

- 使用 `exec.agent.session.header.id`，不接受调用参数。
- 无 Agent、空上下文、正常上下文、策略缺失和后端失败均有稳定结果。
- 推荐状态组合覆盖 `active/passed` 及所有非推荐组合。
- `symbols`、`tickers` 命中与未命中分别产生 `direct`、`method_only`。
- 工具只注册读取能力，不调用策略状态变更接口。

### 13.4 前端组件

- `portfolio` 路由显示共享对话和两个输入栏控件，不显示固定模块选择器。
- 其他路由原助理控件与停靠/展开行为回归通过。
- 策略全部显示，推荐分组正确，状态有文字说明。
- A 股和 ETF 搜索结果类型显示正确。
- 保存成功后才更新芯片；保存失败保留旧值。
- 会话 A/B 隔离，新会话为空，历史会话恢复。
- 快速搜索、快速切会话和乱序保存响应不会污染当前状态。
- 生成中选择器只读，生成结束恢复。
- 投研资料面板开关不影响草稿和上下文。
- 键盘、焦点返回、明暗主题和窄屏测试通过。
- 投研概览五张卡片打开对应当前页模态框，不调用 `navigate('portfolio')` 或锚点滚动。
- “查看完整风险详情”打开风险中心模态框，展示预算、突破和全部预警。
- “持仓明细”在当前模态框完成新增、编辑、删除、校验和保存；成功后保持打开并刷新持仓、行情、风险与预警。
- “持仓明细”可同层切换到批量导入，覆盖文件选择、拖放、粘贴、逐行校验、替换提示、失败保留和成功刷新。
- 模态框关闭按钮、遮罩、`Escape` 和焦点返回通过回归测试；明确跨模块入口仍保持原导航。

### 13.5 集成与 UAT

- 验证 A 股、ETF、推荐策略、候选策略和已退役策略各至少一个案例。

## 15. 风险与控制

| 风险 | 影响 | 控制 |
| --- | --- | --- |
| 模型未读取当前选择 | 回答忽略策略或标的 | 无参数专用工具 + 系统指令 + 工具调用测试 |
| 策略状态在历史会话期间变化 | 用户误用旧结论 | 只保存 ID，每轮重新读取策略详情 |
| 用户把验证结果迁移到新标的 | 误解证据适用范围 | `method_only` 结构化警告并要求回答展示 |
| 快速切换造成上下文串线 | 错误标的或策略进入回答 | 会话键、请求代次和修订号三层保护 |
| 共用 CSS 改动破坏其他路由 | 助理或工作台回归 | 独立 `conversation-primary` 状态与跨路由回归测试 |
| ETF 工具能力弱于 A 股 | 回答范围被夸大 | 类型分流并明示 ETF 首期能力边界 |
| 后端不可用 | 选择无法确认 | 旧确认态保留、分域失败和通用聊天降级 |
| 工作台详情再次复制数据请求 | 口径不一致、加载竞态 | 模态框只消费工作台已加载资源，不注册新数据操作 |
| 模态框层级过深 | 焦点混乱、难以返回 | 风险中心直接展开完整预警详情，不从汇总模态框再叠加第三层模态框 |
