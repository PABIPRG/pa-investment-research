# 投研智能体容器部署与回滚

本文是单主机 Docker Compose 部署的维护者教程与运行契约。镜像在一个容器内运行 Node Host、Web 前端和三个 Python 后端；三个 Python 端口只绑定在容器回环地址，主机只发布 Web 认证入口。

## 教程：首次部署

### 前置条件

主机需要 Docker Engine 与 Docker Compose v2、一个终止 TLS 的反向代理、一个仅供本部署使用的持久卷，以及能够读取待部署镜像归档或镜像仓库的权限。反向代理必须覆盖浏览器访问的完整 Host，并从固定地址连接 Compose 发布到 `127.0.0.1` 的 Web 端口。

### 1. 固定镜像身份

Pull Request 工作流上传 `investment-container-<commit SHA>` 归档、归档 SHA-256、镜像 ID 和 BuildKit 元数据。下载后先核对归档校验值，再载入镜像；生产配置优先把 `DSH_IMAGE` 固定为不可变 registry digest，使用归档时至少固定为完整 commit SHA 标签，不使用 `latest`。

```bash
sha256sum --check investment-container.tar.gz.sha256
gzip --decompress --stdout investment-container.tar.gz | docker load
```

### 2. 生成密码哈希和环境文件

不要把明文密码放入命令行、Compose 文件或环境变量。以下命令从标准输入读取至少 12 个字符的密码，只把版本化 scrypt 哈希写入主机文件；运行时会把只读 secret 复制到容器 tmpfs 并收紧为 `0600`。

```bash
sudo install -d -o root -g root -m 0755 /srv/pa-investment-research
hash_file=$(mktemp)
chmod 0600 "$hash_file"
read -r -s DSH_ADMIN_PASSWORD
printf '%s\n' "$DSH_ADMIN_PASSWORD" \
  | docker run --rm -i --entrypoint node pa-investment-research:<commit-sha> \
      /opt/dsh/lib/bin.js web-password-hash \
  > "$hash_file"
unset DSH_ADMIN_PASSWORD
sudo install -o 10001 -g 10001 -m 0400 \
  "$hash_file" /srv/pa-investment-research/web-admin-password.hash
rm -f "$hash_file"
cp .env.container.example .env.container
chmod 0600 .env.container
```

文件型 Compose secret 保留宿主文件的 owner 和 mode，因此密码哈希文件必须由容器身份 `10001:10001` 所有且为 `0400`；不能改成 group/world-readable 来绕过读取失败。编辑 `.env.container`：将 `DSH_IMAGE` 固定为已核对身份的镜像，将 `DSH_WEB_TRUSTED_HOSTS` 设为浏览器实际 authority（含非默认端口时写端口），并将 `DSH_WEB_TRUSTED_PROXIES` 设为反向代理连接容器时的精确源 IP。不要使用网段或 `0.0.0.0` 作为受信代理；网络重建导致地址变化时先重新核对地址，再更新配置。

### 3. 启动并核对

```bash
docker compose --env-file .env.container up -d --no-build
docker compose --env-file .env.container ps
docker compose --env-file .env.container logs --tail 200 investment
curl --fail --silent --show-error \
  -H 'Host: research.example.com' \
  http://127.0.0.1:3080/healthz
```

`Host` 必须替换为 `.env.container` 中 `DSH_WEB_TRUSTED_HOSTS` 列出的实际非回环 authority（端口不是默认值时包含端口）；否则 PAB-17 的 Host 边界会正确返回 `403`。生产上若健康检查经过 TLS 反向代理，应直接请求其 HTTPS URL，使用真实 authority，不覆盖 `Host`。

Compose 只有一个 `investment` 实例，不能使用 `--scale`。容器健康检查要求 Web 认证配置可用且 `trading-core`、`market-watch`、`industry-chain` 三个后端身份全部就绪；`starting` 或 `unhealthy` 不能作为部署成功。最后通过 HTTPS 反向代理完成登录和三项业务能力验收；直接 HTTP 仅用于无 Cookie 的本机 `/healthz` 诊断。

## 参考：配置与所有权

`DSH_HOME=/var/lib/dsh` 是唯一持久根，命名卷 `dsh-data` 保存设置、配置、会话、附件、业务存储、备份和三个后端状态，目录契约及迁移边界见[单实例数据目录与迁移](单实例数据目录与迁移.md)。绑定主机目录时，运维人员必须预先把目录所有者设为容器 UID/GID `10001:10001`，并保持 `0700` 或更严格权限。

容器每次启动都会读取并应用 `$DSH_HOME/profiles/investment-research/cordis.patch.yml` 与 `$DSH_HOME/cordis.patch.yml`；这些持久化配置不会被忽略。容器不暴露 Node internals，因此出于生产安全边界，不启用运行时 profile 文件 HMR：运行中的进程不会自动接收这两个文件的后续修改。修改后使用 `docker compose --env-file .env.container restart investment` 走优雅停止并重新启动；若同时修改了镜像、环境变量、secret 或 Compose 配置，则使用 `docker compose --env-file .env.container up -d --no-build --force-recreate investment` 重建。两种方式都必须重新等待聚合健康检查通过。

`TZ` 与 `TIMEZONE` 必须是同一个有效 IANA 时区；缺失或不一致会阻止启动，从而让 Node 调度和 Python 调度使用同一墙上时间。一个 `dsh-data` 卷只能由一个 Compose 项目挂载：容器入口通过原子目录和每两秒更新的共享卷心跳租约拒绝第二个调度实例，异常退出十秒后才允许接管。CLI 把外层租约 token 写入既有 `application.lock`，重启时只有携带已过期 token 的内层锁会被隔离；未标记或属于当前租约的锁不会被盲删，即使另一个 PID 命名空间复用了相同数字。NFS 等不能可靠提供原子 `mkdir`、一致 mtime 和持久写语义的存储不受支持。

根文件系统只读，容器以 `dsh` 用户运行，Linux capabilities 全部移除，`/tmp` 与 `/run/dsh` 是临时内存文件系统。运行阶段不会执行 pnpm、pip、源码编译或下载；依赖变化必须产生新镜像。

## 教程：升级与回滚

升级前记录当前镜像 ID/digest、完整 commit SHA、Compose 配置和卷备份身份；停止旧容器后按[单实例数据目录与迁移](单实例数据目录与迁移.md)的离线一致性要求备份整个 `$DSH_HOME`，再载入或拉取新镜像并更新 `DSH_IMAGE`。使用 `docker compose --env-file .env.container up -d --no-build` 重建单个实例，等待聚合健康检查通过后执行 HTTPS 登录与三后端业务验收。

应用启动失败但未写入持久格式时，把 `DSH_IMAGE` 恢复为已记录的旧 digest 并重建容器。新版本已经写入或迁移持久数据时，不要只回退镜像；先停止容器，按迁移文档恢复与旧镜像匹配的整卷备份，再启动旧 digest。不得让新旧容器同时挂载同一卷，也不得删除 `.container-instance.lock` 绕过活性判断。

## 故障定位

`container startup failed` 表示认证、secret、时区、端口或单实例前置条件失败；修复配置而不是放宽安全开关。`services not ready` 只列出未就绪服务名，不输出凭证；结合容器日志定位对应 Host 托管后端。收到 SIGTERM 后入口把信号转发给 CLI，Compose 提供 30 秒宽限期；持续超时说明关闭路径有缺陷，应保留日志和卷快照后回滚，不延长宽限期掩盖问题。
