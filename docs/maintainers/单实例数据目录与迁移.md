# 单实例数据目录与迁移

本文面向单用户 Web／容器部署维护者。业务数据备份另见[首次使用与数据迁移](../user-guide/首次使用与数据迁移.md)。

## 部署契约

把一个持久卷挂载为绝对 `$DSH_HOME`。Host 管理的三个 Python 后端会分别收到：

```text
$DSH_HOME/investment-research/trading-core
$DSH_HOME/investment-research/market-watch
$DSH_HOME/investment-research/industry-chain
```

容器层只消费这个根目录契约，不应把仓库 `backend/*/data` 当作持久卷。自定义 `.pabackup` 目录如果位于 `$DSH_HOME` 外，必须单独声明并挂载；否则重建容器后该目录不可恢复。

## 首次初始化

只对新的空 volume 调用 `initializeDshInstance()`。已有文件时停止初始化并先做清单审计，不要通过删除文件让检查通过。初始化仅创建目录和 `.dsh-instance.json`，设置、会话和业务记录仍由各所有者首次写入。

## 离线迁移

1. 停止 Host 与三个 Python 后端，确认没有活动导入、重置、seed 下载或后台写任务。
2. 对旧 `$DSH_HOME` 制作文件系统副本或快照，后续命令只读取该副本。
3. 选择一个不存在或为空的新绝对目录作为目标；目标可以是已经挂载的空 volume。
4. 先以 `mode: 'quiesced'` 调用 `dryRunDshInstanceMigration()`，核对文件、主动排除项、总字节数、复制策略与阻塞原因。该操作不会创建目标或修改已有目标权限。
5. 使用相同参数调用 `migrateDshInstance()`，再核对返回的相对路径、字节数和 SHA-256，并从新根启动应用。
6. 验证设置、会话与附件、storage、投研历史、industry-chain 报告和 `.pabackup` 列表。
7. 保留旧副本直到目标版本验收完成。

来源与目标按规范化后的物理路径比较，并在复制和发布阶段重复核验身份。目标非空、路径别名重叠、符号链接、特殊文件、未知布局版本、输入变化或复制失败都会阻止发布。已有空目标保留 inode，正式迁移时权限收紧为 `0700`。迁移器只复制白名单；managed `profiles/**/node_modules` 是可重建依赖，不会迁移，真实 profile 配置仍会迁移。凭据、cache、logs、`runtime.json`、实例锁、事务协调日志或未完成上传也不在清单中。

`backup-settings.json` 中物理上位于旧 `$DSH_HOME` 内的绝对备份目录会重定位到新根下的对应位置；外部目录保持原值，必须由部署方另行快照、挂载和验证。

## 在线 SQLite

普通 JSON/JSONL 仍应优先在停机副本上迁移。必须在线处理 SQLite 时，为 `backupSqlite(source, target)` 提供 SQLite 官方 backup API、`VACUUM INTO` 或等价一致性实现；不得直接复制运行中的数据库文件。迁移器按扩展名和 SQLite 文件头识别数据库，完成一致性备份后排除 WAL、SHM 与 rollback journal；没有回调时拒绝在线 SQLite。

Host 的 `sessions/` 与 `attachments/v1/` 必须共享同一个停止写入或文件系统快照屏障，不能在线逐文件组合。当前迁移器检测到非空 Host 会话或附件时会拒绝 `online`，部署方应改用停机副本或先生成整体一致快照。

## 恢复失败与回滚

迁移器在目标内部 staging 完成复制和校验，再按顶层条目事务发布，并最后发布 `.dsh-instance.json`。它不会用 rename 替换已有挂载点；常规失败会把已发布条目移回 staging 并清理现场。若外部路径替换或文件系统错误使回滚不完整，迁移会失败且不产生版本标记，并保留事务日志和 staging 供人工核对；修正原因后从空目标重试，不覆盖第一次失败的证据。

应用回滚与数据回滚分开执行：应用回滚先确认旧版本可读取当前数据版本；数据回滚则停止所有进程并恢复迁移前的完整目录快照。不要用 PAB-14 的业务 reset 代替数据回滚，也不要把更换旧镜像当作数据已经还原。
