# 单实例数据目录与迁移

本文面向单用户 Web／容器部署维护者。业务数据备份另见[首次使用与数据迁移](../user-guide/首次使用与数据迁移.md)。

## 部署契约

把一个持久卷挂载为绝对 `$DSH_HOME`。Host 管理的三个 Python 后端会分别收到：

```text
$DSH_HOME/investment-research/trading-core
$DSH_HOME/investment-research/market-watch
$DSH_HOME/investment-research/industry-chain
```

容器层只消费这个根目录契约，不应把仓库 `backend/*/data` 当作持久卷。自定义 `.pabackup` 目录如果位于 `$DSH_HOME` 外，必须单独声明并挂载；否则重建容器后该目录不可恢复。

## 首次初始化

只对新的空 volume 调用 `initializeDshInstance()`。已有文件时停止初始化并先做清单审计，不要通过删除文件让检查通过。初始化仅创建目录和 `.dsh-instance.json`，设置、会话和业务记录仍由各所有者首次写入。

## 离线迁移

1. 停止 Host 与三个 Python 后端，确认没有活动导入、重置、seed 下载或后台写任务。
2. 对旧 `$DSH_HOME` 制作文件系统副本或快照，后续命令只读取该副本。
3. 选择一个不存在或为空的新绝对目录作为目标。
4. 以 `mode: 'quiesced'` 调用 `migrateDshInstance()`。
5. 核对返回的相对路径、字节数和 SHA-256，并从新根启动应用。
6. 验证设置、会话与附件、storage、投研历史、industry-chain 报告和 `.pabackup` 列表。
7. 保留旧副本直到目标版本验收完成。

目标非空、符号链接、特殊文件、未知布局版本或复制失败都会阻止发布。迁移器只复制白名单，不复制凭据、cache、logs、`runtime.json`、实例锁、事务协调日志或未完成上传。

## 在线 SQLite

普通 JSON/JSONL 仍应优先在停机副本上迁移。必须在线处理 SQLite 时，为 `backupSqlite(source, target)` 提供 SQLite 官方 backup API、`VACUUM INTO` 或等价一致性实现；不得直接复制运行中的数据库文件，也不得把 `.db` 与 WAL/SHM 分开搬运。迁移器没有该回调时会拒绝在线 SQLite。

## 恢复失败与回滚

迁移器在同级 staging 目录完成复制和校验，成功后才发布目标。失败时来源不变且正式目标不存在或仍为空。保留 staging 相关错误与来源快照，修正原因后从新目标重试，不覆盖第一次失败的证据。

应用回滚与数据回滚分开执行：应用回滚先确认旧版本可读取当前数据版本；数据回滚则停止所有进程并恢复迁移前的完整目录快照。不要用 PAB-14 的业务 reset 代替数据回滚，也不要把更换旧镜像当作数据已经还原。
