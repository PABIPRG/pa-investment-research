# 实例密码管理

本文面向维护单管理员投研实例的部署管理员。用户在“设置 → 账号安全”输入当前密码与两次新密码；成功后本实例全部旧会话失效，使用新密码重新登录，研究数据不变。用户名由部署配置管理。

## 持久化与升级

容器首次启动把部署 secret 初始化到 `$DSH_HOME/web-auth/password.hash`，父目录 `0700`、文件 `0600`。后续启动读取该记录，修改初始 secret 不会覆盖用户设置的密码。备份必须包含整个数据卷及密码文件，并按凭据保管。既有目录缺少密码文件、空文件或不安全权限会阻止启动，不会静默恢复初始密码。

从旧版升级时保留原数据卷与初始化 secret；首次运行本版会创建持久化记录。原生 Web 需显式设置 `DSH_WEB_PASSWORD_CHANGE_ENABLED=1`，并把 `DSH_WEB_ADMIN_PASSWORD_HASH_FILE` 指向本实例独占的私有可写目录。每个密码文件仅支持一个服务进程，不支持多副本共享；鉴权和请求协议见 [Web 鉴权](../../frontend/docs/web-auth.zh.md)。

## 管理员恢复步骤

以下为管理员在自己的部署目录执行的示例，Agent 不会自动执行。先确认 Compose 项目、环境文件和数据卷属于目标实例，并停止该实例服务；不停止其他项目。恢复工具持有与应用相同的实例锁，活跃实例会被拒绝。先完成受保护的整卷备份，不删除锁文件绕过占用。

```bash
# 在目标 Compose 项目目录执行；替换为实际的项目名、环境文件和 Compose 文件。
project_name=research
project_env=.env.container
project_compose=compose.yaml

docker compose -p "$project_name" --env-file "$project_env" -f "$project_compose" stop investment
read -r -s -p '输入新密码（至少 12 个字符）：' reset_password
printf '\n'
printf '%s' "$reset_password" | docker compose -p "$project_name" --env-file "$project_env" -f "$project_compose" run --rm -T --no-deps --entrypoint /nodejs/bin/node investment /opt/container/reset-web-password.mjs
unset reset_password
# 仅在重置成功后执行：
docker compose -p "$project_name" --env-file "$project_env" -f "$project_compose" up -d investment
```

密码仅经标准输入传递，不写入命令参数、环境文件、日志或研究设置。工具只替换该卷的密码记录；不会清理聊天、持仓、自选或通知数据。看到“密码已重置”后启动对应实例，用新密码登录，并确认旧密码被拒绝。失败时保持停服，先处理权限或占用问题，保留备份。

用户名变更需修改对应环境文件中的 `DSH_WEB_ADMIN_USERNAME` 并重新创建该实例服务；它不会改写密码记录。

## 回滚限制

旧版本容器会重新读取初始 secret，可能恢复旧 secret 对应的密码，而忽略本版持久化密码。回滚前必须核对旧版鉴权路径，离线更新受保护的初始化 secret 或接受并明确记录预期凭据；保留当前密码文件与整卷备份。重新升级本版后持久化记录仍优先。仅切换镜像不能证明凭据和数据已经正确恢复。
