# 结构化事件与策略生成技术原理

本文讲解 `pa-investment-research` 后端中「新闻快讯 → 结构化事件 → 可回测策略」这条链路的实现原理。

两个模块各管一段，通过 `/news/events` 的字段契约解耦：

- **market-watch (:8100)** 负责「新闻 → 结构化事件」；
- **dsh-trading-core (:8000)** 负责「事件 → 可回测策略」。

## 一、总体链路

```text
多源快讯 ──fetch_flash──▶ 聚合去重 ──extract_events──▶ 结构化事件
   (market-watch :8100, 增量游标 + LLM/规则降级)         │ GET /news/events
                                                        ▼
                              trading-core fetch_events（TTL/stale/退避/fail-open 分层）
                                                        │
                                          impact.expand_events（?8200 图谱扩展 impact_codes）
                                                        ▼
                                          generate_hypotheses（LLM + 统计先验 / 规则降级）
                                                        ▼
                                          create_candidates（校验 + 双层去重 + 基因 + 账本）
                                                        ▼
                                                  candidate → 回测 → 影子 → 自进化
```

## 二、结构化事件的技术原理

代码：[events.py](../backend/market-watch/market_watch/events.py) + [news.py](../backend/market-watch/market_watch/news.py)

### 1. 输入层：跨源快讯聚合

`fetch_flash` 把新浪 7x24、财联社电报、华尔街见闻、IT之家 RSS、36氪/虎嗅（经 Google News RSS）合成一条时间流，关键机制：

- **分档**：base 档只读新浪+财联社，受 `flash_first_paint_deadline`(1.5s) 约束先发首屏快照；full 档读全部源、deadline 10s。用 `wait()` 先发首屏再等所有源收敛，同时保持真实 single-flight。
- **跨源去重**：按**标题归一化**后比对，不是按 URL。
- **稳定的 `it["id"]`**：这是下游一切增量和去重的基础。

### 2. 增量抽取：游标 + 每轮预算

```python
seen = _seen_ids()                                    # events/seen_ids，200 条环形
fresh = [it for it in items if it["id"] not in seen][: settings.event_batch]   # 每轮 ≤15 条
```

- 只对**未见过的**快讯做抽取，无新内容时开销接近零；
- **无论抽取结果多少都推进游标**（`_save_seen`）——否则失败的条目会被反复喂给 LLM；
- 常驻 `event-warm` 线程每 45s 以 `force=True` 续热，保证 TTL 到期时不是空窗冷启动；
- 缓存 TTL `event_ttl` 默认 300s。

### 3. LLM 抽取：一次批量、严格 schema

不是「一条新闻一次请求」，而是把 ≤15 条拼成一个编号块一次性送：

```text
[0] 标题 正文前200字
[1] ...
```

system prompt 把**业务约束写死**（[events.py:87](../backend/market-watch/market_watch/events.py#L87)）：

- `type` 是闭集 9 类：公告/业绩/价格异动/政策/产业/合作/评级/宏观/其他；
- `direction` 三态：利好/利空/中性——**有明确倾向才标，否则中性**；
- 无信息量的纯行情播报跳过；
- `tickers` 只给**中文名**（降级路径要自己做名称解析）。

返回 `{events:[{idx,type,tickers,industries,direction,summary}]}`，用 `idx` 回指原条目；越界的 idx 直接丢弃。事件 id = `md5(item_id + summary)`——同一快讯、不同摘要会得到不同 id。

### 4. 名称 → 代码解析（关键兜底）

LLM 只给中文名，`_resolve_code` 分两级：

1. 全局名称表**精确**匹配（`quotes.resolve_company_codes`）；
2. 失败则用**关注股（自选+持仓）名称做子串模糊匹配**。

第二级专门解决「N宇树」这类新股/简称不在名称表里的情况——没有它，LLM 事件就命中不了预警。

### 5. 规则降级

LLM 不可用或抛异常 → `_extract_rule`，两条正交规则**可叠加**：

| 触发 | 判定 |
|---|---|
| 文本含 `\d+%` 或「涨停/跌停」 | 事件类型 = 价格异动；再用 `_DIR_UP`/`_DIR_DOWN` 正则定方向 |
| 文本子串命中自选/持仓股名 | 事件类型 = 相关（无 LLM 下预警仍可用） |

都不命中则返回 `None`（该条不产生事件）。所以降级后 `direction` 可能是「中性」——这是契约允许的，下游必须处理。

### 6. 定向个股新闻（不经过 LLM）

对每只持仓+自选单独走东财搜索 JSONP（`curl_cffi` 指纹模拟），**直接标注已知 code**，id 前缀 `ev-stock-`，受 `directed_news_deadline`(8s) 预算约束。合并时**定向事件恒排最前**——否则它们日期偏旧会被 `[:limit]` 截断，个性化面板的定向卡片就消失了。

### 7. 事件形状 = 硬契约

```json
{ "id": "ev-...", "type": "公告|业绩|价格异动|...", "tickers": [{"name":"中文名","code":"600519"}],
  "industries": ["半导体"], "direction": "利好|利空|中性", "summary": "一句话",
  "title": "...", "time": "...", "source": "...", "url": "..." }
```

字段 `type / tickers / industries / direction / summary` 是全部个性化与策略功能的底座，**前端与 trading-core 都按它消费**。

## 三、事件 → 策略生成的技术原理

代码：[strategies.py](../backend/dsh-trading-core/adapter/strategies.py) + [impact.py](../backend/dsh-trading-core/adapter/impact.py)

### Step 0：取事件 —— 分层降级 + 影响图谱扩展

`fetch_events_with_status` 是四层阶梯，任何一层都不抛错给主路径：

```text
fresh-cache（TTL 内且条数够）→ stale-cache（放宽到 stale TTL）→ failure-backoff（上次失败后短期直返）
→ fail-open（返回空列表）
```

- **single-flight**：`_EVENTS_REFRESH_LOCK.acquire(blocking=False)`，已有刷新在跑就直接用 stale 返回，不排队；
- 返回值带 `status` 字典（`degraded/stale/source/reason/age_seconds/retry_after_seconds`），把「降级到什么程度」显式暴露给调用方；
- 有两条取数入口：`fetch_events_with_status`（允许 stale，供风险/卡片）与 `fetch_events`（只接受 fresh/upstream，失败返回空，供假设生成）。

**影响图谱扩展**是这个环节最有意思的设计。[impact.py](../backend/dsh-trading-core/adapter/impact.py) 头部注释写得很清楚——注入点是 `strategies.fetch_events`，即 **market-watch 返回之后、TTL 缓存之前**，所以下游的卡片流（D）和假设生成（E）**自动吃到扩展标的，不需要改任何路由**。

扩展算法（每个事件 ≤2 次子请求）：

| 维度 | 请求 | 得到 |
|---|---|---|
| 产业链 | `GET /graph/chain/{code}?depth_up=1&depth_down=1` | 上游供应商 + 下游客户各 1 跳 |
| 同行业 | `GET /companies?keyword={行业}&limit=50` | 行业模糊子串命中的公司 |

护栏：`timeout=1.5s`、TTL 300s、缓存上限 2000 条、**连续 2 次失败 → 30s 熔断**；503「种子数据尚未下载」单独识别为**就绪状态**而非服务故障，退避期间**不写缓存**（避免把空结果固化 5 分钟）。新标的会排除事件直连标的自身。

降级语义很干净：`:8200` 挂掉 → 事件保持原样（没有 `impact_codes` 字段），卡片/假设行为与没有图谱时**完全一致**。

### Step 1：可用性过滤 + 下标映射

```python
usable = [(i, e) for i, e in enumerate(events)
          if e["direction"] in ("利好","利空")
          and (任一提及股票有 code or e["impact_codes"])]
```

**保留的是过滤前的原始下标 `i`**。因为 LLM 提示里按 usable 位置编号（`[0] [1] ...`），返回时再重映射回原始下标——这样 `create_candidates` 里 `events[ev_idx]` 才能取到假设真正对应的事件。`event_idx` 因此只对后端内部有意义，前端不能当事件 ID 用。

### Step 2：假设生成 —— LLM 为主，统计先验增强，规则兜底

**LLM 路径**（[strategies.py:888](../backend/dsh-trading-core/adapter/strategies.py#L888)）：把每条事件压成一行紧凑上下文 `direction / type / 名称:代码 / 前3个行业 / summary前80字`，system prompt 把可用空间**收窄成闭集**：

- `kind` 六选一；利好→`ma_cross`/`momentum`/`breakout`/`volume_breakout`（按事件语义挑最贴合的），**利空→只能 `rsi_reversal`/`bollinger`**（因为系统只做多）；
- params 只可在默认值附近微调；
- symbols 只填事件明确涉及、有 6 位代码的 A 股；
- `rationale` 一句话解释**因果**。

**统计先验注入（P6 自进化）**：`PRIOR_REPLAY_ENABLED` 时，`priors.build_hint(store)` 以「方向 × 因子族」为桶统计历史样本外过验率（样本 ≥ `EVOLVE_PRIOR_MIN_TRIALS`(3) 才报，`优`/`慎` 标注），追加到 system 之后。妙处在于它**把上游假设生成和下游样本外筛选接成闭环**——哪类打法历史上容易过样本外，下次就让 LLM 多考虑那类。设计上明确是「倾向提示」而非硬约束，且提示里重申不违背规则 1/2/4。

**规则降级**：LLM 失败或无 Key → 利好一律 `momentum{n:10}`、利空一律 `rsi_reversal{n:14,oversold:30,overbought:70}`，`symbols = tickers.codes + impact_codes`。行为与无 LLM 版本完全一致。

### Step 3：校验入库 —— 五道闸门

`create_candidates` 把「LLM 的自由输出」收敛成「可控的策略记录」：

1. **符号白名单** `_normalize_symbol`：正则取 6 位数字，剥 `sh./sz.` 前缀，**只保留 0/3/6 开头**（排除北交所 4/8、B 股 2/9）。
2. **方向守卫**：`kind ∉ KINDS` 或 `direction ∉ {利好,利空}` 或 symbols 为空 → 整条丢弃；**利空且 kind 不是反弹类 → 强制改写成 `rsi_reversal`**（代码兜住 prompt 的约束，不信任模型）。
3. **参数夹取** `_clamp_params`：逐 kind 上下界，并处理**关系约束**——`ma_cross` 强制 `fast < slow`（`slow = max(fast+1, min(120, slow))`），`rsi_reversal` 若 `oversold ≥ overbought` 回落默认值。
4. **双层去重**：
   - 主键 `sid = "strat-" + md5(event_id + kind + 排序后symbols)[:10]`；
   - 语义指纹 `_candidate_semantic_key(kind, symbols, direction, params, hypothesis, holding_window_days)` 与池内任一条相同 → 跳过。这一层是跨事件的——**防止「不同事件产出同一条可执行假设」把策略池灌水**（也能解释池里为什么仍有同标的重复：假设文本不同就会各自入库）。
5. **原子性**：查重与插入都在 `store.mutate_document` 的**同一个锁内回调**里完成，避免并发重复入库。

通过后落三样东西：

| 落点 | 内容 | 目的 |
|---|---|---|
| 策略记录 | `gene` 基因组 | 自进化载体，见下 |
| `events_ledger` | `{event_type × direction}` → 本次 symbol 池（first/last/次数） | 符号迁移与先验统计的样本来源 |
| 策略记录本体 | `status="candidate"`、`verification_status="insufficient"`、`backtest=None` | 待回测 |

**基因组**（[genome.py](../backend/dsh-trading-core/adapter/genome.py)）把平铺的 `kind+params+symbols` 升级成结构化基因，**以增量 `gene` 键落在现有记录上**（老记录没有 `gene` 时由 `read_gene` 回退推导，行为不变）：

```json
{ "factor": {"family": "momentum", "params": {"n": 10}},
  "scope": {"pool_ref": {"event_type": "政策", "direction": "利好"}},
  "symbols": ["600519"], "direction": "利好",
  "regime_gate": {"allow": ["high_vol","trend_up","trend_down","oscillation"], "miss_mode": "on_default"},
  "meta": {"source_event_id": "ev-..."} }
```

`regime_gate` 是 P0 阶段「结构先落地、行为不改变」的保守默认：全开 + 检测不到行情状态时按默认放行，总开关 `REGIME_GATE_ENABLED` 在 P5 之前恒为 false。生态位族（`NICHE_FAMILIES`）则决定变异子代能否**族内换打法**（利空反弹族可 `rsi_reversal ↔ bollinger`，利好动量族可 `momentum ↔ breakout`）。

**事件账本**的意义在 [ledger.py](../backend/dsh-trading-core/adapter/ledger.py) 注释里说得直白：把瞬态 flash news 沉淀成**带日期的历史事件账本**，否则「一条策略只是某次事件的复盘，只在那一两只票上证明过自己」；有了「这类事件 × 这个方向」的历史候选股池，符号迁移验证才能证明**规律可复用**。账本写入失败被 try 包住——**绝不影响候选入库**。

### Step 4：候选 → 回测 → 生命周期

首次回测任务完成后**无条件**把 `candidate` 推进为 `active`（[strategies.py:153](../backend/dsh-trading-core/adapter/strategies.py#L153)），不看是否达标。所以状态是两条**正交轴**：

- `status`（生命周期）：`candidate → active / rejected`，`active → retired`，另有观察态 `watch`；
- `verification_status`（回测结论）：由样本外 `n ≥ 4 && 胜率 ≥ 50% && 平均收益 > 0` 派生 `passed` / `not_passed` / `insufficient`。

`active` 只代表「已回测、仍参与」——想知道好坏必须看 `verification_status`（或 `backtest.out_of_sample.*`）。

## 四、贯穿全链的设计原则

| 原则 | 体现 |
|---|---|
| **LLM 永远是增强，不是依赖** | 抽取、假设生成、卡片点评都有规则兜底；LLM 挂了返回规则结果或 `null`，绝不 500、绝不阻塞主路径 |
| **边界封闭** | kind/direction/type 都是闭集，符号走前缀白名单，参数夹取，不信任模型输出 |
| **因果与幂等** | 指标只用 ≤t 数据、t 信号 t+1 成交；`sid` 主键 + 语义指纹去重；游标无条件推进 |
| **慢依赖短路** | 全链路 deadline + TTL/stale + single-flight + 熔断退避，任何外部依赖挂了都有明确降级语义 |
| **可解释** | `rationale`（假设因果）、`impact_by`（谁波及的）、卡片 `reasons`（为什么推给你）、`gene`/账本（策略从哪来） |
