# 投研智能体：首次使用与数据迁移

适用版本：`0.1.0-rc.11` 独立桌面预发布包。本文是配合首次发布的使用指南；安装包以 [GitHub Releases](https://github.com/PABIPRG/pa-investment-research/releases) 实际发布的附件为准。

## 一、下载与校验

Mac 在“关于本机”查看芯片：M 系列选 `darwin-arm64`，Intel 选 `darwin-x64`。Windows x64 选择 `win32-x64`。不要选择 Source code 附件。

同时下载 `SHA256SUMS`。在 ZIP 所在目录计算文件的 SHA256，和 SHA256SUMS 中同名文件的一行比较：

macOS（Apple Silicon 示例）：

```bash
shasum -a 256 investment-agent-0.1.0-rc.11-darwin-arm64.zip
```

Windows PowerShell：

```powershell
Get-FileHash .\investment-agent-0.1.0-rc.11-win32-x64.zip -Algorithm SHA256
```

结果应完全一致（字母大小写不影响哈希含义）。不一致时不要运行，重新下载并反馈。校验一致用于确认文件与发布附件一致，不等于应用经过操作系统厂商公证。

## 二、安装与第一次打开

### macOS

1. 解压 ZIP，将“投研智能体.app”移到“应用程序”。
2. 打开应用。当前包使用临时签名，首次运行可能遇到系统信任提示。
3. 如果系统阻止，先确认来源及校验值，再按 [Apple 官方说明](https://support.apple.com/zh-cn/102445) 判断是否允许单个应用运行。不同系统版本的提示可能不同；不要关闭全局保护或执行来源不明的解除隔离命令。

### Windows

1. 完整解压 ZIP 到独立文件夹，不要覆盖一个正在运行的旧版本目录。
2. 保持全部文件与子目录在一起，运行“投研智能体.exe”。
3. 当前没有正式代码签名，可能出现发布者或信誉提示。先核对来源、文件校验和系统提示；若仍不能运行，提交错误信息，不要禁用杀毒软件。

下载包已经带有运行时，不需要运行 `start.sh init`。源码开发者才需要按仓库 README 准备开发环境。

## 三、配置模型与检查后端

打开“设置”中的“投研”：

- **项目模型**：点击“管理可用模型”配置自己的服务，再设置“默认主模型”。新会话采用该默认值，已有会话保留自己的模型选择。
- **投研就绪**：查看股票分析、盘中盯盘和产业链的运行状态。独立包应使用“应用随附 Python 环境”。若提示资源缺失或损坏，请保留错误信息并重新下载完整包。
- **后端凭据**：股票分析与部分盯盘增强使用后端专用 DeepSeek。配置会话模型不代表这两个后端已有凭据；按设置页状态配置。Key 更新后若提示重启，需要完整退出应用再启动。

行情扫描和产业链检索并不都需要模型调用，AI 解读与报告则可能需要相应服务。不要为解决“模型未配置”去手工编辑安装包内文件。

## 四、建立研究数据

先添加少量自选和研究持仓，核对股票代码、数量及成本，再尝试研究和报告功能。首次空白环境没有你的历史记录；策略回测和自进化需要实际数据及任务执行，不会自动生成完整历史。

使用同花顺读取时：

1. 选择模拟或真实账户，确认客户端处于对应账户的持仓页面。
2. 按向导检查客户端和权限。macOS 读取需要辅助功能权限；按当前应用提示授权。
3. 读取后检查预览，确认无误再保存。本功能不提交买卖委托。
4. 读取失败时可改用手动录入，不要反复授权无关程序。

## 五、备份与跨电脑迁移

### 源电脑

1. 打开“设置 → 投研 → 数据与备份”，点击“创建备份”。
2. 选择“策略与自进化、持仓、自选与预警、研究记录、偏好”等需要的分类。
3. 创建完成后，从备份列表或“打开文件夹”找到 `.pabackup`，复制到目标电脑。保留源文件和源电脑数据。

### 目标电脑

1. 安装准备使用的版本，打开“数据与备份 → 导入数据”。
2. 选择备份，检查新增、冲突及各分类的处理方式。
3. 保留默认启用的“导入前备份当前数据”，确认后执行“导入所选数据”。
4. 导入是增量更新，不会修改、移动或删除来源备份。确认持仓、策略、研究记录和偏好后，再决定后续迁移安排。

备份不是完整的系统镜像：凭据、日志、缓存和机器配置不在该迁移范围内，目标电脑需要重新配置模型凭据及客户端权限。当前对话有独立的“导出当前对话”入口，不要假定投研全量备份等于全部对话和附件已备份。备份是 ZIP 结构，不应当作加密保险箱。

### 历史进化动作的已知限制

已发现旧后端导出的 v1 备份没有携带历史进化动作。即使文件名为“全量数据”、界面显示同为 `0.1.0-rc.11`，也不能据此确认这些记录存在。

当前代码的 trading-core 导出格式为 v2，包含已执行进化记录；但跨电脑完整迁移验收仍在 `0.2.0-alpha` 跟进。若导入后历史为空，请保留源电脑，确认实际运行的代码与进程后重新导出，不要通过清空数据或删除备份尝试修复。

源码 Windows 用户可在启动仓库根目录提供以下只读诊断结果：

```powershell
git log -1 --oneline
git status --short
Select-String -Path backend/dsh-trading-core/adapter/data_transfer.py -Pattern '^SCHEMA_VERSION','evolution_previews'
```

如果源代码显示 v2，但实际备份仍是 v1，需要继续核对启动目录和仍在运行的后端。不要直接结束所有 Python 进程，以免影响其他程序。

## 六、更新与反馈

更新前创建并保留备份；退出旧应用，将新版本解压到独立位置，再打开并核对数据。遇到异常先保留原状态及旧文件，别反复清空或覆盖目录；恢复旧应用文件也不等于业务数据自动回滚。
