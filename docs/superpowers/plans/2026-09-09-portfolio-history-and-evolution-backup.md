## 目标

让用户可以在不篡改原始持仓快照的前提下校正组合历史起点，并确保持仓历史、自进化审计与长期进化知识可以通过 `.pabackup` 在设备间完整迁移；同时修复盈亏弹窗加载和刷新状态下的内容间距。

## 数据与兼容策略

- `holdings` 文档新增可选 `history_start_override`，记录 `effective_date`、`original_effective_date`、`source=user_corrected` 与 `corrected_at`。
- 原始 `snapshots` 保持不可变；收益计算仅在投影层把首份持仓视为从校正日期开始生效。
- 校正日期不得晚于今天；存在第二份快照时不得晚于第二份快照日期，避免生成倒序持仓状态。
- trading-core 领域快照升级为 schema v2，新实现继续读取 v1；`.pabackup` 容器格式保持 v1。
- `strategies` 分类新增长期集合 `gene_archive`、`events_ledger`，并从 `evolution_previews` 只导出已应用审计与最近闭环运行摘要；待执行、失败、过期预案和内部令牌不迁移。
- 行情索引、市场状态等可重建缓存不进入备份。

## 验收标准

- 用户能校正首次持仓日期，刷新和重启后仍保留，界面区分“系统记录”与“人工校正”。
- 导出后在空数据目录导入，持仓起点、持仓快照、最近自动进化、基因存档和事件账本均可恢复。
- 导出的进化集合不含 pending/superseded/failed 预案、预览令牌、过期时间和状态版本。
- 旧 schema v1 备份仍可预览和导入。
- 加载、刷新和错误状态下时间区间、状态区和收益曲线之间均有稳定间距。
- 不把缺失历史或行情显示为 `0`。
