# 投研数据备份、导入与重置设计

**目标版本：** `0.1.0-rc.12`

该能力不追加进入已作为当前代码基线的 `0.1.0-rc.11`。备份契约、跨后端写入和重置均会改变数据安全边界，需要在独立候选版本中完成迁移兼容与真实产品验收；包版本在验收门禁通过后统一更新。

## 目标

在“设置 → 数据与备份”中提供一套安全、可理解、可迁移的本地数据管理能力，使用户可以：

- 手动创建可分享的投研数据备份；
- 从其他电脑提供的备份文件或应用内备份列表增量导入数据；
- 查看、定位和主动删除备份；
- 按分类或全量清空当前数据；
- 在导入、重置等危险操作前默认创建安全备份，同时允许用户取消勾选。

本功能不依赖模型推理，所有分类、校验、冲突识别、合并和重置行为均为确定性程序逻辑。

## 已确认的产品口径

1. 顶层主操作为“创建备份”和“导入数据”，不再单独提供同义的“导出全量数据”。
2. 备份列表中的操作统一称为“导入”，不使用另一套“恢复”语义。
3. 导入只更新当前数据；来源备份是只读文件，不会因导入而被修改、移动、改名或删除。
4. 备份允许用户主动删除，但必须经过二次确认；第一版没有自动清理、到期删除或保留数量策略。
5. 第一版不提供定时备份。自动备份仅作为导入、重置前的可选安全措施出现，默认勾选，允许取消。
6. 重置只清空当前数据，不清空备份目录、备份设置或已有备份。
7. 文件名必须可读，包含创建原因、内容和本地时间，不得把内部随机编码作为主要文件名。

## 信息架构与主要流程

### 设置页

“数据与备份”区按以下顺序组织：

1. 操作区：“创建备份”“导入数据”；
2. 备份位置：展示完整路径，提供“更改位置”和“打开文件夹”；
3. 备份列表：展示时间、原因、内容范围、数量、大小和可用状态；
4. 危险区域：“重置本地数据”；
5. 现有“导出当前对话”保留为独立能力，不与投研数据备份混为一谈。

### 创建备份

用户选择“全部投研数据”或一个以上分类后创建备份。成功后新文件立即出现在列表顶部，并提供“打开文件夹”。创建过程中禁用重复提交，失败时保留原有列表并展示可操作错误。

### 导入

导入有两个来源：

- 从电脑选择 `.pabackup` 文件；
- 在备份列表对某个文件点击“导入”。

两者之后进入完全相同的流程：

1. 校验文件格式、版本、路径、大小、校验和与数据结构；
2. 展示分类、数量、新增项、冲突项和不支持项；
3. 允许按分类选择处理规则，并可进入逐项冲突处理；
4. 默认勾选“导入前备份当前数据”，允许取消；取消后显示不可自动回退警告；
5. 二次确认后增量写入当前数据；
6. 成功后刷新相关页面，来源备份保持原样；失败时回滚所有已写入分类。

默认冲突规则：

- 策略：保留两份，并为导入副本生成新的策略标识，同时重写已知依赖引用；
- 自选与预警：按证券代码及规则身份合并去重；
- 持仓：保留本地，不对数量、成本或金额求和；
- 研究记录：同标识内容相同则去重，内容不同则保留两份；
- 偏好与个性化：默认保留本地，可按分类改为使用导入数据。

### 重置

用户可以选择一个以上数据分类，或选择“清空全部投研数据”。确认弹窗必须：

- 明确列出将被清空的分类与数量；
- 默认勾选“清空前备份当前数据”，允许取消；
- 取消备份后显示不可自动回退警告；
- 使用清晰的破坏性按钮文案“清空所选数据”；
- 明确说明已有备份不会被删除。

## 数据范围

第一版的“全部投研数据”指五类可迁移、用户产生的持久数据：

| 分类 | 主要内容 |
| --- | --- |
| 策略及验证记录 | 策略、回测历史、影子运行、净值与演化结果 |
| 持仓 | 手工保存的证券、数量、成本及持仓分析输入 |
| 自选与预警 | 两个投研后端中的自选列表及用户创建的预警规则 |
| 研究记录 | 报告、决策记录、简报与研究上下文 |
| 偏好与个性化 | 风险/KYC 偏好、本地学习设置与用户反馈事实 |

以下内容必须排除：

- API Key、券商凭据、Webhook、`.env`、`.credentials.yaml`；
- 机器相关地址、进程状态、PID、日志与临时文件；
- 行情、新闻、事件和技术指标缓存；
- 可重新下载的产业链种子数据；
- 未完成任务的运行时锁、队列占位和临时预览。

## 文件格式

外部文件使用 `.pabackup` 后缀，内部是标准 ZIP，媒体类型为 `application/vnd.pa-investment.backup+zip`。导入以文件魔数与内容而不是扩展名判定文件是否有效。

ZIP 固定包含：

```text
manifest.json
domains/trading-core.json
domains/market-watch.json
```

`manifest.json` 包含：

- `format: "pa-investment-backup"`；
- `formatVersion: 1`；
- `createdAt`、`createdByAppVersion`、`reason`、`scope`；
- 分类及数量摘要；
- 每个领域文件的 `schemaVersion`、相对路径、字节数和 SHA-256；
- 不包含任何绝对路径、凭据或设备标识。

各领域独立维护 `schemaVersion`。读取方必须支持当前版本和明确实现的旧版本迁移；遇到更新版本时只展示内容概要并禁止导入，不得猜测兼容。

文件命名规则：

```text
投研备份-{内容}-{YYYY-MM-DD_HH-mm-ss}.pabackup
投研备份-{导入前|清空前}-{内容}-{YYYY-MM-DD_HH-mm-ss}.pabackup
```

名称冲突时追加易懂序号，如 `-2`，内部事务标识不得出现在用户可见主文件名中。

## 存储与安全边界

- 默认目录为 `$DSH_HOME/investment-research/backups`，用户可选择其他绝对目录；配置原子写入 `$DSH_HOME/investment-research/backup-settings.json`。
- 列表以扫描配置目录为事实源，不维护可能失真的独立备份数据库。
- 损坏、不完整或版本过新的文件仍显示在列表中，但禁用导入并说明原因。
- 外部文件采用分块上传：单块 256 KiB，压缩文件上限 64 MiB；解压总量上限 128 MiB、条目上限 256，防止 ZIP bomb。Host 最多同时保留两个有效导入预览，列表逐个校验，避免并行解压放大内存占用。
- ZIP 条目只允许清单声明的固定相对路径，拒绝绝对路径、`..`、符号链接和重复条目。
- 临时上传存入 `$DSH_HOME/investment-research/imports`，应用启动时清理超过 24 小时的孤立文件；导入完成或取消后删除临时副本，不触碰用户选择的源文件。
- 删除备份只能作用于当前备份目录的直接子文件，并在 UI 二次确认后执行。

## 一致性与事务

两个 Python 后端分别提供导出、预览、准备、提交、回滚、完成和重置接口。`JsonStore` 增加进程级可重入事务门，所有读写方法经过该门；批量操作持有同一事务门，从而得到分类间一致快照。

上述数据传输接口使用 Host 每次启动生成的高熵令牌鉴权。令牌只注入当前应用拥有的 Python 子进程，不进入浏览器、备份文件、日志或外部后端配置；未授权的本机网页请求统一返回 `401`。

跨后端写入使用协调事务：

1. Host 对所有参与后端执行预览并记录当前版本摘要；
2. 若用户保持安全备份勾选，先创建一个新的独立备份；备份失败则不继续危险操作；
3. Host 对所有后端执行 `prepare`，后端持久化只含当前文档的回滚日志；
4. Host 依次执行 `commit`；任一失败时对已提交后端执行 `rollback`；
5. 全部成功后执行 `finalize` 删除回滚日志；
6. 来源 `.pabackup` 文件在整个流程中只读。

Host 在自身数据目录持久化协调日志，并在全部领域提交后先写入统一的 `committed` 决定再执行完成清理。后端启动时读取该决定：已决定提交则保留当前数据并完成事务，否则按精确前镜像回滚。这样应用或后端在任一阶段崩溃后都不会依赖“清空后重新增量导入”的破坏性补偿。

预览返回的当前版本摘要必须随确认请求提交。若确认前数据已变化，返回“数据已更新，请重新预览”，不得用过期冲突决策覆盖新数据。

## 界面状态与可访问性

必须覆盖：首次加载、空列表、刷新、创建中、上传中、校验中、等待确认、导入中、重置中、成功、权限不足、目录不可用、文件损坏、版本过新、空间不足、回滚成功及回滚失败。

- 弹窗使用原生可聚焦语义、焦点圈与键盘顺序；非提交阶段支持 `Escape` 取消。
- 写入阶段禁用关闭和重复操作，并用 `aria-live` 报告进度。
- 破坏性确认按钮与普通主按钮视觉区分，但不依赖颜色单独传达风险。
- 小屏下备份表格改为卡片；主要确认操作固定在弹窗底部；路径允许换行和复制。
- 成功提示说明新增、跳过和冲突处理数量；失败提示说明当前数据是否已回滚。

## 不在第一版范围

- 定时备份、保留周期和自动清理；
- 云端同步或多人实时协作；
- 备份密码、端到端加密或数字签名；
- 将凭据、机器配置或可重建缓存迁移到另一台电脑；
- 把导入来源自动复制进备份目录。

## 验收标准

1. 手动备份能生成可读文件名和合法 ZIP，清单与 SHA-256 一致。
2. 导入同一备份一次或多次都不会修改或删除该备份。
3. 默认冲突规则符合产品口径，且用户能修改分类规则及逐项规则。
4. 导入或重置前的安全备份默认勾选、允许取消；勾选时备份失败会阻止后续写入。
5. 任一后端提交失败时，已提交数据回到操作前状态，并给出明确结果。
6. “清空全部”不会删除备份、备份位置设置或凭据。
7. 损坏、版本过新、路径穿越和超限文件均被安全拒绝。
8. 设置页在桌面和窄屏下无截断、遮挡和不可达操作，并通过键盘基本操作。
