## 1. 背景与目标

当前五个一级路由虽然复用了 `pageScroll`、`moduleGrid` 和 `moduleCard` 等基础样式，但页面级背景、模块级边界和模块内部边界没有形成统一层级。多个区域同时使用 `border-l1`，在对比度较低的显示器上，大模块与内部卡片容易连成一片；部分状态提示与前一内容块之间也缺少稳定间距。

本轮建立并落地一套“路由表面 → 大模块 → 内部分组”的三级视觉契约，使用户能先辨认页面和大模块，再扫描内部信息。目标不是把所有内容都做成更重的卡片，而是限制边框的职责并统一背景、间距和分隔线。

本轮不改变数据请求、业务状态、路由、按钮行为、AI 能力或后端接口。

## 2. 范围

### 2.1 纳入范围

| 路由 | 当前主任务 | 本轮重点 |
|---|---|---|
| 研究工作台 | 汇总持仓、事件、风险与策略 | 统一概览、大区块和双栏模块的边界层级 |
| 智能分析 | 选择研究能力并进入 AI 分析 | 建立清晰的能力区、说明区和操作区层级 |

| 策略研究 | 管理策略池、回测证据和影子验证 | 统一策略池与影子验证表面，减少内部重复套框 |
| 产业链 | 查看图谱、节点与事件影响 | 区分图谱主模块、导航控制和事件影响证据 |

### 2.2 不纳入范围

- 自进化：作为本轮视觉参考，不重复改造。
- 我的投研：不在用户确认的路由范围内。
- 个股详情、策略详情和进化诊断等二级页面。
- 弹窗、抽屉、浮层和 AI 助理；继续遵循其现有浮层规范。
- 新增或修改后端能力、接口、状态机和持久化。
- 对所有小卡片进行统一重构；只处理大模块层级及与之直接冲突的内部套框。

## 3. 方案选择

采用“共享语义契约 + 路由局部适配”。

不采用五个页面分别覆盖的方案，因为相同意图会分散为多组选择器，后续新增模块时无法判断应复用哪一组规则。不直接全局加重 `moduleCard`，因为该类也服务于未纳入范围的详情页和浮层，全局修改会扩大视觉回归面。

实现时为纳入的一级路由组合统一的路由表面类，并在该作用域内定义大模块边界；只有无法由共享规则表达的布局差异才增加页面专属类。既有 `pageScroll`、`moduleGrid`、`moduleCard`、状态提示和数据组件继续复用，不新建平行组件或业务状态。

## 4. 能力审计

| 用户动作 | 现有入口或接口 | 权威状态与副作用 | 重叠或缺口 | 决策 | 证据或未知 |
|---|---|---|---|---|---|
| 进入一级路由并识别页面 | `InvestmentShell` 路由分支、`PageHeader` / `PageHeading` | 前端路由快照；无新增副作用 | 页面标题存在，路由表面层级不统一 | 扩展 | `pageScroll` 为共同滚动根 |
| 识别页面内大模块 | `moduleGrid`、`moduleCard` 及各页面专属容器 | 各资源状态由原组件持有 | 多数模块使用 `border-l1`，在低对比显示器上不清晰 | 组合 | 自进化已用 `bg-layer-1 + border-l2 + bg-base` 验证方向 |
| 扫描模块内部数据 | 现有列表、表格、指标网格和内容卡片 | 请求结果、筛选与选择状态保持原所有者 | 大模块和内部容器常使用同级完整边框 | 扩展 | 可在路由作用域内弱化非独立内部容器 |
| 识别成功、错误和刷新状态 | `importNotice`、`DataError`、`ResourceProgress` 等 | 原状态和 `role` 保持不变 | 个别相邻组合缺少上方间距 | 扩展 | 影子范围栏后成功提示可稳定复现 |
| 在窄桌面完成主要操作 | 现有容器查询与媒体查询 | 不改变交互和数据 | 视觉层级调整可能增加拥挤或溢出风险 | 复用并验证 | 已有 1024px 与 768px 响应式规则 |

所有输出均为确定性的前端呈现规则，不引入模型推断。证券、状态、指标和提示内容仍来自现有权威接口或组件状态。

## 5. 视觉契约

### 5.1 三级层级

1. **路由表面**
   - 纳入路由的滚动内容区与自进化保持一致，使用 `--dsw-alias-bg-layer-1`；浅色主题下保持白色背景，模块依靠边界、留白与内部层级分组。
   - 页面标题区与正文之间使用 `--dsw-alias-border-l2` 底部分隔。
   - 标题区与第一个大模块之间保留明确的垂直节奏。

2. **大模块**
   - 使用 `--dsw-alias-bg-base` 作为模块内容面。
   - 使用 `--dsw-alias-border-l2` 作为模块外边界。
   - 默认圆角为 `12px`，默认内边距为 `16px`。
   - 同级大模块间距默认 `20px`。
   - 非浮层模块不使用阴影制造层级。

3. **内部分组**
   - 默认不再包一层完整边框。
   - 优先使用 `--dsw-alias-bg-layer-1`、`12–16px` 留白和 `--dsw-alias-border-l1` 单向分隔线。
   - 只有内容可独立操作、可重排、可选择，或其边界本身携带业务语义时，才保留完整内部卡片。

### 5.2 边框职责

- `border-l2`：一级路由中的大模块边界、需要明确分区的表格或滚动区域边界。
- `border-l1`：模块内部行分隔、标题分隔和次级信息分组。
- `border-l3` 或业务主色：只用于悬停、焦点、选中和需要强调的交互状态，不作为静态大面积边框。
- 同一视觉区域不得连续出现两层相同强度的完整边框。

### 5.3 状态提示与操作

- 成功、警告和错误提示继续使用语义状态 token，同时保留文本和 `role`，不得只依赖颜色。
- 状态提示与前后内容块至少保留 `12px` 间距；列表末尾提示可使用更大的下间距，但不得紧贴上一模块。
- 同一区域只保留一个主操作；刷新、帮助和查看类动作保持次级权重。
- 焦点、选中、悬停和禁用状态继续由现有控件规则负责，不用静态模块边框代替交互反馈。

## 6. 路由适配

### 6.1 研究工作台

- 保留顶部指标概览和现有业务分区，不改变卡片点击行为。
- 持仓概览、关联资讯、风险预警、策略匹配等独立业务区使用统一大模块边界。
- 指标小卡和持仓条目仍可保留独立交互边界，但不得与父模块使用相同强度形成双重套框。

### 6.2 智能分析

- 页面能力选择区、说明或上下文区、进入分析的主操作形成清晰层级。
- 可点击能力项保留独立交互边界；静态说明块使用背景和留白，不重复卡片化。
- 不改变提示词模板、会话草稿或助理打开逻辑。

### 6.3 实时盯盘

- 大盘概览、市场扫描和右侧市场资讯作为独立大模块。
- 指数项和扫描行保持高密度；内部优先使用行分隔和悬停背景。
- 保留 AI 打开时的右侧表面协调、容器密度和滚动状态。

### 6.4 策略研究

- 策略池与影子验证共享同一路由表面和标题分隔。
- 策略候选仍是可独立操作的卡片，但父级不再额外形成无意义整块框。
- 影子验证使用一个明确的大模块边界；运行摘要、纸面持仓、净值证据和历史记录通过背景、留白与分隔线组织，减少连续完整套框。
- “当前验证范围”后的状态提示增加至少 `12px` 上间距。
- 生命周期、回测、归档、运行验证和报告入口行为不变。

### 6.5 产业链

- 图谱主视口作为页面主模块，控制区属于主模块内部，不再表现为并列大卡片。
- 事件影响和节点证据作为后续独立大模块。
- 图谱节点本身的选中、聚焦和方向语义不因模块视觉调整而改变。

## 7. 状态矩阵

| 状态 | 适用性 | 视觉要求 |
|---|---|---|
| 首次加载 | 适用 | 保留大模块边界和近似最终结构的骨架，不让页面退化为空白 |
| 后台刷新 | 适用 | 保留旧内容和模块尺寸，刷新反馈不改变层级 |
| 空数据 | 适用 | 空态位于所属大模块内部，说明数据为空而不是隐藏模块 |
| 筛选无结果 | 策略研究、实时盯盘适用 | 保留筛选上下文，空态与数据源为空使用不同文案 |
| 部分成功 | 多资源页面适用 | 成功模块继续可用，失败模块独立提示 |
| 过期数据 | 实时盯盘等适用 | 保留来源和更新时间，不用边框颜色暗示新鲜度 |
| 可恢复错误 | 适用 | 错误提示留在所属模块并保留重试入口 |
| 无权限 | 当前无新增状态 | 复用既有行为；本轮不创造权限状态 |
| 禁用 | 适用 | 保持控件禁用语义，不以降低整个模块对比度代替 |
| 成功 | 适用 | 状态提示与相邻模块保持至少 `12px` 间距 |
| 确认或撤销 | 策略归档等适用 | 保持现有弹层和危险操作规范，本轮不改交互 |

## 8. 响应式与主题

- 1440px：确认完整桌面层级、同级模块间距和网格对齐。
- 1024px：确认标题操作换行、双栏收缩、模块内边距和长中文不碰撞。
- 768px：确认已支持页面转为单列且无页面级横向滚动。
- 390px：只对当前产品已支持的页面验证主要操作、列表和局部横向滚动；复杂图谱可维持现有最小宽度降级，但不得丢失退出或核心操作。
- 浅色与深色均使用相同语义 token 和层级关系；不得在功能 CSS 中加入主题选择器或颜色字面量。
- 长证券名、大数值和 200% 文本缩放下不得覆盖主要操作或隐藏关键状态。

## 9. 长期设计约束

实施时同步更新根目录 `DESIGN.md`，增加“一级路由模块层级”小节，记录以下硬约束：

1. 一级路由必须显式使用共享路由表面契约，不能只依赖裸 `pageScroll`。
2. 一级路由的大模块默认采用 `bg-base + border-l2`；内部静态分组默认不用完整边框。
3. 同一区域禁止连续两层相同强度的完整边框。
4. 状态提示与相邻内容至少保留 `12px` 间距。
5. 新页面或大模块必须同时验证浅色、深色、1440px 和 1024px。
6. 若偏离共享契约，代码中应使用语义清晰的页面专属类，并在变更说明中记录原因。

样式契约测试应检查五个路由均挂载共享作用域，并检查共享 CSS 使用语义 token、二级模块边界和规定间距。测试约束结构与 token 角色，不使用脆弱的像素截图断言。
