# 组合盈亏与收益表现设计

## 背景与目标

研究工作台已经展示持仓数量、成本金额和不含现金的实时市值，但用户无法直接判断当前浮动盈亏，也无法按时间区间查看组合表现。现有 `holdings/default` 只保存当前完整持仓快照，缺少首次录入时间、历史仓位和现金流，因此不能诚实计算历史组合收益率。

本设计在“总资产现价”右侧增加“盈亏情况”概览，并建立从首次可用持仓快照开始的组合表现账本。系统提供成本收益率、时间加权收益率和金额加权收益率，任何缺失历史都明确标示，不用当前持仓反向伪造过去仓位。

## 体验契约

| 项目 | 约定 |
|---|---|
| 目标用户 | 维护研究持仓并复盘组合表现的个人投资者 |
| 主任务 | 一眼确认当前盈亏，再按区间和算法核对收益来源 |
| 首要信息 | 浮动盈亏金额、默认收益率、区间、算法、可用数据起点 |
| 主要操作 | 点击“盈亏情况”，切换区间或算法，查看曲线与逐股贡献 |
| 成功结果 | 用户能区分当前成本盈亏、剔除资金流影响的投资表现和考虑资金时点的资金收益 |
| 支持视口 | 1440、1024、768 和 390 像素；页面不产生横向滚动，弹窗表格可在自身范围内降级为移动卡片 |

工作台概览按“持仓数量、持仓成本金额、总资产现价、盈亏情况、风险画像”排列。“盈亏情况”卡默认显示当前浮动盈亏金额和成本收益率，正负值同时使用符号、文字语义和颜色，不只依赖颜色。点击后打开独立“盈亏详情”弹窗，关闭时焦点返回触发卡。

弹窗默认选择“持仓以来”和“时间加权收益率”。预设区间为“7日、15日、30日、半年、1年、持仓以来、自定义”；超出可用历史的区间自动收敛到首个可用日期并展示说明。自定义区间要求开始日期不晚于结束日期、结束日期不晚于今天，且至少覆盖两个可估值交易日。

弹窗首屏展示所选口径收益率、区间盈亏、期初市值、期末市值和净流入；随后展示带文字摘要的组合收益曲线、逐只持仓贡献和口径说明。方法切换只改变收益率及其说明，金额、市值、净流入、曲线和贡献继续基于同一时间窗口，避免同屏口径漂移。

## 能力审计与唯一决策

| 用户动作 | 现有入口或状态所有者 | 缺口 | 决策 |
|---|---|---|---|
| 查看当前成本和市值 | `ResearchWorkbenchPage`、`GET /holdings`、实时行情轮询 | 无盈亏摘要 | 复用当前持仓与行情计算即时成本盈亏 |
| 维护持仓 | `POST /holdings/save`、`JsonStore` 的 `holdings/default` | 整体替换且无时间 | 扩展为原子保存当前持仓和不可变快照 |
| 获取历史价格 | trading-core 的 `_bs_hist` 前复权日线 | 没有组合表现接口 | 在 trading-core 内复用行情能力，不新增平行行情源 |
| 查看概览详情 | `WorkbenchOverviewDialog`、`DetailDialog` | 没有收益筛选、曲线与算法解释 | 新建领域内 `PortfolioPerformanceDialog`，复用现有弹窗焦点和主题契约 |
| 客户端访问后端 | investment python-runtime 操作映射 | 无表现查询操作 | 新增单一只读 `trading-core.portfolio-performance` 映射 |

不采用纯前端倒推方案，因为它只能计算当前成本收益率，无法恢复历史仓位或资金流；不在本阶段建立含现金、分红、手续费和逐笔成交的券商级账户系统，因为当前产品没有这些权威输入。持仓快照账本是当前数据条件下能保持真实边界的最小完整基础。

## 持久化模型

`holdings.json` 继续以 `default` 保存当前持仓，保持既有消费者合同；新增 `snapshots` 数组，与 `default` 在一次 `mutate_document` 中原子更新。每条快照包含：

- `snapshot_id`：内容和时间共同生成的稳定标识。
- `effective_at`：服务本地 ISO 时间；日收益使用其本地交易日期。
- `source`：`manual`、`bulk_import`、`api` 或 `legacy_seed`。
- `positions`：当时完整的 `ticker/quantity/cost_price` 数组，按代码排序。
- `previous_snapshot_id`：上一条快照引用；首条为空。

同一完整持仓内容重复保存不新增快照；同一日多次变化保留全部事件，估值曲线按日内最后快照确定收盘仓位，资金流按每次变化依次计算。快照不可由普通持仓保存接口修改或删除，并随现有 holdings 数据备份；后续若增加历史修订，必须另建可审计修订操作。

旧持仓没有可信首次录入时间。第一次访问组合表现或第一次再次保存持仓时，以当前服务时间创建 `legacy_seed`；界面显示“历史记录始于 YYYY-MM-DD”，不得使用文件修改时间冒充首次买入日期。空持仓不建立首个持仓快照；从空变为非空的保存日期就是“持仓以来”的起点。

快照保留完整历史，不做自动截断。当前个人投研规模下每次保存的数据量有限；若未来需要归档，应在独立迁移中保留聚合日快照和原始审计事件。

## 收益算法

所有历史估值使用前复权日线收盘价，当前日优先使用实时价；返回数据同时携带 `price_basis`、`as_of`、缺失标的和覆盖率。没有足够价格的组合级结果为不可计算，缺失值不按零处理。

### 当前浮动盈亏与成本收益率

当前浮动盈亏为当前持仓逐项 `quantity × (current_price - cost_price)` 之和；成本收益率为当前浮动盈亏除以当前成本金额。该口径只描述当前仍持有仓位，不代表指定区间内的投资管理能力，也不使用历史现金流。工作台概览固定使用此口径，使页面加载可继续复用已有实时行情。

### 时间加权收益率

时间加权收益率是弹窗默认区间口径。后端按持仓快照把区间切成无外部资金变化的子区间，在每次增减仓边界前后分别估值，再把子区间收益按 `Π(1 + r_i) - 1` 链接。这样新增、删除或调整仓位不会被直接当成投资收益。

如果变化日缺少边界价格，系统使用最近可用交易日收盘价并返回 `estimated=true` 与原因；无法形成两个有效估值点时返回 `value=null` 和不可计算原因。系统不把成本价当成历史市场价。

### 金额加权收益率

金额加权收益率使用 XIRR：首次组合估值作为流出，中间持仓变化按变化日市场价值推算外部净流入，期末组合估值作为流入，求使净现值为零的年化收益率。因为当前系统不记录真实成交金额、现金、分红和费用，该结果标记为“金额加权收益率（估算）”，同时展示推算资金流和限制说明。

现金流少于两个异号项目、日期不足或数值求解不收敛时返回 `value=null`，界面显示“当前现金流不足，无法计算”，不得回退为成本收益率。未来接入真实交易流水后，接口保持同一字段并把质量标记从 `estimated` 升级为 `exact`。

### 区间盈亏与逐股贡献

区间盈亏为期末市值减期初市值再减净流入，属于基于快照和市场价的金额变化解释。逐股贡献使用各标的区间市值变化减去该标的净流入，并同时展示期初/期末是否持有、有效天数和价格覆盖；贡献合计与组合区间盈亏允许因价格四舍五入产生最小展示误差。

## API 合同

新增 `GET /portfolio/performance`，参数为 `start_date`、`end_date`；省略开始日期表示首个可用快照，省略结束日期表示今天。接口一次返回同一窗口的所有算法，客户端切换算法不重复请求。

返回对象包含：

- `available_since`、`start_date`、`end_date`、`as_of`、`price_basis`。
- `quality`：`exact`、`estimated`、`partial` 或 `unavailable`，以及面向用户的 `limitations`。
- `summary`：`start_value`、`end_value`、`net_flow`、`profit_loss`、`current_cost`、`current_profit_loss`、`cost_return`。
- `returns`：`twr` 和 `xirr`，每项含 `value`、`annualized`、`quality` 与不可计算原因。
- `series`：按交易日升序的 `date/value/profit_loss`。
- `contributions`：按绝对贡献降序的逐标的明细。
- `cash_flows`：供金额加权解释使用的日期和金额列表。
- `missing_tickers` 与 `coverage_ratio`。

日期格式不合法、开始晚于结束或结束晚于今天返回 422；没有持仓历史返回 200 的 `quality=unavailable` 空结果；行情源失败返回 503。读取接口允许写入一次 `legacy_seed`，这是显式迁移行为，后续读取保持只读。

前端 python-runtime 新增 `trading-core.portfolio-performance`，只允许上述两个可选日期字段并将其映射到查询参数。既有 `/holdings` 与 `/holdings/save` 返回形状保持兼容；保存响应可追加 `snapshot_id` 与 `effective_at`，既有只读取 `saved` 的消费者不受影响。

## 页面与交互

“盈亏情况”概览卡在持仓或行情尚未完成时显示“—”；持仓为空时辅助文案为“录入持仓后开始记录”；部分实时价缺失时不计算合计，并说明缺少行情。可计算时主值展示带正负号的盈亏金额，辅助行展示“成本收益率 ±x.xx% · 查看详情 →”。

弹窗使用现有宽版 `DetailDialog`。区间控件采用可换行分段按钮，自定义日期在选择“自定义”后出现并保留草稿；算法控件采用单选分段按钮并展示当前口径的常驻解释。曲线使用仓库内原生 SVG，不引入图表依赖，提供 `aria-label` 摘要和同数据的明细表作为非视觉替代。

桌面端首屏摘要为五列；1024 像素允许三加二重排；768 和 390 像素按单列或双列重排。弹窗在窄屏保持全宽、筛选控件可换行，逐股贡献转为每项纵向事实组，不产生页面级横向滚动。

## 状态矩阵

| 状态 | 行为 |
|---|---|
| 首次加载 | 概览保留五卡结构并显示“—”；弹窗展示近似摘要与曲线结构的骨架 |
| 后台刷新 | 保留上次成功结果，显示“更新中”及旧数据时间 |
| 空持仓 | 概览显示“—”；弹窗说明录入持仓后才开始记录并提供关闭路径 |
| 筛选无结果 | 说明区间内不足两个有效估值日，保留区间选择 |
| 部分成功 | 展示可用明细、覆盖率和缺失标的；组合汇总不足时显示“—” |
| 过期数据 | 展示行情时间和过期/估算说明，提供重试 |
| 可恢复错误 | 保留旧结果并在弹窗内显示错误及重试按钮 |
| 无权限 | 本地 profile 当前不设细分权限；若后端返回 401/403，明确显示不可访问，不伪装为空数据 |
| 禁用 | 请求进行中禁用重复刷新；XIRR 不可计算时方法仍可选择并解释原因 |
| 成功 | 更新摘要、曲线、贡献、算法说明和 `aria-live` 状态 |
| 确认或撤销 | 本功能是只读分析，不需要危险确认；自定义日期可重置为“持仓以来” |

## 测试与真实验收

后端测试覆盖快照原子写入、重复保存、旧数据种子、空到非空起点、同日多次变化、日期校验、历史价格缺失、时间加权链结、XIRR 收敛与不可计算、区间盈亏和逐股贡献。前端 runtime 测试覆盖参数白名单与查询映射；组件测试覆盖概览值、默认区间与算法、自定义日期、加载/空/部分/错误状态、算法说明、焦点返回和可访问名称。

真实 UAT 使用隔离状态目录和独立服务端口，至少录入两次不同日期或通过确定性测试夹具建立快照，核对工作台卡片、弹窗筛选、曲线、贡献和限制说明。检查 1440、1024、768、390 像素，浅色与深色主题，键盘 Tab/Shift+Tab/Escape，长证券名称、大额负收益和缺行情标的；记录截图、服务配置、操作结果和未验证项。

## 兼容、恢复与范围边界

既有 holdings 消费者继续读取 `default`，无需迁移调用方。快照与当前持仓必须原子更新，写入失败时两者都不变化。行情查询不改写持仓快照；缓存可以删除并重建，账本不能依赖缓存恢复。

本阶段不纳入现金余额、分红、税费、手续费、逐笔成交、已实现与未实现盈亏拆分、基准指数和多币种。界面明确“总资产现价不含现金”“XIRR 基于录入时市场价估算”。这些字段只有获得权威交易流水后才能升级，不能通过当前成本价或模型推断补齐。
