# Agent Note: 桌面冷启动隔离与最终 ZIP 验收

Status: proposed

[English](2026-10-13-desktop-startup-hotfix.md) | 中文

## Problem

DESKTOP-STARTUP-001 / [PAB-34](https://linear.app/pabiprg/issue/PAB-34) 记录 alpha.3 的 2000ms 健康探测超时。用户机器上的包内清单共 19842 个文件，同步完整校验实测约 2779ms，期间事件循环无法处理计时器；默认端口另有长期运行的源码后端。现有成品检查只证明 Python 导入和资源完整性，不能证明 Electron 插件树、窗口、真实后端、退出及重启可用。

## Proposal

校验继续复用完整清单规则，并在文件及目录之间让出事件循环。Runtime 以单个共享异步任务校验包内资源，缓存成功或失败；readiness 只读取结果，不触发同步全量扫描。每个文件仍整体读取并计算 SHA-256，超大单文件仍可能造成短暂阻塞。

Electron 的 managed 后端使用本实例选取的三个互不相同的空闲回环端口；托管启动跳过旧端口探测，子进程健康响应必须匹配本次启动 UUID。UUID 只用于区分进程，不是访问凭据。Runtime 将实际盯盘和产业链地址传给子进程，状态目录继续使用原 DSH_HOME。显式 external 模式保持原地址和生命周期。端口释放到 Uvicorn 绑定之间仍有竞争窗口，竞争失败时明确退出，只清理自身持有的进程句柄，不按端口或磁盘 PID 杀进程。

启动期间的单次探测超时与暂时不可达在总启动期限内重试；身份不符立即失败，子进程已退出时不能发布健康 lease。运行期健康失败继续失效，不自动拉起新实例。

最终 ZIP staging 后，在独立临时 HOME、DSH_HOME、Electron userData 中解包并启动真实应用两次。验收检查三个包内后端身份、代表性无模型业务请求、禁用提醒规则的跨进程持久化、真实渲染和退出后的进程清理。报告、截图、日志及 ZIP SHA-256 保留；失败阻断附件上传及后续发布，不重新构建附件。

成品验收发现 `public-observatory` 仍依赖桌面禁用的 Web 服务；Electron overlay 必须同时禁用该 Web 专属入口。业务后端启动成功不能代替整个插件树激活检查。

这是对 [Python runtime 生命周期](../../implemented/architecture/2026-08-20-investment-python-runtime-profile.md) 中桌面 managed 路径、[桌面发布](../../implemented/process/2026-09-07-investment-desktop-github-release.md) 中验收步骤的局部扩展；其他消费者和发布版本锁定机制继续适用，不整篇替代旧记录。

## 实施与验证顺序

1. 先取得事件循环与旧服务接入的失败测试，再实现 runtime 与健康标识；补慢响应、错误身份、外部模式和清理测试。
2. 编译真实 Host/Electron，生成本机 ZIP；只使用独立临时资源，不访问远程服务器或共享服务。
3. 执行成品双启动验收，检查截图和持久化；针对失败修正后重新生成、重新验收 ZIP。
4. 记录本机证据及未验证平台；本 PR 准备 alpha.4；合并与发布分别需要授权。

## Alternatives considered

**只增加 2000ms 超时。** 不能消除主线程阻塞，也不能阻止接入旧端口上的服务。

**跳过完整性校验。** 会让损坏或不完整的依赖进入启动路径，违背既有成品完整性要求。

**自动清理固定端口上的进程。** 无法仅靠端口、健康名称或磁盘 PID 证明进程归属，可能影响用户开发服务。

**只运行 Python 导入 smoke。** 不能覆盖 Electron 插件树、真实窗口和退出生命周期，保留它作为完整性辅助证据。

## Risks

ZIP 验收属于深度跨层验收，签名、公证、下载隔离属性以及所有业务页面的人工交互不因启动成功而视为通过。此变更不调整页面布局、颜色或交互；真实渲染检查聚焦正常打开入口，界面筛选、危险操作和响应式重排不属于本次改动。全局进程状态不是终止授权。

回滚通过恢复本次代码变更并重新构建完成；没有持久数据迁移或不可逆配置更改。alpha.3 不应以“构建成功”作为启动稳定性的证据，alpha.4 在未完成原生验收前不得标记可发布。
