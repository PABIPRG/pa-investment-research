# Agent Note: 以失败关闭方式清理本地已合并分支

Status: implemented

[English](2026-08-28-local-merged-branch-cleanup.md) | 中文

## 问题

合并 PR 只会更新共享基线，不会删除本地分支及其绑定的 worktree。远端引用裁剪不会删除本地分支，而当其他 worktree 仍占用分支时，Git 也会拒绝删除。反复执行 Agent 任务会因此积累分支与临时 worktree；若直接批量强制删除，又可能丢失分支提交合并后遗留的人工文件。

普通祖先关系不足以识别所有已吸收分支，因为经过 rebase、squash 或 cherry-pick 的改动可能与基线补丁等价，却不会成为基线祖先。只看补丁等价也不充分，因为非祖先 merge commit 可能包含冲突解决产生的独有改动。

## 决策

仓库提供 `pnpm --dir frontend run branch:cleanup` 作为本地清理规划器。命令默认只读，并显式以 `public/master` 作为默认基线。只有 `--apply` 模式会删除 worktree 和本地分支；命令永不删除远端分支、获取引用、切换分支或更新基线。

规划器保护 `master`、`main`、当前分支以及每个通过 `--protect` 显式指定的分支。它只处理仓库约定的功能分支前缀：`codex/`、`feature/`、`fix/`、`docs/`、`chore/`、`refactor/`、`perf/` 和 `test/`。

## 安全模型

当分支头是已解析基线的祖先，或者基线之外的全部非 merge commit 都与基线补丁等价且不存在非祖先 merge commit 时，分支才可删除。任何独有 commit、非祖先 merge commit 或无法得出结论的 Git 结果都会让分支保留以供复核。

绑定的 worktree 只有在完全干净或仅含范围严格的依赖与编译残留时才可移除。已跟踪的人工改动，以及允许列表之外的任何未跟踪路径，都会使 worktree 和分支保留。生成残留允许列表覆盖嵌套 `node_modules`、后端 `env` 或 `.venv`、Python 字节码缓存和 TypeScript 增量状态；任意 JavaScript、文档或仅凭名称看似生成的普通路径不会被判定为可丢弃。

执行删除前，apply 阶段会验证基线、每个候选分支头和每个候选 worktree 状态仍与 dry-run 规划一致。任一观测状态发生变化时，命令会在首次删除之前中止。干净 worktree 使用普通移除；仅含生成文件的 worktree 因仍有可丢弃未跟踪文件而使用强制移除。祖先分支使用安全分支删除；另行证明补丁等价的分支只会在完成该证明后使用强制删除。

仓库忽略文件采用同一组严格的依赖与编译残留规则，使普通依赖安装不会让 worktree 看似包含人工改动。根协作约定把 dry run 设为合并后的必做检查，并为 `--apply` 保留既有的用户授权边界。

## 考虑过的替代方案

**依赖 `fetch --prune` 或代码托管平台删除分支。** 远端裁剪只删除失效的远端跟踪引用，不会删除本地分支或 worktree；代码托管平台也无法修改开发者的本地仓库。

**删除 `git branch --merged` 列出的全部分支。** 这种方式遗漏 squash、rebase 和 cherry-pick 集成，也不检查绑定 worktree 的改动。

**把没有正向 `git cherry` 记录的分支全部视为可删除。** 普通补丁等价推理不包含非祖先 merge commit，而这些提交可能带有独有冲突解决，因此规划器会保留它们供复核。

**删除前自动归档脏 worktree。** 归档位置、保留期限、敏感文件策略和恢复责任人都需要用户判断。命令只报告脏分支，并保持每个字节不变。

**在清理命令内部获取远端、切换到基线并同步镜像。** 这些操作会把网络凭据与共享引用变更混入本地删除工具。外围工作流继续显式负责引用更新和镜像同步。

## 后果

当 Git 无法证明安全时，命令会有意保留部分实际已经过时的分支供人工复核。这种偏向漏删的策略会带来偶尔的人工清理成本，但能防止未提交工作或 merge commit 独有改动被静默擦除。

合并后的清理在普通合并和补丁等价历史中都成为可重复、可测试的流程。维护者仍需在规划前获取最新公仓和私仓引用、检查 dry-run 输出，并单独授权破坏性的实际删除。
