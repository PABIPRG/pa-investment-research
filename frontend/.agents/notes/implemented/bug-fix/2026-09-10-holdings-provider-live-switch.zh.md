# Agent Note: 持仓数据源即时切换

Status: implemented

[English](2026-09-10-holdings-provider-live-switch.md) | 中文

## Problem

持仓数据源设置只写入 `backend.env`，没有更新正在运行的 trading-core 进程。设置页因此要求重启应用，但源码模式启动时不会加载刚写入的文件，项目 `.env` 也可能优先于用户保存的选择。持仓弹窗提供同步操作却没有数据源选择入口，展示兜底值时还可能暴露 `manual` 等内部码值。

## Decision

`PUT /holdings/user-config` 持久化 `HOLDINGS_PROVIDER` 后同步更新运行中的 `Settings` 实例和进程环境。响应返回当前生效的数据源；仅修改这一项时不要求重启，其他环境配置仍保持重启后生效。

启动过程在托管状态目录和源码模式下都会先加载用户 `backend.env`，再加载项目 `.env`，所有文件均使用 `override=False`。最终优先级为显式进程环境、用户配置、项目 `.env`、代码默认值。

投研设置页与持仓同步面板都展示适合当前平台的数据源选项和产品 label。切换成功后明确反馈当前窗口已经生效；持仓同步面板会重新读取数据源可用性，并在手动输入模式下禁止券商同步。

## Alternatives considered

**每次选择后重启完整应用。** 该方案保留启动时不可变设置，但会打断用户维护持仓的任务，而且仍不能修复源码模式的持久化和配置优先级问题。

**只在设置页保留选择入口。** 用户需要理解和更改数据源时正处于同步流程，把入口留在另一个页面会继续造成发现困难。

**展示后端 provider 标识符。** 稳定标识适合 API 载荷，但作为界面文案会增加用户理解平台和券商选项的成本。

## Consequences

数据源切换无需重启即可观察到，并能在普通的后续启动中恢复。显式传入的进程环境变量在启动时仍具有最高优先级，因此开发者管理的启动方式可以有意覆盖产品保存值。数据源元数据目前分别存在于后端和两个本地化 UI 所有者中，新增或重命名数据源时必须同步更新这些列表。
