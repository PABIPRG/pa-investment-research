# Agent Note: 投研反馈状态转换

Status: implemented

[English](2026-09-09-investment-feedback-state-transitions.md) | 中文

## Problem

三个投研界面虽然展示了有效数据，但可见状态没有跟随用户动作结束。浮动研究窗打开完整证券页面时只是隐藏而非结束，因此保留路由可能复活一个控制按钮不可靠的研究窗。策略诊断把累计收益埋在次级事实中。备份导入成功后，Host 的持久状态已经更新，但已挂载的浏览器界面仍保留导入前的快照。

## Decision

从浮动研究窗打开完整证券详情时，会消费并清空该研究窗状态，同时在返回实时盯盘时抑制一次查询恢复。其他证券详情入口继续保留既有的返回查询行为。

每条策略诊断把带正负号的累计收益作为最右侧主值。正值使用红色市场语义 token，负值使用绿色市场语义 token，零值或缺失值保持中性；参与状态与置信等级继续作为次级文字，展开证据仍保留同一原始指标。

可迁移备份导入在 Host 确认成功后，调用由包注册注入的浏览器刷新回调。导入失败时不刷新，并保留在现有弹窗恢复路径中。组件不再用无人负责的自定义事件代替已挂载数据所有者的刷新。

## Alternatives considered

**在证券详情期间暂停研究窗。** 这种方式保留了已请求内容，但用户明确离开研究窗后仍保留其所有权，使路由恢复能够重新产生故障状态。

**通过浏览器事件刷新每个投研存储。** 旧事件没有任何已挂载所有者订阅；增加分散监听还会要求当前和未来的所有数据界面协调缓存失效。成功导入后刷新页面，为所有所有者提供统一的权威重启边界。

**只在展开证据中显示收益。** 这种方式保持了行内视觉安静，却隐藏了主要比较值，使策略表现扫描不必要地变慢。

## Consequences

三个动作都具有明确的完成边界：详情导航结束来源研究窗，策略行在保留诊断状态的同时暴露可比较表现，导入成功后重新载入完整浏览器产品。刷新会丢弃滚动位置和已打开弹窗等临时呈现状态；对于广泛数据导入，这是有意行为，而导入失败仍保留这些状态以便恢复。
