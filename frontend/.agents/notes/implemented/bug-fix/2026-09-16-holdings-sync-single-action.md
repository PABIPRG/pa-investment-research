# Agent Note: 持仓同步单次执行交互

Status: implemented

## Problem

Electron 原先先尝试一次普通预览，遇到需要前台导航后才展示原生执行确认。用户因此需要依次点击读取、查看说明和允许执行，返回应用后还容易误以为需要再次点击。同步弹层同时把数据源、客户端、权限、账户和预览拆成编号步骤，主任务不够明确。

## Decision

持仓同步弹层只保留“操盘账户”和“获取持仓”两个任务区，不再把客户端检测、权限检查和预览拆成编号步骤。数据源继续由已有全局配置决定，不在本次同步中重复选择。工作项为 [PAB-25](https://linear.app/pabiprg/issue/PAB-25)。

读取条件满足时，Electron 的“获取持仓”直接调用受限原生入口。主进程显示唯一一次影响说明，用户点击“开始执行”后切换到同花顺并等待；用户手动进入“交易 → 对应账户 → 股票 → 持仓”，读取器检测到正确账户和完整表格后自动读取、恢复投研智能体焦点，不要求返回弹层后再次点击。

同花顺 macOS 的主导航是自绘控件，辅助功能 `AXPress` 和系统事件点击都可能返回成功却不真正切页。应用不再猜测无标签按钮顺序，也不再移动鼠标或模拟点击；前台读取改为短周期被动检查，单次检查限制为两秒，总等待时间沿用 `MAC_THS_TIMEOUT`。账户未选中、表格未出现和页面切换中的短暂读取超时都继续等待，其他读取错误立即返回。

批量导入复用既有文件入口、预览和 `holdings-save` 保存契约，新增 `.xls/.xlsx` 工作簿解析。解析器读取首个工作表，在前 20 个非空行中寻找完整表头，因此兼容同花顺导出文件中的标题与导出时间行；CSV、TSV、TXT 和粘贴内容继续使用同一字段校验、重复代码检查与整体替换确认。

同步弹窗沿用宽详情弹层的桌面信息密度，并为持仓预览提供 `1040px` 上限；预览标题、表格和完成操作占满可用内容宽度。窄屏仍由既有响应式规则重排，不通过压缩桌面表格来换取适配。

缺少辅助功能或自动化权限时，获取按钮不出现，界面只说明需要开启的系统权限、完全退出并重开应用的要求和手动录入退路。读取仍只生成五分钟预览，替换本地持仓继续要求单独确认，因此交互收敛不改变数据覆盖保护。

## Alternatives considered

**保留后台探测并自动进入原生确认。** 这仍会执行一次已知无法完成的预览请求，并把可恢复的导航需求先呈现为失败状态，因此没有采用。

**记住永久前台授权并完全取消确认。** 这会让后续读取在没有当次意图确认的情况下切换外部交易客户端，不符合前台动作按次确认的安全边界，因此没有采用。

## Consequences

用户从选择账户到开始读取只需一次获取点击和一次明确确认，原生确认后读取连续完成。权限不足时界面更短，授权后需要完全退出并重新打开应用。最终替换仍保留独立确认，因此减少的是导航摩擦，不是持仓覆盖保护。

同花顺停留在非持仓页时需要用户完成一次页面切换；应用会保持等待并自动继续，但不会代替用户操作交易客户端。等待超时、客户端弹窗遮挡或无法确认账户时，本地持仓保持不变。

## 打包运行时完整性

排查安装版反复出现 `plugin tree failed to load: loader fibers failed` 后确认，直接使用应用包内 Python 做诊断时生成了未登记的 `__pycache__/*.pyc`，导致实际文件集合与 `runtime.json` 的闭包描述不再一致。过去的启动提示只展示最外层聚合错误，因此用户无法看到“运行时文件列表不完整”这一真实原因。

打包流程现在会在最终签名后再次执行 sidecar 冒烟校验，并把 Python sidecar 递归封装为只读：目录为 `0555`，普通文件为 `0444`，原本可执行的文件保留执行位。启动失败时会展开 `cause` 与 `AggregateError`，把完整错误树写入 Electron 日志，并针对运行时不完整给出重新安装干净构建产物的可操作提示。安装测试必须以整体替换应用包的方式进行，不能把新产物覆盖合并到旧目录。

macOS 辅助功能授权还依赖稳定的代码签名指定要求。打包器现在优先使用 `DSH_MAC_CODESIGN_IDENTITY`，其次使用 Electron 生态通用的 `CSC_NAME`，并把同一身份用于 Electron Helper、Python Mach-O 与最终应用。没有可用证书时仍回退到 ad-hoc 签名，但 ad-hoc 构建内容变化后系统可能要求重新授权；发布构建必须配置稳定的 Developer ID 身份并完成公证，才能让授权在版本更新后可靠延续。
