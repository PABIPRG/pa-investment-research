# Agent Note: 券商持仓同步引导

Status: implemented

[English](2026-09-11-holdings-guided-sync.md) | 中文

## Problem

持仓工作台需要一条由券商辅助、但不会静默清空或覆盖本地持仓的替换流程。最初的同步引导已经提供“先预览、后提交”和分平台导航，但 macOS 仍缺少可长期保存的产品授权、券商成交时间归因、读取中取消约定，以及阻止 Renderer 获得后端预览凭证或绕过原生授权的严格边界。

工作项：[PAB-16](https://linear.app/pabiprg/issue/PAB-16) 与 [PAB-25](https://linear.app/pabiprg/issue/PAB-25)。实施上下文见 [PAB-16 handoff](../../../../../docs/superpowers/handoffs/2026-09-11-holdings-sync-implementation.md) 和 [PAB-25 实施计划](../../../../../docs/superpowers/plans/2026-09-15-pab25-macos-holdings-accessibility.md)。

## Decision

### 平台与授权

Windows 保留独立的 easytrader 实现和既有同步行为。PAB-25 只修改并验证 macOS Electron 行为；macOS 验证不作为 Windows 回归证据。

macOS 不执行定时或后台持仓读取。读取只能由用户主动点击发起。产品授权可选择按次或长期：长期授权只能在原生确认后建立，仅免除以后由用户主动发起读取时的重复询问，可在设置中关闭，并且不替代 macOS 辅助功能或自动化系统权限。

### 数据与归因

每份预览包含股票代码、持仓数量和成本价。当客户端暴露当前历史成交查询范围的明细时，持仓还包含券商成交时间、方向、数量和价格，来源为 `broker_detail`；界面同时提示该范围尚未证明覆盖当前持仓的全部形成过程。无法取得明细时，读取时间作为明确的 `read_fallback`；用户可修改为 `user_modified`，后续只有兜底时间的读取会保留该人工值。

快照身份包含真实或模拟账户来源。同一账户重复读到相同持仓时忽略新生成的兜底读取时间，但保留券商成交明细和用户修改的归因。无变化提交复用最新快照并返回 `changed=false`，不创建重复业务变更。

### 宿主边界与写入安全

Electron 拒绝通用持仓预览和提交 operation。主进程持有长期授权、后端预览 token、不透明 Renderer 会话和最终原生替换确认。Renderer 消息只允许固定动作，不能提供命令、URL、客户端路径、任务标识或后端 token。私有后端路由要求仅宿主可见的凭证和自管本机后端。

空持仓、必填字段缺失、过期、取消、冲突或已消费的预览都不会替换本地持仓。仅成交明细未完成时，已验证的持仓仍可以读取时间兜底显示，必须向用户展示真实原因，并且只有用户主动确认才能替换。成功提交会在原子写入前校验账户、数据源、存储根目录、限定于预览股票的时间修改，以及未变化的本地基线。

### 取消与焦点

Renderer 可以取消进行中的 macOS 读取。主进程用自己生成的 operation id 发送私有取消并中止请求；后端取消事件停止 AX 遍历，生产 AppleScript 降级路径会终止其子进程。取消不会生成 Renderer 会话，也不会写入持仓。成功、失败或取消后，主进程都会尝试恢复投研智能体。

macOS AX 导航不再把 `AXPress` 返回成功视为页面已切换。每一步都重新遍历当前可见窗口，并且只有所选账户和目标表格在同一窗口被证明时才继续。多个无法区分的入口或验证码、登录/解锁、协议和风险提示会导致安全停止，而不是猜测点击。

## Testing

后端测试固定预览/提交隔离、时间来源、人工时间保留、取消、逐步导航、同窗口账户/表格验证、不完整明细降级、账户感知去重和 macOS 解析。Electron 测试固定长期授权、关闭授权、仅前台主动发起、不透明会话、原生确认、取消和焦点恢复。Runtime 与组件测试固定非 Remote 边界、macOS 仅手动主动读取、部分成功提示、可编辑兜底时间、设置页关闭授权及无变化预览。

签名宿主连接已安装且已登录的真实同花顺后，仍须验证 TCC 归属、真实 AX 标签、导航、成交表兼容、取消和焦点恢复。自动化检查不能代替这项 UAT；当前状态与关闭条件记录在 [PAB-25 UAT handoff](../../../../../docs/superpowers/handoffs/2026-09-15-pab25-macos-holdings-uat.md) 中。

## Alternatives considered

**每次读取都强制原生询问。** 该方案授权模型简单，但不满足已确认的长期授权需求。因此长期授权只属于产品层、可明确关闭，而且本身仍不能发起读取。

**把后端预览 token 暴露给 Renderer 并复用通用同步入口。** 该方案被否决，因为不可信 Renderer 可以绕过原生授权和确认边界。主进程改为把每个后端 token 映射为短期不透明会话。

**所有持仓都使用读取时间。** 该方案被否决，因为存在成交明细时必须使用券商成交时间完成归因。读取时间只作为可见且可编辑的兜底。

**由持仓读取模块直接发送下游通知。** 该方案被否决，因为变更检测与通知投递有不同的状态所有者。当前基线只返回确定性的 `changed` 和 `snapshot_id`；位置计划与通知中心后续集成必须消费这些事实，不能把投递所有权移入本模块。

## Consequences

macOS 流程获得明确且可关闭的信任模型、券商优先的时间归因、幂等快照和可取消的宿主写入边界。代价是流程依赖可能随同花顺版本变化的无障碍标签，源码环境的 TCC 归属也可能不同于签名应用。在真实 UAT 记录这些事实前，macOS 客户端兼容性仍是未验证状态。位置计划与通知中心消费方不在当前基线中，仍需单独集成；这项缺口不允许本模块制造重复事件或直接发送通知。
