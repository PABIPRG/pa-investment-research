# Agent Note: 八域投研工作台

Status: implemented

[English](2026-08-25-investment-research-v002-workbench.md) | 中文

## 问题

投研 Profile 原先只呈现产品流程中的少数环节。用户能够扫描机会、检查持仓，却无法沿着连贯的日常研究流程连接个性化事件、智能分析、实时盯盘、策略研究、影子验证、自进化、个人投研和产业关系。

扩展页面带来两项约束：当后端资源以不同速度完成或没有记录时，视觉层级和交互仍须保持可用；浏览器不能为了让新页面看起来完整而虚构研究数据。新入口还必须沿用正式会话、审批、附件和模型选择行为，不能另建一套助理体验。

## 决策

Profile 现在采用八域导航，并分为总览、分析与盯盘、策略闭环、个人与图谱四组。“研究工作台”是默认入口；“智能分析”“实时盯盘”“策略研究”“影子验证”“自进化”“我的投研”和“产业链”均可一步到达。持续可见的悬浮助理入口提供统一返回路径，同时不占用额外导航行。

具有浏览器安全操作的页面通过 `InvestmentDataOperation` 读取真实数据和执行固定业务流程。“研究工作台”汇总持仓、风险预警、个性化事件卡片、策略匹配和风险画像，并通过全量简报任务生成盘前简报；“智能分析”在页面内发起个股、持仓、简报与历史回测任务；“策略研究”完成假设预览、候选入池、样本外回测和状态迁移；“影子验证”运行每日记账并刷新状态、持仓和净值；“自进化”先预览动作，用户确认后才应用。“我的投研”在自身页面提供持仓保存与分析、自选增删、KYC 问卷与微调、行为画像和组合风险；“产业链”通过独立生命周期插件在自身页面提供公司检索、公司与节点档案、五列链路、多层展开和全局网络。每个数据区自行管理加载、空状态、错误、重试和刷新，因此缓慢或不可用的后端不会清空无关内容。

共享投研助理只承担结果解释和延伸研究。所有模块内 AI 动作和悬浮入口都会以 390px 固定浮窗覆盖在当前业务路由右侧，不压缩业务页面；每次先创建独立新对话，再向该会话输入框预填结构化业务数据。上下文由页面点击时快照、模块后端快照和精简整体数据组成，并明确排除代码与工程研究语义。打开助理不会修改业务路由或复用历史会话，用户仍可在发送前编辑内容。空状态和禁用控件说明下一步，但不会填充虚构的证券、关系、业绩或组合数值。

Host 白名单只通过固定 operation 定义扩展。每项定义绑定一个 backend、方法和路径，并校验允许的输入键与边界；浏览器仍不能选择后端地址、端口或任意路径。

响应式布局保留分组导航、紧凑摘要卡、表格、状态标记、窄屏内容重排、清晰键盘焦点以及明确的忙碌与错误状态。界面文案只描述产品动作和数据状态，不呈现内部实现或评审流程。

## 考虑过的替代方案

**保留原导航，把新动作全部放入助理。** 这样代码变化更少，但会隐藏日常研究顺序，也不利于快速浏览影子净值或自进化就绪状态等持续信息。

**允许浏览器直接调用后端 URL。** 这样会减少 Host 映射工作，却会把地址和任意路径暴露给不可信客户端输入，并绕过租约、校验和生命周期保证。

**用预置证券与业绩填满不可用页面。** 这样每个面板看起来都有内容，但用户可能把装饰数值误认为研究结果。明确空状态并提供共享助理入口，可以保持已获得数据与待请求分析之间的边界。

**为新工作台另建一套助理。** 这会分裂会话能力，并重复消息、附件、审批和模型选择逻辑。在当前路由旁复用正式会话区可以保持单一事实来源，同时通过每次新建对话隔离不同模块的研究任务。

## 后果

用户现在可以从稳定的默认工作台进入完整研究闭环，并在每个产品域内打开独立新助理对话而不离开当前页面。分析、策略、影子、自进化、我的投研和产业链核心业务都直接在各自页面完成；直接数据页面在局部加载或失败时仍然可用，助理只消费已经取得的业务上下文，不再代替业务接口。代价是路由和操作范围扩大、页面需要维护更多区域状态，而且新工作流在直接读取后端数据前必须先增加固定 Host operation 和后端生命周期接入。

## 验证

`packages/client/ui-investment-research/tests/state.client.spec.ts` 与 `apply.client.spec.ts` 覆盖默认路由、分组导航、搜索清空、当前路由助理浮窗和逐次新建会话；`assistant-context.client.spec.ts` 验证整体/模块快照与模块路由；`my-research-page.client.spec.tsx` 与 `industry-chain-page.client.spec.tsx` 覆盖持仓/KYC 和产业链业务；`v2-pages.client.spec.tsx` 覆盖分析任务、简报、策略、影子与自进化流程。Runtime、生命周期插件、Bundle、Profile 和侧车测试验证所有固定路由、第三后端装载以及无效输入的请求前拒绝。
