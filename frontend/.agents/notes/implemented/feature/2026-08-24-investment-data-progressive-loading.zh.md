# Agent Note: 投研数据页按资源渐进加载

Status: implemented

[English](2026-08-24-investment-data-progressive-loading.md) | 中文

## Problem

“机会发现”和“持仓分析”各自需要读取多个延迟与故障互不相关的后端资源。整页等待所有请求完成会让一个慢接口阻塞其他已经可用的数据，一个失败也会清空整页；刷新时移除旧数据还会造成白屏和布局跳动。用户看不到已经完成多少项，也无法只重试失败区域。

筛选条件变化还会产生另一类竞态：旧请求可能晚于新请求返回，并覆盖用户当前选择对应的数据。现有 Host transport 没有为这些页面提供可用的网络取消协议，因此界面不能把“忽略旧结果”承诺成真实取消。

## Decision

`OpportunityPage` 分别维护市场扫描、实时资讯和技术信号状态，`PortfolioPage` 分别维护持仓、组合风险和风险预警状态。每个资源具有独立的 `loading`、`refreshing`、`success` 和 `error` 阶段；页面在任一资源成功后立即展示该区域，而失败只产生区域内的错误说明和重试入口。

同一请求键正在执行时，`useRequestResource` 不再启动重复请求。同一键刷新会保留上次成功值并进入 `refreshing`，不同键请求则清除不匹配的旧值。每次请求都分配代次，只有当前代次可以提交结果；被筛选切换取代的晚到响应会被忽略。该代次守卫不取消 Host 或后端工作，也不更改 Typert transport 或 Host 协议。

页面顶部使用实际资源状态公布已完成项数，初次加载使用固定高度骨架，刷新使用旧数据和“更新中”标签。资源容器暴露 `aria-busy`，进度使用 `role="status"` 和礼貌播报，错误使用 `role="alert"`。键盘焦点样式覆盖新增交互控件，窄屏下扫描类型横向滚动，页头按钮与内容改为纵向排列并维持触控尺寸。

## Testing

`packages/client/ui-investment-research/tests/data-pages.client.spec.tsx` 使用可控的 deferred promise 固定以下行为：资源逐项完成、部分失败不清空成功区域、失败区域独立重试、刷新保留旧数据、重复动作不产生额外调用，以及旧代次响应不覆盖新筛选结果。测试同时检查关键 `aria-busy`、`status`、`alert` 和 `aria-pressed` 状态。

## Alternatives considered

**继续使用整页 `Promise.all` 和统一重试。** 这会把独立资源绑成同一故障域，最慢请求决定整页可用时间，且用户无法保留或只重试已经明确失败的区域。

**把代次失效称为取消。** 代次守卫只能阻止旧结果写入 React 状态，Host 与后端仍会继续执行。把它呈现为取消会给用户和维护者错误的资源释放保证。

**显示估算百分比或虚构处理阶段。** 当前接口没有服务端进度事件。页面只公布已完成资源数和加载、更新阶段，避免把不可观测的后台工作包装成伪精确进度。

## Consequences

慢接口或局部故障不再阻塞其他可用数据，刷新期间页面保持稳定，用户能够知道完成范围并只恢复失败区域。代价是页面需要维护更多局部状态和竞态测试；被取代的后端调用仍会消耗资源直到自然结束。将来若 transport 提供真实取消，可在不改变当前渐进展示语义的前提下接入。
