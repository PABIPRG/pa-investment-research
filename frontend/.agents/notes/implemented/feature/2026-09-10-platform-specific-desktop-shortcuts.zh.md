# Agent Note: 分平台桌面快捷键

Status: implemented

[English](2026-09-10-platform-specific-desktop-shortcuts.md) | 中文

## Problem

Electron 产品此前没有通过键盘打开设置或控制窗口的路径；而跨平台共用一张映射表会违背 macOS、Windows 与 Linux 的既有习惯。自定义还需要可持久化、可恢复默认的边界，并且不能让一个操作系统覆盖另一个系统的选择。

## Decision

`ui-desktop-shortcuts` 包拥有三个应用动作和按平台隔离的自定义设置层。macOS 默认使用 `Command+,`、`Control+Command+F` 与 `Command+M`；Windows 和 Linux 默认使用 `Ctrl+,` 与 `F11`，最小化继续由系统管理。默认值从代码派生，只持久化覆盖项；因此恢复默认会删除当前平台的覆盖，而不是写入一份当前版本默认值的副本。

Electron 主进程只为当前前台窗口匹配 `before-input-event`，并在主进程执行原生窗口操作，不使用 `globalShortcut`。沙箱化 preload 只暴露平台、录制期间暂停匹配和动作通知；Connection 服务把这组可信桌面能力投影给功能插件，避免客户端包之间被禁止的运行时导入。主进程只接受窗口主 frame 发出的录制状态 IPC。

设置页记录基于物理按键的组合，验证固定按键范围，拒绝未搭配修饰键的输入键、系统保留键和同平台动作冲突，并支持恢复单项与经确认后恢复当前平台全部默认值。基础设置域提供一个带修订号的小型导航服务，使主进程的“打开设置”动作能直接打开快捷键页。普通 Web 和远程 Web 组合不会出现桌面快捷键页面。

## Alternatives considered

**注册操作系统全局快捷键。** 未采用，因为这些动作属于当前活动的产品窗口；应用在后台时抢占按键会与其他应用冲突，还会扩大操作系统权限与生命周期处理范围。

**持久化完整的已解析快捷键表。** 未采用，因为复制出的默认值会随版本演进而过时，恢复时也可能误删其他操作系统的自定义。

**从 Connection 客户端包直接导入 Electron bridge。** 未采用，因为客户端 bundle 图禁止插件之间的运行时导入；可选能力改由注入的 Connection 服务提供。

## Consequences

桌面用户获得符合系统习惯的默认值、即时冲突提示、持久化自定义与可预测的恢复行为。同一份设置文档可以跨操作系统使用，而不会混淆各平台选择。代价是有意限制物理按键范围，不支持后台快捷键，并且 Windows 与 Linux 没有应用自有的最小化默认键。单元和 UI 测试固定了标准化、校验、持久化、设置面板导航、安全 IPC 归属、Host 实时采纳及原生动作分发。
