# Agent Note: 自进化只读看板、单策略诊断与唯一自动闭环

Status: implemented

[English](2026-09-01-evolution-dashboard-strategy-diagnostics.md) | 中文

> 本决策部分取代[投研产品生命周期工作台](2026-08-26-investment-product-lifecycle-workbench.md)中的人工生成进化预案与确认界面。旧 preview/run 接口继续作为兼容合同保留，但不再是产品 UI 动作。

## Problem

自进化曾有两个相互竞争的执行主体：产品引导操作者生成并应用预案，调度器又能独立运行自动闭环。全局页面还把组合级观测与单策略动作混在一起，导航可能丢失策略作用域，模型上下文也会读取产品并不需要的待确认预案。结果是权威执行路径不明确，一个以研究读取为主的页面看起来却能修改生命周期状态。

## Decision

侧栏“自进化”是全局只读看板。它只读取无作用域的 evolution status 与 attribution，展示闭环开关、参与状态分组、置信层级、变异来源标记、当前判定、生效策略母链和最近自动应用动作。参与状态使用“正常运行”“观察中”“候选”“已淘汰”“已拒绝”的产品词汇，tier 2 独立展示为“已升级”。变异只作为来源标记和谱系输入，不作为单独计数的参与状态。策略行、参与状态条目、链路节点与历史动作都会携带受控策略标识和可选返回分组，进入策略研究第 4 步。

策略研究第 4 步是固定单策略诊断。它用同一个经过验证的 `strategy_id` 读取 scoped status 与 attribution，展示证据、预计判定、母子链和自动执行历史，并可返回发起跳转的看板分组。“重新评估”只表示重复这两次读取，不请求预案、不应用动作，也不改变策略状态。只有 active 且未归档策略展示这项只读刷新。AI 上下文遵循相同拆分：全局和 scoped evolution intent 都只读取 status 与 attribution。

启用的调度器是唯一产品写入路径。统一自动闭环依次运行影子验证、归因、进化应用、候选验证和通知，隔离各阶段失败，并记录已应用动作，供看板和单策略诊断追溯。preview/run 与 scoped run 只为兼容而保留安全校验和回归测试。

## Alternatives considered

**让人工预览与自动应用继续作为同等产品路径。** 两个执行主体可能针对不同状态版本做判定，使审计链含混。

**让侧栏看板在全局与单策略作用域之间切换。** 作用域切换会把导航状态藏进观测页，并重复策略研究阶段已有职责。

**把重新评估实现成 dry-run 预案。** 预案会创建可变令牌状态并暗示后续人工应用；重复 scoped 读取即可得到最新诊断，不需要创建临近写入的状态。

## Consequences

产品现在只有一种可见观测模型和一个执行权威。全局与 scoped 请求不会静默互相回退，非 active 策略仍可查看历史，模型上下文也不会引入隐藏的预案流程。兼容 API 仍大于产品表层，因此仍需安全和回归测试。过去期待确认按钮的操作者需要改为检查自动审计历史，并通过部署配置控制闭环。
