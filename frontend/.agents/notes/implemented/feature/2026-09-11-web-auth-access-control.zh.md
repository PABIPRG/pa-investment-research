# Agent Note: Web 单管理员全链路访问控制

Status: implemented

[English](2026-09-11-web-auth-access-control.md) | 中文

## Problem

Web 组合此前只有 Host/Origin 信任检查，用于阻止 DNS rebinding 和跨站请求，但没有身份鉴别。只要能访问受信地址，调用者就可能到达 `/api`、事件 WebSocket 以及会操作本机的业务能力；把服务绑定到局域网地址时尤其缺少明确的安全边界。

## Decision

新增 `@deepseek-ai/dsh-api-web-auth` 作为 Web 组合的唯一身份权威。部署通过 `DSH_WEB_AUTH=required`、管理员用户名和受保护的版本化 scrypt 哈希文件启用鉴权；密码不进入命令行、环境变量、配置对象或日志。认证启用但配置缺失、文件不可读或记录格式无效时保持 fail-closed，健康检查报告未就绪。

服务签发高熵不透明 Cookie，会话只保存在进程内，并同时实施空闲超时和绝对超时。所有非安全业务请求使用会话绑定的 CSRF 令牌；登录尝试按有效客户端 IP 限流，密码校验受全局并发上限保护。退出、过期和插件卸载都会撤销会话并销毁该会话已建立的事件 WebSocket。

连接层在任何 `/api` 业务分发和 WebSocket 升级前依次执行共享 Host/Origin 信任检查与身份检查。既有回环特权方法栅栏继续保留在身份检查之后，因此管理员身份不会自动放宽必须本机调用的能力。浏览器客户端为所有状态变更请求注入 CSRF，并在收到 `401` 时回到登录页。

Web 入口在现有应用启动前显示响应式登录门禁，覆盖加载、错误凭据、限流、配置不可用、过期、成功和重试状态；认证成功后才启动原应用。Electron 入口继续使用现有 IPC 边界并显式绕过 Web 登录门禁。默认 Cookie 要求 HTTPS；只有 `127.0.0.1` 开发服务能显式启用非 Secure Cookie。

## 本地验证码决策

PAB-17 / WEB-AUTH-001 的管理员入口使用自适应本地 PNG 验证码；本轮基准为 PR #103，分支为 `codex/login-captcha-uat`。挑战状态继续由同一个认证服务拥有，登录页组合共享 Input/Button 与 CSS Modules，不引入第二套鉴权状态或远端验证码依赖。PNG 使用固定大小灰度像素和 Node zlib 编码，避免字体文件与原生图形库部署依赖；只有服务端持有答案摘要，浏览器只获得像素。

两次凭据失败后启用验证码，观察期长于一分钟限流窗口，防止等待限流解除即可恢复无验证码爆破。客户端记录在异步 KDF 前预留，单 IP 串行、全局四个并发，解决同一身份同时跨越阈值和多个身份越过容量上限的问题。验证码原子消费发生在密码校验之前，插件卸载后的在途结果不能创建会话。完整协议与限制以[包说明](../../../../packages/api/web-auth/README.zh.md#本地自适应验证码)为准。

体验使用原表单，第二次凭据失败后显示验证码并聚焦输入；刷新保持图片尺寸并清空旧答案。错误、限流、网络、配置、传输、过期和成功均有中文反馈及 live region，提交时防重入。表单支持浅色/深色与 1440/1024/768/390 视口；空数据、筛选、部分成功和撤销不适用于登录。

### 复用审计

| 用户动作 | 现有入口与状态所有者 | 缺口与唯一决策 |
|---|---|---|
| 提交账密 | LoginGate → WebAuthService.login | 在已有登录判定之前扩展挑战校验，复用可信 IP、KDF、Cookie 与 CSRF |
| 刷新或重载 | LoginGate /auth/session | 同一个服务增加 /auth/captcha，重载只读取服务端要求，不相信浏览器失败计数 |
| 获取图片 | 认证包没有验证码生成器 | 包内 captcha.ts 生成 PNG；不增加公共组件、图形依赖或独立认证服务 |

## 运维与后续契约

密码通过 `dsh web-password-hash` 从标准输入生成哈希。轮换采用原子替换哈希文件并重启服务，新进程加载新记录且旧进程会话全部失效。PAB-19 可在受信 HTTPS 反向代理后部署同一组合，但必须保留 Host allowlist 与默认 Secure Cookie；PAB-20 的发布封装必须注入哈希文件路径而不是明文秘密，并以 `/healthz` 作为就绪证据。

## Verification

聚焦测试覆盖哈希格式、配置缺失、错误登录、限流、登录成功、CSRF、退出、空闲/绝对过期、密码轮换需重启、HTTP 与 WebSocket 业务分发前拒绝，以及浏览器登录状态。Host 与 Client 正式库构建、Web 生产构建和真实浏览器 UAT 作为交付证据；UAT 使用独立临时状态与端口，不操作共享开发服务。

## Alternatives considered

**只依赖 Host/Origin 信任栅栏。** 已否决：该机制防御请求来源欺骗，但不能证明调用者身份，局域网可达者仍能调用业务能力。

**由反向代理独占登录能力。** 已否决：本地回环开发、直接启动和未来发布封装会得到不同的鉴权边界，且 WebSocket 与进程内会话撤销难以保持同一语义。

**使用长期 Bearer Token。** 已否决：浏览器需要自行持有可重放秘密，也缺少会话超时、退出撤销和 CSRF 分层保护。

**外部验证码服务。** 不采用：大陆 UAT 的可达性和本次无外部服务要求不允许依赖 Turnstile、Google 或其他远端服务。

**明文算术题或 SVG text。** 不采用：客户端脚本直接读取答案或题目即可机械提交。PNG 提高直接脚本门槛，但不能防御 OCR。

**音频验证码。** 本次不实现：本地语音素材、混音和可用性需要额外验证；因此图片无法视觉识别者仍需管理员协助，保留为明确的无障碍限制。

## Consequences

所有 Web 业务入口现在共享一条可撤销、默认安全且配置缺失时关闭的身份边界；代价是会话不跨进程持久化，也不支持多副本共享。当前只有单管理员身份，不提供角色权限模型。TLS 终止、发布包注入或容器编排仍由后续交付项承接。
