# Agent Note: 持仓止盈止损计划

Status: implemented

## Problem

持仓模块原先只有数量、成本与市值，没有可持续监控的止盈止损计划。用户需要一份与风险画像相符的全局默认配置，同时允许单个持仓覆盖或关闭监控；未配置单股计划时不能复制并维护一份独立配置，而应实时继承全局配置。

## Decision

在现有持仓模块内增加止盈止损计划，不新增独立的“持仓计划”模块。工作项为 [PAB-27](https://linear.app/pabiprg/issue/PAB-27)。

配置采用“全局默认 + 单股稀疏覆盖”模型：单股存在完整覆盖时使用覆盖值；不存在覆盖时读取当前全局配置；显式关闭监控时不再继承全局配置。百分比目标在确认配置时依据持仓成本固化为目标价，后续成本或全局配置变化不会静默改写已激活目标。

trading-core 持有配置、激活状态、去重和提醒生命周期；market-watch 只接收派生后的固定目标价规则，使用带来源、时间和新鲜度的行情判断是否命中，再通过内部令牌回传确定性事件。提醒只进入现有风险预警中心，不执行交易。

持仓表直接展示监控状态、配置来源、止盈价和止损价；“全局止盈止损”维护默认配置，“调整”维护单股覆盖、恢复全局或关闭监控。风险画像建议只作为可解释的填写参考，不自动保存为用户配置。

## Alternatives considered

**为每个持仓复制一份全局配置。** 这会产生重复数据，并使后续全局调整无法清晰区分继承值和历史副本，因此没有采用。

**新增独立持仓计划模块。** 计划与当前持仓的数量、成本和生命周期强关联，拆成独立入口会增加导航和状态同步成本，因此继续集成在持仓模块。

**命中后自动提交卖出委托。** 当前能力只承担研究与提醒，自动交易会扩大权限和资金风险边界，因此明确不执行交易。

## Consequences

用户只需要维护一份全局默认配置，并在少数持仓上保存覆盖。导入或同步持仓后会重新协调派生规则；删除持仓时对应规则停止生效。已命中的目标需要用户明确重新启用，避免相同行情持续重复提醒。

行情过期、内部规则同步失败或服务暂不可用时，界面保留现有配置并显示同步状态，不把失败解释为已完成监控。持仓计划、运行状态和触发记录纳入数据备份与恢复契约。
