# Agent Note: 语义形状层级与产品内品牌身份

Status: implemented

[English](2026-09-20-semantic-shape-and-brand-identity.md) | 中文

## 问题

共享控件、登录界面和投研界面对相同视觉角色使用了互不相关的圆角。按钮呈胶囊形，而输入框保持矩形；浮层圆角从 14px 到 24px 不等，页面自有模块又引入了更多取值。登录入口展示 APP-ICON-001，但产品内品牌区使用文本星形符号；事件和研究控件也使用了外观随平台变化的 emoji 式文本符号。这些差异削弱了层级，也让入口与工作界面的产品身份不一致。

## 决策

客户端主题拥有 5 个语义形状 token：`--dsw-alias-radius-compact` 为 6px、`--dsw-alias-radius-control` 为 8px、`--dsw-alias-radius-module` 为 12px、`--dsw-alias-radius-overlay` 为 16px、`--dsw-alias-radius-pill` 为 999px。共享按钮、输入框、分段控件、提示条和弹层按角色使用对应 token。产品界面中本次涉及的模块和浮层复用同一组 token；全圆角 token 仅用于状态、元数据和明确采用胶囊形的操作元素。[`DESIGN.md`](../../../../../DESIGN.md) 持有长期视觉规则。

Web 登录入口和投研品牌区都使用 APP-ICON-001 作为产品身份。登录主操作、焦点样式和克制的页面光晕使用业务蓝语义色。研究、AI 助理、标的与事件类型操作使用确定性的内联 SVG 路径，同时保留可见中文标签和可访问名称；文本 emoji 不作为产品图标。

## 验证

组件测试锁定共享应用图标路径，以及事件类型 SVG 与文本标签。聚焦客户端测试、类型检查、Web 构建和桌面及窄屏尺寸下的浅色／深色真实渲染复核覆盖受影响的入口与工作台界面。

## 曾考虑的替代方案

**保留组件局部的数字圆角。** 这种做法保留各历史截图，但会让等价控件继续呈现不同外观，并提高后续再次漂移的概率。

**让所有交互元素都使用胶囊形。** 这种做法可以形成统一轮廓，但会抹平普通控件与状态或筛选标签之间的区别，也与高密度投研布局冲突。

**继续使用文本符号作为紧凑图标。** 这种做法可以减少 SVG 标记，但符号外观取决于操作系统和字体，无法可靠保留已批准的产品身份。

## 影响

入口与产品内界面共享同一个品牌资源，普通控件与浮层具有可预测的轮廓，业务图标也能跨平台和主题稳定渲染。语义 token 为客户端 CSS 增加了一项明确依赖；未来例外需要先选择合适角色，或记录标准层级无法表达该界面的原因。应用图标源文件和平台 mask 声明保持不变；平台专属的图标裁切不属于本决策范围。
