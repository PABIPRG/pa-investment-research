# 风险偏好分析框架（risk_profile）

风险偏好贯穿 Python 后端的个股分析、持仓分析和市场简报。它保存于 Python adapter 的数据目录，也可以通过单次 API 请求覆盖。`adapter/risk_profiles.py` 是预算、逐股分档和确定性护栏的唯一事实来源。

## 三档画像与准确阈值

| 画像 | key | 组合预算（波动率 / HHI / 单股 / β） | `risk_bands`（高 / 中） | 护栏 | 简报最大风险 |
| --- | --- | --- | --- | --- | --- |
| 保守型 | `conservative` | 12% / 0.20 / 15% / 0.80 | 0.35 / 0.20 | 买入风险分 **> 0.50** 降级为持有 | 中 |
| 稳健型 | `balanced` | 18% / 0.30 / 25% / 1.00 | 0.50 / 0.30 | 买入风险分 **> 0.65** 降级为持有 | 高 |
| 进取型 | `aggressive` | 30% / 0.50 / 40% / 1.50 | 0.70 / 0.45 | 卖出风险分 **< 0.30** 降级为持有 | 高 |

`risk_bands.high` 和买入降级阈值是不同概念：前者用于把逐股 `risk_score` 标成低/中/高，后者只在引擎明确给出“买入”时应用。因此保守档分数 `0.40` 已是高风险，但不会因护栏单独改写动作；保守档“买入”在分数严格大于 `0.50` 时才改为“持有”。同样，稳健档的高风险分界是 `0.50`，买入护栏却是严格大于 `0.65`。

## 确定性规则

`calibrate_stock_decision()` 只在风险分可以转换为数值且动作与当前画像的护栏直接冲突时改写结果；其他动作与缺失/非法风险分保持引擎原样。发生校准时，它把说明附加到 `signal.reasoning` 并返回 `calibrated=True`：

- 保守型与稳健型：动作是“买入”且风险分超过各自 `buy_risk_score_max`，改为“持有”。
- 进取型：动作是“卖出”且风险分低于 `sell_risk_score_min`，视为弱卖出并改为“持有”。

逐股风险等级由 `risk_level_for()` 按 `high`、再按 `medium` 阈值计算；`None` 返回 `—`。市场简报按机会点风险等级过滤，保守型只保留低/中风险项；进取型把高风险项排在前面。

优先级为：调用参数 > 持久化设置 > `.env` 的 `RISK_PROFILE` > `balanced`。

## Python 后端实现

- `adapter/risk_profiles.py`：画像表、风险分档与确定性校准。
- `adapter/engine_bridge.py`：将画像注入引擎并校准输出。
- `adapter/holdings_runner.py`：风险预算与调仓建议。
- `adapter/brief_engine.py`：机会点分级和简报提示词。
- `adapter/app.py`：`GET/POST /risk_profile` API。

宿主侧工具和呈现源码位于 [frontend/packages/investment-research/stock-analysis](../../../frontend/packages/investment-research/stock-analysis)，并消费该 API；它不改变 Python 后端中的画像规则。

`dsh electron --profile investment-research` 是**阶段二交付，当前阶段尚未启用**。当前可通过 Python API 的 `risk_profile` 参数和端点验证全部行为。
