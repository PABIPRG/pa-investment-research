# 风险偏好分析框架（risk_profile）

风险偏好贯穿 Python 后端的个股分析、持仓分析和市场简报。它保存于 Python adapter 的数据目录，也可以通过单次 API 请求覆盖。`adapter/risk_profiles.py` 是预算、逐股分档和确定性护栏的唯一事实来源。

## 三档画像与准确阈值

| 画像 | key | 组合预算（波动率 / HHI / 单股 / β） | `risk_bands`（高 / 中） | 护栏 | 简报最大风险 |
| --- | --- | --- | --- | --- | --- |
| 保守型 | `conservative` | 12% / 0.20 / 15% / 0.80 | 0.35 / 0.20 | 买入风险分 **> 0.50** 降级为持有 | 中 |
| 稳健型 | `balanced` | 18% / 0.30 / 25% / 1.00 | 0.50 / 0.30 | 买入风险分 **> 0.65** 降级为持有 | 高 |
| 进取型 | `aggressive` | 30% / 0.50 / 40% / 1.50 | 0.70 / 0.45 | 卖出风险分 **< 0.30** 降级为持有 | 高 |

`risk_bands.high` 和买入降级阈值是不同概念：前者用于把逐股 `risk_score` 标成低/中/高，后者只在引擎明确给出“买入”时应用。因此保守档分数 `0.40` 已是高风险，但不会因护栏单独改写动作；保守档“买入”在分数严格大于 `0.50` 时才改为“持有”。同样，稳健档的高风险分界是 `0.50`，买入护栏却是严格大于 `0.65`。

## 确定性规则

`calibrate_stock_decision()` 只在风险分可以转换为数值且动作与当前画像的护栏直接冲突时改写结果；其他动作与缺失/非法风险分保持引擎原样。发生校准时，它把说明附加到 `signal.reasoning` 并返回 `calibrated=True`：

- 保守型与稳健型：动作是“买入”且风险分超过各自 `buy_risk_score_max`，改为“持有”。
- 进取型：动作是“卖出”且风险分低于 `sell_risk_score_min`，视为弱卖出并改为“持有”。

逐股风险等级由 `risk_level_for()` 按 `high`、再按 `medium` 阈值计算；`None` 返回 `—`。市场简报按机会点风险等级过滤，保守型只保留低/中风险项；进取型把高风险项排在前面。

## 如何推断画像（KYC 问卷）

> 产品壳 `#/kyc` 页面提供「问卷推断 → 滑块微调 → 语音速答」三条路，把用户风险偏好落地为 `preferences.risk_profile`（即上方三档画像）。KYC 不另造平行系统——推断结果就是现有体系的单一事实源。

### 数据模型（`preferences.json`）

```jsonc
{
  "risk_profile": "balanced",        // 当前生效画像（KYC 写入，兼容全部下游）
  "kyc": {
    "status": "completed",           // not_started | completed | adjusted
    "completed_at": "2026-08-21T02:19:44+00:00",
    "method": "questionnaire",       // questionnaire | voice
    "version": 1,
    "score": 24,                     // 问卷原始总分（quick 满分 15 / full 满分 40）
    "inferred_profile": "balanced",  // 问卷/语音推断画像（不被手动微调污染）
    "answers": [{"qid": "horizon", "label": "1-3年", "score": 3}],
    "manual_adjust": {               // 滑块微调记录；空/缺省表示未微调
      "risk_tolerance": 0.6,
      "horizon_years": 3,
      "note": "滑块微调"
    },
    "voice_source": null             // 语音作答时存的原始转写文本
  },
  "last_profile": "conservative"     // 上次画像（UI 展示「从 X 改为 Y」）
}
```

**推断 vs 生效语义**：
- `risk_profile` = 当前**生效**画像（问卷/滑块/手动设置都会写它），下游全链路读它。
- `kyc.inferred_profile` = 问卷**推断**画像，滑块微调不写它，保证「微调过后的原始推断」可回溯。
- `POST /risk_profile`（手动设置）也不动 `kyc.inferred_profile`，避免问卷推断被无意识覆盖。

### 计分映射（`adapter/kyc.py`）

- **quick**（3 题，满分 15）：`horizon`（期限）/ `loss_tolerance`（最大回撤）/ `goal`（目标）
- **full**（8 题，满分 40）：quick 3 题 + `income_stability` / `experience` / `drawdown_reaction` / `knowledge` / `product_pref`
- 每题 5 选项，得分 1~5（越高越进取）；阈值按满分等比折算：

| 画像 | full（满分 40） | quick（满分 15） |
|---|---|---|
| 保守型 | 1–18 | 1–7 |
| 稳健型 | 19–29 | 8–11 |
| 进取型 | 30–40 | 12–15 |

- 滑块微调 `apply_manual_adjust`：`idx = round(2 × risk_tolerance)`（0=保守 / 0.5=稳健 / 1=进取），`horizon_years` 作辅助约束——期限 <2 年最多到稳健，≥5 年至少稳健。
- 语音/文本解析 `parse_preferences_to_answers`：有 `DEEPSEEK_API_KEY` 走 LLM（`llm.summarize(..., response_format="json_object")` 输出 `{qid: label}`），失败/不可用降级到中文关键词规则。双路径保证始终可用。

### `/kyc/*` 端点

| 端点 | 说明 |
|---|---|
| `GET /kyc/profile` | 现状（状态/推断/生效/得分/微调）+ 题组 schema + 阈值 + 各档护栏，前端唯一事实源 |
| `POST /kyc/questionnaire` | 提交答案 → 计分 → 写 `preferences.kyc`（全新记录，清空此前微调）+ `risk_profile` |
| `POST /kyc/adjust` | 滑块微调 → 更新 `risk_profile`，保留 `inferred_profile`；未完成问卷返回 409 |
| `POST /kyc/parse` | 整段自然语言 → 结构化 answers（LLM + 关键词降级） |

> 重做问卷 = 全新推断（清空手动微调）；「恢复问卷推断」即用已存答案重跑问卷。

## 如何设置

优先级为：调用参数 > 持久化设置 > `.env` 的 `RISK_PROFILE` > `balanced`。

## Python 后端实现

- `adapter/risk_profiles.py`：画像表、风险分档与确定性校准。
- `adapter/engine_bridge.py`：将画像注入引擎并校准输出。
- `adapter/holdings_runner.py`：风险预算与调仓建议。
- `adapter/brief_engine.py`：机会点分级和简报提示词。
- `adapter/app.py`：`GET/POST /risk_profile` API。

宿主侧工具和呈现源码位于 [frontend/packages/investment-research/stock-analysis](../../../frontend/packages/investment-research/stock-analysis)，并消费该 API；它不改变 Python 后端中的画像规则。

`dsh electron --profile investment-research` 是**阶段二交付，当前阶段尚未启用**。当前可通过 Python API 的 `risk_profile` 参数和端点验证全部行为。
