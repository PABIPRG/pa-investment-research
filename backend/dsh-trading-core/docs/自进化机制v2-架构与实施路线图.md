# 自进化机制 v2 —— 架构与实施路线图（评审稿）

> 范围：把「策略参数微扰」进化升级为「基因座开放 + 多维适应度 + 有性繁殖 + 种群治理 + regime 自适应 + 上游反馈」的进化程序。
> 状态：**评审稿**。评审通过后再按 P0 起步编码（本路线图为 P0–P6 各阶段的验收基线）。

## 0. 背景与要解决的本质问题

现机制（`adapter/evolution.py`）把进化对象限定为「同构技术规则的参数小步扰动」，且只判绝对净值。把每条策略看作一条基因，当前弱点对应基因学缺陷：

| 你指出的弱点 | 现在的代码事实 | 本质缺陷 |
|---|---|---|
| 变体 b0/b1 只继承母体 3 票+同 kind，仅 n/超卖线挪几格 | `_mutate_params`（[evolution.py:469](adapter/evolution.py#L469)）只做小步长邻域扰动；`_mutate_symbols`(:499) **从不引入新标的**，只把母体 symbols 子集化到 `symbols[:2]` | 基因座没打开 —— 只进化「参数是多少」，不进化「策略是什么」；影子盘里同生态位克隆，高度相关、同涨同跌 |
| 1.03 是对自身 10 万本金的绝对净值，不扣 beta | `attribution`(:379)/`_per_strategy_decisions`(:586) 用 `return_pct = nav − 1.0`，无任何指数/板块基准对照 | 判「赚不赚钱」，没判「是本事还是行情」 |
| 单亲无性变异 | `_per_strategy_decisions` 只会从一个升级 parent 变异出子代 | 无 recombination，永远够不到参数变异碰不着的空间 |
| 只有破 0.90 才退役 | 淘汰/降级只看 `evolve_retire_nav/demote_nav` 绝对线；无停滞、无生态位去重、无存档 | 没有种群级治理，克隆膨胀 + 平庸占槽 |
| 无「环境 vs 能力」区分 | 全库无 regime/市场状态概念（探查确认 0 命中） | 环境不配合会被误判为能力不行，一退永退 |
| 进化结果不回传假设生成 | `generate_hypotheses`（[strategies.py:874](adapter/strategies.py#L874)）无状态，只看当批事件 | 下游单机刷，上游不协同进化 |

**核心命题**：把进化的基本单位从 `kind+params+symbols` 的平铺记录，升级为带**因子座 / 生态位 / 标的池作用域 / regime 开关基因 / 归因注释**的「基因组」，并配一套**多维适应度 + 扩展证据落库**。所有 6 点共用这个底座。

## 1. 现状事实核对（三路探查确认，行号为当下 HEAD）

关键存取件与函数锚点（`backend/dsh-trading-core/adapter/` 下）：
- **策略记录**：`strategies` collection。字段 `id,name,kind,params,symbols[],direction,source,source_event_id,generation,mutated_from,status,verification_status,backtest,evolve`。`kind∈{ma_cross,rsi_reversal,momentum,breakout,bollinger,volume_breakout}` 全部纯多头。
- **生命周期 vs 证据是两个正交轴**：`status`（candidate/active/watch/retired/rejected）与 `verification_status`（insufficient/not_passed/passed）。**candidate→active 发生在首次回测完成时**（[strategies.py:147](adapter/strategies.py#L147) `_persist_strategy_backtest`），不看通过与否。
- **影子账本**：`shadows/trades:{sid}` 是**最强的按标的归因种子** —— 每条平仓 `{symbol, entry_date, exit_date, entry_price, exit_price, ret_pct}`（[shadow.py:84](adapter/shadow.py#L84)），可按 symbol 聚合出笔数/胜率/累计/持有期。
- **影子净值**：`shadow_equity/{date}` 存 `overall_nav` + 每策略 `nav` + `per_symbol` 点快照（当前持仓市价，**非历史序列**）。策略级净值序列靠读端 join 稀疏日期重建（`_shadow_series`:284 / `_per_strategy_series`:345）。
- **回测**：`StrategyBacktestRunner`（[strategies.py:1051](adapter/strategies.py#L1051)）内联纯 pandas，t+1 open 撮合，70/30 拆 in/out，聚合 `compute_summary`（[backtest_engine.py:534](adapter/backtest_engine.py#L534)）。
- **闭环调度**：`scheduler.py:_run_closed_loop_once`(:231) 每个交易日 15:35 串行：0 事件→`create_candidates`；A `ShadowRunner.run`；B `evolve_auto`；C `trigger_first_backtests`；D 摘要+`record_closed_loop_run`。
- **配置**：`adapter/config.py:83-102` 纯 env 读取（无校验）。`EVOLVE_*` 阈值：promote 1.03 / demote 0.95 / retire 0.90 / retire_closed_win 0.35 / branches 2 / cooldown_days 7 / min_days 5。
- **唯一"基准"**：`holdings_runner.py:165 _fetch_index_hist()` 只取沪深300 close，仅服务持仓 L1 报告 beta，**不进策略/影子路径**。广度数据只在 `brief_engine.py:317`（乐咕 涨停/跌停家数，盘前盘后简报）。

## 2. 目标架构：一个「基因组 + 多维适应度 + 扩展证据」模型

把进化对象显式化为基因组对象，所有点在其上操作。**策略记录仍是存储载体**，基因字段以增量键落到现有记录上（保持向后兼容，老记录字段缺省 = v1 行为），而非另起一套表。

```text
strategy genome =
  factor        { family: ∈6 kind,  params }        # 因子座；允许族内迁移（利空反弹族 rsi_reversal↔bollinger）
  scope         pool_ref = {event_type, direction}  # 「从哪类事件的历史候选股池」取标的（新增）
  symbols       [6位代码]                            # 实际标的（可超出母体、跨事件池增删）
  direction     利好|利空
  regime_gate   {allow:[trend|oscillation|high_vol], miss_mode:on_default}
                 # regime 开关基因（本期建最小检测，先默认全开、结构先落地）
  meta          {parentA,parentB?, attribution_note, archive_epoch}
```

配套**扩展证据**（追加持久化，供 fitness / 归因 / 治理）：
- `extended_backtest`：per_symbol 的 `{in_winrate,out_winrate,in_ret,out_ret,oos_ok, traded}` + 每日组合净值曲线 `[{date,nav,daily_return}]`（当前丢弃）。
- `fitness`：聚合多维打分（见 §3/P1）落库为 `evolve.fitness` 与维度分解，替代单一绝对 nav 判定。
- regime 画像：策略存活期的市场状态指纹 → 供冬眠 & 存档复活。
- 关联事实：有日期**事件账本**、按 `event_type×direction` 聚合的**同类事件标的池**、`market/` 下对齐的**基准日序列 + regime 日序列**。

## 3. 六个改进点 → 分阶段实施计划

按「共享底座优先、低绿字段先行」排序。每阶段独立可验收、可独立合入/回退，改动全部收敛在 `backend/dsh-trading-core/adapter/` + `config.py` + `tests/`。

### P0 —— 基因座 / 扩展证据 / 数据管道底座（前置，跨全部点）
**内容**
1. **基因结构落库**：`config.py` 增加新 tunable；策略记录增量加 `gene`（factor/scope/regime_gate/meta）与 `extended_backtest`、`evolve.fitness`。老记录读取时按缺省回退 v1。
2. **事件账本 + 同类事件标的池**：新 collection `events_ledger`，在 `create_candidates`（[strategies.py:994](adapter/strategies.py#L994)）写入时把事件 `{id,type,tickers,direction,date}` append（幂等）。按 `event_type×direction` 聚合出 `symbol_pools/{pool_id}`（含带日期的历史候选股）。这一步同时是 §P6 先验的统计源。
3. **基准序列接入回测/影子并按日落库**：抽 `holdings_runner._fetch_index_hist`（[holdings_runner.py:165](adapter/holdings_runner.py#L165)）为可复用模块 `adapter/benchmark.py`；`StrategyBacktestRunner._run_impl` 与 `ShadowRunner` 每个标的窗口拉对齐基准（默认沪深300，科创可加科创50两档），写入 `market/index_equity`（按 trade_date）。这也是 regime 检测的输入源。
4. **扩展证据持久化**：`_run_impl` 不再丢弃 `portfolio_equity_curve`（[strategies.py:784](adapter/strategies.py#L784)）的 `[{date,nav,daily_return}]`；`_persist_strategy_backtest`(:133) 追加 per_symbol IS/OOS 汇总进 `extended_backtest`。
5. **最小 regime 检测器**：新 `adapter/regime.py` —— 输入沪深300日序列（+可选 breadth），输出按 trade_date 的 `{regime: trend|oscillation|high_vol, 置信}` 落 `market/regime`。实现用已实现动量/波动率规则+阈值，不引重型库。挂在 `shadow_daily`/`closed_loop` 每日跑（见 P5 复用）。本期先做**分类器 + 落库 + regime_gate 字段接线（默认全开不 gate）**。
6. **基因存档**：新 collection `gene_archive`（genome + 存活期 regime 画像 + fitness profile），供 §P4 复活。

**改动文件**：`config.py`、`benchmark.py`(新)、`regime.py`(新)、`strategies.py`、`evolution.py`、`shadow.py`、`scheduler.py`、`backtest_tasks.py`。
**验收**：跑一次回测+影子后，`extended_backtest.per_symbol` 与 `market/index_equity`、`market/regime` 有按日数据；老策略记录仍可被进化读（无 `gene` 时回退 v1，全量回归测试绿）。

### P1 —— 第 2 点「升级适应度」（判本事 vs 行情）★ 低绿字段、可尽早单独收
**内容**
- **剥离板块/指数的超额**：fitness 里 `excess = nav 系列 − 对齐基准日收益`；用事件窗内该股/板块基准算超额，去掉同行涨幅（对应「牛市人人过线/熊市误杀」）。
- **相对适应度（百分位）**：`1.03/0.95` 绝对线改为「同批同期全池影子净值中位数的百分位」。熊市 0.98 全池第一也值得升。
- **可成交性惩罚**：信号→成交的可行性建模（t+1 open 是否涨停封死/跌停/停牌，需成交额 ≥ 口径×threshold，费用/滑点/best-lot）。回测与影子统一记账口径；**信号成交不动的那部分不产生纸面幻觉净值**。
- **过拟合罚分**：`in_sample` 与 `out_of_sample` 差距大的基因（如 IS 暴涨/OOS 崩）提前标记（`evolve.overfit_flag` + 警告），不等跑 5 天破 0.90 才退役。判别用 §P0 已落库的聚合 IS/OOS + per_symbol 细粒度。
- 裁决入口仍是 `_per_strategy_decisions`(:586)/`evolve_auto`，但判定输入从单一 nav 换成 fitness 元组，阈值改为多档（retire/demote 看「适配区内 excess 分位 + 可成交 + 过拟合罚」的组合）。
**验收**：造两条策略（一条纯吃大盘、一条真 alpha），用一段历史数据验证：吃大盘那条在指数上涨窗口不被 promote；真 alpha 在普跌窗不被误杀；小票成交不动者净值被扣罚。加 `tests/test_evolution_fitness.py`。

### P2 —— 第 1 点「打开基因座」（策略是什么，不只是参数多少）
**内容**
- **因子族内迁移**：`_mutate_params` 升级为「同一生态位族内迁移」。定义生态位族（首个 = **利空反弹族**：`rsi_reversal ↔ bollinger` 本就是互斥备选，赢者上输者下；利好侧 = `momentum↔breakout`）。变异子代除参数微扰，还可**换 kind 到同族备选并带默认参数**，写回 `meta.attribution_note`。
- **跨事件池符号迁移/泛化验证**：`_mutate_symbols`(:499) 不再只把母体 symbols 截短，而是从 `scope.pool_ref`（同类事件历史候选股池，§P0.2）增删标的再回测。解决「一条策略=某次事件复盘，只在那一两只票上赚过」的最大过拟合 —— 迁移验证证明「这类事件下规律可复用」，策略从「复盘」→「规律」。
- **regime 开关基因接线**（依赖 §P0.5/P5）：`regime_gate` 已可落库，本期默认全开；真正的触发门控在 P5 启用。
**改动**：`evolution.py`（`_mutate_params`/`_mutate_symbols`/新 `_mutate_factor_migration`）、`strategies.py`（`create_candidates` 或 migration 回测）、`symbol_pools`。
**验收**：由「某次利空事件 + 固定 2 票」母体，能产出一个**把 symbols 换成同池其它利空反弹历史股、kind 迁到 bollinger**的变异子代，并能回测验证「同类事件跨票复用」而非单票复盘；单测覆盖迁移约束（只准族内换 kind、只准同池换票）。

### P3 —— 第 3 点「有性繁殖 + 归因引导的有向变异」
- **重组（crossover）**：`_per_strategy_decisions` 在 promote 达标池里取**两条高 fitness parent** 交叉基因片段：A 的 factor 结构 × B 的 symbol 池（新 `crossover()`），生成带 `meta.parentA,parentB` 的子代。遗传算法 recombination 探索力 >> 纯 mutation。
- **归因引导有向变异**：用 §P0.3/扩展证据的 per-symbol 归因把「这条策略的胜率是哪几只票、哪类事件贡献的」写回 `meta.attribution_note`；下次变异朝已证有效方向微调（换掉拖累票、加码胜因票），而非盲摇骰子。以 `shadows/trades` 实时归因 + 扩展证据 per-symbol IS/OOS 双源。
**验收**：`tests/test_evolution_recombination.py`：两条不同 parent 能产出带双亲谱系且 factor×symbols 重组正确的子代；有向变异替换的标的确实是被归因拖累的标的（断言归因 topN/bottomN 选择）。

### P4 —— 第 4 点「种群治理」
- **生态位 + 相关性去重**：按 `因子族 × 标的池` 分组，同生态位只留最优；变异前查与现有 active 的影子净值序列相关，**>0.8 且更差的不允许入池**（新 `_population_governance()` / `_shadow_correlation()`）。直接堵住克隆膨胀。
- **停滞退役**：`status()`/`_per_strategy_decisions` 加「连续 N 天未刷新影子净值新高/长期平庸」检测，平庸尽早让位（新 `evolve.stagnant_days`）。
- **基因库存档与复活**：淘汰基因进 §P0.6 `gene_archive`（带 regime 画像）；当 `market/regime` 切回其擅长档时，从存档召回复测（进化版「经验保留」）。
**改动**：`evolution.py`、`gene_archive`、`scheduler`（复活探测可并入闭环）。
**验收**：造两组高相关克隆 → 只允许一组入池；构造平庸多日不创新高 → 触发 stagnation retire；存档基因在 regime 切换回匹配档时被召回为 candidate。

### P5 —— 第 5 点「运行时自适应：不退役，学冬眠」
- 策略带 regime 感知：`ShadowRunner.run`（或其选股 `_active_strategies`:158）检测 `market/regime`，当市场状态离开策略 `regime_gate.allow` 适配区时**自动停触发（1→0 空仓等待，不产生新信号）**；回到适配区再醒。
- **进化裁决只针对「在适配区里还做不好」的策略**：把「环境不配合」（regime mismatch，记录为 hibernating，不扣 fitness 不 retire）和「能力不行」（在适配区仍破线）分开。
**改动**：`shadow.py`（门控）、`evolution.py`（区分 hibernating vs fail 的裁决分支）、`regime.py`。
**验收**：注入一段 regime=high_vol/不匹配的日期 → 策略在 shadow 里空仓停触发、evolve 不因这段 net drawdown 判 fail；回归适配区自动恢复出信号。

### P6 —— 第 6 点「进化反馈到上游：让假设生成也进化」
- **先验学习回路**：定期统计「哪类事件 × 方向 × 因子族更容易过样本外」（源 = 扩展证据 OOS + `events_ledger`/存档），产出统计先验（例：`减持利空×rsi_reversal 胜率高、概念炒作动量必死`），缓存成 `priors`。
- 把先验注入 `generate_hypotheses` 的 `_HYPOTHESIS_SYSTEM`（[strategies.py:857](adapter/strategies.py#L857)）提示，让上游假设生成倾向与下游策略筛选协同进化。
**改动**：`strategies.py`（generate_hypotheses 注入先验）、新 `priors.py`（聚合+缓存）、`scheduler`（定期刷新）。
**验收**：先验内容能出现在 generate_hypotheses 的 LLM 上下文中（可开关 `PRIOR_REPLAY_ENABLED`），且来源统计与扩展证据/存档一致（单测断言字段映射）。

## 5. 最小 regime 检测器设计（本期做）

## 8. 交付顺序与估算（评审后可逐 PR 执行）

P0(底座) → P1(fitness) → P2(基因座) 是**关键路径**，三者互为依赖且都能先单收；P3/P4/P5/P6 依赖 P0，多数还依赖 P1（fitness/归因）与 P2（regime_gate）。推荐顺序：
**P0 → P1 → P2 → P3 → P4 → P5 → P6**（P0–P1 先合入并观察真实影子数日，再放 P2+）。

估算（人日，工程规模参考，非承诺）：
- P0 ≈ 5–7 天（含基准/regime/事件账本/扩展证据四条新管道 + 基因落库）。
- P1 ≈ 3–4 天（fitness 多维化 + 成交可行性 + overfit）。
- P2 ≈ 3–4 天（族内迁移 + 跨池符号迁移 + regime_gate 接线）。
- P3 ≈ 2–3 天（crossover + 归因引导）。
- P4 ≈ 2–3 天（治理三件套 + 存档/复活）。
- P5 ≈ 1–2 天（冬眠门控 + 裁决分流，依赖 P0.5 已落库）。
- P6 ≈ 2 天（先验聚合 + 注入假设 prompt）。
合计约 **18–25 天**，跨多 PR，每 PR 独立可回退。

## 9. 决策点 —— 已锁定默认值（2026-09-08 拍板）

1. **基准口径**：采用**按板块映射的两档基准**。默认沪深300；代码前缀 `688/689`（科创板）→ 科创50（`sh.000688`）。映射表集中在 `adapter/benchmark.py`，按需可扩展创业板指等。系统纯多头，超额对指数足够。
2. **成交可行性数据源**：用 **baostock 价量近似**，无新增数据商依赖；口径先粗后细。可行性模型规则：
   - 涨停封死近似：t+1 当日 `open≈high≈close` 且相对前收接近涨跌幅上限（主板10%/科创创业20%/ST 5%）→ 视为成交不动，该笔按未成交计，不产生净值。
   - 流动性：t+1 成交额 < 需求名义 × `FILL_LIQUIDITY_MIN`（默认 20）→ 降级/未成交。
   - 费用：佣金默认万2.5（最低 5 元）+ 卖出印花税 0.05% + 滑点默认 5bp，全部参数化。
   - 回测与影子共用同一 `adapter/feasibility.py`，杜绝「回测能成交、影子成交不动」漂移。
3. **每日净值曲线持久化**：`per_symbol` IS/OOS 汇总**总是**落 `strategies.{sid}.extended_backtest`；每日组合净值曲线也落同处，但受 `EVOLVE_PERSIST_CURVE`（默认 true）开关控制，且只保留最近 `EVOLVE_CURVE_KEEP_DAYS`（默认 400）——防止 `strategies.json` 单文件无限膨胀。
4. **regime_gate 默认**：结构落库阶段**全开不 gate**（`allow=all`），门控只在 P5 由 `REGIME_GATE_ENABLED`（默认 false）开启。绝不让老策略在无 regime 画像下被误禁。
5. **先验来源可信度**：P6 先验**只作倾向提示、非硬约束**，加最小样本底：仅纳入 `evaluated≥5` 的 bucket；`PRIOR_REPLAY_ENABLED`（默认 true）可随时关闭。

**实现期补充约束**：以上所有阈值均进 `adapter/config.py` env 读取并补取值范围校验；可行性口径单一实现；新增 collection 命名与 `store.py` 白名单一致。

- crossover 只挑「同一裁决批里 ≥2 条同向 promote 亲本」，暂不对高 fitness 做排序择优（P1 fitness 快照已落 `evolve.fitness`，择优选取可后续叠加强化——先落地机制不抢优化）。
- guided prune 的证据源优先 `extended_backtest.per_symbol`；老记录无该字段 → 自动跳过（回退 v1），不误裁。
- 重组/剪枝产出的子代仍是 `candidate`，须经回测验证「跨票重组/剪枝后规律是否成立」，过拟合把关归 P1/P4 已就位。

## 15. P5 实施状态（第 5 点 · 运行时自适应：不退役，学冬眠）

> 已按 P5 编码（2026-09-08）。把「环境不配合」与「能力不行」分开：策略带 regime 感知，市场离开其 `regime_gate.allow` 适配区时**自动停触发（空仓等，不产生新信号）**，回到适配区再醒；进化裁决只判「在适配区里还做不好」的策略。配套把 P4 的**存档复活**真正接进每日闭环。**默认 `EVOLVE_HIBERNATE_ENABLED` / `EVOLVE_REVIVE_ENABLED` 全关 → 行为与 v1 一致**；任一开启才引入对应自适应。

### 15.1 已落地
| P5 子项 | 落地 | 说明 |
|---|---|---|
| 冬眠门控（影子） | 新 `shadow._regime_hibernation(strategies, store, trade_date)`：当日 `market_regime` 不在策略 `gene.regime_gate.allow` → 从本次触发剔除，走既有 skipped「冬眠」语义（不产新信号、不落当日净值点） | 复用被证明安全的 skip 通路；regime unknown/无 regime → `miss_mode=on_default` 全放行（conservative） |
| 裁决分流（进化） | `_per_strategy_decisions` 判据前置「冬眠 hold」分支：当日 regime 不在适配区 → 记 `behavior=冬眠` 并整段跳过升/降/汰（不因环境判 fail） | 与影子门控同读 `read_gene(...).regime_gate.allow`，不依赖 `REGIME_GATE_ENABLED` 而独立由 `EVOLVE_HIBERNATE_ENABLED` 控制 |

### 15.2 验证
- 新增 `tests/test_evolution_hibernation.py` **11 条全绿**：`_regime_hibernation` 关/unknown 放行、不在适配区剔除、在适配区保留；进化关=照判降、开=记 冬眠 不判降、适配当下策略不误冬眠；`reactivate_archived` regime 匹配→复活 candidate、不匹配/unknown/仍在跑→不复活。

### 15.3 口径说明（诚实边界）
- 冬眠门控的**适配区由每个基因的 `regime_gate.allow` 显式声明**：默认基因 allow=全部 regime → 永不冬眠（结构保守、不开不 gate）。只有当某策略（含存档基因）被显式标成"只擅长某几档"后，门控才对它生效。
- 进化"冬眠≠判 fail"是**整段跳过判定**：休眠中的策略既不升也不降不汰，直到 regime 回到其适配区由下一次闭环自然恢复出信号。
- 影子层冬眠通过"该策略当日不进净值快照"实现：其净值序列在休眠窗口出现**日期间断**。归因/相关性按存在的点做交集、停滞判据要求连续样本且样本不足时保守不裁，故日期间断不会误触发（governance 边界已处理）。
- 复活产出的 `revive-*` 是**新 candidate**（原 sid 通常仍为 retired 老记录），需经首测验证；这与"旧经验复活重验"的产品语义一致，避免用旧回测结果直接复活。

### 16.3 口径说明（诚实边界）
- 先验目前**只回注假设生成的 kind/方向倾向，不构成下游任何硬约束**：假设仍由 LLM 按事件语义挑选 kind，先验只是"参考倾向"（标『优』多考虑、标『慎』谨慎并写清 rationale）。样本稀少时先验甚至不出现（`min_trials` 之下不报），从设计上避免"少样本冷启动偏见"压过单次事件本身。
- 统计源是**策略回测的 OOS 过验结论**（`verification_status`/`oos.win_rate`），不是影子实时净值——先验反映"这类策略历史上过不过验证"，与 P6 路线图"来源统计与扩展证据一致"的口径一致。
- 桶键用**因子族**而非单个 kind：动量族 = momentum+breakout、利空反弹族 = rsi_reversal+bollinger，P2/P3 的族内迁移让同族共享一条先验，避免拆到 kind 后样本被稀释到几乎不可用。单例 kind（ma_cross/volume_breakout）回落自身。
- `PRIOR_REPLAY_ENABLED` 独立于 `REGIME_GATE` / `EVOLVE_*`：只动假设生成的上游文本，不改任何下游裁决，故可安全热开关，与其余 v2 能力正交。
