# macOS 同花顺持仓同步

从研究工作台的持仓明细进入“从券商同步持仓”。首次默认模拟操盘，后续记住已保存的选择。模拟路径为“交易 → 模拟 → 股票 → 持仓”，真实路径为“交易 → A股 → 股票 → 持仓”。

未安装时使用[同花顺 Mac 官方下载页](https://download.10jqka.com.cn/free/mac/)，自行安装并登录。随时可返回持仓明细进行单条录入或批量导入。

## 读取权限

1. 打开“系统设置 → 隐私与安全性 → 辅助功能”。Electron 提供直接打开按钮；Web 需自行打开。
2. 开启实际读取进程的权限。正式宿主可能显示投研智能体；源码运行时可能显示 Python 或启动终端。未在列表中出现时通过“+”添加实际应用。
3. 授权后完全退出并重新打开投研智能体。Web 可返回后点击“重新检查”。不会持续轮询或循环弹出权限提示。

默认使用 PyObjC 的 AXUIElement，先读取当前辅助功能树，不要求自动化权限，也不会模拟鼠标。开始读取前应先在同花顺手动打开目标持仓页并保持窗口可见；当前页已经就绪时会直接返回预览，不切换页面。只有当前页无法确认时，才会在用户授权后尝试按固定路径切换；超时后停止，不以不完整结果覆盖持仓。

产品授权与 macOS 系统权限是两层独立授权。产品内可选择“每次询问”或“长期允许主动读取”；长期授权只在用户点击读取时免除重复弹窗，不会开启定时或后台同步，并可在设置中手动关闭。macOS 系统的辅助功能或自动化授权仍由系统设置管理。

## 前台与数据确认

macOS Electron 不执行定时或后台自动同步，只在用户主动点击后读取。界面会先提示用户打开对应持仓页；点击“我已打开，开始读取”后，应用先读取当前页面。若无法确认所选账户和完整持仓表格，Electron 才说明可能发生的短暂窗口切换，取得产品授权后尝试按固定路径导航。每一次 `AXPress` 后都会重新遍历当前可见窗口；只有所选账户与目标持仓表格出现在同一窗口时，才把页面切换视为成功。多个同名入口、验证码、登录/解锁、协议或风险提示会中止自动点击并返回具体原因。成功、失败或取消都尽力返回；取消会停止 AX 遍历和 AppleScript 降级进程，不保存持仓或预览。

批量导入支持 CSV、TSV、TXT、同花顺导出的旧版 Excel `.xls` 和 `.xlsx`。工作簿只读取首个工作表，并在前 20 个非空行中识别股票代码、数量和成本价表头；标题与导出时间等说明行会自动跳过。所有文件仍先展示预览，确认后才替换本地持仓。

Windows 继续使用独立的 easytrader 实现；本指南和本轮验证只覆盖 macOS，不代表 Windows 不受支持，也不以 macOS 环境声称完成 Windows 回归。

成功读取持仓后立即展示预览，包含账户、来源、读取时间、当前与新条数，以及股票代码、持仓数量、成本价。持仓同步不进入历史成交页，避免成交页导航或查询范围拖延持仓预览；没有成交明细时使用读取时间兜底，用户可在预览中修改。已有成交明细仍按券商成交时间归因，来源分别记录为 `broker_detail`、`read_fallback` 或 `user_modified`。用户修改的时间不会被后续无明细读取静默覆盖；成交明细由对应功能单独读取，不阻塞持仓同步。

五分钟内点击“确认替换”并通过原生确认才保存快照。Renderer 只持有不透明会话标识，后端预览 token 不下发。空持仓、必填字段缺失、账户或数据源变化、本地持仓已被其他操作修改、过期、取消或已使用的预览均不能覆盖当前数据。仅成交明细未完成时，在明确显示读取时间兜底后仍允许用户主动确认；业务内容与账户来源均未变化时不创建重复快照。

## 开发与验证限制

源码环境需安装 requirements 中的 macOS PyObjC 依赖，权限必须属于真正的读取进程，不能以 Electron 自身的权限推断 Python 已获授权。同花顺版本可能不暴露可确认的账户选中状态或表格，遇到这种情况会拒绝伪装成完成导航；持仓表一旦验证成功则立即进入预览。自动化测试不能证明真实客户端兼容性；发行前需在签名宿主上验收权限归属、真实 AX 标签、逐步导航、同窗口账户/表格验证、失败返回以及真实/模拟账户隔离。
