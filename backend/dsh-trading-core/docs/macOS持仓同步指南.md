# macOS 持仓同步指南

> 从同花顺 Mac 版一键读取真实或模拟账户持仓，覆盖本地持仓并重算组合风险。

## 前提

| # | 条件 | 说明 |
|---|------|------|
| 1 | macOS | 本功能仅支持 macOS（Windows 用户请用 easytrader 通道） |
| 2 | 同花顺 Mac 版 | 从 [同花顺官网](https://www.10jqka.com.cn/) 下载安装，拖入 `/Applications` |
| 3 | 券商交易账号 | 在同花顺 Mac 版中登录你的券商交易账号（不是行情账号） |
| 4 | 自动化与辅助功能授权 | 两项均为一次性操作，见下文 §授权 |

同花顺 Mac 版内置 80+ 券商的登录入口，包括平安证券、国金证券、银河证券、中信证券、广发证券等。**你不需要安装券商自己的 Mac 客户端**，在同花顺里选你的券商登录即可。

> ⚠️ 部分券商在同花顺 Mac 版上只有行情权限、没有交易权限。此时点「交易」会失败，应用会提示具体原因。如遇此情况，请改用「导入持仓」手动维护。

## 一、授权自动化与辅助功能

macOS 出于安全考虑，分别控制“发送 Apple 事件”和“操控界面元素”两类能力。读取同花顺持仓需要通过 AppleScript 调用 System Events，因此自动化与辅助功能两项权限都可能被系统拦截。

### 打包版（.app）

1. 打开 **系统设置 → 隐私与安全性 → 自动化**，允许“投研智能体”控制 **System Events**
2. 打开 **系统设置 → 隐私与安全性 → 辅助功能**
3. 点击左下角 **＋**，找到并添加 `/Applications/投研智能体.app`，确保开关为 **开**
4. **重启投研智能体**

### 开发版（从终端跑源码）

1. 打开 **系统设置 → 隐私与安全性 → 自动化**，允许实际启动服务的应用（Codex、Terminal.app、iTerm、Warp 等）控制 **System Events**
2. 打开 **系统设置 → 隐私与安全性 → 辅助功能**
3. 点击左下角 **＋**，添加同一个启动应用，确保开关为 **开**
4. **重启该应用并重新启动投研服务**

> 授权后如果不重启，辅助功能权限不会对已在运行的进程生效——这是 macOS 的行为，不是应用的限制。

### 授权失败的典型症状

| 现象 | 原因 | 解决 |
|------|------|------|
| 报「未获得授权将 Apple 事件发送给 System Events」或 `-1743` | 自动化未授权 | 在“自动化”中允许启动应用控制 System Events，然后重启 |
| 报「not allowed assistive access」或 `-25211` | 辅助功能未授权 | 在“辅助功能”中勾选启动应用，然后重启 |
| 同花顺已切换了部分页面但同步仍失败 | AppleScript 在权限错误发生前完成了部分动作 | 按错误中指出的具体权限入口授权；页面已跳转不代表表格读取完成 |

## 二、配置持仓数据源

在“设置 → 持仓数据源”或持仓弹窗的“从券商同步持仓”面板中选择“同花顺（macOS）”。切换会立即用于当前窗口并保存到用户配置，后续启动会继续使用同一数据源。

### 开发版（从源码运行）

源码调试也可以在 `backend/dsh-trading-core/` 目录下创建或编辑 `.env` 文件：

```env
HOLDINGS_PROVIDER=mac_ths
HOLDINGS_ACCOUNT_MODE=real    # real=真实操盘，simulated=模拟操盘
```

可选配置项（一般不需要改）：

```env
MAC_THS_APP_NAME=同花顺    # 同花顺的进程名，留空即默认「同花顺」
MAC_THS_TIMEOUT=60         # 读取超时秒数，默认 60
```

然后正常启动后端即可：

```bash
cd backend/dsh-trading-core
./init.sh
./start.sh
```

### 打包版（.app）

直接双击启动应用，然后通过应用内的数据源选择器切换即可，不需要从终端传入 `HOLDINGS_PROVIDER`。应用把选择保存到投研状态目录下的 `user-config/backend.env`，并在每次启动时优先于项目 `.env` 加载；终端显式传入的环境变量仍保持最高优先级。

## 三、同步持仓

1. 打开**同花顺 Mac 版**，确认真实券商账号或模拟账户已经登录
2. 打开投研智能体，进入**研究工作台**
3. 点击持仓区域的 **「持仓数量」** → 打开「持仓明细」
4. 点击 **「从券商同步持仓」**
5. 在“操盘账户”中选择 **真实操盘** 或 **模拟操盘**
6. 等待检测完成：数据源应显示为 **可用**
7. 点击 **「同步真实持仓」** 或 **「同步模拟持仓」**

系统会自动进入“交易 → A股/模拟 → 股票 → 持仓”。同步成功后，持仓明细会刷新为所选账户的持仓，组合风险指标自动重算。

### 同步面板各区域说明

| 区域 | 含义 |
|------|------|
| 数据源 / 状态 | 当前 `HOLDINGS_PROVIDER` 配置与可用性；不可用时会给出中文原因 |
| 本机券商客户端 | 检测到的同花顺 Mac 版（路径、运行状态） |
| 重新检测 | 修改配置或重启同花顺后点此刷新 |
| 操盘账户 | 明确选择真实账户或同花顺模拟账户；选择会立即保存 |
| 同步真实/模拟持仓 | 一键读取所选账户并覆盖本地持仓 |

> 同步会**整体替换**本地已保存的持仓，不是追加。模拟持仓与真实持仓会使用不同的快照来源标记，但不会同时保留两套活动组合。

## 四、常见问题

### 「同花顺 Mac 版未运行」

同花顺没有启动，或者启动了但还没登录。请先打开同花顺并登录券商交易账号，然后点「重新检测」。

### 「无法切换到「交易 → A股/模拟 → 股票 → 持仓」」

先按错误信息排除自动化或辅助功能权限。如果权限完整，说明交易模块的界面布局与脚本预期不符；请手动进入所选账户的持仓页并重试。

### 「未在交易窗口找到持仓表格」

同花顺版本更新后，持仓表格的控件位置可能变化。请确认：
- 同花顺窗口确实停在持仓页，且能看到表格
- 表格第一行（表头）包含「代码」字样

如果确认能看到持仓表格但仍然报此错误，说明同花顺版本的控件结构已变化，需要更新 `mac_ths.py` 中的 AppleScript 常量。请将同花顺版本号和此错误信息反馈给开发者。

### 「macOS 拒绝脚本控制 System Events」

根据错误中的 `-1743` 或 `-25211` 分别处理自动化或辅助功能权限，并重启实际启动服务的应用。

### 读取超时

默认 60 秒超时。如果同花顺被弹窗（验证码、公告、升级提示）阻塞，脚本无法继续操作。请关闭弹窗后重试。如需更长超时，设置环境变量 `MAC_THS_TIMEOUT=120`。

### 空持仓 / 拒绝同步

如果券商端确实没有持仓（空仓），同步会被拒绝——这是保护机制，防止「窗口没停在持仓页」被误判为空仓而清空本地数据。如果确实是空仓，请通过「导入持仓」手动清空。

## 五、技术说明

### 工作原理

投研智能体通过 macOS 自带的 `osascript` 执行一段 AppleScript，利用 System Events 辅助功能 API 遍历同花顺的 Cocoa 控件树，按账户类型模拟点击「交易 → A股/模拟 → 股票 → 持仓」，然后读取持仓表格的文本内容。输出以 TAB/换行分隔传回 Python 后端，按表头名映射列后生成持仓记录。

这与 Windows 上 easytrader + pywinauto 做的事等价：都是 GUI 自动化读取客户端界面。

### 为什么不直接支持券商自己的 Mac 客户端

每家券商的 Mac 客户端 UI 结构不同，AppleScript 的控件路径是跟具体应用绑定的。同花顺 Mac 版作为 80+ 券商的通用交易入口，只需要适配一次控件路径就能覆盖所有券商。如果要支持平安证券 Mac 版、银河证券 Mac 版等，每个都需要单独写一套控件路径，维护成本很高。

### 已知局限

- **GUI 自动化天然脆性**：同花顺版本更新可能导致控件路径失效，与 Windows 侧 easytrader 同源风险
- **完整表格读取仍需权限后实测**：macOS 真机已经验证客户端可启动并发生部分页面跳转；当前开发进程缺少自动化授权，尚未完成真实与模拟表格的端到端读取
- **显式环境变量优先**：从终端传入 `HOLDINGS_PROVIDER` 时，该值会在下次启动时优先于应用内保存值；普通用户直接使用应用内切换即可
- **macOS 不做磁盘扫描**：检测只认同花顺 Mac 版这一个客户端，不会递归搜索磁盘
