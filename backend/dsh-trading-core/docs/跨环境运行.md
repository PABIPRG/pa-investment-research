# 跨环境运行指南

> 面向：后端/运维/前端同学在自己机器或服务器上把 dsh-trading-core 跑起来。
> 覆盖：环境要求、本地开发（Win/Mac/Linux）、生产部署、`.env` 配置全表、数据源、网络/代理、常见坑。

---

## 1. 环境要求

| 组件 | 版本 | 说明 |
|---|---|---|
| Python | **≥ 3.10**（实测 3.12.4） | 低于 3.10 会装不上部分新版依赖 |
| Node.js | ≥ 18（实测 24） | 仅 dsh Web UI 需要；纯调适配器不需要 Node |
| npm / npx | 随 Node | dsh 通过 `npx @deepseek-ai/dsh` 拉取 |
| pnpm | ≥ 8 | 仅从 `frontend/` 源码构建 dsh 时需要（一般用不上） |
| 网络 | 需能访问 `api.deepseek.com` | LLM 必需 |
| 网络 | 需能直连国内行情站 | akshare/baostock 数据源（详见 §6） |
| 磁盘 | ≥ 2GB | pip 依赖 + 行情缓存 |

**两个服务的端口**：适配器 `8000`，dsh Web UI `3080`。启动前先确认端口未被占用。

## 2. 目录结构速览

```
dsh-trading-core/
├── adapter/            # FastAPI 无状态服务（接口全在 app.py，见 API-接口文档.md）
├── tradingagents/      # TradingAgents-CN 引擎核心（多智能体）
├── dsh-plugin/         # dsh TypeScript 插件（9 工具 + SSE 客户端 + 渲染）
├── config/             # 引擎配置（models/pricing/logging/settings）
├── docs/               # 本文档 + 风险偏好框架 + 集成设计
├── data/adapter/       # 运行时 JSON 存储（watchlist/holdings/preferences/briefs）
├── data/tushare/       # tushare 缓存（如启用）
├── env/                # Python venv（gitignore）
├── start_all.bat       # Windows 一键启动（适配器 + dsh UI）
└── requirements.txt / .env.example / .env
```

## 3. 本地开发（三步）

### 3.1 装依赖

```bash
cd dsh-trading-core
python -m venv env                              # 建议 Python 3.10+
# Windows
env\Scripts\python.exe -m pip install -r requirements.txt
# macOS / Linux
env/bin/python -m pip install -r requirements.txt
```

> 国内网络可加清华镜像加速：`-i https://pypi.tuna.tsinghua.edu.cn/simple`。
> Windows 注意：`python3` 可能是 Microsoft Store 的 shim（`-m venv` 会无输出退出），请用真实解释器全路径（如 `C:\...\Python312\python.exe -m venv env`）。

### 3.2 配置 .env

```bash
cp .env.example .env      # 然后按 §5 填写
```

最低必要配置：`DEEPSEEK_API_KEY`（必填，否则分析/简报无法用 LLM）。其余都有默认值。

### 3.3 启动两个服务

```bash
# 终端 1：适配器（engine 模式）
env/Scripts/python.exe -m uvicorn adapter.app:app --host 127.0.0.1 --port 8000 --log-level warning
#   Windows 建议同时设置：ADAPTER_RUNNER=engine PYTHONIOENCODING=utf-8 PYTHONUTF8=1

# 终端 2：dsh Web UI（带插件，可选）
# ⚠️ 必须从一个"没有 .env 的目录"启动（见 §7 坑 #2）
cd /tmp/dsh-run  # 任意空目录
npx @deepseek-ai/dsh web --patch "<绝对路径>/dsh-plugin/cordis.yml"
```

验证：
- 适配器：`curl http://127.0.0.1:8000/health` → `{"status":"ok",...}`
- dsh UI：浏览器打开 `http://127.0.0.1:3080`，Settings→Models 里填 DeepSeek API Key 后即可对话
- 插件冒烟：`cd dsh-plugin && npm install && npx tsx test/plugin-load.smoke.ts`（9 工具注册即通过）

## 4. 生产部署

适配器是无状态 HTTP 服务，dsh 是可选 UI。**只部署引擎能力，则只需部署适配器**。

### 4.1 方案 A：systemd（Linux）

```ini
# /etc/systemd/system/dsh-adapter.service
[Unit]
Description=dsh-trading-core adapter
After=network.target

[Service]
WorkingDirectory=/opt/dsh-trading-core
Environment=ADAPTER_RUNNER=engine
Environment=PYTHONUNBUFFERED=1
ExecStart=/opt/dsh-trading-core/env/bin/python -m uvicorn adapter.app:app --host 127.0.0.1 --port 8000 --log-level warning
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
systemctl daemon-reload && systemctl enable --now dsh-adapter
```

### 4.2 方案 B：Docker（建议自写 Dockerfile，官方未提供镜像）

```dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
COPY . .
EXPOSE 8000
# 运行时挂载 .env 与 data/ 卷
CMD ["env/bin/python", "-m", "uvicorn", "adapter.app:app", "--host", "0.0.0.0", "--port", "8000"]
```

> 注意：**不推荐**把 akshare 行情服务容器化时禁用网络（需直连国内行情站）；容器内需保证 `NO_PROXY` 生效。

### 4.3 对外暴露（必读）

适配器**无鉴权、CORS 全开**，仅应监听 `127.0.0.1`。对外提供时在前面套：
- 反向代理（Nginx/Caddy）+ API 网关鉴权（Token / Basic Auth）
- HTTPS
- 若容器内 `--host 0.0.0.0`，务必只在受信内网使用

## 5. .env 配置全表

| 配置项 | 默认 | 说明 |
|---|---|---|
| `DEEPSEEK_API_KEY` | 必填 | DeepSeek API Key（分析引擎 + 简报 LLM 都用） |
| `DEEPSEEK_BASE_URL` | `https://api.deepseek.com` | DeepSeek 端点（自建代理/网关时改） |
| `DEEPSEEK_ENABLED` | `true` | 是否启用 DeepSeek 引擎 provider |
| `OPENAI_API_KEY` | 同 DEEPSEEK | 引擎侧 openai 兼容端点（engine_bridge 会显式覆盖为 DeepSeek） |
| `RISK_PROFILE` | `balanced` | 全局默认风险偏好（conservative/balanced/aggressive） |
| `DEFAULT_CHINA_DATA_SOURCE` | `akshare` | A 股数据源：`akshare` / `baostock` / `tushare` |
| `TUSHARE_TOKEN` | 空 | tushare 数据源所需 token（可选） |
| `NO_PROXY` | 见模板 | 国内行情站直连白名单（eastmoney/sina/baostock 等） |
| `MEMORY_ENABLED` | `true` | 引擎记忆（本项目引擎侧实际置 `use_memory=false`） |
| `TA_CACHE_STRATEGY` | `file` | 缓存策略：`file`（本项目用）/ `integrated`（需 pymongo/redis） |
| `USE_MONGODB_STORAGE` | `false` | 保持 `false`，本项目固定 JSON 文件存储 |
| `HOLDINGS_PROVIDER` | `manual` | 持仓数据源：`manual` / `joinquant`（演示）/ `qmt`（预留） |
| `BRIEF_LLM_MODEL` | `deepseek-chat` | 简报 LLM 模型 |
| `BRIEF_PUSH_ENABLED` | `false` | 是否启用外部推送（企业微信/Server酱） |
| `BRIEF_PUSH_CHANNELS` | 空 | 逗号分隔：`serverchan` / `wecom` |
| `SERVERCHAN_SENDKEY` | 空 | Server酱 SendKey |
| `WECOM_WEBHOOK_KEY` | 空 | 企业微信 webhook key |
| `BRIEF_SCHEDULE_ENABLED` | `false` | 是否启用定时盘前/盘后简报 |
| `BRIEF_PRE_MARKET_TIME` | `08:50` | 盘前简报触发时间 |
| `BRIEF_POST_MARKET_TIME` | `15:30` | 盘后简报触发时间 |
| `ADAPTER_RUNNER` | `engine` | `engine`（真引擎）/ `fake`（假任务，联调用） |
| `TIMEZONE` | `Asia/Shanghai` | 调度时区 |

> `.env` 只被**适配器**（Python）读取；dsh Web UI 请勿放在含 `.env` 的目录下运行（见 §7 坑 #2）。

## 6. 网络与数据源

### 6.1 两层网络需求

| 方向 | 目标 | 说明 |
|---|---|---|
| LLM | `api.deepseek.com` | 分析引擎与简报生成必需；若走系统代理，确保代理可用 |
| A 股行情 | 国内行情站（东财/新浪/baostock） | 部分站点会被科学上网代理干扰（`push2.eastmoney.com` 直连被墙） |

### 6.2 NO_PROXY 的作用

`.env` 里 `NO_PROXY` 已列出国内行情站（`eastmoney.com`、`sinaimg.cn`、`baostock.com` 等）。
适配器通过 `load_dotenv(override=True)` 注入这些环境变量，**国内数据请求绕过系统代理走直连**。
如果你的系统代理全局开启，**不要**动这个白名单——否则行情拉取会失败（任务 `failed`）。

### 6.3 数据源选型

- **akshare**（默认）：覆盖广；`py_mini_racer` V8 引擎**并发会崩**，`/brief` 必须串行
- **baostock**：socket 稳定、与引擎数据源一致；持仓/简报的逐股历史行情用它（带锁串行）
- **tushare**：需 `TUSHARE_TOKEN`；部分数据源可选

> 引擎侧 `data_source_manager` 按 `DEFAULT_CHINA_DATA_SOURCE` 选 provider；切换后建议清空 `data/tushare/` 缓存重新验证。

## 7. 常见坑（已踩）

1. **`python3` 是 Microsoft Store shim（Windows）**：`-m venv` 无输出退出（exit 49）。用真实解释器全路径。
2. **dsh 拒绝加载含 `.env` 的目录**：新版 `@deepseek-ai/dsh` 扫描 cwd 的 `.env`，遇 `DEEPSEEK_BASE_URL` 直接报错退出（"which only the launching environment may set"）。**解决方案：从一个没有 `.env` 的空目录启动 dsh**，用 `--patch` 绝对路径指向插件。
3. **`cordis.yml` 路径硬编码**：插件入口是 `file:///C:/Users/%E5%BE%90%E8%AF%97%E9%9D%96/...`（中文用户名需 URL 编码）。**移动项目后必须改** `dsh-plugin/cordis.yml` 里的路径。
4. **端口被旧项目占用**：本仓库与旧项目 `Desktop/tradingagentCN` 各有一套服务，都占 `8000/3080`。启动前 `netstat -ano | findstr ":8000"` 检查。
5. **单股分析很慢（3–9 分钟）**：SSE 超时给足；联调可用 `ADAPTER_RUNNER=fake`（假任务不耗 LLM/不拉行情）。
6. **`/brief` 并发崩溃**：akshare V8 引擎非线程安全，**串行调用**。
7. **首次分析失败常因行情网络**：检查 `NO_PROXY` 是否被覆盖、行情站是否可达；`holdings` 数据源行业分类 best-effort（失败标"未知"，不影响主体）。
8. **dsh 与适配器是两套 LLM Key**：适配器读项目 `.env`；dsh Web UI 在 **Settings→Models** 里单独配置，两者都要填。

## 8. 快速故障排查

| 现象 | 排查 |
|---|---|
| `curl :8000/health` 不通 | 适配器没起来 / 端口被占；看启动日志（`--log-level info` 更详细） |
| 分析任务 `failed` | `GET /analyze/{id}` 的 `error` 字段；多半是行情网络或 LLM 调用失败 |
| dsh 起不来报 `.env` 错误 | 见 §7 坑 #2，换无 `.env` 目录启动 |
| 插件工具不出现 | `npx tsx test/plugin-load.smoke.ts` 验证插件本身；检查 `cordis.yml` 路径 |
| 简报生成失败 | 多为单数据源拉取异常（日志 WARNING）；LLM 失败会自动降级模板，简报仍可用 |
| 推不到微信 | 检查 `BRIEF_PUSH_ENABLED`、`BRIEF_PUSH_CHANNELS`、`SERVERCHAN_SENDKEY` / `WECOM_WEBHOOK_KEY` |
