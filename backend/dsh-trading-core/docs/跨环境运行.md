# 跨环境运行指南

> 本文档只描述 `dsh-trading-core` Python API 在 Windows、macOS 和 Linux 上的初始化、运行和部署。

## 要求

- Python 3.10 或更新版本
- 可访问所需的 LLM 和行情服务（engine 模式）
- 本地端口 `8000`

本后端目录不包含 Node、npm、Cordis 或产品生命周期管理。

## 本地运行

```sh
cd backend/dsh-trading-core
./init.sh
cp .env.example .env
./start.sh                 # 默认 ADAPTER_RUNNER=engine
ADAPTER_RUNNER=fake ./start.sh
./verify.sh
```

Windows 使用 `init.bat`、`start_all.bat [fake|engine]` 和 `verify.bat`。服务命令为 `uvicorn adapter.app:app --host 127.0.0.1 --port 8000`；启动日志位于 `logs/adapter.log`。

停止脚本仅按 `8000` 停止手工启动的 Python 服务。它不是阶段二 Runtime 的 PID 或端口所有权实现；阶段二只会停止它自己创建的子进程。

## 配置、网络与数据源

从 `.env.example` 创建 `.env`，为 engine 模式设置 `DEEPSEEK_API_KEY`。`ADAPTER_RUNNER=engine|fake` 控制真实引擎或确定性假任务。生产部署时使用任意 Python 进程管理器运行同一 uvicorn 命令，并把 `.env` 与 `data/` 作为运行时配置和数据处理。

`DEFAULT_CHINA_DATA_SOURCE` 可选 `akshare`、`baostock` 或 `tushare`（后者需要 `TUSHARE_TOKEN`）。默认 `akshare` 覆盖面较广；baostock 可用于相应行情路径；切换数据源后应按实际数据源清理或验证缓存。`NO_PROXY` 必须保留模板中的国内行情站域名（包括 Eastmoney、Sina 和 baostock）；这些请求经系统代理常会失败，必须直连。

`/brief` 生成会调用 akshare 数据原语。akshare 的相关 V8 路径不适合并发简报请求，因此客户端应串行提交简报任务并通过 SSE 等待完成；不要以并发请求绕过这个约束。行情或 LLM 不可用时，任务会报告失败或按后端实现降级，调用方应读取任务状态和错误信息。

可选的定时简报由 `BRIEF_SCHEDULE_ENABLED`、`BRIEF_PUSH_ENABLED` 和 `BRIEF_PUSH_CHANNELS` 控制；默认关闭。部署后应确认时区、网络直连和密钥，再启用推送。

服务仅应监听受信网络：该 API 没有面向公网的鉴权层。需要远程访问时，在反向代理后添加鉴权和 TLS。

`dsh electron --profile investment-research` 是**阶段二交付，当前阶段尚未启用**。产品 Runtime 将在未来按 owned-handle 规则管理它启动的 Python 子进程；本手工 wrapper 不承担该职责。
