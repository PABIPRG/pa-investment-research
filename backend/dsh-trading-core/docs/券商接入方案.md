# 券商持仓与成交明细接入方案

> 代码入口：`adapter/holdings_providers/`（读取）与 `adapter/trades_source.py`（成交导入流程）；产品用户通过设置页或持仓弹窗选择数据源，源码调试也可使用 `HOLDINGS_PROVIDER` 环境变量

## §manual — 手动录入

当前默认方案。用户通过 `POST /holdings/save` 或 dsh 对话维护持仓，落 `JsonStore`（`data/adapter/holdings.json`）。

**配置：** 应用内选择会立即生效并持久化；源码调试也可使用：
```env
HOLDINGS_PROVIDER=manual
```

无需额外配置。

## 真实与模拟账户

产品通过 `HOLDINGS_ACCOUNT_MODE=real|simulated` 明确区分操盘账户，缺省为 `simulated`。数据源和账户类型都通过持仓同步面板即时切换并持久化；同步结果分别记录为 `broker_real` 与 `broker_simulated` 快照来源，避免把模拟持仓误标为真实持仓。

各平台使用自身稳定能力实现账户选择：macOS 同花顺优先被动 AX 读取，只有 Electron 本次获准后才导航“A股”或“模拟”tab；Windows easytrader 在已连接进程中匹配真实交易窗口或标题含“模拟炒股”的窗口；QMT 使用单独的模拟账号 ID。系统不会在找不到模拟窗口或模拟账号时回退读取真实账户。

## §easytrader — CLI/GUI 自动化接入

通过 [easytrader](https://github.com/shidenggui/easytrader) + pywinauto 操控券商客户端窗口，读取持仓/资金/委托。

### 覆盖范围：按内核适配，覆盖贴牌券商

国内券商 PC 客户端大多是「贴牌」生态（采购同花顺/通达信内核定制），因此按内核适配一次即可覆盖一大批券商：

| 内核 | easytrader 模式 | 锚定程序 | 覆盖券商 |
|------|----------------|----------|---------|
| 同花顺 | `thstrader` | `xiadan.exe` | 80+ 家（平安/国金/银河/华泰/招商/中信建投…） |
| 通达信 | `tdxtrader` | `tdxw.exe` | 60+ 家（各家通达信定制版） |

全部券商档案见 `adapter/holdings_providers/broker_profiles.py` 注册表
（`THS_BROKERS` / `TDX_BROKERS`，遗漏的券商在表尾追加一行即可）。
CLI 随时可查：

```bash
env\Scripts\python.exe holdings_cli.py detect --list   # 列出全部支持券商
```

### 快速接入（推荐：自动发现）

```bash
# 1. 装依赖
env\Scripts\python.exe -m pip install easytrader pywinauto
# 2. 扫描本机已装券商客户端，自动识别券商并生成 .env 建议
env\Scripts\python.exe holdings_cli.py detect
# 3. 把建议配置粘进 .env，启动并登录券商客户端后自检
env\Scripts\python.exe holdings_cli.py check
```

### 前置条件

1. **Windows 系统**（pywinauto 依赖）
2. **券商客户端**：安装对应内核客户端（同花顺贴牌券商装其「同花顺版」）并登录；
   同花顺通用版内置 80+ 券商账号登录，装一个即可覆盖大多数券商
3. **Python 依赖**：
   ```bash
   pip install easytrader pywinauto
   ```

### 配置（.env，二选一）

```env
HOLDINGS_PROVIDER=easytrader
# 方式 A：按券商档案（推荐，detect 自动生成）
EASYTRADER_BROKER=pingan                 # 档案 id 见 detect --list
EASYTRADER_CLIENT_PATH=C:\平安证券\同花顺版\xiadan.exe
# 方式 B：按内核（不区分具体券商）
EASYTRADER_CLIENT_TYPE=thstrader         # thstrader(同花顺) | tdxtrader(通达信)
EASYTRADER_CLIENT_PATH=C:\同花顺\xiadan.exe
# 模拟交易窗口由不同程序承载时可单独指定；同一程序承载时留空
EASYTRADER_SIM_CLIENT_PATH=
```

`EASYTRADER_BROKER` 优先于 `EASYTRADER_CLIENT_TYPE`；进程检测与报错文案按档案执行。

### 字段映射

字段候选名由 `adapter/holdings_providers/_ths_fields.py` 统一维护，与 §mac_ths 共用：

| easytrader 返回字段 | HoldingItem 字段 | 转换说明 |
|---------------------|-----------------|----------|
| `证券代码` / `股票代码` / `stock_code` | `ticker` | 截取前6位数字 |
| `股票余额` / `持仓数量` / `证券余额` / `volume` | `quantity` | int → float |
| `成本价` / `参考成本价` / `成本均价` / `avg_price` | `cost_price` | 直接映射 |

### 已知问题

- 客户端窗口**必须保持打开且已登录**，最小化或遮挡可能导致操作失败
- 券商客户端版本更新后，UI 控件定位可能失效，需更新 easytrader 配置
- 查询速度受 GUI 操作延迟影响（约 2-5 秒/次）
- 推荐 fork：[shidenggui/easytrader](https://github.com/shidenggui/easytrader)（社区持续维护）
- 模拟操盘会优先匹配标题含“模拟炒股”的交易窗口；如果窗口尚未创建，用户只需首次在 Windows 同花顺中进入“交易 → 模拟 → 持仓”，后续同步会复用该窗口
- **读成交明细的导出方式与 easytrader 自带实现不同**：2026-09-15 在平安同花顺版真机验证，向
  `CVirtualGridCtrl` 发 WM_COMMAND（easytrader 自己走的那条路）不生效，只能发 Ctrl+S 触发
  「另存为」。后者会弹出风控验证码，需 tesseract OCR 识别。细节见
  `adapter/holdings_providers/_ths_export.py` 的模块注释

### 降级

当 easytrader 不可用（客户端未启动/未登录）时，`is_available()` 返回 `False`，`get_holdings()` 抛 `ProviderUnavailable`。上层可 fallback 到 manual。

## §mac_ths — 同花顺 Mac 版 AX 读取

安装、实际读取进程的辅助功能权限、按次前台同意和 Web 降级见 [macOS 持仓同步指南](macOS持仓同步指南.md)。默认使用 AXUIElement；只有获准原生导航的 AX 路径失败才尝试 AppleScript，且仅在实际遇到自动化拒绝时追加该权限步骤。

```env
HOLDINGS_PROVIDER=mac_ths
HOLDINGS_ACCOUNT_MODE=simulated
MAC_THS_TIMEOUT=60
```

应用目标限定为同花顺。读取只生成预览，确认后保存；空结果、缺失必填字段和无法确认的账户类型拒绝覆盖。导航不以 `AXPress` 返回成功作为切页证据；每一步都重新遍历可见窗口，最终要求所选账户和目标表格位于同一窗口。持仓已验证但成交明细未完成时，返回部分成功、具体原因和读取时间兜底，不伪装为完整明细。真实同花顺版本、签名宿主权限归属和焦点恢复需要发行前验收。

同一 Provider 还提供 `read_trades()` 读取历史成交，导航标签同样未经真机验收，且**没有** AppleScript 兜底（见[成交明细导入](#成交明细导入)）。

## §QMT — 迅投 miniQMT/xtquant 接入

通过 [xtquant](https://pypi.org/project/xtquant/) 连接 miniQMT 客户端进程，获取真实持仓/资金/委托。**推荐的生产级方案。**

### 前置条件

1. **券商开户** + **开通 QMT 权限**（部分券商需 10 万+ 资产门槛，华鑫证券门槛较低）
2. **miniQMT 客户端**：下载并登录（券商官网或 QMT 官网获取）
3. **Python 依赖**：
   ```bash
   pip install xtquant
   ```

### 配置

```env
HOLDINGS_PROVIDER=qmt
QMT_ACCOUNT_ID=你的资金账号
QMT_SIM_ACCOUNT_ID=你的模拟账号   # 使用 simulated 时必填，不回退到真实账号
QMT_SESSION_ID=888888
```

### 字段映射

| xtquant 字段 | HoldingItem 字段 | 转换说明 |
|-------------|-----------------|----------|
| `stock_code` | `ticker` | `"600519.SH"` → `"600519"`（去后缀取6位数字） |
| `volume` | `quantity` | int → float |
| `avg_price` | `cost_price` | 直接映射 |

### 扩展能力

QMTProvider 额外提供 `get_asset()` 方法查询账户资金：

```python
provider = QMTProvider()
asset = provider.get_asset()
# {"total_asset": 1000000.0, "cash": 500000.0, "market_value": 500000.0, "frozen_cash": 0.0}
```

后续可扩展：
- `query_stock_orders()` — 查询当日委托
- `query_stock_trades()` — 查询当日成交
- 下单/撤单（需合规确认 + 风控层）

### 支持 QMT 的常见券商

| 券商 | 门槛 | 说明 |
|------|------|------|
| **华鑫证券** | 较低 | 推荐，miniQMT 开通门槛低 |
| **国金证券** | 中等 | QMT 支持较好 |
| **中泰证券** | 中等 | 同时支持原生 XTP 接口 |
| **华泰证券** | 较高 | 需 50 万+ |
| **东方财富** | 中等 | EMQuantAPI |

### 降级

当 QMT 不可用（xtquant 未安装 / miniQMT 未运行 / 账号未配置）时，`is_available()` 返回 `False`，`get_holdings()` 抛 `ProviderUnavailable`。

## §joinquant — 聚宽数据源

**聚宽不提供真实券商持仓**，仅提供行情/财务数据。设 `HOLDINGS_PROVIDER=joinquant` 会直接抛 `ProviderUnavailable`。

本 Provider 保留结构供未来扩展（如拉历史行情补充 L1 风险分析），不作为持仓数据源使用。

## 成交明细导入

持仓是「现在有什么」，成交是「怎么变成这样的」。成交明细把每次买卖落成一条可回放的记录，
交给 `adapter/trade_profile.py` 算交易频率、集中度与数据覆盖度。

> **成交读取与持仓读取走的是两套代码路径**：Provider 上的 `read_trades()` 与 `get_holdings()` 独立，
> 前置检查（平台/依赖/档案/客户端路径/客户端在跑）复用同一份实现，但导航与取数完全不同。
> 成交导入的编排（预览 → 确认 → 落库）在 `adapter/trades_source.py`，不经过 `holdings_source.py`。

### 两条读取路径

| | **Windows（easytrader）** | **macOS（mac_ths）** |
|---|---|---|
| 页面 | `查询[F4]` → `历史成交` | `交易 → <A股 \| 模拟> → 股票 → 历史成交` |
| 取数 | 客户端「另存为」（Ctrl+S）导出表格后读回 | AX 直接遍历表格 `AXRows` |
| 需要前台 | ✅ 必须 | ❌ 被动可行；主动导航时才需要 |
| 可能弹窗 | ✅ 风控验证码（tesseract OCR 识别） | ❌ |
| 验收状态 | 真机已验证（2026-09-15，平安同花顺版） | ⚠️ 导航标签未在真机验收 |

**Windows 不能被动读**：导出靠向窗口发 Ctrl+S 并接管「另存为」对话框，会抢焦点、可能弹验证码。
因此 `read_trades()` 在非 `foreground=True` 时直接抛 `navigation_required`，且**不连接客户端**——
失败发生在动手之前。CLI 的 `trades` / `trades-sync` 只能被动读取，所以 **Windows 上必定失败**，
这是设计而非缺陷：请从桌面端入口读取。

**macOS 没有 AppleScript 成交明细兜底**：持仓那条 AppleScript 脚本硬编码了「持仓」页，仅作为兼容路径，不构成真机验收证据；
成交页没有对应脚本。主动导航失败时抛 `navigation_required`，提示用户手动打开
`交易 → <账户> → 股票 → 历史成交`，**不会**退到 AppleScript 去猜。

### 通用性：按内核写，但只在一台客户端上验过

代码里**没有任何一处**按具体券商分支——没有 `broker_id == "pingan"` 这种东西。
通用性靠这几点实现：

- 69 家同花顺贴牌券商共用一份档案结构（`xiadan.exe` + `hexin.exe`）；
- 找窗口按标题 `网上股票交易系统` / `模拟炒股`，是同花顺下单程序的通用标题；
- **列名按候选名表匹配**（`_ths_fields.FIELD_CANDIDATES`，与持仓共用），不按列号——
  列序变了、多一列少一列都不影响；
- 导出按 GBK 制表符文本读。

但下面的每一条都**只在一台平安同花顺版上观察过**，属于假设而非验证：

| 假设 | 不成立时会怎样 |
|------|----------------|
| 历史成交在 `查询[F4] → 历史成交` | 已收敛到档案字段 `trades_menu_path`，改一家不影响别家 |
| 风控验证码框控件 id `0x965` / `0x964` | 抄自上游 easytrader 的 Copy 策略。别家可能压根不弹，也可能弹另一个结构的框——此时 `_solve_captcha` 返回 False，走「请手工输入验证码」的分支，不会盲点「确定」 |
| 「另存为」对话框标题 | 依赖中文 Windows |
| 导出无手续费列、代码是 `="159607"` 形式 | 前者只影响成本口径（本来就不含费用），后者被 `_trade_ticker` 吃掉 |

真机验收状态见计划里的闸门 1–4：闸门 1–3（Windows）已在平安同花顺版通过，
闸门 4（macOS 导航标签）**未做**。

### 去重与合并语义

同一个交易日会被反复导入（今天导一次、明天再导一次），所以合并不是覆盖：

- 去重键 `trade_key() = 账户口径 | 成交日期 | 成交编号`；
- 重复项按**多重集**语义计数，即同一天成交 3 笔完全相同的记录会保留 3 条，而不是压成 1 条；
- 新导入只**追加**新增成交，已存在的记录不更新、不删除；
- 读取回的结果带 `source` 与 `account_mode` 由 Provider 填写，不由映射层猜。

### HTTP 接口

三条路由与持仓那三条同构（同样的 `readiness` / `blocking_reason` / `reason` 错误形态）：

| 路由 | action | 说明 |
|------|--------|------|
| `POST /trades/sync` | `preview`（默认） | 读一次客户端，返回待写入的明细、条数与 `preview_token` |
| `POST /trades/sync` | `commit` | 带 `preview_token` 落库 |
| `POST /trades/clear` | `preview` / `commit` | 清空全部成交，同样需要 token |
| `GET /trades` | — | 返回 `entries` / `imports` / `last_cleared` / `profile` |

预览有 300 秒 TTL。提交时会重新核对基线、根目录、数据源与账户口径，
任何一项变了或存储已被别处改动，都会抛 `preview_conflict` 而不是照旧写入。

### 覆盖率为什么要记账

`profile.coverage` 只报告**确实没被任何一次读取覆盖过**的日期区间，靠的是每次导入时把
命中的日期范围（`range_start` / `range_end`）记进 import 记录，合并所有区间后取补集。
这样能区分「那天没交易」和「那段日子从来没读过」——后者是数据缺口，前者不是。
`status` 取 `complete` / `partial` / `unknown` / `empty`。

### 已知局限（第一期）

- 集中度只统计**股票**：`_STOCK_PREFIXES` 白名单之外的（ETF/LOF、可转债、逆回购、B 股）
  不计入 HHI 与金额合计，但会在 `excluded_non_stock_trades` 里报出条数；
- 成交金额**不含**佣金、印花税、过户费，与对账单口径不会完全一致；
- 没有 FIFO 配对，因此推不出单笔已实现盈亏，只有频率与集中度；
- `manual` 与 `qmt` 数据源暂不支持成交读取，`read_trades` 动作不会出现在它们的能力列表里。

### CLI

```bash
env\Scripts\python.exe holdings_cli.py trades            # 预览并导入（Windows 必失败，见上）
env\Scripts\python.exe holdings_cli.py trades-sync       # 同上，显式走 trades_source 编排
env\Scripts\python.exe holdings_cli.py trades-profile    # 打印频率/集中度/覆盖率，无需客户端
env\Scripts\python.exe holdings_cli.py trades-clear --yes # 清空，需显式 --yes
```

`trades-profile` 与 `trades-clear` 是纯本地操作，任何平台都能跑。

### 能力闸门

是否给出 `read_trades` 动作要过**三道闸门**，缺一不可：

| 闸门 | 判据 | 挡掉谁 |
|------|------|--------|
| 数据源 | `_TRADES_PROVIDERS = {"easytrader", "mac_ths"}` | `manual` / `qmt` / `joinquant` |
| 运行界面 | 需要前台的数据源只在 `surface == "electron"` 时暴露 | 本地 Web 界面上的 Windows |
| 券商档案 | `profile.trades_menu_path is not None` | 专用客户端内核的六家 |

第二道：本地 Web 界面没有认证宿主通道，`easytrader` 在那里放行只会拿到一个
`navigation_required`。`trades_requires_foreground()` 目前只对 `easytrader` 返回 True
（macOS 走 AX 被动遍历，网页版也能读）。

第三道：**同是 `easytrader` 数据源，不等于都能读成交。** 档案表里 69 家同花顺内核
贴牌券商共用 `查询[F4] → 历史成交` 左树，但银河 / 华泰 / 五矿 / 海通 / 国金 / 广发
这六家的**专用客户端**有各自的交易界面，没有这套菜单，本期未接入。它们在档案里的
`trades_menu_path` 留空，能力列表里就不会出现这个动作；即使绕过界面直接调用，
`read_trades()` 也会在连接客户端**之前**抛 `unsupported_action`。

**「历史成交」的菜单路径是档案字段，不是模块常量**（`BrokerProfile.trades_menu_path`，
默认值 `DEFAULT_TRADES_MENU_PATH`）。各贴牌版本的菜单树未必一致，某一家不一样时
只改那一行档案，不影响其余 68 家。新增券商时若不填，`test_trades_capability` 会失败——
漏填会静默退化成「这家不支持读成交」。

## 降级链

```
用户请求 → get_provider()
  │
  ├─ HOLDINGS_PROVIDER=qmt
  │    └─ is_available()?  → ✅ get_holdings()
  │                     → ❌ fallback 到 easytrader
  │
  ├─ HOLDINGS_PROVIDER=easytrader   （仅 Windows）
  │    └─ is_available()?  → ✅ get_holdings()
  │                     → ❌ fallback 到 manual
  │
  ├─ HOLDINGS_PROVIDER=mac_ths      （仅 macOS）
  │    └─ is_available()?  → ✅ get_holdings()
  │                     → ❌ fallback 到 manual
  │
  └─ HOLDINGS_PROVIDER=manual（始终可用）
       └─ get_holdings() → JsonStore 或空列表
```

> 注：当前降级由用户在设置页或持仓弹窗手动切换数据源实现，不会在读取失败时自动改用其他来源。
