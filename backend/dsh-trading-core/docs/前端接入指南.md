# 前端接入指南 —— Python Adapter 与 UI 对接

> 面向：接入 `dsh-trading-core` Python API 的前端或宿主团队。
> API、请求和 SSE 数据结构的唯一事实来源是 [API-接口文档.md](API-接口文档.md)。

适配器是 **HTTP + SSE** 服务，默认地址为 `http://127.0.0.1:8000`。两套交互面：

- **异步任务式**（六类：个股 / 持仓 / 简报 / 回测 / 策略 / 影子）：POST 启动 → 拿 `task_id` → 订阅
  `/analyze/{task_id}/stream` 或轮询状态 → 取结果。进度事件统一（`pipeline/stage/trace/progress/result/error/done`）。
- **同步接口**：读写自选、持仓、风险偏好、KYC，以及回测/策略/影子/简报的**查询**端点，直接返回结果。

可复用的 TypeScript 客户端源码位于 [frontend/packages/investment-research/stock-analysis/src/client.ts](../../../frontend/packages/investment-research/stock-analysis/src/client.ts)。
该客户端属于 frontend workspace；后端不负责安装、验证或启动它。

## 接入边界

```text
UI or host
  -> HTTP/SSE client
  -> Python adapter (127.0.0.1:8000)
  -> tradingagents engine            // 个股/持仓/简报（LLM）
     baostock + pandas              // 回测/策略/影子（纯逻辑，无 LLM）
     market-watch :8100 /news/events  // 策略假设的事件源（HTTP 拉取）
```

客户端应负责：请求序列化、SSE 帧解析、超时和取消、把六类任务的事件流映射为 UI 状态
（进度条 / 阶段 / 最终结果）。后端负责任务生命周期、引擎执行和 API 契约；UI 不应复制
回测指标计算、策略阈值判定或影子记账逻辑。

## 本地联调（当前阶段）

```sh
cd backend/dsh-trading-core
./init.sh
ADAPTER_RUNNER=fake ./start.sh
curl http://127.0.0.1:8000/health
curl http://127.0.0.1:8000/strategies
```

`fake` 运行器只把 `stock`/`holdings`/`brief` 换成确定性假实现；**`backtest`/`strategy`/`shadow`
三个 runner 走真实逻辑**（baostock + pandas，无 LLM）。所以联调回测/策略/影子**需要行情可达**
（baostock 联网），而个股/简报的 LLM 部分可离线。

**任务式接口三步走**（回测 / 策略 / 影子 / 个股 / 持仓 / 简报一致）：

```sh
# 1) 启动任务 → task_id
curl -X POST http://127.0.0.1:8000/backtest/run -H 'Content-Type: application/json' \
  -d '{"code":"600519","limit":20}'
#   → {"task_id":"<tid>"}

# 2) 订阅进度（SSE，Ctrl+C 断开）
curl -N http://127.0.0.1:8000/analyze/<tid>/stream

# 3) 任务 done 后取结果
curl http://127.0.0.1:8000/analyze/<tid>/result
```

**策略研究链路**（`#/strategies` 页面依赖，需先起 market-watch :8100）：

```sh
# 事件 → 假设 → 候选入库（同步慢，LLM 10-30s；事件源不可用返回空候选不 500）
curl -X POST http://127.0.0.1:8000/strategies/hypothesize -H 'Content-Type: application/json' \
  -d '{"limit":20}'
# 回测某候选（异步任务）→ 自动迁移 active/rejected
curl -X POST http://127.0.0.1:8000/strategies/run -H 'Content-Type: application/json' \
  -d '{"strategy_id":"strat-xxx"}'
# 影子验证（异步任务）→ status/positions/equity 三表
curl -X POST http://127.0.0.1:8000/shadow/run -H 'Content-Type: application/json' -d '{}'
curl http://127.0.0.1:8000/shadow/status
curl http://127.0.0.1:8000/shadow/positions
curl http://127.0.0.1:8000/shadow/equity
```

关键 `.env` 配置（项目根 `TradingAgents-CN/.env`，`override=False`）：

| 变量 | 默认 | 说明 |
|---|---|---|
| `ADAPTER_RUNNER` | `engine` | `fake` = 个股/持仓/简报换假实现；回测/策略/影子恒真 |
| `MW_URL` | `http://127.0.0.1:8100` | 策略假设的事件源（market-watch `/news/events`） |
| `EVENT_CACHE_TTL` | `60` | 事件源拉取 TTL（秒） |
| `SHADOW_SCHEDULE_ENABLED` | `false` | 是否定时跑影子验证（15:30 job）；手动 POST 永远可用 |
| `SHADOW_RUN_TIME` | `15:30` | 影子每日运行时刻（`HH:MM`） |
| `SHADOW_INITIAL_CAPITAL` | `100000` | 影子/策略回测的初始资金（`initial_capital=0` 时使用） |
| `BRIEF_SCHEDULE_ENABLED` | `false` | 是否定时生成盘前/盘后简报 |
| `BRIEF_PRE_MARKET_TIME` / `BRIEF_POST_MARKET_TIME` | `08:50` / `15:30` | 简报 job 时刻 |
| `DEEPSEEK_API_KEY` | 空 | 简报/假设生成/KYC 解析的 LLM；为空则自动降级 |
| `HOLDINGS_PROVIDER` | `manual` | 持仓数据源 |

## 前端用法（当前 product/ 前端为准）

### 六类任务统一消费（`PA.runTask`）

启动端点：`POST /analyze`、`POST /holdings/analyze`、`POST /brief`、`POST /backtest/run`、
`POST /strategies/run`、`POST /shadow/run`。全部返回 `{task_id}`，SSE 协议统一（§API 5.3）：

- `pipeline`（管道清单）→ 可初始化步骤指示器；
- `progress`（`percent`）→ 进度条；`trace` → 可选内容摘要；
- `stage` 兼容两种形态（结构化 `node_id/phase/…` 或旧式 `node/message`）；
- `result` → 最终结果（各类型结构见 API 文档 §3）；`error`/`done` → 收尾。

晚订阅任务完成会补发 `result` + `done`；`heartbeat` 帧 data 为空，忽略即可。

### 同步直连端点（无需 task_id）

- **查询类**：`GET /holdings`、`/strategies`、`/strategies/{sid}`、`/shadow/status|positions|equity`、
  `/backtest/results|performance[/{code}]`、`/brief/latest` —— 页面加载/切换时按需拉取。
- **操作类**：`POST /watchlist`、`/holdings/save`、`/risk_profile`、`/strategies/{sid}/{action}`
  （activate/reject/retire，返回 `{id,status}`）、`/brief/{id}/dsh-pushed`。
- **KYC**：`GET /kyc/profile` 是渲染问卷的**唯一事实源**（题组/档位/当前状态一次取全）；
  `POST /kyc/questionnaire`（提交计分即生效）、`POST /kyc/adjust`（滑块微调，未问卷返回 409）、
  `POST /kyc/parse`（语音/手打文本→答案，供"补答"预填）。
- **注意 `POST /strategies/hypothesize` 是同步慢接口**（LLM 10–30s），调用方要设足够超时、
  按钮加 loading，不要走 SSE。

### 渲染要点

- 策略池列表（`GET /strategies`）：`status` 用彩色 pill（candidate 灰 / active 绿 / rejected 红 /
  retired 灰）；`backtest.out_of_sample` 展示 `win_rate_pct` / `avg_simulated_return_pct` /
  `portfolio.portfolio_max_drawdown_pct`；样本外不足（`thresholds_pass=false`）提示仍为 candidate。
- 影子三表：`status` 顶部摘要（`overall_nav`/`strategy_count`）；`positions` 每行是"策略×代码"仓位；
  `equity` 不带 `strategy_id` 时按日期画整体净值，带 `strategy_id` 时叠加单策略净值（`strategy.nav`）。
- 简报/简报相关 `summary` 是 Markdown，轻量渲染（同 market-watch 的 `PA.mdLines`）。
- 所有数值字段可能为 `null`（未评估/未触发/从未运行）—— 渲染成 `—`，不要做 `0` 处理。

### 跨模块联动

- `#/strategies`（本模块）的事件源是 market-watch `GET /news/events`；market-watch 未起时
  hypothesize 返回空候选 + `note`，前端应展示提示而非报错。
- 首页"持仓命中"由 market-watch 消费本模块 `GET /holdings`（:8000 在线才显示 hold 命中）。
