# 前端接入指南 —— 桥接层与 UI 对接

> 面向：前端团队（做桥接层 + 自有 UI）。
> 本文档回答三个问题：**① 前端能拿到什么能力 ② 桥接层怎么调 ③ 有哪些坑**。
> 配套阅读：[API-接口文档.md](API-接口文档.md)（端点与数据结构的唯一事实源）。

---

## 0. 一句话总结

适配器是一个 **无状态 HTTP + SSE 服务（127.0.0.1:8000）**，CORS 全开、无鉴权。
前端只需要：
- **发起长任务**：`POST /analyze` 等 → 拿到 `task_id`
- **订阅进度**：`GET /analyze/{task_id}/stream`（SSE，`stage* → result → done`）
- **轻量读写**：自选 / 持仓 / 风险偏好 / 最近简报，同步 GET/POST

不需要任何 SDK。一个 `fetch` + SSE 解析就够了。仓库里 **`dsh-plugin/src/client.ts` 就是一个可直接参考的纯 Node 参考实现**（与 dsh 解耦，可整段借鉴）。

## 1. 能力清单（前端 UI 可展示的 9 个能力）

| 能力 | 触发方式 | 产出 | 耗时 |
|---|---|---|---|
| 📈 个股分析 | POST `/analyze` | 决策信号（买卖/目标价/置信度/风险分）+ 7 段分步报告 | 3–9 分钟 |
| 🧺 持仓分析 | POST `/holdings/analyze` | 组合风险（市值/浮盈/集中度/β）+ 逐股明细 + 调仓建议 | quick 秒级 / deep 3–5 分钟 |
| 📊 市场简报 | POST `/brief` | Markdown 简报 + 机会点列表（带风险等级） | ~1–3 分钟 |
| ⭐ 自选列表 | GET/POST `/watchlist` | 股票代码数组 | 秒级 |
| 💼 保存持仓 | POST `/holdings/save` | 保存条数 | 秒级 |
| 🎯 风险偏好 | GET/POST `/risk_profile` | 三档画像（保守/稳健/进取） | 秒级 |
| 📥 最近简报 | GET `/brief/latest` | 最近一份简报（含播报标记） | 秒级 |

> 所有"分析类"能力都由**后端引擎 + DeepSeek LLM** 驱动，前端只负责调用与展示，不做任何计算。

## 2. 桥接层职责与边界

建议前端建一个 `adapterClient` 模块（参考 `dsh-plugin/src/client.ts`），封装成对 UI 友好的 API：

```
UI 组件
  │
  ├─ adapterClient.analyzeStock({ticker, depth})  → AsyncGenerator<StageEvent> + TaskResult
  ├─ adapterClient.analyzeHoldings({holdings, mode})
  ├─ adapterClient.generateBrief({period})
  ├─ adapterClient.getWatchlist() / setWatchlist([])
  ├─ adapterClient.saveHoldings([])
  ├─ adapterClient.getRiskProfile() / setRiskProfile('balanced')
  └─ adapterClient.getLatestBrief()
  │
  ▼
  fetch → 适配器 HTTP / SSE (127.0.0.1:8000)
```

**桥接层职责**：
1. **SSE 解析**：把 `event:`/`data:` 帧转成结构化事件（`client.ts` 的 `parseSse` 可直接抄）
2. **进度注入**：`stage` 事件 → UI 进度条 / 阶段列表（不必做 LLM 注入——那是 dsh 场景的专属逻辑）
3. **任务编排**：启动 → 订阅 → 拿到 result 的完整生命周期管理
4. **错误归一化**：404 / 409 / SSE error 事件 → 统一错误对象

**桥接层不该做**：不解析/渲染引擎报告的具体业务（Markdown 直接透传给 UI 渲染即可）、不做业务计算。

## 3. 核心流程（长任务，三种分析通用）

```
1. POST /analyze
   body: { ticker: "600519", research_depth: "standard" }
   2xx → { task_id: "3f9a…" }

2. GET /analyze/3f9a…/stream        (SSE)
   → event: stage   data: {"node": "...", "message": "🔍 市场分析师…"}
   → event: stage   data: {...}
   → event: result  data: {"signal":{...}, "reports":{...}, "performance_metrics":{}}
   → event: done    data: {}
```

**前端 UI 建议**：
- 进入 `stage` 事件 → 显示分析阶段列表（市场/基本面/新闻/情绪/辩论/交易员/风险），`message` 就是进度文案
- 收到 `result` → 渲染决策卡 + 分步报告
- 收到 `error` 事件 → 中断并展示 `message`
- 收到 `done` → 结束

### 参考实现（TypeScript，可直接使用）

```ts
// adapterClient.ts —— 参考 dsh-plugin/src/client.ts 精简版

const BASE = 'http://127.0.0.1:8000'

async function startTask(path: string, body: unknown): Promise<string> {
  const res = await fetch(`${BASE}${path}`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(body),
  })
  if (!res.ok) throw new Error(`适配器 HTTP ${res.status}: ${await res.text()}`)
  const { task_id } = await res.json()
  if (!task_id) throw new Error('适配器未返回 task_id')
  return task_id
}

/** 订阅 SSE：onStage 进度回调，resolve 时返回最终 result。 */
export async function consumeSse(
  url: string,
  opts: { signal: AbortSignal; timeoutMs: number },
  onStage?: (msg: string) => void,
): Promise<unknown> {
  const res = await fetch(url, {
    signal: AbortSignal.any([opts.signal, AbortSignal.timeout(opts.timeoutMs)]),
  })
  if (!res.ok || !res.body) throw new Error(`SSE HTTP ${res.status}`)
  const reader = res.body.getReader()
  const decoder = new TextDecoder('utf-8')
  let buf = ''
  let final: unknown

  const handleFrame = (frame: string) => {
    let event = '', data = ''
    for (const line of frame.split('\n')) {
      if (line.startsWith('event:')) event = line.slice(6).trim()
      else if (line.startsWith('data:')) data = line.slice(5).trim()
    }
    if (event === 'stage') {
      try { onStage?.(JSON.parse(data).message ?? data) } catch { onStage?.(data) }
    } else if (event === 'result') {
      try { final = JSON.parse(data) } catch { /* 忽略坏帧 */ }
    } else if (event === 'error') {
      let msg = ''
      try { msg = JSON.parse(data).message ?? '未知错误' } catch { msg = data }
      throw new Error(`分析失败：${msg}`)
    } else if (event === 'done') {
      // 正常结束
    }
  }

  try {
    for (;;) {
      const { done, value } = await reader.read()
      if (done) break
      buf += decoder.decode(value, { stream: true }).replace(/\r\n/g, '\n')
      let idx: number
      while ((idx = buf.indexOf('\n\n')) >= 0) {
        handleFrame(buf.slice(0, idx)); buf = buf.slice(idx + 2)
      }
    }
    if (buf.trim()) handleFrame(buf)
  } finally {
    reader.releaseLock()
  }
  if (final === undefined) throw new Error('SSE 流结束但未收到 result')
  return final
}

// 使用示例：跑一次个股分析
export async function analyzeStock(ticker: string, onStage?: (m: string) => void) {
  const taskId = await startTask('/analyze', { ticker })
  return consumeSse(`${BASE}/analyze/${taskId}/stream`, {
    signal: new AbortController().signal,
    timeoutMs: 600_000,   // 单股 3-9 分钟，超时给足
  }, onStage)
}
```

> 原始 SSE 帧可能以 `\r\n\r\n` 分隔、末尾残留未换行帧——上面的 `buf` + `indexOf('\n\n')` + 尾部 flush 已处理。

## 4. 轻量接口调用示例

```ts
// 自选
await fetch(`${BASE}/watchlist`)                        // → { tickers: [...] }
await fetch(`${BASE}/watchlist`, {
  method: 'POST', headers: {'Content-Type':'application/json'},
  body: JSON.stringify({ tickers: ['600519', '000858'] }),
})                                                      // → { saved: 2 }

// 风险偏好
await fetch(`${BASE}/risk_profile`)                     // → { risk_profile, label }
await fetch(`${BASE}/risk_profile`, { method:'POST', body: JSON.stringify({ risk_profile: 'aggressive' }) })

// 持仓
await fetch(`${BASE}/holdings/save`, { method:'POST',
  body: JSON.stringify({ holdings: [{ ticker:'600519', quantity:200, cost_price:1480 }] }) })

// 最近简报（尚无简报时返回 null 字段，非 404）
await fetch(`${BASE}/brief/latest`)                     // → { id, period, trade_date, summary, dsh_pushed }
```

## 5. 数据结构（前端 TypeScript 类型）

完整字段见 [API-接口文档.md §6](API-接口文档.md)。这里给出 UI 最关心的部分：

### 5.1 个股分析结果

```ts
interface AnalyzeResult {
  signal: {
    action: string          // 买入 | 持有 | 卖出
    ticker: string
    company_name?: string
    target_price?: number
    confidence?: number     // 0~1
    risk_score?: number     // 0~1
    reasoning?: string
    risk_profile?: string   // conservative | balanced | aggressive
    calibration?: boolean   // 是否被风险偏好护栏修正
    calibration_note?: string
  }
  reports?: {
    market?: string; fundamentals?: string; news?: string
    sentiment?: string; debate?: string; trader?: string; risk?: string
  }                        // 全部是 Markdown 字符串
}
```

**UI 渲染建议**：顶部决策卡（action/target_price/confidence/risk_score），下方按固定顺序折叠展示 7 段 Markdown 报告。

### 5.2 持仓分析结果

```ts
interface HoldingsResult {
  signal: {
    total_market_value?: number
    total_cost?: number
    floating_pnl?: number
    floating_pnl_pct?: number
    weighted_risk_score?: number   // 0~1，越大风险越高
    concentration_hhi?: number     // >0.3 偏高
    portfolio_annualized_vol?: number
    n_positions?: number
    sector_exposure?: { industry: string; weight: number }[]
    risk_breaches?: { indicator: string; label?: string; value?: number; limit?: number; excess?: number }[]
    rebalance_suggestions?: string[]
    per_stock?: Record<string, {
      name?: string; weight?: number; last_price?: number; market_value?: number
      floating_pnl?: number; annualized_vol?: number; max_drawdown?: number
      beta?: number | null; industry?: string; risk_level?: string  // 低/中/高
      risk_score?: number | null; action?: string | null; reasoning?: string | null
    }>
  }
  reports?: { portfolio?: string }
}
```

**UI 渲染建议**：组合概览卡（总市值/成本/浮盈/加权风险/HHI）+ 预算对照表（超限项标红）+ 逐股明细表 + 调仓建议列表。

### 5.3 简报结果

```ts
interface BriefResult {
  signal: {
    period?: 'pre_market' | 'post_market' | 'now'
    trade_date?: string
    summary?: string          // Markdown 简报正文（LLM 或模板）
    opportunities?: { kind: string; risk_level: '低'|'中'|'高'; title: string; ticker?: string }[]
  }
  reports?: { brief?: string }
}
```

**UI 渲染建议**：`summary` 直接 Markdown 渲染；机会点列表按风险等级上色（低绿/中黄/高红）。

## 6. 关键注意事项（踩坑清单）

1. **任务在内存里，进程重启即失**。长任务期间不要重启适配器；`task_id` 不做持久化。
2. **`GET /analyze/{id}/result` 未完成返回 409**。要么等 SSE 的 `result` 事件，要么先轮询状态再取。
3. **SSE 事件类型是 `stage`/`result`/`error`/`done`**，不要和 HTTP 状态码混淆——即使 200，任务也可能在流里以 `error` 事件失败。
4. **`/brief` 必须串行调用**（akshare 的 V8 引擎并发会崩适配器）。前端如有并发简报需求，自己排队。
5. **简报 `id` 含 `:`**，标记 `dsh-pushed` 时路径参数要 URL 编码（`encodeURIComponent`）。
6. **单股分析很慢（3–9 分钟）**，SSE 超时给足（≥600s）；中途允许取消（abort fetch）。
7. **首次分析会拉行情数据**（akshare/baostock），国内行情站需直连（见 [跨环境运行.md](跨环境运行.md) 的 NO_PROXY）；拉数据失败任务会 `failed`。
8. **风险偏好影响所有输出**（决策护栏、持仓预算、简报机会点过滤）。UI 里展示"当前画像"能让结果可解释。
9. **CORS 全开、无鉴权**：仅限本机/内网使用，对外暴露务必套反向代理 + 鉴权。

## 7. 如何本地联调（不依赖 dsh UI）

后端起两个服务（见 [跨环境运行.md](跨环境运行.md)）：

```bash
# 终端 1：适配器（engine 模式）
env/Scripts/python.exe -m uvicorn adapter.app:app --host 127.0.0.1 --port 8000

# 终端 2：dsh Web UI（带插件，可选）
cd %TEMP%/dsh-run && npx @deepseek-ai/dsh web --patch "项目路径/dsh-plugin/cordis.yml"
```

**不装 dsh 也能联调**：直接对着 `127.0.0.1:8000` 调上面 §3/§4 的接口即可。想快速验证 SSE 链路，可把 `ADAPTER_RUNNER=fake` 启动（假任务，每个 stage 0.3–0.4s，返回假数据，不耗 LLM 额度、不拉行情）。
