# 前端接入指南 —— Python Adapter 与 UI 对接

> 面向：接入 `dsh-trading-core` Python API 的前端或宿主团队。
> API、请求和 SSE 数据结构的唯一事实来源是 [API-接口文档.md](API-接口文档.md)。

适配器是 **HTTP + SSE** 服务，默认地址为 `http://127.0.0.1:8000`。两套交互面：

- **异步任务式**（六类：个股 / 持仓 / 简报 / 回测 / 策略 / 影子）：POST 启动 → 拿 `task_id` → 订阅
  `/analyze/{task_id}/stream` 或轮询状态 → 取结果。进度事件统一（`pipeline/stage/trace/progress/result/error/done`）。
- **同步接口**：读写自选、持仓、风险偏好、KYC，以及回测/策略/影子/简报的**查询**端点，直接返回结果。

可复用的 TypeScript 客户端源码位于 [frontend/packages/investment-research/stock-analysis/src/client.ts](../../../frontend/packages/investment-research/stock-analysis/src/client.ts)。
该客户端属于 frontend workspace；后端不负责安装、验证或启动它。

## 接入边界

```text
UI or host
  -> HTTP/SSE client
  -> Python adapter (127.0.0.1:8000)
  -> tradingagents engine            // 个股/持仓/简报（LLM）
     baostock + pandas              // 回测/策略/影子（纯逻辑，无 LLM）
     market-watch :8100 /news/events  // 策略假设 & 个性化卡片的事件源（HTTP 拉取）
  -> personalized（O 策略×画像匹配 / D+P 卡片流 / R 行为埋点）
     // 全读本机 store + 事件源，无 LLM 强依赖（comment 可选）
```

客户端应负责：请求序列化、SSE 帧解析、超时和取消、把六类任务的事件流映射为 UI 状态
（进度条 / 阶段 / 最终结果）。后端负责任务生命周期、引擎执行和 API 契约；UI 不应复制
回测指标计算、策略阈值判定或影子记账逻辑。

## 本地联调（当前阶段）

```sh
cd backend/dsh-trading-core
./init.sh
ADAPTER_RUNNER=fake ./start.sh
curl http://127.0.0.1:8000/health
curl http://127.0.0.1:8000/strategies
```

`fake` 运行器只把 `stock`/`holdings`/`brief` 换成确定性假实现；**`backtest`/`strategy`/`shadow`
三个 runner 走真实逻辑**（baostock + pandas，无 LLM）。所以联调回测/策略/影子**需要行情可达**
（baostock 联网），而个股/简报的 LLM 部分可离线。

**任务式接口三步走**（回测 / 策略 / 影子 / 个股 / 持仓 / 简报一致）：

```sh
# 1) 启动任务 → task_id
curl -X POST http://127.0.0.1:8000/backtest/run -H 'Content-Type: application/json' \
  -d '{"code":"600519","limit":20}'
#   → {"task_id":"<tid>"}

# 2) 订阅进度（SSE，Ctrl+C 断开）
curl -N http://127.0.0.1:8000/analyze/<tid>/stream

# 3) 任务 done 后取结果
curl http://127.0.0.1:8000/analyze/<tid>/result
```

**策略研究链路**（`#/strategies` 页面依赖，需先起 market-watch :8100）：

```sh
# 事件 → 假设 → 候选入库（同步慢，LLM 10-30s；事件源不可用返回空候选不 500）
curl -X POST http://127.0.0.1:8000/strategies/hypothesize -H 'Content-Type: application/json' \
  -d '{"limit":20}'
# 回测某候选（异步任务）→ 自动迁移 active/rejected
curl -X POST http://127.0.0.1:8000/strategies/run -H 'Content-Type: application/json' \
  -d '{"strategy_id":"strat-xxx"}'
# 影子验证（异步任务）→ status/positions/equity 三表
curl -X POST http://127.0.0.1:8000/shadow/run -H 'Content-Type: application/json' -d '{}'
curl http://127.0.0.1:8000/shadow/status
curl http://127.0.0.1:8000/shadow/positions
curl http://127.0.0.1:8000/shadow/equity
```

## 前端用法（当前 product/ 前端为准）

### 六类任务统一消费（`PA.runTask`）

启动端点：`POST /analyze`、`POST /holdings/analyze`、`POST /brief`、`POST /backtest/run`、
`POST /strategies/run`、`POST /shadow/run`。全部返回 `{task_id}`，SSE 协议统一（§API 5.3）：

- `pipeline`（管道清单）→ 可初始化步骤指示器；
- `progress`（`percent`）→ 进度条；`trace` → 可选内容摘要；
- `stage` 兼容两种形态（结构化 `node_id/phase/…` 或旧式 `node/message`）；
- `result` → 最终结果（各类型结构见 API 文档 §3）；`error`/`done` → 收尾。

晚订阅任务完成会补发 `result` + `done`；`heartbeat` 帧 data 为空，忽略即可。

### 同步直连端点（无需 task_id）

- **查询类**：`GET /holdings`、`/strategies`、`/strategies/{sid}`、`/shadow/status|positions|equity`、
  `/backtest/results|performance[/{code}]`、`/brief/latest` —— 页面加载/切换时按需拉取。
- **操作类**：`POST /watchlist`、`/holdings/save`、`/risk_profile`、`/strategies/{sid}/{action}`
  （activate/reject/retire，返回 `{id,status}`）、`/brief/{id}/dsh-pushed`。
- **KYC**：`GET /kyc/profile` 是渲染问卷的**唯一事实源**（题组/档位/当前状态一次取全）；
  `POST /kyc/questionnaire`（提交计分即生效）、`POST /kyc/adjust`（滑块微调，未问卷返回 409）、
  `POST /kyc/parse`（语音/手打文本→答案，供"补答"预填）。
- **注意 `POST /strategies/hypothesize` 是同步慢接口**（LLM 10–30s），调用方要设足够超时、
  按钮加 loading，不要走 SSE。

### 渲染要点

- 策略池列表（`GET /strategies`）：`status` 用彩色 pill（candidate 灰 / active 绿 / rejected 红 /
  retired 灰）；`backtest.out_of_sample` 展示 `win_rate_pct` / `avg_simulated_return_pct` /
  `portfolio.portfolio_max_drawdown_pct`；样本外不足（`thresholds_pass=false`）提示仍为 candidate。
- 影子三表：`status` 顶部摘要（`overall_nav`/`strategy_count`）；`positions` 每行是"策略×代码"仓位；
  `equity` 不带 `strategy_id` 时按日期画整体净值，带 `strategy_id` 时叠加单策略净值（`strategy.nav`）。
- 简报/简报相关 `summary` 是 Markdown，轻量渲染（同 market-watch 的 `PA.mdLines`）。
- 所有数值字段可能为 `null`（未评估/未触发/从未运行）—— 渲染成 `—`，不要做 `0` 处理。

### 跨模块联动

- `#/strategies`（本模块）的事件源是 market-watch `GET /news/events`；market-watch 未起时
  hypothesize 返回空候选 + `note`，前端应展示提示而非报错。
- 首页"持仓命中"由 market-watch 消费本模块 `GET /holdings`（:8000 在线才显示 hold 命中）。

### 个性化资讯卡片（O 匹配 / C 影响 / D+P 卡片流 / R 行为埋点 / K 画像增强）

首页左栏的个性化资讯流走本模块 `GET /personalized/*`（market-watch 只作事件源，个人化逻辑全在 :8000）：

- **`GET /personalized/cards`** —— 卡片流主端点。`limit` 默认 30（1–100）；`match=1` 只留命中
  关注（持仓/自选/策略）的卡；`bucket=` 可按桶过滤（`holdings|watchlist|strategy|fresh`）。
  排序已由服务端定好（桶优先级 > relevance），前端直接渲染 `cards[]` 顺序即可。
  每张卡 `card_id` 跨刷新稳定，是 R 埋点的回传键；`reasons`（≤3 条）与 `risk.level` 直接展示。
  **C 影响**：卡多出 `impact{codes, industries, by}`（间接波及标的 + 可读原因）。命中关注时
  `reasons` 会追加「间接波及：…」。:8200 挂掉时 `impact` 为空对象，前端不报错。
- **`GET /personalized/matches`** —— "为你推荐"策略（active 策略 × 画像，已排序）。
  渲染 `match_score` + `match_reasons[]`（维度/说明/分数）；`fits_profile=false` 的卡要展示
  `caution` 文案，并可降灰。响应带 `effective_aggression` 与 `behavior`（K 画像增强），
  `profile_fit` 的 note 可能出现「行为画像±Δ：你近期利空事件点击占比 x%」。
- **`POST /personalized/interactions`** —— **view/click 埋点契约**：`card_id` 必须回传渲染时的值；
  `action` 用 `view`（每卡每会话一次）和 `click`（每次打开都记）；`meta` 带上
  `{bucket, ticker, strategy_id, direction, industries}` —— **`direction` 是 K 画像方向偏差的输入**
  （服务端按 `利好`/`利空` 统计；旧记录/缺失按不参与）；**`industries` 是行业亲和归因的输入**
  （取卡片 `impact.industries` 或 `industries`）。埋点是 fire-and-forget，
  **不要 await、不要阻塞渲染**。前端近期 `click` 会让同 ticker 事件卡在服务端 +5 relevance。
- **`POST /personalized/feedback`** —— **显式反馈契约（P→R 决策信号）**：卡片或预警的
  `sentiment` ∈ `useful`(有用) / `useless`(没用)。卡片反馈 `card_id` 用渲染时的 card_id、
  `meta` 带 `{bucket, ticker, strategy_id, direction, industries}`（进 K 画像修正与 V→D 排序）；
  预警反馈 `card_id` 用 `/risk/alerts` 的 `item.id`、`meta` 带 `{source, codes, title}`（进 V→Q）。
  同 fire-and-forget。前端可对按钮即时高亮 + 禁用，防重复。
- **`GET /personalized/interactions?limit=`** —— 调试用：最近埋点。
- **`GET /personalized/profile`** —— **K 行为推断画像**（KYC 页「🧠 行为推断画像」卡的数据源）：
  `base_aggression` vs `effective_aggression`、`behavior.{focus_tickers, direction_skew,
  feedback(useful/useless/delta), outcome(delta/engaged/avg_return_pct/note), outcome_delta,
  interest_tickers, interest_industries, ignored_tickers, industry_affinity, watchlist_tickers,
  trading_affinity, strategy_affinity, notes}`。
  行为数据不足时 `effective_aggression=base`、`notes` 有说明。
  **`behavior.outcome`（R→S→U→K）**：你参与/激活的策略影子 outcome——`samples>0` 时展示
  影子均收益 + outcome 修正量（决策被影子验证则强化激进度、受挫则纠正）；影子净值 <2 日时
  `delta=0` + `note` 说明，**不要渲染成 0 收益**。
- **`GET /personalized/matches`** —— 响应新增 `portfolio_concentration`（N→O 组合集中度信号），
  `items[].breakdown` 含 `diversification` 维度（集中度超标时：重叠持仓策略降权、无重叠加分）。
- **`GET /personalized/cards`** —— **V→D 反馈归因**：你反馈「有用」的个股/行业在服务端 relevance
  +6/+4、反馈「没用」的个股 -4，`reasons` 会带「你反馈有用的个股 / 你关注的行业 / 你反馈无用的个股」。
- **`GET /personalized/impact?limit=`** —— **C 调试端点**：原样返回事件 + `impact_codes/impact_by`，
  验证 :8200 扩展与降级（chain 挂时 impact 为空、接口仍 200）。

**降级语义**：事件源冷缓存时 `cards` 首屏可能为空（下一轮轮询恢复）；`comment=1` 是可选慢增强
（LLM 10s+），前端只在按钮触发时用并给 loading，失败服务端置 `llm_comment=null` 不报错；
**:8200 不可用 → C 扩展自动降级**（卡片/假设行为与无影响图谱时完全一致）。

### 风险预警中心（N 组合风险 / Q 四源预警 / R→V 效果归因）

首页右列顶部「⚠️ 风险预警」面板数据源：

- **`GET /risk/alerts`** —— 四源聚合（组合 N + 影子 I + 事件 F + 画像 K），已按
  `severity 高>中>低` 排序。每项渲染 `severity`（高红/中黄/低灰）+ `source` 标签
  （`portfolio→组合 / shadow→影子 / event→事件 / profile→画像`）+ `title` + `detail` +
  命中 `codes` + 反馈计数 `feedback{useful,useless}`。事件源（market-watch）不可用时该源
  自动缺失，不影响其它源。
- **V→Q 灵敏度校准**：`source=event` 的预警被标记「没用」≥2 次且 ≥ 有用次数时，服务端自动
  `severity` 降一档（高→中/中→低）并在 `detail` 注明「灵敏度已下调」——**组合/影子/画像源永不抑制**。
  前端可给每项预警加 👍/👎 反馈按钮（`POST /personalized/feedback`，`card_id` 用 `item.id`）。
- **R→V 效果漏斗**：响应顶层 `effect{views, clicks, useful, useless, ctr}`（近 N 小时
  曝光→点击→有用/没用），可显示在面板 meta 行作整体归因观察。
- **`GET /risk/portfolio`** —— N 模型明细（`summary` + `breaches[]`），供"组合风险详情"展开。
  影子净值不足 2 日时 `summary.data_note="数据不足"`，回撤/波动为 `null`，**不要渲染成 0**。
  集中度 breach（N=1 单股权重 100% vs 稳健上限 25%）天然命中，是正常提示而非错误。

### 策略自进化闭环（S_shadow→T→W→H + R→S→U→K，`/evolution/*`）

`#/strategies` 页「🧬 自进化」区数据源。闭环用**影子组合**（真实行情+虚拟资金）替身实盘组合：

- **`GET /evolution/status`** —— 就绪度 + 生命周期统计。`ready=false`（影子净值不足
  `min_days`，默认 5 日）时显示「待数据 x/5 日」并给 hint；`counts.watch` = 降级观察中的策略、
  `counts.mutated` = 变异回流后代数。
- **`GET /evolution/attribution`** —— S→T 归因（只读）：`overall` 整体收益/回撤 + 每策略
  `return_pct` / `max_drawdown_pct` / `closed_win_rate_pct` / `closed_trades`。样本不足字段为
  `null`，渲染成 `—`。
- **`POST /evolution/run`** —— `{apply:false}` 预览动作清单；`{apply:true}` 写库执行。返回
  `actions[]`，`type` ∈ `promote/demote/retire/mutate`。数据不足返回 `status=waiting_data` +
  `count=0`，**前端应提示「影子数据不足」而非报错**。执行后刷新 attribution 看生效。
- **策略池联动**：`GET /strategies` 里 `evolve.state=watch` 的策略显示「观察」、`retired` 显示
  「已淘汰」；`source='evolution'` 的 candidate 是变异回流后代（`mutated_from` 指向父策略），
  走正常「回测 → 达标进 active」流程即完成 W→H 再验证闭环。
- **`GET /personalized/profile` → `behavior.outcome`**：R→S→U→K 的 outcome 归因（见上节）。
