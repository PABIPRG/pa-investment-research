# 前端接入指南 —— market-watch 盯盘适配器与 UI 对接

> 面向：接入 `market-watch` Python API 的前端或宿主团队。
> API、请求和响应数据结构的唯一事实来源是 [API-接口文档.md](API-接口文档.md)。

盯盘适配器是**同步 HTTP** 服务，默认地址为 `http://127.0.0.1:8100`。全部端点秒级返回，无任务式接口、无 SSE：前端发起请求 → 直接拿到结果渲染。自选 / 规则 / 简报 / 速递为写操作（落本地 JSON），行情 / 快讯 / 事件 / 扫描 / 技术信号为读操作（TTL 缓存复用，天然适合轮询）。

## 接入边界

```text
UI or host
  -> HTTP client
  -> market-watch adapter (127.0.0.1:8100)
  -> akshare / 东财直连 / 新浪 (行情、新闻、交易日历)
     trading-core :8000 /holdings（事件预警的持仓来源）
```

客户端应负责：请求序列化、超时与取消、轮询节奏、以及把 `null` 行情字段 / 降级数据优雅渲染为 UI 状态。后端负责行情聚合、降级、规则评估、事件抽取和落库；UI 不应复制行情计算或规则判定逻辑。

## 本地联调（当前阶段）

```sh
cd backend/market-watch
# 首次：复制 .env.example 并配置（可选 LLM / 推送，见下）
python -m uvicorn market_watch.app:app --port 8100
curl http://127.0.0.1:8100/health
curl http://127.0.0.1:8100/news/flash?limit=5
curl -X POST http://127.0.0.1:8100/brief/generate -H 'Content-Type: application/json' -d '{"period":"pre","manual":true}'
```

关键 `.env` 开关（前缀 `MW_`）：

| 变量 | 默认 | 说明 |
|---|---|---|
| `MW_SCHEDULE_ENABLED` | true | 定时盯盘/速递/简报 job。本地联调建议关掉，用手动 `/scheduler/tick` 与 `/brief/generate` |
| `MW_LLM_ENABLED` | false | 触发解读 / 新闻摘要 / 简报需 LLM（配 `DEEPSEEK_API_KEY`） |
| `MW_EVENT_ENABLED` | true | 快讯→结构化事件。不开则 `/news/events` 返回空 |
| `MW_FUND_FLOW` | true | 主力资金流（`/overview` 的 `fund_flow_yi`）。关掉可提速、避免东财限流 |
| `MW_PUSH_ENABLED` | false | Server酱 / 企业微信推送（配 `SERVERCHAN_SENDKEY` / `WECOM_WEBHOOK_KEY`） |
| `MW_TRADING_CORE` | `http://127.0.0.1:8000` | 事件预警的持仓来源；trading-core 未起时预警自动降级为仅自选 |

无 LLM / 推送 / 资金流配置时接口**全部可用**（自动降级），是联调的默认姿势。

## 前端用法（当前 product/ 前端为准）

### 轮询节奏（TTL 与缓存决定了合理频率）

| 数据 | 推荐轮询 | 后端缓存 | 说明 |
|---|---|---|---|
| `/news/flash?limit=30&enrich=1` | 30s | 8s | 增量插顶（`time` 字符串比大小去重），上限 60 条；`personal=1` 时全量替换（服务端已重排命中置顶） |
| `/news/event-alerts` | 60s | 事件 60s TTL | 首页预警列表 |
| `/news/latest` | 手动刷新 | — | 速递是"生成一次看一次"，不轮询 |
| `/overview` | 手动 / 30s+ | 行情 60s | 盯盘面板 |
| 其余读接口 | 手动 | 各自 TTL | 扫描 / 技术信号 / 简报都是按钮触发 |

> **别打太密**：行情快照是整市分页拉取（55+ 请求），TTL 60s 就是保护东财 push2 不被限流的闸门；前端 30s 轮询已足够。

### 事件流渲染要点

- 快讯 `enrich=1` 后每项带 `event`（结构化）与 `matched`（`"hit"` 或 `""`）。`direction` 三态映射：利好 → 绿/红、利空 → 红/绿、中性 → 灰；`matched="hit"` 可置顶或加高亮徽标。
- 事件预警 `hit` ∈ `watch` / `hold` / `both` → 显示「自选 / 持仓 / 自选+持仓」；点击条目可跳产业链 `#/chain`（`code` 已含在条目里）。
- 简报 / 速递的 `digest`、`content` 是 Markdown：`## ` 段落、`- ` 列表、普通行三类轻量渲染即可（见 `product/js/home.js` 的 `PA.mdLines`）。
- 所有数值字段可能为 `null`（停牌、新浪源无量比）—— 渲染成 `—`，不要做 `0` 处理。

### 跨模块联动

- `#/strategies`（trading-core）消费本模块 `GET /news/events` 作为事件源 → 假设 → 策略池 → 影子验证。
- 首页 / 盯盘页的"持仓命中"依赖 trading-core `:8000` 在线；不在线时 `/news/event-alerts` 的 `hold` 为空、`watch` 照常。

## dsh 插件（对话工具）

`backend/market-watch/dsh-plugin/` 是 DeepSeek Harness（dsh）插件，把本模块 7 个只读能力注册为对话工具（`mw_` 前缀，全同步）：

- 加载：`npx @deepseek-ai/dsh web --patch backend/market-watch/dsh-plugin/cordis.yml --port 3082`
- 工具：`mw_flash` / `mw_events` / `mw_event_alerts` / `mw_overview` / `mw_scan` / `mw_tech_signal` / `mw_latest_brief`
- 契约：output.schema 与上文「接口契约」各端点一致（`additionalProperties:false`，嵌套结构用 `type:json`）；`npm run smoke` 会对线上返回做实时 schema 覆盖校验，防止字段超纲被拦截。
